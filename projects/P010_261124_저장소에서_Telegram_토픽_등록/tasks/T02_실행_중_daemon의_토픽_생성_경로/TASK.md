## 목적

승인한 로컬 `workspace add`로 실행 중 daemon에 저장소를 추가하고 Telegram 토픽까지 생성·결속한다. 동시 요청과 불명확한 응답은 기존 결속이나 생성 의도를 재사용한다.

## 증명 범위

- 판정 주체: 임시 PACE_HOME·loopback Gateway·가짜 Bot API의 자동 시험과 독립 검토가 P-3·P-4를 판정한다. General 정책은 PROJECT의 사용자 결정에 따른다. P-5 실사용 대상·승인·결과는 사용자가 확인한다.
- 포함: 설정 반영 뒤 토픽 생성·결속, 두 진입점의 동시성·멱등, 확정 실패와 결과 불명 복구, 설정된 이름 범위와 조회 권한, 하위 폴더 CLI에서 첫 토픽 조회까지. 실제 포럼 실측은 PROJECT의 P-5에 연결한다.
- 범위 밖: 토픽·워크스페이스 삭제는 후속 범위다. 실제 Telegram 전송은 main과 사용자가 승인한 시험의 기록을 통해 대조한다.

## 기준

| # | 완료 기준 |
|---|---|
| T-1 | 승인한 로컬 add가 인증된 daemon에서 설정과 코어에 반영되고, 확인된 포럼에서 토픽을 생성하거나 같은 등록 ID의 기존 결속을 쓴다. 정지·어댑터 불가·포럼 불일치 시 설정과 결속 상태를 각각 알린다. (P-3) |
| T-2 | CLI 및 General 요청이 겹치거나 Gateway 응답을 잃고 다시 요청해도 설정이 유실되지 않고 한 등록 ID의 토픽은 하나다. 확정 실패는 안전한 재시도를 허용한다. 결과 불명이나 생성 뒤 결속 기록 실패는 재기동 후에도 의도와 등록 ID를 유지하며 같은 ID의 `/bind`를 안내한다. (P-3) |
| T-3 | General의 `/new <이름>`은 명시적으로 daemon에 노출되고 현재 신원이 유효한 항목만 결속한다. 입력에 경로 또는 추가 인자가 있으면 사용법과 로컬 등록 명령을 안내하고 경로 검증·등록·설정·토픽·생성 의도를 변경하지 않는다. Gateway 인증·Origin 거부, Telegram chat·사용자 허용, 읽기 전용과 쓰기 작업별 승인을 유지한다. (P-4) |
| T-4 | 미등록 Git 저장소의 하위 폴더에서 승인한 뒤 첫 토픽 조회가 그 저장소의 표식에 답한다. 성공·실패 출력, 포럼 본문과 로그에 로컬 경로, 토큰, 채팅 및 토픽 ID가 없다. 자연어 진입점에서 실제 포럼까지의 사용자 확인은 PROJECT P-5에 연결한다. (P-5) |

## 접근

- Gateway는 T01 승인 신원으로 설정을 반영한다. CLI는 확인된 포럼과 daemon이 사용하는 대상을 비교할 수 있는 값을 요청에 전달한다. 토픽 결속 결과는 설정과 별도로 반환한다. 확인 화면 이외의 출력에는 워크스페이스 이름과 상태를 사용한다.
- Telegram 어댑터의 공통 토픽 생성·복구 경로를 Gateway와 General이 함께 쓴다. 같은 워크스페이스의 요청을 합치고 Bot API 호출 전에 생성 의도를 원자적으로 기록한다. 결과 불명·상태 기록 실패가 남아 있으면 설정 확인은 다시 할 수 있고 Bot API 생성 호출은 반복하지 않는다.
- General 명령 입구에서 추가 인자를 거부한다. 정상 입력만 daemon 설정의 이름을 찾고 등록 ID가 붙은 항목은 승인 경로와 파일 신원을 재검증한다. 원격 경로 등록 경로를 제거하고 기존 로컬 등록 경로를 사용한다.
- P-5 실제 포럼 검증은 코디네이터에게 승인과 증거를 요청한다. 이 worktree의 시험은 가짜 Bot API를 사용한다.
