# P-3 기존 결속 표시 회귀

재현은 임시 PACE_HOME, 루프백 Gateway, 가짜 Telegram API에서 실행했다. 실제 CLI로 Git 하위 폴더를 승인하고 자동 생성된 토픽에서 읽기 전용 첫 조회를 확인했다. 같은 등록을 다시 요청할 때만 포럼 조회에 HTTP 503을 주입했다.

| 단계 | 관측 |
|---|---|
| 수정 전 | 기존 결속이 남은 상태에서 CLI가 미결속과 포럼 대조 실패를 표시해 새 단언이 실패했다 |
| 수정 후 | 기존 결속과 포럼 대조 실패를 함께 표시했다. 생성 호출은 전체 한 건에 그쳤고 결속 표는 재요청 전후 동일했다 |
| 미결속 | 포럼 확인 실패 또는 설정 변경 뒤 새 워크스페이스에는 생성 호출이 없고 설정 반영과 미결속을 각각 표시했다 |
| 결과 불명 | 생성 응답을 끊자 의도 한 건과 수동 결속 안내를 유지했다. 고정 이벤트 `telegram_topic_result_unknown reason=api_uncertain`을 한 번 기록했고 재기동 후 재요청은 호출과 진단을 반복하지 않았다 |
| 비노출 | CLI 성공·실패 출력, 모의 포럼 본문 및 로그에 로컬 경로·토큰·채팅 및 토픽 ID가 없었다 |

이 시험의 HTTP 503은 실제 결속 표시 불일치를 재현하기 위한 대역 조건이다. 실제 Telegram 재시험에서 포럼 대조 실패나 생성 결과 불명을 일으킨 원인은 관측되지 않았다.
