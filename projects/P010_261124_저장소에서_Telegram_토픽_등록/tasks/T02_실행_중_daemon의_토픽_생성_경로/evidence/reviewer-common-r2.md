# P010 T02 독립 목표 대조 (1단계)

## 읽은 범위·노출
- 읽은 것은 호출문에 실린 `impl-diff.patch` 본문뿐이다. 저장소 파일은 열지 않았고, 테스트도 실행하지 않았다. 아래 판단은 코드와 시험을 정적으로 읽은 결과다.
- 작업 문서(TASK·테스트 표·자체 판정·지적 대응)는 받지도 읽지도 않았다.
- 호스트가 자동 첨부한 맥락(CLAUDE.md·AGENTS.md, gitStatus, 사용자 이메일)은 이미 노출된 상태다. gitStatus에는 T02 태스크 폴더명이 보이지만 내용은 열지 않았다.
- 읽기 전용이라고 해서 완전한 격리가 보장되는 것은 아니다.
- 사용자 홈과 실제 서비스에는 접속하지 않았고, 파일도 고치지 않았다.

## 시험 검출력
- **임의 형식 오류 시험은 검출력이 있다.** 외부 오류 본문에 home·TOKEN·CHAT·thread를 자유 형식으로 넣고, 출력·daemon 로그·Telegram 송신 본문 전체를 검사한다. 어댑터가 원문을 되돌려 보내면 home·CHAT·thread 검사에서 걸린다. TOKEN은 redactor가 가릴 수 있어 변별력이 약하다.
- **thread 번호가 좋은 표식이다.** 876543210처럼 흔치 않은 값에 숫자 경계 정규식을 써서 우연 일치를 막는다.
- **`createForumTopic` 매개변수 키가 `chat_id`, `name`뿐임을 확인한다.**
- **첫 답변 목적지는 시험 1에서만 검증한다.** `message_thread_id === thread`이고 표식이 포함된 호출이 있는지 본다.

## 지적

1. **should_fix** — 시험 3(General `/new offered` 경로)은 `READ-ONLY-MARKER`를 `mock.texts().some(...)`로만 확인한다. 첫 답변이 새 토픽으로 갔는지 General로 새지 않았는지 가리지 못한다. `message_thread_id === thread`와 General 쪽 미송신을 단언해야 한다. 쓰기 승인 프롬프트의 목적지도 `awaiting_approval` 상태만 보고 있어 같은 문제가 있다.

2. **should_fix** — `getChat` 실패나 `is_forum=false` 상태로 `--yes`를 실행하는 경우, 즉 proof가 null인 경우의 시험이 없다. 시험 2는 확인 뒤 시크릿이 바뀌는 경우만 다룬다. proof가 null이면 생성하지 않는다는 핵심 안전 분기가 코드로만 보장된다.

3. **should_fix** — Gateway 경로에서 `permission`과 `not-forum` 결과를 확인하는 시험이 없다. `telegram-use`의 `/new <이름> <경로>` 경로만 시험한다. 공통 `rejectedTopicState`를 공유하긴 하지만, CLI 출력(`topicStateText`)까지 닿는 시험은 없다.

4. **note** — 이전 버전 상태(`forumKey` 없음)는 첫 기동 때 현재 포럼에 귀속된다. 포럼을 이미 바꿨다면 오귀속될 수 있다. 문서에 경고가 있어 수용 가능하다. 다만 이 경우 자동 감지는 불가능하다.

5. **note** — 의도 기록 뒤 API 호출 전에 daemon이 죽으면 실제 토픽이 없는데도 `/bind`를 안내한다. 사용자가 토픽을 수동으로 만들어야 한다. 안전 쪽 선택이며 문서의 "불명확하면 확인" 문구로 포괄되지만, 토픽이 없으면 직접 만들라는 안내는 없다.

6. **note** — `existing.registryId === undefined && intent === ws.registryId` 합류 조건은 읽기 어렵고 별도 시험이 없다. 레거시(registryId 없는) `/new <이름> <경로>`와 Gateway 요청이 겹치는 경우다.

7. **note** — 시험 4는 `fs.renameSync`를 프로세스 전역에서 바꿔 끼운다. daemon이 같은 프로세스 안에서 돌기 때문에 동작하고 `finally`로 복원도 한다. 시험이 병렬 실행되면 다른 시험에 영향을 줄 수 있다. `node --test` 파일 단위 격리에서는 문제없다.

## 질문별 답

4. **결정 추적:** 문서(`DAEMON.md`)·CLI 도움말·코드가 일관되게 이어진다. 각 결과 코드가 사용자 안내 문구와 복구 절차로 연결된다.
