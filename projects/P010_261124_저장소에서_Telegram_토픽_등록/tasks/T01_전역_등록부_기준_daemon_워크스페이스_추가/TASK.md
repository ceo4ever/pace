## 목적

저장소 안에서 명시적으로 승인한 워크스페이스만 daemon에 노출한다. 전역 등록부의 등록 ID와 승인 당시 경로를 함께 확인해 등록부 이전으로 원격 조회 대상이 조용히 바뀌는 것을 막는다.

## 재료

- `src/project/workspace-registry.ts`의 정의 생성·검증, 등록부 활성화와 이동.
- `src/daemon/instance.ts`의 기기별 인스턴스 소유권, `config.ts`의 원자적 설정 교체, `core.ts`의 작업 접수·파일 조회 대상 확인, `telegram/`의 토픽 결속과 생성 의도.
- [daemon 운영 문서](../../../../docs/DAEMON.md), [보안 기준](../../../../docs/SECURITY.md), [Telegram 어댑터 설계 함정](../../../../.pace/brain/pages/synthesis/telegram-어댑터-설계-함정.md).

## 증명 범위

- 판정 주체: 임시 PACE_HOME·테스트 저장소의 CLI 및 자동화 assertion으로 P-1, P-2의 T01 범위를 판정한다. 독립 사전·사후 검토는 경로·신원·승인 경계를 확인한다.
- 포함: 저장소 발견, 확인과 등록, 설정 소유권, 이전 거부와 명시적 재추가, 기존 설정과 안전한 토픽 신원 호환, 작동 중 설정 반영.
- 범위 밖: Gateway와 Telegram의 공통 토픽 생성 및 사용자 진입점부터 첫 조회까지의 통합 증명은 T02에서 한다. 실제 포럼에서의 증명은 승인과 사람 확인이 필요한 P-5다.

| T-2 | 승인 뒤 신규 저장소는 표준 등록 절차를 사용하고, 기존 활성 저장소는 등록 ID와 이름을 재사용한다. 잘못된 이름·충돌·비활성·정의 불일치·경로 불일치는 설정을 변경하지 않는다. 반복 add는 멱등이며 list는 신원 연결 상태를 경로 없이 보여 준다. (P-1) |
| T-3 | 정지 중에는 포트 소유권을 잡아 설정을 기록한다. 실행 중에는 인증된 소유자가 직렬로 재검증·기록하고 메모리에 반영한다. 소유권·인증·설정 저장 실패는 성공으로 보고하지 않는다. 설정 반영과 토픽 결속 상태는 각각 보고하며 토픽 생성은 T02에서 연결한다. (P-1, P-3의 설정 반영) |
| T-4 | 기동 시 이전되거나 유효하지 않은 등록은 그 항목만 사용에서 제외하고 안내한다. 옛 경로가 남아 있어도 실행 중 다음 작업·파일 조회에서 거부한다. 동일 ID의 명시적 add만 이동을 반영하며 다른 ID의 이름 충돌과 옛 토픽 재연결을 거부한다. 기존 ID 없는 설정과 그 토픽은 호환한다. (P-2) |

## 접근

- CLI는 git 최상위 또는 명시 경로를 실경로로 해석한다. 승인 전에 이름과 대상 계획을 읽고, 승인 뒤 소유권 구간에서 현재 등록·설정을 재확인한다. 등록부의 경로 조회와 ID 조회는 기존 AGENT 검증을 공유하고 비활성·중복·경로 이탈은 거부한다. 등록을 먼저 완료하고 설정 기록이 실패하면 정상 활성 등록을 유지해 재시도할 수 있게 하며, 그 상태를 출력으로 구분한다.
- 기존 이름이 같은 경로를 이미 가리키면 동일 경로·파일 신원 검증 뒤 등록 ID를 보강한다. 이름이 다른 ID에 연결된 항목이나 신원을 확인할 수 없는 이전 결속은 자동 이전하지 않는다. 같은 ID가 이전되면 기존 이름을 유지하고 경로 변경을 다시 승인한 뒤 반영한다. 이전 경로에 고정돼 있던 사용자 지정 워크트리는 새 경로의 조회 대상으로 자동 변환하지 않는다.
- 정지 중 add는 기동과 같은 인스턴스 포트를 사용한다. 실행 중에는 Gateway의 인증 구간에 설정 추가 요청을 연결한다. 설정 변경의 검증·원자적 쓰기·코어 반영을 공통 경로로 묶고 Telegram의 기존 쓰기도 같은 소유자 안에서 직렬화한다. Gateway 연결 실패는 정지 중 쓰기로 대체하지 않는다.
- 기동과 작업 접수 및 파일 조회 때 승인 경로와 등록부·AGENT를 다시 대조한다. 등록형 토픽 결속과 보류 의도는 등록 ID를 사용한다. 기존 이름만 있는 상태는 기존 ID 없는 설정과 호환하되, 신원이 확인된 동일 경로 설정을 보강하는 경우에만 기존 결속의 ID를 기록한다. 이미 해석한 파일 대상의 실경로·dev·ino 확인도 유지한다.
- 승인 화면을 제외한 결과·오류에는 로컬 경로·토큰·채팅 및 토픽 ID를 출력하지 않는다. Telegram 포럼 이름 조회는 읽기 전용으로 하고 시험에서는 가짜 Bot API만 사용한다. 대상 이름을 확인할 수 없어도 정지 중 설정 추가는 할 수 있으며, T02의 외부 토픽 생성은 확인된 대상에만 연결한다.
