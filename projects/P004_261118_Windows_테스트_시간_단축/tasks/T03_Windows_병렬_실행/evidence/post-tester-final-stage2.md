## 대조 중 확인한 사항

- 기본 8의 실제 전체 실패는 제품 시험이 검출한 popup의 `step-failed`다. 단독 1건과 중첩 19파일 181건의 이후 정상 진단은 범위가 다르다. 8이 원인이었는지 확인할 원래 RPC 사유는 남아 있지 않다. BR03의 원인 조사에 대한 실제 처리는 PROJECT의 main 판단대로 8 제외와 별도 4 검증이며, 원인 수정 성과는 보고하지 않는다.
- 초기 프로파일 대조기 종료 1은 Git LF blob과 현재 CRLF 파일의 byte 비교에서 생긴 별도 도구 오류다. 보존된 최초 소스 SHA와 종료 기록을 확인했다. 독립 대조에서 작업본 95개 byte SHA가 측정 환경과 같았다. T02와 Git blob을 직접 비교하면 94개 차이였고, 비교 본문에만 CRLF→LF를 적용하면 변경은 `test/test-command.test.ts` 하나였다. 기본 검사 pass/fail 합계에 초기 대조기 실행을 섞지 않는다.
- TASK 재료의 “현재 worktree의 기본8”은 당시 후보 상태를 적은 문장이며 현재 파일과 시간 표현이 어긋난다. 승인된 TASK의 해시를 바꾸는 대신 마감 문서에서 현재 4와 당시 8을 시점으로 구별할 수 있다. S-2 표는 PID를 명시하며 실제 배리어의 시간 겹침과 RED/GREEN은 시험 코드와 사전 재검토 처리 문서에 남아 있다.
- T01 중앙값 1425.464초 대비 새 기본 4 중앙값 680.918초는 T03 시점의 누적 감소 52.232%다. Git 준비 재사용·중첩 격리·실행기 변경 효과를 분리할 수 없다. 현재 후보나 어느 운영 조건의 장래 무실패를 보장하지 않는다.

독립 실행은 `node --test test/test-command.test.ts` (8 통과, 실패·취소·건너뜀 0), 임시 `cross-check.mjs` (종료 0), 읽기 전용 Git 속성·hash 확인이다. 전체 실행 재수행 및 작업트리 편집은 하지 않았다.
