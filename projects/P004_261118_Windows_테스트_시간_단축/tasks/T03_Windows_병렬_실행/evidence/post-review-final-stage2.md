## 4. reconcile 최초 오류와 수정

**최초 도구의 오류**
- Git LF blob의 해시를 작업본 CRLF byte 해시와 직접 비교해, 여러 파일이 변경된 것으로 잘못 판정했습니다.
- 이는 검증기의 결함이며, 측정 결과에는 영향이 없습니다.
- 도구, 로그, 결과(종료 1)가 보존되었고 시험 실패로 집계되지 않았습니다. 처리가 적절합니다.

**수정된 `reconcile-profile.mjs`**
1. 먼저 작업본의 **정규화하지 않은 byte SHA**를 측정 당시 기록과 대조합니다. 원본 provenance가 유지되고, 측정 뒤 편집이 있었다면 검출됩니다.
2. 그다음 T02 본문 비교에만 CRLF를 LF로 정규화합니다. 정규화가 적용되는 범위가 좁고, 판단 순서도 올바릅니다.
3. 결과는 변경된 test 파일이 `test-command.test.ts` 하나뿐이며, 이는 의도된 변경과 일치합니다.

**남은 한계**
- 줄바꿈만 다른 변경은 의도적으로 같은 것으로 취급합니다(TS 의미상 무해).
- BOM 차이는 변경으로 검출됩니다. 보수적인 쪽으로 동작합니다.
- 그 밖의 대조(파일 집합 = `3ab9b94` ls-tree, 970건 식별자 완전, skip 이름·사유 동일)는 적절합니다.
