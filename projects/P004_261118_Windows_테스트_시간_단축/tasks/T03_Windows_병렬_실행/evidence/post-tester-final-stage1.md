# T03 독립 테스터 1단계

## 판정

관측 자료는 기본 후보 4의 운영 합격 기준을 뒷받침한다. 원시 실행 로그·상태·소스 경계·시험 코드와 T02 원문만 읽고 판단했다. 태스크·프로젝트·사전 검토·작성자 분석을 읽거나 전체 검사를 실행하지 않았다.

- ABBA 4회 모두 970건·통과 961·실패 0·취소 0·건너뜀 9였다. 중앙값 4는 697.559초, 8은 645.735초로 두 표본씩의 중앙값 차이는 7.43%다.
- 기본 8 로그는 실제 override 없이 실행됐다. 당시 실행기 사본의 기본 상수는 8이다. 첫 회 실패의 중첩 원문은 `healer-e2e.test.mjs:206` popup 시나리오에서 `done` 대신 `step-failed`를 관측했다. 현행 실행기와 당시 실행기 차이는 기본값 8→4 한 곳이고, 시험 파일 사본의 차이도 첫 단위 시험 기대값 8→4 한 곳이다.
- 기본 4의 다섯 raw npm 실행 줄에 override가 없었다. 경과 중앙값 680.918초, 범위 680.448~685.689초다. 이 값은 고정 T02의 단회 1423.024초보다 52.15% 짧다. 단회 T02와의 누적 관측 차이다.
- 원시 spec 행 전부를 이름·판정·중복 수·건너뜀 사유로 독립 대조했다. 정상 ABBA·새 기본 4 로그의 T02 대비 차이는 기존 runner 이름 1건 교체와 runner 2건 추가였다. 기존 건너뜀 9개 이름·사유는 동일하다.
- 별도 profile JSONL의 970건 이름·판정·중복 수·건너뜀 사유는 기본 4 원시 인벤토리와 정확히 일치했고, entryFile 요약 95건과 전역 요약 1건을 확인했다. 기본 4 및 profile 종료 경계의 runner와 시험 파일 95개 SHA는 현재 작업본과 일치했다.

## 한계

관측으로 8이 popup 실패를 일으켰는지, 4에서 같은 실패가 재발할지, 외부 호스트 부하가 얼마나 달랐는지는 확인할 수 없다. 4의 다섯 회와 4·8 각 두 회는 이 PC의 표본이다. 기본 로그의 동일 이름은 파일까지 구별할 수 없으며 별도 profile이 파일 식별을 보완한다.
