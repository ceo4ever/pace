## 목적

같은 Windows PC의 다중 코어를 사용해 전체 회귀 시간을 줄이면서 검증 범위와 실패 검출력을 보존한다(P-3·P-6). 범위는 BR03이며, T02에서 승인 선행한 중첩 TMP 최소 수정은 이미 완료됐다. 이번에는 실제 파일 동시성 4·8을 비교하고 안정한 기본값을 검증한다.

- 기준 문서: AGENTS.md·docs/README.md 검사/보안 선언, pace-project-dev testing·reviewer·typescript/verification 색인, 기존 runner/test-command 코드. 공유 가변 상태·실패 재시도 은폐·옵션 전달의 형식만 검사하는 안티패턴을 대조한다.

## 접근

- `scripts/test.ts`에서 Node 옵션을 glob보다 앞에 놓아 기존 extra 인자의 실제 전달을 바로잡는다. 별도 env override나 제품 CLI는 만들지 않고 Node의 `--test-concurrency=N`을 그대로 전달한다. 기본 Windows 값은 비교 중 1을 유지하고, S-4 뒤 선택한 4 또는 8로 바꾼다. 기존 종료·신호 전달은 유지한다. test-command의 기존 순차라는 시험 이름은 새 동시성 계약에 맞게 한 건 명시적으로 이름을 바꾸고 원래 검증을 새 기본값/옵션·실제 실행 검증으로 강화한다. 이름 변경과 새 시험 수를 기준 대조에서 공개한다.
- T01 `measure.ts`에 선택적인 `--concurrency 4|8`과 프로젝트 내부 evidence 출력 위치를 추가한다. 기본 인자 없으면 기존 `npm run check` 경로와 원시 판정은 같다. 명시 비교는 npm의 인자 경계를 거친 `npm run check -- -- --test-concurrency=N`으로 실제 전체 타입 검사와 모든 시험을 실행한다. 보조 프로파일도 같은 옵션 빌더를 사용한다. 가벼운 임시 npm 표본에서 실제 전달을 먼저 확인하고, command/argv/선택값·실행 전 test 파일 목록/해시를 metadata에 남긴다. 실패·취소·불완전 관측 즉시 중단, 원래 실패를 재시도로 대체하지 않는다.
- T03 도구는 4→8→8→4를 각각 새 폴더/소유 TMP에서 직렬 호출하고 원문·각 판정·이름/판정 다중집합·skip 사유를 대조한다. 초기 속도 후보 규칙은 두 값 모두 정상일 때8 중앙값이4보다 최소5% 빠르면8, 그 외는4다. 이 비교에서 얻은 초기 후보8과 비교 JSON은 바꾸지 않는다. 후속 안정성 묶음에서 실패한8을 제외하고4를 다음 후보로 삼는 main 판단을 별도 선택 결정 자료로 연결한다. 안정성 우선 선택은 원인 수정이나8의 실패가 사라졌다는 주장이 아니다. 다른 후보로의 전환만으로 기존 비교4회를 다시 성공 표본으로 고르지 않으며, 실제 비교 소스/환경을 무효화하는 차이나 버그 수정은 양쪽 새4회 묶음으로 구분한다.
- 새 사전 재검토 통과 뒤 Windows 기본값과 첫 unit 기대만8→4로 바꾼다. 고정 코드에서 override 없는 새 연속5회를 수행하며, 비교4회나 실패한8의 첫 회차를 섞지 않는다. 소스 시작/종료 경계는95개 test 목록/SHA·runner/helper·측정5개 도구 SHA·commit·관련Git 상태/diff로 대조하고, raw npm 줄의 override 없음과 고정 runner의 기본4를 연결한다. 이는 시작/종료 스냅숏이지 연속 감시는 아니다. 선택 대조 도구는 숫자 인자만 믿지 않고 원래 비교의 초기8 선택·8 안정성 실패·main 판단의 다음 후보4를 연결한 결정 자료와 일치시킨다.
- 4에서도 전체 실패·취소·중단이나 실제 소스 차이가 생기면 원문을 보존하고 즉시 main에 판단을 올린다. 성공을 고르는 재시도나 시험/skip 완화는 하지 않는다. 8의 전체 부하 진단과 제품 동작 수정도 현재 범위에서 진행하지 않는다. 적합한 후보가 없을 때의 순차1 유지/필요 순차 파일 분리는 main 판단으로 올리며, 미검증 후보를 완료로 표시하지 않는다.
- 연속5회가 통과한 뒤1회 별도 보조 프로파일에서 실제 파일/시험 식별자와 판정을 대조해 기본 spec의 중복 이름 한계를 보완한다. T02 대비 시험 이름/수의 의도한 변경과 이유를 목록으로 남기며 기존19개 중첩·검증 단언·skip은 보존한다. 다른 시험/진단을 측정과 겹치지 않고 기록/읽기 부하 한계는 공개한다.
- 원시 증거를 보존하도록 프로젝트 evidence 경로에만 Git text 변환을 끄고, core.autocrlf=true checkout 필터를 읽기 비교해 해시를 확인한다. 도구 소스/호스트/부하/동시 작업의 한계를 공개하고 가변 원본·사용자 Git 설정을 수정하지 않는다. 보조 프로파일·진단은 성능 평가 표본과 분리한다. T03 완료가 P-6 최종 달성 자체를 뜻하지 않으며 T04 이후/최종3회로 다시 판단한다.
