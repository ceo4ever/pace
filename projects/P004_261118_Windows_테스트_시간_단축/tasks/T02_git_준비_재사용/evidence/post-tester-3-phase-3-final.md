## 독립 실행과 증거 경계

- 작업본에서 저장된 증거를 읽고 owned temp에만 사본·TAP·결과를 기록했습니다. phase-3-executable.mjs와 phase-3-executable.log가 독립 대조의 실행 원문입니다. 첫 파싱은 spec의 들여쓴 하위 검사 4건을 놓쳤고 이를 포함하도록 파서를 바로잡아 다시 실행했습니다. 수정한 비교는 기준 세 원문 및 후보에서 모든 fixture를 포함한 이름/순번/판정을 각각 JSON과 일치시켰습니다.
- trace 진단은 원래 상속 OWNER/PARENT를 지웠으므로 그 자체는 실제 상속 경로의 증거 범위를 벗어납니다. 독립 짧은 guard 실행은 실제 helper로 부모를 먼저 초기화해 OWNER/PARENT를 상속했습니다. guard peer/own 두 자식 모두 부모 TMP 아래가 아닌 형제 소유 루트와 별도 PACE_HOME을 받았고 종료 뒤 각 루트가 사라졌습니다. peer-inherited.tap 및 own-inherited.tap이 직접 증거입니다.
- 최초 실패 전체 관측은 상태 1로 보존됐습니다. 별도 자연 중첩 진단은 같은 저장 경계 사례의 실패를 드러냈지만, 최초 실행의 잘렸던 내부 로그에서 같은 사례를 확정할 수 없습니다.
- 전체 벽시계는 기준 3회 중앙값 1425.464초와 수정 후 단회 1423.024초로 2.440초(0.17%) 차이입니다. 수정 후 표본에는 격리와 캡처 변경도 포함됩니다. 차이를 Git 준비 재사용 단독 효과나 확정된 전체 개선율로 귀속할 근거는 없습니다. P004 최종 절반 시간 목표와 반복 안정성은 이후 계약에 속합니다.
- 전체 또는 19파일 중첩 검사는 별도로 다시 돌리지 않았습니다. 현 판정은 보존된 타임스탬프 원문과 두 개의 짧은 상속 검증을 바탕으로 합니다. 동일 제공자 내 독립 자식 세션이라는 한계는 phase-1.md에 기록했습니다.
