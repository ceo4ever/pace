판단 근거는 diff, 테스트 원문, 벤치마크 JSON, 전체 검사 인벤토리, 그리고 이번에 받은 TASK·PROJECT·BR02·audit·helpers 코드입니다. 작성자 결론은 근거로 쓰지 않았습니다.

## 1. 코드 판정: **pass** (blocking 0 · should_fix 0 · nit 5)

### 1단계 지적 처리 (새 문맥으로 재판정)

| 1단계 지적 | 판정 | 근거 |
|---|---|---|
| `PACE_TEST_TMP_PARENT` 미설정 시 테스트 실패 | **해소** | `test/helpers.ts`가 import될 때 항상 이 값을 설정합니다. `tempRoot` 기준 상대 경로가 `..`이므로 거부 경로가 정상 동작합니다. |

### nit (승인을 막지 않음)

1. `test/helpers.ts`의 `reusableGitFixture`: `firstDestination` 인자를 두 소비자 모두 쓰지 않습니다. SF-1 처리 과정에서 설계가 바뀌었는데 TASK의 "접근" 절 문구는 갱신되지 않았습니다. 이는 문서 계층의 문제입니다.
2. 같은 함수의 자기완결 검사가 `objects/info/http-alternates`와 `.git/commondir`를 확인하지 않습니다. callback을 시험이 소유하므로 위험은 낮습니다.
3. HEAD 확인의 `timeout: 5000`은 Windows의 백신 부하 상황에서 일시적 실패 여지가 있습니다.
4. `test/project-harness.test.ts`의 새 테스트가 원본을 `pace-git-seed-` 접두사로 찾고, 원본 경로에서 Git을 실행합니다. 읽기 전용 조회이긴 하지만 "원본은 읽기 전용으로 취급"한다는 규칙을 테스트 자신이 건드리는 셈이고, 내부 명명에 결합되어 있습니다.
5. 원본 준비가 실패하면 `fixtureContexts`에 해당 항목이 남습니다. 정상 경로에는 영향이 없습니다.

### 실제 지원 경계

- **지원:** 동기 prepare, 일반 파일만 있는 트리, 자체 `.git` 디렉터리, 소유 `tempRoot` 아래의 빈 대상. 캐시는 Node 파일 프로세스 하나, 형태 하나 단위입니다.
- **미지원·거부:** symlink, gitfile, alternates, worktree나 hooksPath 연결, unborn 저장소, 프로세스 간 공유.
- dashboard-init 등 init 경로 자체를 검증하는 시험은 전환하지 않았습니다. BR02의 제외 범위와 맞습니다.

### 소유권과 실제 Git 동작

- 원본과 대상 모두 프로세스 소유 `tempRoot` 안에 있습니다.
- helper는 사용자 Git 설정을 바꾸지 않습니다. HEAD 확인에는 원본 전용 HOME을 씁니다.
- agent-chain의 원본 준비는 기존 프로세스 환경을 그대로 상속합니다. T02가 새로 도입한 동작은 아닙니다.
- 복사본은 실제 Git 저장소입니다. 초기 SHA와 커밋 시각을 공유하고 index stat 정보가 다시 계산되는데, 이 점은 audit에 공개되어 있습니다.

### 회귀 검출력

- hardlink나 shared object로 바꾸면 object 손상 단언에서 검출됩니다.
- config를 공유하게 되면 `only-a` 단언에서 검출됩니다.
- 원본이 변경되면 digest 비교에서 검출됩니다.
- 실패한 준비나 복사가 캐시되면 `called === 2` 단언에서 검출됩니다.
- HOME 문맥 가로채기는 owner 태그 단언에서 검출됩니다.
- index 독립성은 직접 단언하지 않고 commit 뒤 `status`가 깨끗한지로 간접 확인합니다.

## 2. 사전 검토 should_fix 처리 확인

- **SF-1 확인:** 원본 전용 HOME과 bin을 쓰고, 문맥 키는 원본의 정확한 경로만 등록합니다. 조회는 정확 일치와 자손 접두사를 모두 확인하며, 세 HOME이 분리된다는 실제 Git 테스트가 통과했습니다.
- **SF-2 문서상 확인:** audit에 SHA, 커밋 시각, index 대조가 있고 기존 본문 해시가 바뀌지 않았습니다. 다만 audit이 인용한 원래 행 번호는 이번 검토에서 직접 대조하지 못했습니다.
- **SF-3 확인:** agent-chain은 기존 `git` helper를 그대로 사용합니다.
- **SF-4 확인:** 대상 경로는 `pace-harness-…/app`과 `tempDir` 그대로이고, `basename === "app"`을 단언합니다.
