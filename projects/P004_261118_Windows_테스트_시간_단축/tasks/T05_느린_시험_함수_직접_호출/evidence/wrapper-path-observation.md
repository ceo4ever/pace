# Windows 래퍼 경로 좁은 관측 1회

main이 승인한 소유 임시 사본의 대상 시험 1회만 실행했다. 실제 시험·제품·설치 스크립트·사용자 설정은 바꾸지 않았다. 원래 경로 문자열 단언을 포함해 기존 단언을 유지했고, 두 Bash 안에서 각각 경로의 Windows 변환값과 환경을 stderr로 관측했다. 추가 관측 호출은 스케줄을 바꾸므로 원래 전체 실패의 정확한 재현이 아니다.

`wrapper-path-diagnostic/manifest.json`과 `run.log`에 원문·실행 인자·소스 SHA가 있다. 대상 1건 통과, 실패/취소/skip 0, 종료 0, 벽시계 3418.043ms다. 첫 Bash의 command-v와 둘째 Bash의 cygpath 결과는 모두 `/tmp/...`였다. 같은 문맥에서 Windows로 변환한 두 경로와 Node 예상 파일은 native realpath가 같고 dev=346249331, ino=15762598696625277인 파일로 확인했다. 원래 경로 단언 통과 뒤 hook 단계에 도달했고 나머지 기존 단언까지 통과했다.

이번에는 서로 다른 `/tmp/...`와 `/c/Users/...` 표기가 발생하지 않았다. 따라서 서로 다른 표기가 동일 물리 파일을 가리킨다는 과거 실패의 원인은 미확정이다. 관측에서 확인한 동일 파일은 이번 한 실행의 세 경로에만 해당한다. 과거 전체 실패에서 hook/인자 단계는 경로 단언 뒤라 미도달이었다. 추가 재현·시험 수정·새 전체 실행은 하지 않았으며 T-2 전체, T-3/P-6, T05 마감과 finish는 미충족으로 유지한다.

# 함수 전환 독립 사후 검토 연결

main이 제공한 새 독립 reviewer(Claude Opus 5.5/anthropic)의 2단계 읽기 검토는 함수 전환 3개·어댑터·Telegram 수정 코드 pass, blocking 0, should_fix 0, nit 4다. 새 독립 tester(Codex/openai)의 2단계 읽기 검토는 T-1/P-5 및 T-2 구현·집중 증거를 통과로 판단했다. 두 검토 모두 전체 세트 무효와 T-2 전체/T-3/P-6 및 마감 미충족을 유지한다. 새 시험이나 설치를 실행한 검토가 아니다.

원문 4개는 비밀 탐지 확인 뒤 `function-independent-post-review/`에 그대로 복사했고 provenance에 출처와 SHA를 남겼다. nit 때문에 실행 소스를 바꾸지 않았다. M1은 status 단언에서 먼저 검출, M2는 실제 직접 merge 뒤 검출, M3는 유지 CLI 증거라는 한계, 좁은 단회 전후 비교와 원문 소스 참조 방식의 한계도 유지한다. 검토의 구현 pass를 태스크 전체 pass로 사용하지 않는다.
