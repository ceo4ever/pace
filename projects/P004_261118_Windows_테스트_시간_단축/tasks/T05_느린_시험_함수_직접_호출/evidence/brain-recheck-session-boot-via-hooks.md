
## 결정

**세션 시작 훅이 `pace boot --host <도구>`를 호출**해 SOUL·USER·RULES·메모리·현재 위치를 주입한다.
RULES는 프로필이 아니라 설치본의 시스템 규칙(`~/.pace/app/templates/RULES.md`)을 읽는다. POSIX 훅이 부르는 `~/.pace/bin/pace`는 설치본을 실행하는 작은 스크립트다(복사 설치). Windows 훅은 슬래시 경로의 Node 진입점을 직접 호출한다.

버린 대안: 첫 메시지마다 활성화 명령을 실행하게 하고 문서 receipt·이벤트를 불러오는 방식 — 약 6~8천 토큰과 도구 호출 1회가 매 세션 든다.

## 이유

- 호스트 훅을 이용해 부트를 시도한다. Cursor 비차단 훅이 첫 응답보다 늦어지는 사례가 관측돼 수신은 별도로 검증한다.
- 도구 호출 한 번과 이벤트 로딩이 사라진다.
- 도구별 차이는 출력 형식(`--host`)에만 둔다 — `hookSpecificOutput.additionalContext`(Claude·Codex·Gemini), `additional_context`(Cursor).

## 대체 규칙

훅이 없거나 맥락이 안 들어가는 도구를 위해 "`[PACE-BOOT]` 표지가 없으면 첫 응답 전에 `pace boot --host plain`을 실행하라"는 한 줄을 둔다.
Codex `config.toml` developer_instructions, Gemini의 `GEMINI.md`, Cursor 규칙을 사용한다. Cursor는 시작 훅과 표지 확인 규칙을 병행하기로 결정했으나 전역 규칙 적용 및 훅 후착 시 중복 방지는 검증하지 않았다.

## 지킬 것

부트는 어떤 오류에도 종료 코드 0과 유효한 형식을 낸다(세션을 막지 않음). 표준입력이 닫히지 않는 도구가 있어 0.5초 뒤 진행한다.
부트의 git 호출은 시간 제한(2초)과 원격 지연 가져오기 금지로 묶는다 — 큰 저장소나 느린 원격에서 세션 시작이 늘어지지 않게(보안 검토).

## 크기 예산과 순서

함정: Claude Code는 훅 출력이 약 1만 자를 넘으면 파일로 빼고 모델에는 앞 약 2,000자만 준다 — 2026-10-31 실측 10,437자(표시 "10.2KB" = 글자 수÷1024)에서 RULES 중간까지만 전달되어 메모리·현재 위치 없이 일하는 조용한 실패가 났다.

- 예산 `BOOT_BUDGET = 8000`자(JS 문자열 길이). 넘으면 메모리 목록 절(rule·open·index)을 10→5→3→1→0개로 줄이고 "외 N건 — `pace memory list`" 줄을 남긴다. SOUL·USER·지침·RULES는 줄이지 않는다. 메모리 파일은 한 번만 읽고 렌더만 반복한다.
- 순서: 머리말 → 첫 응답 지침 → SOUL → USER → 현재 위치(+하네스) → 프로젝트 메모리 → 프로필 메모리 → RULES. 잘려도 정체성·상태가 먼저 간다.
- RULES는 한글로 압축했다(같은 문장 영어가 1.86배 길어 글자 수 한도에 불리). 상세는 영어 스킬(`pace-memory`·`pace-brain`)로 뒀다. 처음 1,200자였던 RULES 단위 상한은 공통 사고 원칙 추가에 맞춰 1,700자로 조정했다. 부트 8,000자·전문 보존 가드는 유지한다.

## 전달 경계 재확인 (2026-11-01)

현재 부트는 SOUL·USER·RULES·프로필/프로젝트 메모리·상태를 같은 훅 출력에 넣는다(`src/boot.ts`). 8,000자 예산은 메모리 항목만 줄이는 최선 노력 가드라 긴 비축약 절이 있으면 절대 상한이 아니다.

Claude Code 2.1.316 변경 기록은 훅 출력 10,000자 초과 시 파일 저장과 앞 2,000자 미리보기를 명시한다. Codex 공식 문서는 핸들러당 기본 약 2,500토큰 초과 시 파일 저장·앞뒤 미리보기를 명시한다. Cursor의 sessionStart는 비차단이며 숫자 출력 한도는 문서에서 확인되지 않는다. Antigravity IDE의 SessionStart 직접 수신은 합성 세션에서 관측했고 전역 공유 훅은 소스에 구현됐다. 실제 설치본의 수신은 검증하지 않았다. Antigravity 규칙 파일 한도는 각 24,000바이트, 활성 규칙 합계 20,000토큰이다. 이 숫자들은 서로 다른 전달 경로의 한도라 하나의 글자 수 예산으로 첫 응답 수신을 보장하지 않는다. 근거: https://github.com/anthropics/claude-code/blob/v2.1.316/CHANGELOG.md, https://learn.chatgpt.com/docs/hooks, https://cursor.com/docs/hooks, https://antigravity.google/docs/hooks, https://antigravity.google/docs/rules/ (2026-11-01 확인).

호스트 지침 파일에 옮긴 내용도 모델의 같은 컨텍스트를 차지한다. 전달 경로와 총 맥락 사용량은 별개로 검증해야 한다.

## 묶음 조회와 관측의 로컬 성능

2026-11-01, Apple M1 Pro·Node v25.8.2·합성 데이터 홈에서 애플리케이션 캐시 없이 실험했다(`scripts/benchmark-boot.ts`). 파일 묶음 읽기·SHA-256·시각·휴리스틱 토큰 추정·버퍼 JSONL append를 각 200회 교차 실행한 최종 p95는 4파일 0.298ms, 24파일 1.092ms, 104파일 4.243ms였다. 기존 부트 결과에 절별 관측을 붙인 코드 구간만의 p95는 0.384ms였다. 로컬 지연 기준을 넘지 않아 캐시는 구현하지 않았다.

24파일을 벤치마크 모듈 하나로 반환하는 Node 프로세스 호출은 p95 193.377ms(로그 포함), 파일별 프로세스 24개 순차 호출은 4280.837ms였다(각 12회). 이 값은 동일 모듈 로딩을 포함하며 호스트 네이티브 읽기 도구·LLM 왕복 비용이 아니다. 초기 부트에서는 반복 호출을 줄이는 방향을 검토할 근거이며 운영 기능을 배포한 결과는 아니다.

OS 캐시는 비우지 않았고 fsync·원격 디스크·동시 세션·모델 토크나이저·다섯 호스트 첫 응답은 미측정이다. 토큰 수는 ASCII/4+비ASCII/2 휴리스틱으로 정확도 미검증이다. 기존 부트의 전체 실행 차이는 git 지연 변동도 포함하므로 관측 자체 시간과 구분한다.

## 하네스 worktree의 프로젝트 역할

전역 등록부에는 기동 원본 워크스페이스만 둔다. 개발 worktree는 기존 하네스가 현재 `project/P###` 분기·실제 경로와 진행 상태를 검증하며, 원본 활성 등록과 현재 worktree의 유효 AGENT ID가 같을 때만 현재 worktree의 역할을 읽는다. 다른 분기·clone·중첩 정의·ID 불일치는 주입하지 않는다. Git 지연은 부트 공유 기한으로 제한하고 하네스나 변경 상태를 확인하지 못하면 미확인으로 표시한다. 합성 Claude·Codex worktree 새 세션의 첫 응답은 역할을 수신했으며 GUI 호스트와 Windows 실측은 미검증이다.

## 프로필과 역할 표제

새 역할 정의는 선택한 프로필 이름을 표제에 넣고 예약 주석이 붙은 자동 표제는 부트 전달 시 현재 프로필 이름으로 렌더링한다. 원본은 보존하며 예약 관리 주석 단독 행은 모델 맥락에 전달하지 않는다. 표지가 없는 기존 사용자 표제는 그대로 둔다.

## 업무 독립 사고 원칙의 전달 예산

2026-11-08 측정에서 RULES는 원문 1,632자(trim 1,631자)였다. 기본 SOUL의 합성 대표 프로필(메모리 18건)은 3,787자, 대형 프로필(240건·긴 진행 상태)은 5,506자로 8,000자 예산 안에서 RULES 전문을 보존했다. 소스 출력 실측은 호스트 실제 수신을 보장하지 않으므로 새 세션 수신 판정은 별도로 받아야 한다. 긴 SOUL·USER 등 비축약 절만으로 예산을 넘는 기존 한계도 남는다.

### 독립 검토 뒤 합성 조건 강화

후속 검토에서 작은 일은 전략을 속으로 따질 수 있고 따로 보고하지 않아도 됨을 명시했다. RULES 원문은 1,632자(trim 1,631자), 원칙 추가 전 원문 1,191자 대비 +441자다. 2026-11-08 개인 rule 16건 이상, SOUL 1,097자·USER 281자로 합성 조건을 강화한 소스 부트는 대표 5,853자·대형 6,258자(Codex 표기), Claude 표기는 각각 1자 더 길었다. 둘 다 전문을 보존한다. 사용자 전체나 긴 보호 절의 모든 경우를 대표하지 않으며, 호스트 봉투 길이로 토큰 한도나 실제 모델 수신을 보장하지 않는다.

## 변경 기반 검사 추가 뒤 근거 대조 (2026-11-19)

P004 T04의 근거 변경을 대조했다. cli.ts 변경은 test changed 도움말이며 기존 부트·브레인·프로젝트 명령 분기는 그대로다. harness.ts는 정의서 목록 export, changed 전용 검증 commit 인자 및 셸의 구조화된 실행 상태를 추가했다. 인자를 생략한 기존 all/finish의 main 기준과 ok/output 계약은 유지하며, 설치·프로젝트 생명주기·지표·사건·부트 전달은 변경하지 않았다. README의 OPAL 채택 경로도 유지했다. 따라서 위 기존 주장과 실측의 역사적 한계를 유지한다. 원래 시험 본문과 최종995건의 범위/판정 보존은 T04 TASK-CLOSE 및 t03-regression-comparison에 연결되어 있다.

변경 기반 검사는 별도 경계다. 현재 staged/unstaged/untracked 작업본만 대상으로, 기준 commit과 같은 map의 명시 checks를 먼저 실행한다. 숨김 index/sparse·삭제·미분류·불확실성은 실제 전체 검사로 전환하고, 시작 후 실제 실패1·예외 확인 불가3은 성공으로 숨기지 않는다. 커밋된 브랜치 차이는 빠른 범위에 포함하지 않으며 finish 전체 검사를 유지한다. 자세한 근거는 [[변경-기반-검사와-실행-선언-신뢰-경계]]다. Windows 관측을 실제 설치기·POSIX·다른 프로젝트 일반 성능 검증으로 확대하지 않는다.
