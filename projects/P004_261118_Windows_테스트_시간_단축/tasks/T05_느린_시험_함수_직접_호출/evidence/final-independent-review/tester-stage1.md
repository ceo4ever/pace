# T05 최종 독립 검토 1단계

최종 실행 원문, 코드 diff와 계산 결과를 먼저 검토했다. 최종 TASK·PRE-REVIEW·작성자 마감 판정은 이 단계에서 읽지 않았다.

## 판정

새 고정 소스에 대한 전체 검사 3회는 각각 종료 0, 996건 중 987통과, 실패·취소 0, skip 9였다. 각각의 원래 로그에서 집계와 사례별 이름·판정·밀리초를 다시 파싱해 `results.json`과 일치함을 확인했다. T03 기준 로그 다섯 회 각각의 970건에 T04 소스에서 읽은 25개 이름과 T05 신규 어댑터 한 건을 더한 결과가 최종 세 회의 인벤토리와 모두 일치했고, skip의 이름·사유·개수도 모두 동일했다. T04 복구 후 전체 원문 995건과 별도로 대조해 어댑터 한 건만 추가됐음을 확인했다.

## Windows 경계

Windows 실제 Git Bash 사례 하나와 그 import만 바뀌었다. `command -v pace`의 실제 선택 경로를 cygpath의 Windows 절대 경로로 읽고, 일반 파일, fixture의 canonical 부모 디렉터리, wrapper의 canonical 경로와 bigint 장치·inode까지 확인한다. 버전 출력, 기존 커밋 훅과 인자 단언은 diff에서 유지됐다. 소유 fixture 실측에서 `/tmp/…`와 `/c/Users/…` 별칭은 동일 경로·파일 정체성이었고, 다른 파일은 구별됐다. 테스트 파일 전체는 10/10 통과했다. 틀린 파일 대조용 사본은 후보 경로 하나만 `.pace/app/bin/pace.ts`로 바꿨고, 해당 단독 테스트가 실제 `.pace/bin` 부모 단언에서 실패했다. 실행된 양성 사본 SHA는 현재 파일과 같고, 음성 사본 SHA는 실행 기록과 같았다. 과거 실패 회차의 스케줄이나 그 시점에 별칭이 선택된 원인은 재현·확정하지 않았다.

## 소스 및 도구 경계

609개 파일의 시작·종료 목록과 해시는 일치한다. 현재 파일도 609개 모두 직접 해시해 일치함을 확인했다. 직전 함수 전환 세트의 종료 스냅샷과 비교했을 때 실행 소스 차이는 Windows wrapper 테스트 한 파일이다. 기준 T03의 95개 기존 테스트 파일 중 92개 SHA가 그대로이며 세 예외는 Telegram, 프로젝트 하네스, Windows wrapper다. T04 신규 테스트 파일 하나도 기록과 일치한다. runner와 공용 테스트 helper 해시는 T03과 최종에서 동일하다. 세 원문 로그와 결과 JSON의 해시를 최종 고정 바인딩과 대조했다.

최초 결과 검증기의 기준선 탐색은 원래 숫자 1425464.3326999997ms를 문서 반올림 숫자 1425464.3327ms와 엄격 비교해 실패했다. 실행된 검증기의 원본과 수정본 diff를 확인했다. 새 검증기는 원래 유효한 비계측 3회 기준선의 유일성을 요구하고 원래 회차에서 중앙값을 다시 계산한다. 기존 부분 결과 폴더를 보존하고 새 검증 결과만 다른 폴더에 쓴다. 최초 검증기 실패와 원래 전체 검사 프로세스의 종료 0은 별개다. 이전 세 측정 세트의 각 `valid:false` summary와 원래 로그가 남아 있다.

이 검토에서 전체 검사·테스트를 실행하지 않았다. 읽기, 독립 파싱, 해시와 diff만 사용했다.
