# T05 최종 독립 검토 2단계

## 테스터 판정

T-1~T-3, BR05 및 P-5/P-6의 결과 증거를 통과로 판단한다. 최종 독립 테스터 기준에 미해결 차단은 없다. 사후 reviewer 판정 및 TASK-CLOSE/check/done/커밋과 이후 프로젝트 finish는 이번 결과로 대신하지 않는다.

현재 TASK의 CRLF와 상태 행을 저장소 규칙대로 정규화해 SHA-256을 계산했다. PRE-REVIEW 마지막 시도의 `492ef2ab5b79e6bbeab52d3a9f7754d77cb098a9550325ccb4f92d786a794e02`와 일치한다. 마지막 검토는 동일 교차 제공자의 pass, blocking 0, continuity same이다. 사전 검토의 두 후속 항목은 실제 diff에서 확인했다. 관측 경로의 일반 파일·실제 native 부모·예상 native 파일·장치·inode를 모두 단언하며, Bash에서 변환 전 `command -v` 원본을 stderr에 기록하고 `&&`로 실패를 전달한다.

- T-1/P-5/BR05. 세 로직 시험의 반복 실행은 동일 fixture 안에서 실제 제품 main을 직접 호출한다. 대표 CLI, 실제 Git 및 EIO 주입 경계는 유지한다. 같은 세 사례 선택의 단일 전후 벽시계는 121.918초→107.391초이며 변이 검증과 기존 단언, 74건 하네스 파일 통과가 앞선 원문에 남아 있다. Telegram의 의도 저장 후 토픽 표 단계 주입 검증을 새 최종 세 회의 결과에도 연결했다. 전체 시간 목표에 도달했으므로 추가 전환 없이 종료한다.
- T-2. 기존 970건, T04 신규 25건, T05 신규 1건의 이름·판정·개수·skip 사유를 T03 다섯 세트와 T04 최종 원문에 각각 대조했다. Windows 잘못된 파일 변이는 일반 파일 단언을 통과하고 부모 native 경로 단언에서 실패했다. 독립 별칭 비교가 실제 장치·inode의 양성·음성 차이를 보완한다. 파일 전체 10건과 최종 모든 회차가 통과했다. TASK의 S-4에 적힌 93개 동일은 원래 함수 전환 단계의 범위다. 이후 사전 검토를 거친 Windows 수정으로 최종 허용 예외는 3개, 동일 원본 파일은 92개이며 원래 함수/Telegram 감사 근거는 유지됐다.
- T-3/P-6. 새 고정 609개 소스로 실행한 비계측 `npm run check`가 연속 3회 종료 0이며, 회차마다 996건 중 987통과, 실패·취소 0, skip 9다. 동일 장비와 검증된 원래 T01 기준에서 중앙값은 1425464.3326999997ms→705472.9278ms로 50.5093% 줄었다. 절반 기준과의 차이는 7259.23855ms다. 다른 장비·실행에 대한 속도 보장이나 T05 단독 기여도 추정에는 이 수치를 적용할 수 없다.

## 오류 및 원문 보존

이전 무효 세트를 판정에 넣지 않았다. 세 세트의 원문과 `valid:false`를 확인했다. 각 실패는 Telegram /new 저장 단계, 동시 stale-lock 복구, Windows Git Bash 문자열 비교였다. 이번 결과가 과거 stale-lock이나 Git Bash 경로가 달라진 발생 조건을 확정하지 않는다.

집중 검사 도구의 최초 종료 1은 두 실행이 끝난 뒤 발생했다. `validate-wrapper.mjs`가 음성 로그에 단언 코드가 반드시 인쇄될 것으로 가정했으나 사용자 지정 오류 메시지가 `generatedMessage:false`와 함께 표시됐다. 원문 스택 124행·10열, 기록된 시험 사본의 실제 단언, 정해진 음성 변경, 원본 SHA 및 두 로그를 읽기 전용으로 대조했다. 양성 10건 통과와 의도한 음성 실패가 그대로다.

전체 회차 판독기의 최초 종료 1은 세 npm check와 측정 종료 0 이후, 원래 기준선 중앙값과 문서에 반올림한 숫자의 엄격한 일치 비교에서 발생했다. 검증기와 이를 호출한 launcher의 종료 1 기록 및 최초 부분 산출물은 남아 있다. 수정 판독기는 날짜형 디렉터리에서 유일한 원래 유효 비계측 3회 자료를 고르고 원문으로 중앙값을 다시 검증한다. 별도 폴더에 읽기 결과를 냈고 시험·측정 샘플을 다시 실행하거나 바꾸지 않았다. 검증기 전후 및 최초 집중 도구 원본 해시가 해당 기록과 일치한다.

이 단계에서 업데이트된 TASK·PRE-REVIEW·PROJECT P-5/P-6·BR05와 작성자 결과를 읽고 독립 1단계 결과에 대조했다. 두 단계 모두 시험을 재실행하거나 worktree를 변경하지 않았다. 시작·종료 스냅샷은 그 두 시점의 바이트를 확인하며 연속 호스트 감시는 아니다.
