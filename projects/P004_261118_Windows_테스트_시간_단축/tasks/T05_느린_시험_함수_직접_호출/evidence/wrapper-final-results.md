## 최종 판독기 오류와 읽기 검증 정정

세 npm check와 측정 도구 자체는 모두 종료0이었다. 종료 스냅숏과 binding 작성 뒤 verify-final.mjs가 기준선 후보를 원값 `1425464.3326999997`과 문서의 반올림 표시 literal `1425464.3327`의 엄격한 동일성으로 찾으려다 `Find original valid three-run baseline` 단언에서 종료1이었다. 이를 호출한 launcher도 종료1이었다. 실패를 성공으로 덮어쓰지 않는다. 첫 판독기의 실행 소스는 `wrapper-final-first-attempt-verify-final.mjs.txt`, launcher는 대응한 `run-wrapper-final.mjs.txt`, 완료된 세 회 범위 비교와 부분 산출물은 원래 `final-views/`에 그대로 보존했다.

측정 종료 뒤 읽기 판독기만 고쳤다. 원래 날짜형 baseline 디렉터리에서 profile 재사용본을 제외한 유일한 유효3회를 선택하고, 그 원문 로그/저장 회차 시간으로 중앙값을 재검증한다. 반올림 literal을 선택 조건이나 수치 기준으로 사용하지 않는다. 새 출력 이름 `final-v2-views`를 사용해 이전 산출물을 덮어쓰지 않았다. 새 시험·측정 실행은0이며 기존 세 원문 해시도 그대로다. `wrapper-final-read-reconciliation.json`은 측정 종료 때 도구동일 확인과 종료 뒤 판독기1개 변경의 정확한 전후 SHA를 구분한다. 현재 실행 소스609개도 여전히 시작 SHA와 일치한다.
