# 제한된 잠금 단계 관측:20회 비재현

승인 범위는 같은8개 자식·stale-lock 준비·원래 단언, 소유 임시 사본, 최대20회/첫실패중단이었다. `dashboard-trace-2026-11-18T20-07-04-716Z`에 원문20개와 manifest 및 실제 사용 preload/진단기 사본을 보존했다. 원래5회 비재현 진단도 별도 폴더에 그대로 있다.

20개 대상 시험은 모두1건 통과·skip0이었고 총160개 자식은 종료0/신호없음이었다. 제품/실제 시험 파일은 변경하지 않았다. 이 한도에서 더 반복하지 않았다.

preload는 lock/owner/reaper/data 경로의 동기 파일 연산 결과를 최근256건 메모리에만 저장하고 uncaughtExceptionMonitor에서 예외code/syscall/순서와 함께 stderr로 출력한다. 원래 호출 인자/반환/예외를 그대로 전달하며 오류를 주입하거나 결과를 바꾸지 않았다. 정상 경로에 매 연산 출력은 없다. 실패가 없어서 monitor 출력은 관측되지 않았으며 실제 오류가 났을 때의 출력 경로가 실증됐다고 주장하지 않는다. 실제 preload SHA는 manifest의 preloadSha256과 executed-preload 사본에 연결했다.

계측과 출력 수집은 실행 순서/부하에 영향을 줄 수 있다. 단일 시험의8개 자식 조건은 전체 동시성4의 다른 시험 부하를 재현하지 않는다. 따라서 원래 전체 실패 원인은 여전히 미확정이고, 수정 필요성/범위를 판단할 오류도 없다. 새 전체3회·제품 변경·T05 마감·finish는 하지 않았다. 다음 부하 확대는 main 판단이 필요하다.
