## 목적

BR05의 목표 시간 도달 시 중단 조건을 먼저 검증해, 추가 함수 전환이 필요한지 결정한다(P-5). 현재 구현으로 최종 전체 세 회의 P-6을 충족하면 시험을 바꾸지 않고 중단한다. 미달이면 실제 병목과 전환 비용을 근거로 함수 전환 계획을 별도 보완·재검토한다. 대표 CLI 경로와 시험 검출력은 유지한다.

첫 새 세트는2회차의 기존 Telegram 롤백 시험 실패로 중단됐다. 승인된 좁은 조사에서 실패 주입 단계가 offset 저장과 경합하는 시험 결함을 임시 사본에서 재현했다. 해당 한 시험의 주입 지점만 의미 상태로 고정하고 기존 단언·실패 주입·skip·실제 CLI 범위를 보존한 뒤, 새 고정 소스의 연속3회를 측정하는 경로를 재검토받는다. 제품 동작 변경은 포함하지 않는다.

## 접근

1. 이 TASK는 측정과 조건부 중단 경로만 승인받는다. 사전 reviewer pass 전에 측정을 시작하지 않는다. T05 TASK·마감·증거·프로젝트 결정/메모리만 추가하며 제품·시험 실행 소스는 바꾸지 않는다. 코드 변경이 없어 새 RED나 구현 복제 unit을 만들지 않는다. 기존 측정 도구의 검증16건과 T04 comparator를 근거로 실제 전체를 검증한다.
2. 같은 Node24.22.3/npm11.19.1/Windows PC에서 T01 도구를 그대로 호출한다. TMP/TEMP/TMPDIR/PACE_HOME은 회차별 소유 임시 폴더로 격리하며 NODE_OPTIONS/coverage/reporter 주입 없이 원래 npm run check를 사용한다. 각 실행의 명령/환경/부하/원문/결과·시작종료 SHA를 보존한다. 다른 시험·진단·타입 검사를 겹치지 않으며 측정 중 실행 소스를 편집하지 않는다. 읽기/증거 기록과 기타 호스트 부하는 별도 한계로 공개한다.
3. T04 snapshot 도구는 T04 evidence 아래 별도 t05 label로 출력하는 현 인터페이스를 재사용해 원본을 덮어쓰지 않는다. 이를 T05에서 상대 링크로 연결한다. 기존 comparator는1회 폴더만 받으므로 T05 보조 검증기가 원래3회 결과/환경을 해시로 연결한 회차별 view를 만든다. 각 view의 results 배열에 해당 원래1개 항목을 그대로 쓰고 log는 실제 원본 절대 경로를 유지한다. 환경은 원본 byte 복사, view 결과/환경/원문 SHA와 원래 회차 번호를 별도 manifest로 묶는다. 기존 comparator를 view마다 호출하고 기존 범위·신규 literal25건 SHA 검증을 유지한다. 보조 도구는 측정 전에 확정·해시 기록한다. 새 whole3회는 T04 1회/T03 5회/진단과 합산하지 않는다.
