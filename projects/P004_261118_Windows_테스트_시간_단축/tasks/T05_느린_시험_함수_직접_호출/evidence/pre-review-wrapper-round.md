# T05 Windows 래퍼 경로 단언 보완 사전 검토

**검토자:** Anthropic · Claude Opus 5.5 (`claude-opus-5-5`). 도구, 실행, 편집은 쓰지 않았습니다.
**자동 첨부 맥락:** 사용자 계정 이메일 범주가 붙었으나 사용하지 않았고 값도 쓰지 않습니다.

## 판정: **통과(pass)** — blocking 0 · should_fix 2

이 판정은 계획에 대한 것입니다. 다음은 모두 아직 결과가 없습니다: 수정 후 파일 전체 실행, 음성 실행, 새 세 회(아직 main 승인 전). 과거 실패가 왜 났는지도 여전히 모릅니다.

## 1. 원래 의도 보존: 충족
- **원래 단언이 확인하려던 것:** PATH 앞에 넣은 `$P034_BIN`에서 `command -v pace`가 설치된 래퍼를 찾는지입니다. 문자열 비교는 수단이었고, 의도는 파일의 정체입니다.
- **기존 방식의 결함:** 별도 Bash가 계산한 `/tmp`와 `/c` 표기가 서로 달라지는 경우를 실패로 판정했습니다.
- **새 방식:**
  - 실제로 조회된 결과를 같은 Bash 안에서 `cygpath -aw`로 변환합니다.
  - 그 경로를 Node의 `realpathSync.native`와 `statSync({bigint:true})`로 확인해 dev/ino를 비교합니다.
  - 이렇게 하면 짧은 이름(`ROOT-U~1`)과 긴 이름 차이도 흡수합니다. `result.json`에서 native가 `root-user`로 정규화된 것으로 확인됩니다.
- **별칭과 다른 파일 판별:** `result.json`의 결과가 근거입니다.
  - `/tmp` 표기와 `/c` 표기 모두 같은 dev 346249331, ino 14355223813071394로 나왔습니다.
  - 같은 `/c` 형식의 `other` 파일은 ino 13792273859650084로 거부됐습니다.
- **나머지는 그대로 유지합니다:** 버전 상태 0, 마지막 줄과 직접 Node CLI 출력 비교, 훅 거부·오류·발견 단언, 특수문자 인자 전달, 이름, skip, 30초 timeout.
- 별도 `expectedBin` Bash 호출이 빠져 프로세스가 하나 줄어듭니다. 약화가 아닙니다.

## 2. 인용·파싱: 적절
- 경로는 `$P034_BIN` 환경 변수와 `"$actual"`로 인용하고, 코드 문자열에 사용자 경로를 넣지 않습니다.
- 한글·공백·`'$&()`가 든 경로가 통과한 사례가 `result.json`의 `calls[0]`에 있습니다.
- `actual="$(command -v pace)" && cygpath -aw … && pace --version`처럼 이어 붙이면, 앞 단계가 실패할 때 종료 코드가 0이 아니게 됩니다. 그러면 기존 status 단언이 먼저 잡습니다.
- 첫 줄과 마지막 줄을 `/\r?\n/`로 나누는 기존 방식이 CRLF를 처리합니다.

## 3. should_fix

**SF-1 "PATH에서 찾은 파일 자체" 의도를 명시합니다.**
- realpath와 ino는 symlink나 하드링크를 따라가 같은 파일로 봅니다. 그래서 다른 디렉터리에 있는 링크가 먼저 조회돼도 통과할 수 있습니다. 원래 문자열 단언이라면 거부했을 경우입니다.
- 최소 보완(둘 중 하나):
  - 관측 경로를 `lstatSync`로 확인해 일반 파일인지 단언합니다.
  - 또는 관측 경로의 부모 디렉터리 정체가 `bin`과 같은지 단언합니다.
- 범위는 넓어지지 않습니다.

**SF-2 진단용 원래 표기를 보존합니다.**
- 첫 줄이 Windows 경로로 바뀌면 실패했을 때 `/tmp`인지 `/c`인지 원래 표기가 사라집니다.
- `command -v` 원문을 stderr로 출력하거나 단언 메시지에 포함합니다. 파싱하는 stdout 구조는 바꾸지 않습니다.
- 그래야 앞으로 같은 실패가 생겼을 때 원인을 구별할 수 있습니다.

## 4. 음성 fixture와 범위 관리: 적절
- **음성 fixture:** 소유 사본에서 관측 경로만 실제로 존재하는 다른 파일(`app/bin/pace.ts`)로 바꿔 지정하고, 새 단언에서 실패하는지 원문으로 확인합니다. 존재하지 않는 경로는 "실제 파일 확인" 단언으로 따로 거부합니다.
  - 이 음성 실행은 realpath 비교에서 먼저 걸리므로, dev/ino 단독 거부는 alias 진단 근거로 뒷받침됩니다. 한계로 기록하면 됩니다.
- **범위:** 예외 파일은 정확히 3개이고 기존 92개는 byte 동일합니다. 실행 파일 609개, 996건 중 987 통과, 실패·취소 0, skip 9입니다.
  - 기존 함수 감사와 Telegram 감사는 바꾸지 않습니다.
  - 블록 밖 byte가 같은지 감사합니다.
  - 새 세 회는 main 승인 뒤에만 실행하고, 이전 회차는 재사용하지 않습니다.
  - 제품, 설치기, finish는 변경하지 않습니다.

## 5. 한계
- 실제 수정 시험은 환경이 만들어 주는 표기만 관측합니다. 대개 `/tmp`입니다. `/c` 동등성은 통제된 진단 1회로만 확인했습니다. 과거 실패 순서를 재현한 것이 아니고 원인도 확정되지 않았습니다. 함수 전환이나 stale-lock 실패와의 인과관계도 주장하지 않습니다.
- dev/ino는 NTFS 파일 인덱스에 의존합니다. 다른 파일 시스템에서의 성질과 Bash 로캘·코드페이지 변화는 미검증입니다.
- 아직 작성되지 않은 diff, 감사 도구 변경분, `wrapper-path-diagnostic/` 원문, SHA는 직접 확인하지 못했습니다.
