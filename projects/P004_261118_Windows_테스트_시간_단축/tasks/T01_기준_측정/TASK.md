## 접근

- 태스크 폴더에 측정 스크립트·필요한 Node reporter와 `evidence/`를 둔다. 실행 명령은 저장소 루트에서 `node projects/P004_261118_Windows_테스트_시간_단축/tasks/T01_기준_측정/measure.ts --runs 3 --label baseline`로 고정한다.
- **B-1 반영:** 기준 3회는 reporter·preload·추적 환경을 추가하지 않은 `npm run check`의 프로세스 시작 직전부터 종료까지의 벽시계 시간으로 정의한다. 기본 출력 로그의 시간·시험 식별자를 우선 파싱한다. 자식 Node에 계측을 상속할 수 있는 NODE_OPTIONS 등은 기준 환경에 없는지 확인하고 있으면 실행 전에 판단을 요청한다. 계측 없는 실행만 P-6 개선율 계산에 쓰므로 계측 비용 감소가 성능 개선으로 섞이지 않는다.
- 기본 출력에서 파일별 시간·식별자 정보가 부족하면 별도 `--profile` 보조 실행으로 타입 검사와 Node 전체 시험 이벤트를 기록한다. reporter는 명시적 최상위 Node argv로만 지정하고 환경 변수로 전달하지 않으며, 작은 자식 시험 fixture에서 비상속을 먼저 확인한다. fixture가 실패하면 보조 실행을 진행하지 않고 판단을 요청한다. 보조 실행은 기준 3회의 중앙값에 절대 섞지 않고 같은 코드에서 얻은 원인 분석용 관측으로 구분한다.
- 호스트 정보는 OS·CPU·메모리·도구 버전, 전원 계획·Defender 상태·백그라운드 부하 표본을 바꾸지 않고 기록한다. 조회 불가 항목은 미확인으로 표시한다. 각 회차 시작·종료 시각, 실행 순서·시간·최소·최대를 남긴다. 파일·시험 식별자와 결과 인벤토리는 원시 출력과 연결하고 기본 출력에 없는 파일 식별자는 별도 프로파일 관측임을 표시한다.
- 실행마다 소유 임시 루트를 새로 만들고 TMP·TEMP·TMPDIR·PACE_HOME을 자식에게 전달한다. 사용자 홈·Git 설정은 변경하지 않는다. 소유 루트와 원시 로그는 실패 분석이 가능하도록 보존하고 임의 삭제하지 않는다.
- 환경 정보·코드 기준점·실행 명령·reporter 설정·종료 코드·누락 여부와 결과를 함께 저장한다. 정상 종료가 아닌 실행과 불완전 결과는 기준선에 넣지 않으며, 실패를 숨기고 재실행해 3회 성공으로 치환하지 않는다.
- 상위 항목 표본의 git 호출·spawn·대기 코드를 조사하되 시험 코드나 실행기는 바꾸지 않는다. 원시 출력의 비밀을 확인한 뒤 재현에 필요한 자료만 커밋한다.
