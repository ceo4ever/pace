## 3. 영역별 평가

### 구현 정확성
- **환경 오염 차단:** `NODE_OPTIONS` 등이 있으면 실행을 거부합니다.
- **유효 판정(`validResult`):** 종료 코드, 신호, spawn 오류, 완전성, 통과 > 0, 실패 0, 취소 0을 모두 확인합니다.
- **보조 실행 인자:** reporter를 argv 맨 앞에 두는 순서가 실증됐고, 실제 보조 argv에서도 확인됩니다.
- **결과 대조:** 보조 총계 대조에서 tests 963, skipped 9, suites 0, cancelled 0이 같습니다. 차이는 pass→fail 1건뿐입니다. 즉 `totalsMatch: false`는 그 한 건 때문이고, 문서의 설명과 일치합니다.

### 부분 출력 시 동작
- **npm이 0으로 끝났지만 요약 줄이 없는 경우:** `complete=false`가 되어 무효 처리됩니다. self-test로 검증됐습니다.
- **신호 종료나 spawn 오류:** 무효 처리됩니다.
- **측정 도중 중단:** `summary.json`이 없으므로 기준선으로 취급되지 않습니다.
- **첫 실패:** 그 자리에서 중단하고 종료 코드 1을 내며, 실패를 교체하지 않습니다.
- **결함 1건 (SF-1):** 보조 `profile.log`의 마지막 JSON 줄이 잘리면 보고서 생성이 중단됩니다. 실패를 성공으로 바꾸는 방향은 아니지만, 그 상태의 `report.md`가 만들어지지 않습니다.

### 시험의 결함 검출력
- **self-test가 다루는 것:** 홀수/짝수 중앙값, 통과·실패·전부 건너뜀 판정, 불완전 로그 거부, reporter 비상속.
- **실데이터 확인:** 3회 모두 `inventoryCounts`가 totals와 같습니다(954/9). 실제 spec 출력에 대한 파서 정확성이 확인된 셈입니다.
- **self-test가 다루지 않는 것:** 신호 종료, 취소, 잘린 보조 로그, `--profile-only`의 검증 실패 경로. 이는 개선 제안입니다.

### 기존 동작 보존
- 측정 도구는 `npm run check`의 인자와 환경을 바꾸지 않습니다. 바꾸는 것은 TMP 계열과 `PACE_HOME`뿐입니다.
- 보조 실행은 `testArguments`를 그대로 재사용합니다.
- 소스 실행기와 시험을 수정하지 않았다는 점은 산출물 주장 기준입니다(diff 미확인).

### 보안
- **명령 주입:** `--label`은 정규식으로 검증됩니다. 외부 명령은 고정 문자열이고 셸 보간이 없습니다. 주입 경로는 보이지 않습니다.
- **사용자 설정:** 사용자 홈, Git 설정, 보안 설정을 바꾸지 않습니다.
- **남은 문제 (SF-4):** 증거 JSON에 로컬 계정 이름이 섞인 절대 경로가 들어 있습니다. 계약상 요구되는 커밋 전 비밀 검사 기록도 확인되지 않았습니다.

### 재사용성
- 같은 명령, label만 다른 새 폴더, 원시 자료 보존이라는 구조는 적합합니다.
- 다만 이후 비교에서 기준 상태가 같은지 보이게 하는 기록이 부족합니다(SF-3).

## 5. 개선 제안 (비차단)

- **`measure.ts`의 `parse`:**
  - suite 종료 줄과 spec의 failing tests 재출력이 인벤토리에 섞이지 않게 거릅니다. 이번 기준선은 suites 0이고 실패 0이라 영향이 없었습니다.
  - 이후 회차에서 기준선 대비 tests·skipped 수와 이름 집합이 달라지면 경고하도록 합니다(P-6 범위 보존).
- **`report.ts`:**
  - 간극 산식 문구에 "동시성 1 전제"를 적습니다.
  - `totalsMatch`에 키별 차이를 출력합니다.
  - `reusedBaseline`은 절대 경로로 저장합니다.
- **profile-only 폴더의 `summary.json`:** 원본을 복사한 값이라는 표시를 넣어, 기준선으로 오인되지 않게 합니다.
- **self-test:** 신호 종료, 취소, 잘린 로그, `--profile-only` 검증 실패를 다루는 fixture를 추가합니다.
- **T03 인계:**
  - 동시성 4·8로 바꾸면 이름+등장 순번 대조가 깨지므로, 보조 이벤트의 파일·줄 기준 대조로 전환합니다.
  - playbook 내부 .mjs 19개의 시간 분해가 필요합니다.
  - `diagnose-nested.ts`의 argv가 wrapper의 실제 호출과 같은지 확인합니다.
