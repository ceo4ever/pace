# 측정 조건과 출처의 한계

## 동시 작업 공개(SF-2)

기준 1회차(08:56:19~09:20:23 UTC) 중 09:13대 self-test 실행들이 있었다. 이 밖에도 측정 도구 수정, 별도 TypeScript 검사, Git/브레인 조회, 짧은 fixture 실행, 상태 기록과 로그 확인을 같은 PC에서 수행했다. 회차 시작의 run-N-host.json은 시작 시점의 누적 CPU/메모리 표본이며 실행 중 전체 부하 기록이 아니다. 조용한 전용 PC에서 수행한 측정이라고 주장하지 않는다.

보조 실행(10:08:56~10:32:49 UTC)과 중첩 진단(10:22:48~10:25:50, 10:27:49대)이 겹쳤다. 특히 겹친 시간의 project-harness 등 보조 파일 시간은 이런 부하가 있는 상태의 단일 관측이다. 정상 파일의 독립·반복 성능 수치나 원인별 비용 비중을 확정하지 않는다.

위 작업이 각 실행 시간에 준 영향은 별도로 계측하지 않았다. 1회차가 더 느린 원인이나 영향의 상한을 숫자로 추정하지 않는다. 관측된 세 값의 중앙값은 3회차 1425.464초지만, 이 사실이 동시 작업의 영향이 없다는 증거는 아니다. main 판단 A는 이 한계와 보조 실패를 공개한 채 기존 기준선 3회를 유지하는 결정이며 재측정을 요구하지 않았다.

## 원래 도구 버전과 Git 상태(SF-3)

처음 시작한 측정 프로세스는 실행 중 수정되기 전의 모듈을 이미 읽었다. 당시 measure.ts·report.ts 등의 원본 바이트/해시를 별도로 저장하지 않았으므로 기준 경로 코드가 현재와 같았다는 진술을 해시로 입증할 수 없다. 원래 소스를 추정 복원하거나 새 해시를 과거 실행의 해시로 붙이지 않는다.

당시 environment.json은 커밋·git diff --stat·도구/호스트 정보, 실행 명령과 로그를 보존한다. diff --stat은 미추적 시험을 열거하지 않으며 원래 시점의 git status 전체 자료는 없다. 기본 spec 출력에는 파일 식별자도 없어 원래 파일 집합의 완전한 해시 목록은 사후 확정할 수 없다. 세 회차의 이름·판정·skip 사유 963건과 같은 소스의 보조 94개 파일 목록이 있는 범위에서 대조한다.

이후 실행부터는 environment.json에 측정 도구 5개 파일의 SHA-256과 git status --porcelain=v1 --untracked-files=all을 저장한다. profile-only의 원본 경로도 절대 경로로 기록한다. 이 개선을 기존 실행에 소급한 출처 증명으로 쓰지 않는다. T02 이후 비교에서는 측정 전 코드를 고정하고 별도 시험/진단을 겹쳐 실행하지 않는다. 도구 버전·전원 계획·Defender·Git/파일 범위 차이가 있으면 비교 한계 또는 확인 불가로 기록한다.

## 개인정보·비밀 검토(SF-4)

증거에는 저장소 경로, Node 설치 경로, 소유 임시 루트 및 일반 로컬 계정/8.3 별칭을 포함한 절대 경로가 있다. 원시 로그·원래 결과를 보존하고 실제 격리 루트와 오류 지점을 재조회하기 위해 남겼다. 기존 결과를 상대 경로로 치환하면 원시 자료와 경로 대조가 달라지므로 이번에는 원문을 유지한다. 경로를 익명화했다고 주장하지 않는다.

커밋 전 원시 오류/리뷰/환경 자료에서 실제 계정 이메일·자격증명·사용자 문서 내용이 포함됐는지 살피고 secret-scan 결과를 함께 기록한다. 검토 원문에 계정 이메일이 자동 첨부됐다는 언급은 있으나 값 자체는 포함되지 않았다. 증거의 계정/경로는 비밀 토큰과 별개이며, 비밀 검사가 모든 개인정보를 보증하지는 않는다. 이 작업에서 외부 전송·푸시는 하지 않는다.

## 파서·비교 범위

기준 3회는 suites=0이다. 기본 spec/TAP 텍스트에서 suite와 부모 시험을 안정적으로 구별할 수 없는 경우는 불완전으로 거부한다. 결과 수와 모든 판정 수의 합, 개별 인벤토리 수가 요약과 맞아야 완전하다. spec의 요약 뒤 실패 재출력은 중복 계산하지 않는다. 보조는 root·각 entryFile의 요약과 결과 목록을 각각 대조한다.

이름+등장 순번은 이번 순차 기준의 시간 표본을 묶는 용도다. T03 동시성 4·8 비교에서는 원시 이름/판정 다중집합을 보존하면서 보조 entryFile·정의 파일·줄 식별자로 비교해야 하며, 순번만으로 서로 다른 실행의 같은 시험을 확정하지 않는다. 보조 간극 산식은 동시성 1의 기술적 분해에 한정한다. 내부 .mjs 19개 시간 분해와 TMP 교차 실행 검증은 T03에 인계한다.
