# 테스트 설계와 단위 테스트

저장소의 기존 테스트 러너를 사용한다. 태스크·마감 전체 회귀는 저장소의 검사 명령(`docs/README.md` 환경의 "검사")으로 돌린다.

## 시나리오 고르기

TASK.md 테스트 표에 기준(`T-n`)마다 한 줄 이상. **가장 싼 충분한 계층**을 고른다.

| 유형 | 쓰는 때 | 방법 칸 |
|---|---|---|
| `unit` | 함수·명령·모듈의 동작 — 대부분 | 테스트 파일 경로 |
| `e2e` | 화면·프로세스·여러 구성 요소를 거쳐야만 보이는 동작 | `e2e/S-n.md` 또는 E2E 테스트 코드 (`e2e.md`) |
| `check` | 문서·설정·파일 존재처럼 실행할 동작이 없는 것 | 확인 명령(`grep`·`wc`)이나 읽기 |

한 줄에 조건·행동·기대 결과를 관찰 수준으로 적는다("동작함" 금지 — 무엇이 출력되는지, 무엇이 생기는지).

## 단위 테스트 규칙

- 기존 테스트 파일·도우미·명명을 따른다. 새 파일은 기존 배치 규칙대로.
- **버그 수정은 RED 먼저**: 버그를 재현하는 테스트를 쓰고, 고치기 전에 실패하는 것을 확인한 뒤 고친다. TASK-CLOSE에 RED 확인을 적는다. 동작을 바꾸는 기능도 가능하면 같은 순서로. 이미 고친 뒤라면 임시 사본에서 옛 구현으로 돌려 확인한다 — `git stash`는 다른 worktree와 공유되므로 쓰지 않는다.
- 외부 환경을 물려받지 않게 격리한다: HOME·설정 폴더·세션 환경 변수(예: `ORCA_*`, `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `TERM_PROGRAM`)를 임시 값으로. 실제 외부 서비스·CLI를 부르지 않는다(가짜 실행 파일).
- 실행된 테스트가 0건이면 실패다. 전부 skip·필터로 빠진 실행도 실패다.

## 판정 기준 5개 (tester가 쓴다)

기준마다 모두 만족해야 통과, 불확실하면 실패.

1. **실행** — 명령이 종료 코드 0이고 시간 초과가 아니며, 출력이 실제로 그 테스트를 실행했음을 보여 준다.
2. **선택 정확성** — 실행한 테스트가 그 기준을 위한 것이다.
3. **기준 충족성** — 기준 문장의 각 조건과, 설계에서 든 깨지는 상황마다 케이스·단언이 있다.
4. **검출력** — 구현이 틀리면 실제로 실패한다. 항상 통과하는 단언, 구현을 베낀 기대값은 실패.
5. **약화 없음** — 기존 테스트를 바꿨다면 원래 지키던 것을 여전히 지킨다. 단언 삭제·기준 완화는 실패.

## 회귀 범위

기본은 저장소 검사 명령 전체. 검사가 느려 일부만 돌렸다면, 아래 신호가 보이면 전체로 넓힌다.

- 이 태스크와 무관해 보이는 테스트 실패·출력 변화
- 원인 불명 실패, 실행마다 결과가 다른 테스트
- 여러 곳이 쓰는 부분(상태 전이·권한·CLI 목록·오류 코드·기록 형식)을 건드렸다

finish는 rebase 뒤 검사 명령을 다시 돌린다 — 태스크에서 넘어간 회귀는 거기서 잡힌다.

## 개발 중 선택 검사와 전체 회귀

새 테스트는 프로젝트의 기존 위치·관례를 따르고 `.pace/test-map.json`이 있다면 관련 단위에 포함되는지 확인한다. 변경 파일·영향받는 단위와 공통 설정·helper를 함께 판단한다. `pace test file <경로>`는 등록된 테스트 파일이나 소스가 속한 단위를, `pace test unit <id>`는 한 단위를 실행한다. 공통·미분류 경로, 미지원 러너·전제, 결과를 확인할 수 없는 경우에는 확인 불가로 보고 전체 검사를 권고한다. 0건·전체 skip·실패를 성공으로 기록하지 않는다. 구성은 작업본 데이터이며 선택 검사는 타입 검사나 전체 회귀를 대신하지 않는다. `pace test all`은 정의서의 base 우선 `검사`를 쓴다.

`pace test changed`는 staged·unstaged·ignore되지 않은 untracked 변경의 모든 관련 단위를 실행한다. 기준 map/checks는 로컬 main→master→현재 HEAD commit 순이며 작업본 map과 같은 때만 빠른 경로를 쓴다. 타입·공통 선행 검사는 프로젝트가 명시한 checks로 실행하고 필드 부재/구성 차이·공통·미분류·추적 불확실성은 정의서 전체 검사로 실제 전환한다. 실제 실패/중단은 후속 전체 성공으로 숨기지 않는다. 변경 없음/확인 불가는3이며 커밋된 브랜치 차이는 제외한다. HEAD 기준은 리뷰된 브랜치를 뜻하지 않는다. map/checks 채택·신뢰/셸·종료 코드 상세는 README의 변경 기반 빠른 검사와 pace-project-init의 test-map 지침을 따른다.

선택 결과에는 대상·명령·시간·판정을 태스크 기록에 남긴다. 부분 검사 후 전체에서 처음 실패한 테스트는 환경·실행 범위·원인 확인 상태와 함께 누락 후보로 기록하고, 환경 차이·기존 결함·불안정을 배제하기 전 누락으로 단정하지 않는다. 다음 OPI 최신화 때 후보와 구조 변경을 대조한다. 태스크와 finish의 전체 검사는 유지한다.
