## 1. 재검토 대상별 결과

**B1. index 삭제가 같은 경로의 untracked 파일에 가려지는 문제: 해소**
- status에서 X나 Y에 `D`가 있으면 `uncertain`으로 표시합니다.
- raw `D`도 따로 `uncertain`으로 표시합니다.
- 같은 경로가 tracked 상태와 `??`로 함께 나오는 경우도 별도로 판정합니다.
- 경로 `Set`으로 합쳐지기 전에 상태를 `states` Map에 보존하므로, 1차에서 문제였던 합쳐짐이 차단됩니다.
- 시험은 `D  `와 `??`의 공존을 직접 단언하고, 실제 full marker 실행, exit 0, index byte 불변을 확인합니다.
- 기존 unstaged/staged 삭제는 원래 `lstat` 단계에서도 전체 전환되었으므로, 이번 변경으로 동작이 넓어지는 회귀는 없습니다.

**main 차단 항목. assume-unchanged / skip-worktree: 해소**
- `ls-files -v -z`에서 소문자 태그(assume-unchanged)나 `S`(skip-worktree)가 있으면 즉시 전체 전환합니다.
- `core.fsmonitor=false`로 실행하고 `-f`를 쓰지 않으므로, 소문자 태그가 fsmonitor-valid 표시와 섞일 위험이 없습니다.
- 시험은 다음을 모두 확인합니다.
  - 숨겨진 B unit이 실제로 실패함(`unit b`가 1)
  - changed 실행 결과가 1이고, 전체 검사가 실행되었으며, 부분 통과가 아님
  - 플래그와 index byte가 바뀌지 않음
- 실패가 성공으로 덮이지 않음이 실제 실행으로 증명되었습니다.

**sparse checkout / skip-worktree 가시성: 해소 (보수적 처리)**
- `core.sparseCheckout`와 `index.sparse` 설정을 검사하고, 값이 true이면 전체 전환합니다.
- 설정 조회 오류는 예외를 던지고, 이 예외는 `try` 안에서 전체 전환으로 이어집니다. TASK 표의 "기준 commit 확정 뒤 열거 불확실 → 전체 전환"과 일치합니다.
- 실제 cone sparse checkout, 설정만 켠 경우, sparse-index 세 가지 모두에서 full 실행과 index 불변이 확인되었습니다.

**SF2. 예외 상태 분류: 해소**
