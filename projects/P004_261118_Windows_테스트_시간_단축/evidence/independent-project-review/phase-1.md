# P004 독립 결과 검토 1단계

1단계는 사용자가 제시한 목표와 실행 원문, 구조화한 결과, 제품·테스트 소스만 읽었다. PACE 부트가 기본 프로필과 main 위치, P004 진행 상태, 프로젝트 메모리를 자동으로 노출했다. 활성 프로젝트 AGENT 정의는 주입되지 않았다. 1단계 판단을 전달하기 전 프로젝트·태스크의 계약, 마감, 작성자 판단 또는 전체 보안 자료를 열지 않았다.

## 결과

- 같은 Windows PC에서 전체 검사 시간 목표를 달성했다. T01 원래 3회는 1,444.136 / 1,425.406 / 1,425.464초로 중앙값 1,425.464초, 기준의 절반은 712.732초다. T03 기본 동시성 4의 5회는 680.448~685.689초, T04 수정 전체 1회는 710.712초다. T05 최종 3회는 700.563 / 707.020 / 705.473초로 중앙값 705.473초다. 중앙값은 기준의 49.49%, 절반과의 여유는 7.259초다. 가장 느린 회차도 5.712초 여유로 통과했다.
- 원문의 실제 npm 검사 단계와 상태를 확인했다. 최초 963건은 954통과 및 9건 건너뜀, 최종 996건은 987통과 및 9건 건너뜀이다. 실패와 취소는 모두 0건이다. 각 실행에서 시험 이름과 판정을 중복 개수까지 대조했을 때 빠진 이름은 의도적으로 바뀐 Windows 순차 실행 기대 한 건뿐이다. 대체 시험에서 플랫폼별 동시성·추가 인자·실제 호출·실패 전달을 확인했다. 최종 원문 3건과 결과 JSON의 SHA-256은 직접 다시 계산해 모두 일치했다. 측정 609개 파일과 7b3a926의 바이트/정규화된 Git blob 대조 기록도 확인했다.
- 별도 Git 표본에서 격리된 설치 앱으로 실제 타입 검사와 관련 시험 11건을 실행했다. 3회 중앙값은 14.794초다. 최종 전체 원문에는 설치된 Windows 진입점과 Node·Python 드라이버, 공통/미분류 및 숨김 인덱스 등에서 실제 전체 명령을 실행하는 시나리오도 통과했다. 이 수치는 부분 실행의 반응 시간이다.
- 소스에는 두 경계가 남는다. 기준 커밋의 전체 선언이 비어 있으면 현재 작업본 선언을 사용하므로 README의 기준 설명을 대조할 필요가 있다. 이미 사전 검사까지 진행한 후 예상 밖의 대상 소실 예외가 발생하면 전체 재실행 없이 확인 불가 3으로 종료한다. 테스트가 그 경계를 명시적으로 검증한다. 일반적인 선택 불확실성과 알 수 없는 결과에서는 실제 전체 검사로 전환한다.

기존 로그와 해시만 읽었다. 다른 PC나 OS의 속도, 연속 부하, 현재 로컬 기본 설치본 반영, 다른 코드와 합친 결과는 이 단계에서 확인하지 않았다.
