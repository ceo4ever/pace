## 판단 검사

검토에 사용한 diff는 제공된 main 35d0da6…7b3a926이다. 실제 39,968,553바이트의 SHA-256을 다시 계산해 전자 기록과 일치함을 확인했다. 전체 패치의 1,548개 파일(추가 1,508, 수정 40)에 대해 경로, 상태, 텍스트 추가 행 및 바이너리 표시를 검사했다. 1,434개는 프로젝트 증거였다. 애플리케이션 실행 경계, 테스트 격리/복사와 실패 주입, 문서-구현 대조를 중심으로 상세 검토했다. 설치기·비밀 검사기·패키지/잠금파일에는 변화가 없었다.

전체 추가 행에서 개인키 표제·긴 인증 토큰 표기·문자열 자격증명 대입·대표 환경 비밀 이름을 패턴으로 찾았다. 식별된 이메일 모양 값은 예시 도메인 fixture였다. 절대 경로는 일반 로컬 Windows 사용자 디렉터리와 짧은 이름, 소유 임시 환경 및 로컬 작업공간 메타데이터로 분류했다. 로컬 사용자 디렉터리 경로 패턴은 텍스트 추가 범위 677개 파일에 나타났다. 대시보드의 생성 자료에도 로컬 경로가 있다. 이를 개인의 실명·메일·자격증명으로 식별할 근거는 없으며, 증거는 익명화된 공개 자료가 아니다. 저장소 밖 원문은 보존하고 생성 자료나 요약에서 경로를 계속 복제할 필요가 있는지는 공개 인계 시 검토할 수 있다. 태스크 마감 기록의 기존 기계 검사 2,526개 파일 통과는 재실행 없이 인용했다.

- **should_fix** — README.md:150 및 src/project/harness.ts:399. README는 map/checks와 전체 선언이 같은 커밋 기준이라고 설명한다. T04 TASK는 실제 조회 오류와 선언 부재를 구분하고, 후자일 때 현재 작업본의 전체 선언을 쓰는 종전 정책을 명시한다. 변동된 정의서도 전체 전환 사유다. README에 기준 우선, 진짜 부재의 작업본 사용, 신뢰하는 저장소에서만 실행한다는 경계를 명시한다. 기존 동작을 바꿀 이유는 확인되지 않았다.
- **should_fix** — README.md:161, src/test-runner/changed.ts:177, test/changed-test.test.ts:155. 일반적인 선택·결과 불확실성은 실제 전체 검사로 전환한다. 사전 검사 통과 후 시험 파일이 사라지는 예상 밖의 실행 예외는 전체 재실행 없이 3이다. T04 마감에서 구분한 계약을 사용자 문서와 마감 문구에도 한 문장으로 명시한다.

## 통합 상태

main에는 Vitest 러너 변경이 이미 있다. 제공된 통합 사전검사 결과에서 src/test-runner/runner.ts, docs/README.md, 초기화 스킬의 test-map.md, 브레인 로그, 생성 대시보드에 충돌이 보고됐다. 이 통합 차단은 검토한 스냅샷의 P-6 측정과 별개다. 통합 후에는 main의 Vitest와 P004 changed 경로가 모두 유지됐는지, 재생성 산출물·실패와 전체 전환의 실행 경계, 최종 P-6 세 회를 새로 확인해야 한다. 충돌 해결·rebase·재시험·보안 명령 재실행을 수행하지 않았다. 1단계에 PACE 부트가 자동으로 공급한 프로젝트 맥락은 phase-1.md에 적었다.
