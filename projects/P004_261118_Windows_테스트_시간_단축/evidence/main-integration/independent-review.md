# P004 main 통합 독립 검토

통합 커밋 a5d1115의 Windows 전체 검사 3회 착수를 막는 항목은 없다. 차단 0건, 수정 필요 0건, 후속 인계 1건이다. 이번 검토는 P004 마감의 1·2단계 검토를 했던 같은 검토자가 이어서 수행했다. 파일·로그 읽기와 해시 재계산만 했으며, 테스트와 측정을 실행하지 않았다.

- main 35d0da6은 통합 커밋의 조상이다. 두 검토 패치의 파일 바이트 수와 SHA-256, 집중 실행 원문 SHA-256을 다시 계산했다. 시험 소스를 포함한 610개 대상 경로, 현 작업본 SHA-256 및 HEAD blob ID를 목록과 직접 대조했고 차이는 0건이다. 패키지·잠금 파일과 npm 전체 진입점, 기존 Windows 동시성 4를 유지했다.
- 기존 Vitest 드라이버와 전용 시험 파일은 main과 Git blob까지 같다. file/unit은 단위의 선택 파일을 한 배치로 같은 Node 드라이버에 전달한다. config/대상은 기존 실경로 검사를 거쳐 개별 argv로 전달되고, cwd·timeout·출력·신호 및 Windows Vitest 자손 회수 판정은 main 동작을 유지한다. 기존 Node/Python은 파일별 실행과 오류 처리를, all/finish는 기존 전체 검사 경로를 유지한다.
- changed는 관련 단위에 Vitest가 있으면 계획 단계에서 사전 검사와 부분 실행 전에 실제 전체 검사로 넘어간다. 별도 Git fixture의 설치형 CLI sentinel은 config 유무 각각에서 부분 실행 없이 선언된 전체 명령의 성공 0, 실패 1, 선언 부재 3을 구분한다. Vitest 대상에서 전체 선언이 있으면 실제 전체 명령은 1회 실행되며, 선언 부재 시 전환 1회·실행 0회다. sentinel의 Vitest 실행은 로컬 모의 실행기 계약을 검증한다.
- 집중 실행 원문에서 40건을 직접 추출해 전부 통과, 실패·취소·skip 0을 확인했다. 통합 전 996건의 원문 인벤토리에 main의 명시적 이름 대체 1건과 새 3건, 통합 sentinel 1건을 적용해 기록된 인벤토리와 정확히 일치했다. 통합 전체의 기대값은 1,000건·991통과·기존 skip 9다. README는 이전 두 개선 지점인 기준 선언 실제 부재의 작업본 대체와 사전 검사 뒤 예상 밖 예외의 확인 불가 3을 명시한다.
- **handoff** — src/test-runner/vitest-driver.mjs의 로컬 모듈 탐색 및 Windows 실행 경계는 main에서 그대로 가져왔다. 신뢰한 프로젝트·로컬 의존성을 실행하는 계약이며, 실제 외부 Vitest 엔진 및 여러 Windows 자손 회수 구성의 실기 증명은 별도 범위다.

P-6은 통합 코드의 비계측 전체 3회 검사가 끝날 때까지 미확인이다. 직전 996건의 측정 결과와 40건의 집중 실행은 새 3회의 표본에 포함하지 않는다.
