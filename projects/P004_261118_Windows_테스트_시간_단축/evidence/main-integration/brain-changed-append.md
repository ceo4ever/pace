## 전체 선언과 사후 실행 예외의 경계 (2026-11-19)

map/checks는 검증한 기준 commit과 작업본 일치를 요구한다. 전체 선언은 그 기준을 우선하되 실제 선언 부재일 때만 작업본 선언을 읽는 종전 정책을 유지한다. Git 조회 오류를 부재로 바꿔 작업본 코드를 실행하지 않는다. 선언은 신뢰한 프로젝트 코드 실행이며 샌드박스가 아니다.

일반적인 계획/선택 결과 불확실성은 실제 전체로 전환한다. 사전 검사 뒤 대상 소실 같은 예상 밖 실행 경계 예외는 전체를 다시 실행하지 않고3으로 끝날 수 있다. 이미 관측한 실제 실패/중단은1을 우선하며, 전체 성공 재시도로 덮지 않는다. 이 가용성 한계를 README와 실제 시험에 명시했다.

## file/unit Vitest와 changed의 구분 (2026-11-19)

main에서 제공한 file/unit은 로컬 Vitest를 Node로 직접 실행하며 단위 파일을 한 batch로 전달하고 config를 지원한다. changed는 관련 Vitest를 계획 단계에서 사전 검사/부분 실행 전에 실제 전체로 전환한다. 공유 실행기의 기능만 보고 changed kind guard를 풀지 않는다. Vitest 내부 실패 뒤 보고서가 없을 때 file/unit이 확인 불가3으로 다루는 계약을 changed의 실패 우선 계약과 단순 연결하면 실제 실패를 전체 성공으로 덮을 수 있기 때문이다.

설치 형태의 외부 Git sentinel은 config 유무의 file/unit 실행 가능성과 changed의 전체 전환0/1/3·부분/사전 검사 미실행을 확인했다. 전체 명령이 있으면1회, 선언 부재3이면 전환1회/실행0회다. 이는 모의 로컬 실행기의 계약 검증이며 실제 외부 Vitest 엔진 전 범위나 Windows 임의 자손 완전 회수 증명은 아니다.
