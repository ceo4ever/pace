# P004 통합 최종 독립 검토 2단계

## 판정

통합 커밋 `a5d1115`의 **P-6 최종 결과 증거 통과, 차단 0건**으로 판단한다. PROJECT-CLOSE의 수치·실행 범위와 최종 결과 문서를 1단계의 독립 계산 및 PROJECT 계약과 대조했으며 중요한 모순을 발견하지 않았다. 별도 독립 보안 검토와 필수 finish 검사는 이 테스터 판정의 범위 밖에 있다.

- PROJECT는 Windows 원래 전체 명령의 새 세 회가 P-1 중앙값의 절반 이하고 실패 0건이며 기존 검증 범위·플랫폼별 판정을 보존할 것을 요구한다. 통합 세 회는 종료 0, 각각 1,000건 중 991통과, 실패·취소 0, skip 9였다. 702115.5500999999ms의 중앙값은 기준 1425464.3326999997ms의 49.2552170%다. 이전 996건과 비교해 main의 승인된 이름 대체 1개, 신규 3개, 통합 시험 1개만 달랐고 skip 사유는 같다. 이전 T05 원래 결과 및 집중 40건은 각자의 검증 근거로 보존되며 통합 전체 표본과 분리돼 있다.
- P-4의 기존 사용자 경계와 관련해 Vitest file/unit을 지원하는 main 시험·driver의 blob이 정확히 유지됐다. 통합 설치 형태 fixture의 sentinel은 config 유무에 각각 changed가 부분 실행·사전 검사 전에 전체 명령으로 전환하고 성공/실패/확인 불가 0/1/3을 구분한다. 여기서 모의 로컬 실행기로 확인한 범위는 실제 외부 Vitest 엔진 전체의 검증으로 확대할 수 없다. P-5의 함수 전환 항목, 기존 CLI·결함 검출력은 앞선 T05 독립 검토와 바이트 연결로 보존됐다. 통합은 마감 전 호환성 범위이며 이전 T01~T05의 완료를 되열거나 기존 승인 범위를 바꾸지 않는다.
- PROJECT-CLOSE의 P-6 행이 수치·범위 통과와 독립 최종 확인 대기를 구분하고, 최종 결과 문서는 finish를 별도 게이트로 둔다. 위 통합 3회의 합격은 finish 자체나 병합, 설치, 푸시를 완료했다는 의미가 없다. 이 세 회와 동일 PC 기준선은 일반 운영환경의 성능 보장이나 개별 변경의 독립 효과로 해석할 수 없다.

## 오류와 기록

초기 launcher는 `--evidence-dir`에 이름이 `evidence`로 끝나지 않는 디렉터리를 보냈다. T01 측정 코드에서 그 가드가 결과 폴더 생성과 npm child spawn보다 먼저 실행된다. 종료 1의 두 도구 원본 SHA와 실패 때 인자가 보존된 기록에 일치했다. 실제 npm check는 0회이고 실패한 시도의 측정 표본은 없다. 전체 stderr 파일은 보존되지 않았다는 문서의 제한과 함께, 원인·원본 도구·실패 상태는 분리 기록됐다. 새 label과 소유 하위 `evidence` 경로에서 실제 세 회를 시작했고 실행 소스 및 합격 기준에는 변화가 없었다. 실제 측정 시점의 9개 도구 해시와 현재 값이 모두 일치한다.

환경 읽기 보조 단언의 최초 오류는 빈 문자열을 기대한 것이었다. 최종 원래 JSON의 `requestedConcurrency` 직렬화는 `default`이고 Windows `/d /s /c npm run check`, Node `--test --test-concurrency=4 test/**/*.test.ts`다. 프로젝트 문서는 이 읽기 정정과 시험 실행을 구분한다. T01에 없던 이후 측정 메타데이터는 공통 조건으로 소급하지 않는다. 스냅숏은 시작·종료 바이트를 확인하는 기록으로, 연속 감시나 장비 부하 고정 증거로 삼지 않는다.

이전 무효 세트와 분석 도구 오류 기록은 유지됐다. 이번에는 앞선 T05 및 통합 검토 맥락을 보유한 같은 독립 테스터로서, 먼저 원문·코드·해시를 확인한 뒤 PROJECT, PROJECT-CLOSE와 작성 결과를 읽었다. 시험·측정·설치 재실행이나 worktree 변경은 하지 않았다.
