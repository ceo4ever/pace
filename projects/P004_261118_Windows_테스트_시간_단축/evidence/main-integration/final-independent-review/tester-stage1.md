# P004 통합 최종 독립 검토 1단계

통합 커밋 `a5d1115b9a63bf35627ef69897be0712417447c5`의 최종 실행 원문과 소스 증거만 먼저 대조했다. 이전 T05 독립 검토 맥락을 유지했다. 이번에는 새 원문을 직접 파싱했고, 아직 통합 이후 PROJECT-CLOSE와 작성자의 최종 결과 설명을 읽지 않았다. 테스트 실행, worktree 수정, 사용자 설치 작업은 하지 않았다.

## 판정

통합 전체 검사 3회 모두 1,000건, 통과 991건, 실패·취소 0건, skip 9건, 종료 상태 0으로 확인됐다. 각 원래 로그의 집계 및 사례별 이름·판정·지속 시간을 원래 저장 JSON과 대조했다. 벽시계는 698136.3187000001ms, 703222.1800999999ms, 702115.5500999999ms다. T01 최초 유효 기준 3회의 중앙값 1425464.3326999997ms의 절반은 712732.1663499998ms다. 통합 중앙값 702115.5500999999ms는 그보다 10616.61625ms 낮으며 단축률은 50.744783%다.

통합 세 회를 이전 T05 원래 세 회의 996건과 각각 비교했다. 이름·판정·중복 건수와 skip 이름·사유는 승인된 다음 변경 외에 동일하다.

- 기존 T02 시험 이름 한 건은 미지원 Vitest에서 로컬 vitest 미설치로 의미가 정확해진 main의 이름으로 바뀌었다.
- main에서 로컬 Vitest 배치 및 설정 전달, 실패·전체 skip·0건·보고서 누락 처리, Vitest 외 러너의 설정 파일 거부를 확인하는 시험 3건이 추가됐다.
- 통합 전용 `changed Vitest uses the full command before checks and preserves 0/1/3 while file-unit stays supported` 한 건이 추가됐다.

통합 측정의 기본 실행은 `/d /s /c npm run check`에서 `node --test --test-concurrency=4 test/**/*.test.ts`이다. T01과 공통 기록의 Node/npm/Git/Python·OS·전원·Defender·명령·비계측 설정을 대조해 같음을 확인했다. 최종 세 회는 다른 임시 루트에 기록됐다.

## 바이트와 출처

610개 전체 실행 파일에 대해 현재 SHA-256, 측정 시작·종료, 사전 기록을 대조했다. 현재 파일의 Git 정규화 해시를 다시 계산해 해당 커밋 트리의 610개 blob과 일치함을 확인했다. 이전 609개 T05 기록 대비 6개 내용 차이, Git 정규화 전 줄바꿈만 달라진 7개, 신규 Vitest driver 1개를 확인했다. 최종 test-runner 시험과 신규 driver의 blob은 통합한 main과 정확히 일치한다. 세 로그와 저장 결과 JSON의 SHA-256도 최종 바인딩과 일치했다.

동일 장비에서 실제 적용 범위와 기본 실행 방법을 고정한 세 회의 결과다. 이 증거로 다른 환경 성능을 추정하거나 작업 하나에 전체 감소 시간을 귀속할 수 없다.
