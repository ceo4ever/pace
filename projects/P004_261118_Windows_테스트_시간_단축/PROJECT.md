## 설계

- T01에서 같은 PC·도구 버전·기준 커밋·명령·임시 폴더 격리 방식으로 실행을 순서대로 3회 반복한다. 전체 벽시계 시간과 Node 파일·시험 시간, 실패·건너뜀과 종료 코드를 기록한다. 기존 공용 임시 폴더 경합이 섞이지 않도록 실행별 전용 임시 폴더를 사용하고 비교 측정에도 같은 방식을 적용한다. 실패가 남으면 원인을 기록하고 BR01의 실패 0건 계약에 따라 판단을 올린다.
- T02와 T03은 BR01 기준선 뒤 순서대로 수행한다. 단계마다 비교 대상 커밋과 시간을 남겨 효과를 확인하고 T04는 두 단계가 끝난 뒤 진행한다. T05는 당시 누적 실측으로 전환 대상과 종료 지점을 정한다.
- T04는 다른 Git 저장소에서도 설치된 PACE CLI로 실행할 제품 기능으로 만든다. 기존 `pace test` 선택기와 `.pace/test-map.json`을 우선 재사용하고 프로젝트별 선언 검사·러너를 존중한다. 명령 이름·타입 검사 연결은 T04 설계에서 결정한다. 선택 근거를 출력하며 매핑이나 추적에서 설명할 수 없는 변경은 해당 프로젝트의 전체 검사로 전달하고 전체 검사 확인 불가를 성공과 구별한다. PACE 저장소의 npm 명령은 필요 시 공용 명령의 얇은 진입점/사용 예로만 둔다. 독립 Git 샘플로 제품 CLI를 검증하고 사용자 문서에 채택 방법을 남긴다. `finish`는 기존 정의서의 전체 검사 명령을 사용한다.
- 보안 영향: 측정 출력에는 재현에 필요한 도구 버전·시간·시험 식별자를 남긴다. 임시 저장소는 시험이 소유한 경로에서 만들고 사용자 Git 설정이나 실제 저장소를 변경하지 않는다. 선택기·실행 경계를 수정할 경우 경로 및 인자 검증과 선택 실패 시 동작을 리뷰한다. T04의 명시 checks는 신뢰하는 프로젝트 코드 실행 선언이며 기준 commit·셸·cwd·구조화된 실행 전/후 오류를 검토한다. 설치 스크립트와 하네스 생명주기는 범위 밖이다. 다른 기본 브랜치를 지원하는 공유 helper의 제한 확장만 T04 계획/사전 검토에 포함한다(기존 all/finish의 기본 동작 보존).
