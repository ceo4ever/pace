- 프로젝트: [P014](../../PROJECT.md) · 브리프: [BR03](../../../../backlogs/BL261125_01_문제_해결_전문가_에이전트/BR03_에이전트_호출_기록.md)

## 목적

PACE 도구와 PM 수동 입력이 실제 호출 시도마다 에이전트·모델·effort·실행 시간·토큰 및 그 값의 출처를 보존한다. 팀 구성원별 시간·토큰과 미확인 값을 따로 보고해 모델과 effort 조정의 근거를 만든다. T07이 이 기록 계약을 호스트 훅과 외부 검토에 연결하고, 두 태스크로 P-7을 판정한다.

## 기준

| # | 완료 기준 |
|---|---|
| T-1 | 프로젝트 또는 백로그 폴더의 `calls/log.jsonl`에 스키마 v1의 실제 시도당 한 행이 있다. 에이전트, 모델·effort 요청/실제, 실행 시간, 토큰 및 측정 출처, 완료·실패·중단 및 대체 사유, 안전한 결과 `ref`를 직접 담는다. 미관측은 null과 미확인이며 0과 다르다. PM 입력과 도구가 같은 타입을 사용한다(P-7). |
| T-2 | 같은 시도 ID의 동일 입력은 다시 써도 한 행이다. 늦게 추가된 값과 참조를 보강하고, 상충하는 측정과 다른 시도 또는 범위 귀속을 합치지 않는다. 병렬 기록과 일시적 오류·재시도는 기존 행과 조회 가능한 JSONL을 보존한다. 알 수 없는 필드, 비밀·원문, 부자연스러운 음수, 외부 또는 링크 경로는 거부한다(P-7). |
| T-3 | PACE 정상 진입점 `agent run`의 p·ACP·체인 및 `agent verify`의 실제 실행은 각 PACE 시도만 기록한다. 연결된 verify 시간·토큰은 원장과 같고 검토 원장 `ref`를 보존한다. 실제 실패·중단은 판정이 없어도 자체 행이다. 실제 교차 시도 실패 후 같은 제공자 대체 성공은 두 행이다. 사전 거부·예약·skip 및 검증 발급 명령은 호출로 계수되지 않는다(P-7). |
| T-4 | stats 호출 절에 기록된 에이전트별 호출 수, 시간·토큰의 알려진 합 및 미확인 수가 나타난다. 전체/구판 사건·검토·채택 팀 지표를 보존한다. 미채택 프로젝트의 호출은 별도 출력만 만들고 마감·회고를 시작하지 않는다. 호출 시간·토큰을 기존 검토 원장 집계에 다시 더하지 않는다(P-3, P-7, P-13). |

## 접근

- `src/project/agent-calls.ts`에 스키마와 잠금·쓰기·조회·집계를 둔다. `safeTeamPath`, 단일 링크 파일 조회, 엄격 JSON, 비밀 스캔과 원자 교체를 재사용한다. 짧은 배타 쓰기 구간에서 기존 행을 읽고 ID로 한 행을 합친 뒤 동일 디렉터리에서 원자 교체한다. 동일 쓰기는 no-op, 충돌·손상·링크는 fail closed다. 유효한 동시 기록은 잠시 대기 후 다시 읽는다. 복구할 수 없는 강제 종료로 남은 잠금은 기존 행을 보존하고 오류로 드러낸다.
- 관측값은 `{value, source}`로 남긴다. 출처는 요청, 호스트 보고, 도구 측정, PM 기록, 미확인이다. actual에는 요청만 전달한 값을 넣지 않는다. 시간·토큰은 알려진 수치만 출처와 함께 둔다. 호스트 총 토큰·입력·출력 토큰은 서로 더하지 않는다. 원장 기록의 `미보고`와 호출 기록의 `미확인`은 원래 집계에서 각각 유지한다. 둘 다 누락을 0으로 추정하지 않는다.
- `src/agent/contract.ts`의 실행 경계는 시작 후 결과/오류의 제한된 관측 구조를 전달한다. `chain.ts`와 `verify.ts`는 실행된 정확한 단계에 대체 이유를 결합한다. `verify-cli.ts`는 실제 실행을 먼저 기록하고 검토 원장에 나중에 등록된 성공 판정 참조로 같은 행을 보강한다. 체인은 read-only 변경 관측이 끝난 뒤 호출 기록을 쓴다. `p-executor.ts`·`acp-executor.ts`는 실행 전에 끝났다는 관측이 필요한 경우에만 보강하며 요청 설정 성공을 런타임 관측으로 취급하지 않는다. 강제 프로세스 종료 전에 호스트 관측이나 실행기 응답이 없던 경우의 결과값은 확인할 수 없다. 회수된 취소·시간 제한은 기록하도록 검증한다.
- `src/agent/call-context.ts`과 `src/cli.ts`는 유효한 프로젝트/백로그·태스크 경로로 귀속한다. 검토는 정규 대상 위치, 실행은 명시 범위 또는 소유 worktree로 귀속한다. 프로젝트 밖이면서 백로그가 확인되면 해당 백로그 아래에 쓰며 범위가 없는 일반 실행은 별도 기록을 만들지 않는다. `--call-agent`로 팀 구성원 이름을 연결한다. PM 입력은 `pace project log P### [T##] --type agent_call --call-file <JSON>` 또는 BL 번호를 사용한다. 호스트 관측이 없는 필드가 수동 보고로 보강될 수 있는 스키마를 T07에 넘긴다.
- `src/project/metrics-report.ts`와 필요 시 `metrics-document.ts`는 호출 원장이 있을 때만 별도 호출 절과 JSON 값을 낸다. 기존 지표·팀 stats 판정은 재사용한다. `docs/WORK-PROCESS.md`·`docs/AGENT-CALL.md`·`docs/TEAM-METRICS.md`에 위치·사용 예·집계·누락·호환 경계를 적는다. 기존 사건 원장 경로와 팀 채택 입력은 유지한다.
