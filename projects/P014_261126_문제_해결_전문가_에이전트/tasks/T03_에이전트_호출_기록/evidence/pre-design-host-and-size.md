## 구판 판독기

T01 전 기준 `bd77aa2`의 소스를 임시 폴더에 펼쳐 기존 note 1행과 후보 1행을 `eventLines`와 `readTeamEvents`에 각각 넣었다. 기존 행 두 개는 양쪽이 2개를 읽었다. 새 종류 `agent_call`과 문자열·null을 포함한 중첩 data는 일반 판독기가 해당 행을 넘겼고, 새 최상위 필드는 일반 판독기가 읽었다. 구판의 채택 팀 판독기는 세 경우 모두 전체 로그 형식 오류로 중단했다. JSON 문자열을 msg에 넣은 note는 두 판독기가 읽었다. 다만 구판은 note도 대표 태스크 범위 관측에 포함하므로 단순히 note로 위장하면 동일 집계가 보장되지 않는다. `src/project/team-metrics.ts`의 `observedScopes`를 포함해 새 형식은 구판의 채택 측정과 비교해야 한다.

## 구판 실제 집계의 위치 대조

`bd77aa2`에서 `bin/pace.ts`, `src/`, `templates/`와 `test/team-metrics.test.ts` 픽스처를 가져온 임시 사본에서 판독했다. 채택 프로젝트에 `representative-task` 기간, 완료 근거, T01에 귀속한 정상 사건 한 행을 입력했다. 다음 세 입력에 구판 `pace project stats P001 --json`을 각각 실행하고 실행 시각인 `team.snapshot.observed_at`만 제외하여 비교했다.

| 입력 | 구판 team 결과 |
|---|---|
| 기존 사건만 있음 | 대표 업무 단독 수집 범위 경고 없음 |
| 기존 사건 + `calls/log.jsonl`에 다섯 항목이 직접 담긴 합성 시도 1행 | 기존 집계와 deepEqual |
| 기존 사건 + 기존 `log.jsonl`에 범위가 없는 프로젝트 수준 호출을 `type: note`·`data.agentCallVersion: 1`로 표현 | 대표 업무 단독 수집 범위 미확인으로 총량·비교 방향 보류. 같은 기준으로 JSON이 일치하지 않음 |

루트 `log.jsonl`의 신규 종류·필드는 구판이 전체 로그를 거부하고, 구판이 수용하는 `note`는 범위에 영향을 준다. 별도 `calls/log.jsonl`은 호출 원장에도 owner가 명시한 파일명과 다섯 값을 유지하고 구판 팀 집계와 사건 기록도 보존한다. `docs/WORK-PROCESS.md`의 기존 루트 경로 관례까지 호출 기록에 요구하는 해석이라면 기존 P-3·P-13과의 충돌을 해결할 결정이 필요하다. 옛 설치본에 알려진 다른 의미의 사건 종류를 사용하거나 관측 시각·귀속을 바꾸는 안은 실제 사건을 다르게 기록하므로 사용하지 않는다.
