# T03 독립 1단계의 재현과 수정

초기 구현 패치 SHA-256은 `14841eecdb3965efd5c8eb1f97f2d2e4e6ef625c79cda9f4b320944cd434918a`다. 두 독립 세션은 동일 Git 기준 `2719c36`과 패치를 사용했다. tester는 선택 검사 57/57을 실행하고 0 토큰을 unknown으로 바꾸면 해당 시험이 실패하는 것을 확인했다. 원상 복구 후 통과했다. reviewer에는 Bash가 없어 초기 diff 명령을 실행하지 못했고, 파일을 읽어 지적했다. 최종 2단계에는 패치를 파일로 직접 제공한다.

| 독립 1단계 관측 | 반영·재현 |
|---|---|
| 호출 원장 추가가 허가 범위 검사 차단 | 선언 전체 검사에서도 동일 세 건이 실패했다. 허가 변경 목록의 프로젝트 및 그 출처 백로그의 정확한 `calls/log.jsonl`만 일반 관리 파일로 추가했다. 다른 경로·비일반 파일에 대한 검증은 적용한다. 같은 기존 탐침·A-3 기대값으로 3/3 재검증했다. |
| p 실행 완료 뒤 `--raw-dir`이 일반 파일이면 호출 0행 | 실행기가 선택 로컬 쓰기 전에 제한된 정상 결과를 제공하고 로컬 쓰기 오류에도 실행 행을 남긴다. p·ACP의 명령 자체는 같은 오류를 반환한다. |
| Codex footer 총량을 출력 수치로 표시 | 호출 행은 알려진 총량으로 기록한다. 검토 원장은 호환 슬롯의 동일한 수치·기존 통계를 보존한다. |
| 남은 잠금이 이후 기록을 계속 놓치게 함 | 소유 표지의 PID가 종료됐음을 확인하고 보조 회수 잠금 안에서 동일 inode를 대조해 회수한다. 상태를 알 수 없는 잠금은 회수하지 않으며 경고에 확인 위치와 재시도 사유를 낸다. |
| 두 체크아웃의 기록 분산, 정규 경로 참조 | run은 소유 worktree에 귀속한다. verify는 실제 대상 파일이 있는 체크아웃의 안전한 ref를 유지한다. stats 조회는 동일 ID를 한 번만 센다. 결산 스냅샷은 자기 체크아웃을 사용한다. 대상 Git 루트 정규화로 경로 별칭 차이를 제거했다. |
| 체인 마지막까지 이전 시도 기록을 보류 | 각 단계의 read-only·변경 관측이 끝나면 바로 기록한다. 다음 실행기는 이전 행이 기록돼 있어야 시험을 통과한다. |

호스트 자체가 완료 결과를 보내기 전의 강제 종료를 완료로 추정하지 않는다. SIGINT·SIGTERM으로 정상 회수되면 실제 실행의 중단 행을 남긴다. 사용자가 동시에 다른 브랜치의 같은 백로그 원장을 편집하면 일반 Git 충돌 해결에서 동일 시도 ID를 대조해야 한다.
