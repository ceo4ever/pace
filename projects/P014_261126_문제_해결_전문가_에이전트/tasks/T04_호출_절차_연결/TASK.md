## 목적

반복 실패에서 해당 PM이 알맞은 기회에 독립 문제 해결안을 받고 결정·적용·독립 재검증으로 잇도록 한다. 실제 조기 신호와 상위 근본 검토를 정상 CLI 진입점에서 관측하고, 같은 기회의 중복과 검토 예산에 대한 회귀를 구별한다.

## 접근

- `skills/pace-project-dev/SKILL.md`, `references/reviewer.md`, `references/coordinator.md`, `evals/scenarios.md`, `skills/pace-team/references/required-roles.md`를 갱신한다. T05 golden의 정본 anchor는 유지한다. 백로그는 동일 폴더의 `calls/log.jsonl`과 단계의 근거 파일을 참조한다.
- 선행 도구 동작을 다시 구현하지 않는다. 실제 관측에서는 합성 이전 검토를 저장소 `./bin/pace.ts`의 실제 CLI로 판정한다. 격리 Git과 임시 `PACE_HOME`을 사용하고 실제 사용자 홈·설치본·훅은 바꾸지 않는다. 합성 검토와 전문가의 실제 새 읽기 전용 호출 및 실행 주체를 증거에서 구분한다.
- 호출 행의 고정 스키마는 유지한다. PM은 대상 단위·단계·발동 근거와 기회 번호의 조합을 `opportunity`로 고정하고 `caller`(`worktree_pm`, `hub_pm`, `document_pm`)와 `callId`, 반환 상대 경로, 실제 근거를 JSON에 둔다. 원장 행의 `id`를 그 `callId`와 대조하고, 같은 행을 `ref`로 보강한다. 조기·공동 기회의 프로젝트 사건 `--ref` 또는 백로그 단계의 근거, 상위 단계 `--upper-review --file`의 `call_ref`(`ledger`, `id`, `receipt`)가 같은 증거를 가리킨다. 모델·토큰 출처는 다섯 항목 원장에 남긴다.
- 검토자가 실행하는 스킬 eval은 원문 기준·해답 없는 작업 사본과 첫 응답을 보존한다. 새 사례의 전분기와 기존 회귀를 상위 목적·금지 행동에 대조한다. 사용자의 미결정 상태를 실승인으로 모사하지 않는다.
