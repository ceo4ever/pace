## 문턱과 선택

- 신호 1. 현재 예산 적용 전의 실제 검토 원장(배포 기준 `4c7621d`)에서 독립 검토의 유효한 전이만 셌다. 같은 원장의 같은 대상에서 pass·결정·진단 이후 연속 2회 fail에 처음 도달한 27개 구간 중 다음 판정이 pass인 곳은 7개(25.9%), fail은 20개였다. P009/T06을 빼면 3/8(37.5%)이다. 오늘의 일반 위치만 보면 P005 프로젝트 단위의 1회 fail→pass 한 건이므로 직접 추정할 분모가 없다. 과거 자료는 그 시점에 예산이 없던 실제 작업을 대리 자료로 썼다. 같은 영역 조건을 결합하면 다른 실패의 과잉 권고를 줄이지만 당시 원장은 구조화된 위치·기준이 없어 같은 모집단으로 그 조합을 입증할 수 없다. 결합 조건의 수렴률 비교 결과는 미확인(동일한 정규 구조화 항목 없음)으로 기록한다. 고정 코드와 원장별 다음 판정은 S-5 증거다. 따라서 일반 신호는 최초 유효 2회 fail로 정하고 조합은 신호 3에 적용한다.
- 신호 2. Node·Python 어댑터가 파일별로 보고한 실제 실패·통과만 센다. 시간 초과·신호·시작 실패·0건·전부 skip·불완전 결과는 불명으로 기록해 그 파일의 연속성을 끊는다. `changed`의 전체 전환 실행과 명시하지 않은 시험은 관측하지 않는다. 명시 file은 Git 변경 선택과 무관해 업무 문서 초안이 있어도 등록 시험을 부를 수 있다. 미선택과 기록 밖 명령은 그 파일의 시도를 관측한 것이 아니므로 기존 streak를 유지한다. 2회를 택해 단발 실패를 제외하면서 세 번째 시도 전에 단서를 제공한다. 기록 밖 실행은 관측되지 않는다.
- 신호 3. 직전과 현재의 같은 기록 단위에 속한 구조화 지적을 비교한다. 같은 정규 상대 경로, 같은 기준 ID 또는 양쪽에 기준 ID가 없을 때 같은 명시 영향(예: goal), 그리고 같은 판정 구분, 근접 행(최대 8줄)으로 영역을 보수적으로 좁힌다. 지적 ID는 사용하지 않는다. 두 판단의 유효한 지적과 달라진 검토 대상이 필요하다. 직전 원장의 증거가 충분한 개별 지적은 전체 판정이 미확인이더라도 첫 유효 fail과 비교할 수 있다. 기존 원장이 정한 유효 비교 기준점과 지적만 쓴다. 신호 2는 파일 관측만 제공하므로 행이나 기준이 입증되지 않은 결과에서 별도의 경계 재발을 추론하지 않는다.
- 신호 4. 신호 3의 두 유효 지적의 적용 등급이 같고, 두 스냅숏에서 해당 파일 내용 변경을 `loadRereview`가 검증한 직전 검토 스냅숏과 현 대상에서 확인한다. 직접 검토 중인 같은 파일의 본문 또는 Git 패치 안 해당 경로의 양쪽 구획이 있어 실제 구획이 달라진 경우만 확인할 때만 낸다. 대리 지표의 출력은 수정 품질의 확정 판정이 아니다.

## 접근

- `verify`에 선택 필드 `troubleshooterSignals`를 붙인다. 유형은 `review_failures`, `test_failures`, `recurring_area`, `superficial_fix`다. 신호 1의 예산 단위는 기존 출력에 맡기고 그 우선순위를 유지한다. 신호 2는 `pace test changed` 선택 분기와 `pace test file`의 안내 줄로 같은 유형·단위·근거를 표시한다.
- 시험 관측은 Git이 등록을 확인한 worktree의 실제 Git 메타데이터 폴더 안 `pace/test-signals/log.jsonl`에 기존 `note`와 숫자 표지로 쓴다. Git common dir의 worktrees 아래에 결속된 경로를 검증하고 안전한 디렉터리·일반 파일에서만 읽고 쓴다. 추적 파일·소통 로그를 변경하지 않아 다음 changed 선택에 영향을 주지 않는다. 경로는 유효한 저장소 상대 시험 파일뿐이다. 테스트 본문·stdout·프롬프트는 기록하지 않는다. 읽기/쓰기 오류는 계산이나 원래 검사 성공 여부를 바꾸지 않는다. 새 사건 종류·팀 채택 표지·외부 전송을 추가하지 않는다.
- 구현 경로는 `src/agent/verify-cli.ts`, `src/agent/review-signals.ts`, `src/test-runner/execute.ts`, `src/test-runner/changed.ts`, `src/test-runner/runner.ts`, `src/test-runner/signals.ts`, `test/agent-review-log.test.ts`, `test/review-signals.test.ts`, `test/test-runner.test.ts`, `skills/pace-team/references/required-roles.md`다.
- 민감 경로에 SECURITY를 적용한다. 기존 실행 인자·경로 검사와 파일 로그 검사를 재사용하며, 링크·다른 저장소·경로/비밀 후보와 시험 실패의 전파를 음성 대조한다. 선언 검사와 비밀 검사를 실행한다.
