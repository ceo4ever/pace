## 목적

반복 실패에서 호출한 PM이 검증할 수 있는 해결안을 얻도록 독립 `pace-troubleshooter`를 정의한다. 두 호스트가 각각 owner가 정한 모델과 effort를 실제 적용하는지, 같은 지침을 쓰는 `high` 대비 해결 능력이 떨어지지 않는지 확인한다.

- 이전 반복 실패의 R9/R10(P005 T04)과 R1/R2(P013 T04), 각각 실패 당시 고정본과 사후 해결 기록. [실행 전 고정한 능력 판정](evidence/eval-rubric.md)

## 증명 범위

- 판정 주체: 명령 출력·실제 두 호스트 세션 보고·작성자와 별개 교차 reviewer 및 tester. 능력 판정자는 응답 작성과 입력 제작에 참여하지 않은 새 세션에서 모델과 등급 이름을 가린 응답을 본다.
- 포함: 역할 원본과 생성물, 조건부 필수 역할 표지, 호출 수단·모델 거부·실제 적용 관문, 버전 1 요건 등록 및 대조, 이전 실패 능력 비교, 운영 문서와 브레인.
- 범위 밖: `src/**` 변경, 일반 worker 매핑이나 기존 구성원 변경, 조기/소진 호출 절차(T04), PM 코드 연결(T05), 계정 신뢰 변경, 설치·병합.

## 접근

- `pace team new pace-troubleshooter --role reviewer` 원본을 `.pace/team/agents-xhigh/`에 두고 xhigh로 바꾼다. `.pace/team/required-roles.json`, `skills/pace-team/references/required-roles.md`를 반영하고 `pace team sync`만으로 native 정의를 만든다. `docs/TEAM.md`, 역할 안내, 작업 하네스 흐름 브레인 페이지를 갱신한다.
- `pace agent run --mode p`와 명시 모델·effort, 새 읽기 전용 맥락, 동일 원본의 본문, 호출 원장 역할 식별을 사용한다. 호출 작성자가 속한 제공자와 다른 제공자를 먼저 배정하고, 실제 불가하면 같은 제공자의 새 맥락 및 `cross_unavailable`을 남긴다. PM이 실제 역할·공급자·새 맥락 식별과 반환의 분석을 연결한다.
- 사전 실측에서는 Claude native 실제가 관측됐고 Codex native는 시작만 확인됐다. 두 호스트에서 관측 가능한 직접 실행을 공통 기본으로 한다. 최종 원본을 써서 다시 관측한다. 모델 거부는 대체 실행 없이 PM에게 돌아간다.
- eval 입력에서 사후 해답·채점 기준을 제외한다. 실패 당시 증거와 각 제공자에서 같은 지침·입력만 쓰고, 독립 판정에는 사후 기준과 식별자를 가린 원응답을 제공한다. 기본에서 실패한 경우에만 별도 표본의 높은 effort를 고려한다.
