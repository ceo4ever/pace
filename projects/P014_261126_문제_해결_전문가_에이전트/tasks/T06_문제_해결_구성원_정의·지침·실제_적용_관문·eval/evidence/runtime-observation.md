# 실제 적용의 관측 경로

사례 A의 두 xhigh 호출에 정본 원본과 정규화한 본문 지문을 연결했다. [관문 결과](runtime-gate.json)에는 같은 실행의 모델·effort·조회한 원장의 값만 들어 있다. [시도별 증거](runtime-receipts.json)는 두 차례 각각의 원장 행, 고정 역할·요청 지문, 허용된 호스트 보고, `HANDOFF`의 저장 파일 지문을 결합한다. 실제 응답은 [Claude](eval-answers/A-claude-xhigh.md)와 [Codex](eval-answers/A-codex-xhigh.md)에 있다.

- Claude에서 지정 model·effort를 명시한 새 `agent run --mode p`를 호출했다. 격리 Git 사본의 `.claude/settings.json`에 `hooks.Stop` 명령으로 `python3 <collect-claude-effort.py> <보호된 로컬 파일>`을 설정했다. [관측기](verification-reproducers.md#claude-종료-훅-관측기)는 `effort.level`과 대조용 `session_id`만 읽는다. 종료 훅의 세션과 실행 결과의 세션이 같은 경우만 실제값을 얻는다. 모델은 실행 결과의 `modelUsage`에서 보고된 단일 모델이다. 기본 p 원장은 이 훅의 수치를 직접 받지 않으므로 PM이 프로젝트 CLI에 같은 호출 ID·시각 및 `effort.actual={"value":"high","source":"host"}`를 넣어 보강했다. 네 Claude 실행에서 각 원장 한 행을 유지했다. 로컬 세션 식별자는 공개 증거에 없다. [보강 대조](claude-effort-enrichment.json)
- Codex의 `agent run --mode p`는 실행 머리글의 `model`·`reasoning effort`를 읽는다. 같은 실행 결과와 원장의 `source: host`를 대조했다. 실행기 원본의 `tokens used`는 총량이다. [관문 결과](runtime-gate.json)
- 가용성 실측은 같은 PACE 호출에서 Codex의 stderr와 종료값을 임시 래퍼로 관측했다. 원래 실행기를 같은 인자로 호출하고 stderr를 보호된 파일로 보관한 뒤 같은 stderr·종료값을 PACE에 전달했다. PACE가 제공한 오류 앞부분에는 거부 원문이 없었으나, 같은 실행의 호스트 기록에서 가짜 모델을 지원하지 않는다는 문장을 확인했다. 두 스트림을 바이트 수까지 대조했고 stdout은 0바이트였다. 오류 앞부분과 로컬 호스트 세션을 실제 비교했으며 래퍼의 실행 시각이 단일 호출 행의 실행 구간 안에 있었다. [진단 래퍼](verification-reproducers.md#codex-거부-캡처) [증거 대조 명령](verification-reproducers.md#같은-codex-시도를-대조하는-검사) 호출 원장 한 행의 요청·미확인 실제 설정·실패를 대조했다. 실제 지정 모델은 두 호스트에서 성공했다. 25ms 제한 시간 대조는 `timeout` 및 `interrupted`여서 모델 거부와 구별된다. [거부 및 중단 대조](model-availability.json)
