# 문제 해결자 능력 평가 기준

후보를 실행하기 전에 이 기준과 두 실패 당시 입력의 출처를 고정한다. Claude·Codex 각각 같은 지침 본문과 사례를 high와 xhigh에 제공한다. 전부 새 읽기 전용 맥락이며 사례 파일과 요청만 제공한다. 별도 판정자는 모델과 등급 배정을 가린 응답과 당시 증거·사후 해결을 받고 항목별 이유를 남긴다.

## 개별 응답 기준

| 항목 | 판정 질문 |
|---|---|
| 목표와 증거 | 목표를 다시 확인하고 당시 원문의 위치를 근거로 재현 또는 범위가 명시된 재현 결과를 설명했는가? |
| 원인 층 | 당시 실패를 일으킨 층과 경계를 구체화하고 다른 원인 후보 또는 땜질을 반증했는가? |
| 해결 비교 | 최소 두 가능한 조치를 비용·위험·되돌리기와 목표 달성 방식으로 비교했는가? |
| 추천 | 추천과 근거가 실제 실패 원인을 제거하는가? 사후 조치와 다른 방법은 같은 원인·경계를 해결하면 인정한다. |
| 검증 | 해소와 재발을 구별하는 긍정·부정 관찰 또는 재현 명세가 있고 실패 시 다음 수가 있는가? |
| 불확실성과 경계 | 사실과 추정을 구분하며, 남은 불확실성과 호출자 인계를 남기고 수정·커밋·판정·결정 대행을 피했는가? |

모든 항목이 충족된 응답을 해당 사례 통과로 센다. 각 제공자의 xhigh는 사례 2건 모두 통과하고 같은 제공자의 high 통과 건수 이상이어야 한다. 실행마다 경과 시간, 모델·effort의 요청값 및 관측값, 공급자가 보고한 토큰과 관측 범위를 적는다. 기본 effort가 이 기준을 통과하면 effort를 올리지 않는다. 실패한 사례가 있으면 같은 고정 입력에 더 높은 effort를 한 번 비교할 수 있으며 고정 요건 변경의 결정 주체는 정본 A로 판정한다.

## 판정자에게 제공할 사후 대조

- A — P005 T04의 R9/R10 검토와 R10 당시 고정본. 원인 층은 검증 설계다. 작성 성공이나 버튼 소실은 대상 actor의 이 시도 callback 증거가 아니다. 추천은 같은 시도·대상과 수락 근거를 결합해야 하며, 이미 처리됐거나 다른 actor가 눌러 버튼이 사라진 경우를 식별해야 한다. P005 T04의 `TASK-CLOSE.md` S-3r을 사후 기준으로 본다.
- B — P013 T04의 R1/R2 구현 검토와 R2 당시 고정본. 원인 층은 구현에서 현재 계약 회차를 선택하는 기준의 누락이다. 예산은 현재 회차를 따르지만 재검토 후보 확인이 이전 회차 unknown의 근거를 가져갔다. 첫 전체 검토와 현재 회차의 실제 증거 이어가기 모두 구별해야 한다. P013 T04의 `evidence/review-disposition.md`와 `TASK-CLOSE.md`를 사후 기준으로 본다.
