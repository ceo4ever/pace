# T06 2단계 교차 검토 지적과 대응

최초 [교차 판정](review-records/R1.json)은 pass, blocking 0이었다. 최종 후보는 [후속 패치](implementation-final.patch) SHA-256 `75f15b443b08c1d2ffc9272460301eb774520fd949fb85d0323af7d3160a3144`다.

| 지적 | 대응 |
|---|---|
| F1 | 진단용 임시 실행기에서 같은 호출의 호스트 stderr와 종료값을 확인했다. CLI 오류 앞부분이 거부 원문을 누락한다는 재현도 함께 남겼다. 문서에 실제 확인 또는 미확인의 조건과 보호된 캡처를 설명했다. [같은 실행 대조](model-availability.json) |
| F2 | 고정 기준을 바꾸지 않고 별도 블라인드 음성 대조를 했다. 실제 응답과 문턱 미달의 합성 답을 독립 판정자가 구별했다. 기본 표본은 그대로 유지했다. [음성 대조](eval-negative.json) |
| F3 | 시간 초과의 완료 결과 부재와 원장 프로세스 경과 시간을 별개 관측으로 명시했다. [거부 및 시간 초과](model-availability.json) |
| F4 | 일반 등급 표의 모델을 배포 기본 모델 및 `worker show` 참조로 고쳤다. 고정된 xhigh 지정값은 정본과 유지한다. |
| F5 | xhigh 원본에서 공통 실행 전 대조 문단을 제거한 별도 fixture는 실제 `team list`가 종료 2로 거부했다. parser의 공통 문단 검사는 이 경로에도 적용된다. 맞춤 보충 문단과 두 표지의 대조는 태스크의 시험으로 보존했다. [음성 대조](team-negative.json) |

독립 tester의 최초 2단계 호출은 시간 제한으로 판정이 없었다. 입력·실행 범위를 좁힌 새 Codex 세션에서 다시 요청했다. [최초 시도 결과](tester-stage2-timeout.json)

첫 F1 확인에서 캡처와 호출 행을 묶는 식별자·시각과 stdout 전달을 증명하지 못해 tester와 별개 reviewer가 blocking 1을 냈다. 원인은 진단 절차 자체보다 실행 증거의 연결 방식이다. 같은 실행이라는 선언에 의존한 데이터를 교체한다. 실제 호스트 세션의 동일성, 호출 ID·시각과 래퍼 실행 구간, 양쪽 스트림의 바이트 전달과 종료값을 실행 중 기록하고 재검증한다. 공개에는 안전한 파생값과 허용된 거부 문장만 넣는다. [첫 확인](reviewer-recheck-initial.json)

두 번째 F1 한정 확인은 통과했다. 로컬 호스트 세션과 오류 미리보기를 대조하고 단일 PACE 호출 ID·시간 구간·양쪽 스트림·종료값을 함께 확인했다. 공개 래퍼 바이트의 SHA가 관측에 사용한 래퍼의 SHA와 일치한다. [최종 확인](reviewer-recheck-final.json) [같은 실행 증거](model-availability.json)

한정 tester는 T-1·T-3·T-4와 두 명령을 통과시켰지만 T-2의 성공 시도를 자료 한 묶음으로 독립 대조하지 못해 fail을 냈다. 최초 게이트 요약과 별도 응답을 서로 찾아야 하는 증명 구조를 보강했다. 각 시도에 역할과 요청 지문, 호스트 출처, 원장 행, `HANDOFF` 포함 응답 파일·지문을 묶었다. T06 평가에는 지정 역할 호출과 실패 사례 능력이 포함된다. 조기·소진의 실제 PM 연결은 T04가 검증한다. [tester 첫 판정](tester-stage2-initial-fail.json) [시도별 증거](runtime-receipts.json)

더 넓게 실행한 2단계 재시도도 전체 시험을 다시 시작해 세션 시간 내에 판정을 반환하지 못했다. 검사 전체 1회와 현재 문서의 집중 30개는 격리 환경에서 이미 별도로 완료했다. 최종 독립 확인은 보강한 시도별 증거와 직접 지문 대조로 한정했다. [두 번째 시간 초과](tester-stage2-retake-timeout.json)

마감 `pace project check`는 실행 형태의 증거 스크립트 네 개가 승인된 구현 경로에 없음을 발견했다. 운영 코드와 스킬은 기존 허가 범위 그대로다. 검증 프로그램 원문과 SHA를 실행 대상이 없는 재현 문서로 보존하고, 실행 파일은 격리 실측 폴더에 뒀다. 동작이나 기존 판정을 바꾸지 않았다. [재현 문서](verification-reproducers.md)
