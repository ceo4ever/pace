## 설계

실제 작업 순서는 T01 → T02 → T03 → T04 → T05 → T09 → T06 → T07 → T08이다. T09는 T02·T05 완료 및 BR09 최종 독립 판정 확인 뒤에 열고, T06·T08은 T09 완료 뒤에 연다. BR↔T 번호는 유지하며 태스크 표도 이 순서로 둔다. T01의 임시 저장소 작업자 실측과 기준선 정의는 실제 적용 저장소와 분리한다. 업무 문서 저장소는 사용자 지정을 받은 뒤 기준선 작업에 들어간다. T05·T06은 임시 프로젝트에서 장치와 출력 계약을 검증하고, 실제 직렬화·비교·회고는 T08에서 닫는다.

역할은 저장소 소속으로 유지한다. 역할 정의·생성물·공유 잠금은 저장소 및 공통 파일 경계를 검사한다. 호스트 역할 선택은 기존 작업자 실행 권한을 넓히지 않으며, 시작 지시 경로의 도구 권한 적용 여부는 기록한다. 잠금과 질문 로그에는 자격 증명이나 질문 원문을 남기지 않는다. 변경 경로는 보안 리뷰에서 경로 경계, 파일 덮어쓰기, 작업자 권한, 낡은 소유 토큰과 오동작을 확인한다. T02는 `.pace/team` 원본·두 native 출력의 조상 링크/파일 종류/하드링크와 foreign 충돌을 전체 사전 검사하고 관리 표지가 있는 출력만 갱신한다. 사용자 등급 설정은 기존 worker 설정과 같은 PACE_HOME의 별도 파일에 보관하며 기존 설정 형식을 바꾸지 않는다. 생성물은 현재 모델 매핑의 스냅숏으로 설정 차이를 별도 진단하며 tools는 권한 제한으로 승격하지 않는다.
