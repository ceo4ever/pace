# R72 자동 Git 반영 경계 결정 자료

[R72 독립 목표 검토](impl-review-output-72.json)는 blocking 2, should_fix 0이었다. R70은 과거 상대 경로, R71은 전송 머리와 회고 전용 영수증, R72는 외부 시도 전체의 시각 순서와 첫 스테이징의 실제 반영 경계를 지적했다. [R72 두 음성 대조](r72-red.txt)와 [수정 후 집중 10건](r72-focused.txt)은 전송 머리와 첫 중간 커밋을 확인한다. 이 집중 시험은 실제 인덱스 보존을 검증하지 않았다.

## 전송 시도 시간

외부 전송의 시작과 나중 확인 사이에 unconfirmed가 있으면 마지막 확인의 시각도 모든 앞 상태와 맞아야 한다. 원장에서 나중에 들어온 성공 또는 실패 신고가 중간 불명보다 이른 시각을 가리키면 도달 또는 실패만 남은 요청을 확정하기 어렵다. 이 부분은 기존 도달 계약으로 수정하고 별도 답과 실패 시도 관측을 살릴 수 있다. 합성 원장에 정상/역전, 기간 안팎을 대조한다.

## Git 반영 경계

R66 A는 선언 영수증의 원문 혼입을 자동 스테이징 전에 보류하는 목적을 승인했다. R72는 회고를 첫 커밋의 트리까지 대조하지만, 실제 인덱스를 먼저 갱신한다. 사이에 영수증에 원문 필드가 생기면 중간 커밋은 막혀도 실제 인덱스에 남는다. 브랜치에는 도입 표지가 없고 main에만 도입된 경우의 합류도 같은 목적에 해당하며, 기존에는 rebase 전 실제 인덱스와 중간 커밋을 갱신할 수 있다. 현재 프로젝트의 실자료 유출 또는 원문 혼입을 발견한 것은 아니다.

- A (추천) · 팀 적용 후보에 한해 첫 자동 스테이징을 임시 인덱스와 임시 객체 경로에서 검증한다. 불일치하거나 main에서만 팀 적용이 확인되면 실제 인덱스와 HEAD 변경 전에 보류한다. 확인된 후보만 기존 자동 마감 흐름으로 반영한다. 정상 마감은 자동 흐름을 유지하고 원문에 닿는 오류는 초기에 막는다.
- B · 팀 적용 후보의 첫 자동 스테이징을 중단하고 사람이 검토한 로컬 커밋이 있을 때만 마감을 계속하게 한다. 구현 경계는 단순하지만 현재 자동 마감 사용법을 바꾼다.
- 직접 지정 · 코디네이터가 다른 방식이나 범위를 지정할 수 있다.

두 방식 모두 합성 Git과 증빙으로 대조한다. 당장 실제 파일 경로나 권한의 변경, 실제 원본 수정, main 병합 또는 전송은 수행하지 않는다.

## 코디네이터 결정과 R73 대조

main 판단으로 A를 승인했다. 실제 인덱스·Git 객체에는 검증한 후보의 커밋과 연결된 자료만 반영한다. 실제 작업 파일을 다시 git add -A 하여 반영하거나, 기준 브랜치 단독 채택 또는 인덱스·HEAD 변경을 무시하는 경로는 허용하지 않는다. 실제 인덱스·객체·HEAD와 기존 staged 내용, 정상 자동 마감과 비팀 호환을 합성 저장소에서 대조한다.

R73은 원장의 같은 시도 시작·불명·최종 신고 전체를 시간 순서로 대조한다. 중간 행이 구간 밖에 있어도 그 순서를 검사한다. 정상 답과 신고된 실패 시도는 보존한다.

마감 후보는 임시 인덱스와 임시 객체 경로에서 스테이징한다. 대시보드는 같은 인덱스를 읽고, 기존 커밋 훅은 격리 HEAD에서 실행한다. 검증한 트리의 후보 commit/직접 부모·후보 인덱스가 일치해야 한다. 실제 인덱스 파일을 잠그고 시작 시점과 비교한 뒤 Git 참조 트랜잭션에서 worktree와 기준 브랜치를 확인한다. 트랜잭션 준비가 성공하면 검증한 후보 커밋에 연결된 객체만 실제 객체 경로에 설치한다. 팀 이력이 기준 브랜치에만 있다면 rebase 전에 보류한다.

[실패 원문](r73-red.txt)은 수정 전 후속 시간 역전, 실제 인덱스 변경과 기준 브랜치 단독 채택을 재현했다. [집중 시험](r73-focused.txt)은 7건을 통과했다. 회고 경합의 비공개 합성 값은 실제 Git 객체로 조회되지 않았고 기존 staged 바이트도 유지됐다. 실제 인덱스 변경과 참조 트랜잭션 직전의 HEAD·기준 브랜치 동시 변경은 해당 새 상태를 유지했고 후보 객체의 추가가 없었다. 후보 커밋 훅의 거부는 실제 인덱스·객체·HEAD와 대시보드 파일을 보존했다. 정상 후보 인덱스에서 생성한 대시보드가 중간 커밋에 들어갔다. [이전 출력 대조](legacy-r73.json)의 비팀 JSON·텍스트·METRICS는 바이트가 같다.
