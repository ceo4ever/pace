# 진단 뒤 R26·tester19 영향 분류와 결정

R23 fail3/SF1 → R24 fail1/SF2 → R25 fail1/SF1에서 design 진단을 기록했고, 새 전체 R26은 fail3/SF1, tester19는 fail1/SF1이었다. 도구의 ask_user 단계는 주체 자동 지정이 아닌 결정 필요 단계다. 이 문서를 수정 전에 기록하고 PM 결정으로 원장을 잇는다. 앞선 pass나 집중105를 목표 달성으로 대체하지 않는다.

같은 입력 결합 영역을 다시 진단했다. 경로의 provenance는 누락을 막았지만 실제 검증 시점의 내용까지 고정하지 못했다. 근본 조치는 각 판독기가 실제 사용한 UTF-8 내용의 지문을 기록하고, finish가 생성할 사건/지표까지 정리한 뒤 고정한 Git tree와 대조하는 것이다. 변경 중인 인덱스나 나중 작업 파일을 검증 원본으로 간주하지 않는다. 기록한 tree로 자기 영수증을 만들며 커밋 후에도 tree 결합을 확인한다. metadata 경로 목록 땜질을 반복하지 않는다.

다른 지적도 같은 목적 안의 일반 갭이다. 중계 제안보다 이른 답은 strict Team 도달 근거가 아니며 기존 원장 보존/호환은 유지한다. 불완전한 리뷰 로그는 유효한 TASK-CLOSE 지적을 지우지 않게 하고 미확인을 표시한다. 검사 부작용 감시는 처음 Team 표지가 없어도 항상 적용해 rebase 중 채택 우회를 막는다. FF 실패 사유는 복구 안내가 아닌 실제 원인에서 분류하며 slash 리뷰 구분자의 기존 유효 입력을 보존한다.

PM 결정 이유: 승인된 T06의 도달/반복 지적/회고 강제성과 기존 유효 입력 호환을 채우는 내부 구현이다. 사용자·비밀·실제 저장소 적용·비용·목적/기준/실증 보류를 바꾸지 않는다. 실제 P009 merge·설치·외부 전송은 하지 않으며 합성 Git/PACE_HOME에서 검출력을 확인한다. main이나 사람의 승인으로 위장하거나 waiver로 실패를 없애지 않는다.

선택은 snapshot 지문/고정 tree 기반의 보완과 전체 목표 재검증이다. 판정이 회수된 뒤 고친 층·실제 입력 포함/제외·검증 결과를 TASK-CLOSE와 완료 보고에 남긴다. 새로운 보안/사용자 자료/합의 영향이 확인되면 수정 전에 그 구체적 범위를 올린다.
