R72→R74 목표 검토 결과는 차례로 2 blocking, 2 blocking·1 should_fix, 1 blocking·1 should_fix다. [R74 판정](impl-review-output-74.json)은 기준 브랜치 동시 채택과 인덱스 설치 거부의 앞선 blocking을 해소했다. 현재 부적합은 실제 인덱스를 설치한 뒤 객체를 옮기기 전에 반영 프로세스가 중단되는 경우다. 외부 전송이나 실제 작업 저장소 손상은 관측하지 않았다. [R74 집중 시험](r74-focused.txt)은 13건 통과했고 [전체 검사](whole-r74-209.txt)는 1,345건 중 1,327통과, 17건너뜀, 대시보드 상위 정션 합성 fixture 1실패였다.

## 원인과 영향

복구 의도가 자식의 예외 처리와 부모의 임시 경로 보존에만 있고 이후에 유효한 HEAD·인덱스 관계를 복구할 소유 기록이 없다. 인덱스 설치 직후 객체 이동 전에 자식이 강제 종료되면 기존 HEAD와 후보 인덱스가 남을 수 있다. 복구해야 할 상태는 Git 참조와 파일이 함께 만든다. 인덱스가 설치되기 전에 기록한 원본·후보 지문이 있어야 앱이 자기 변경과 다른 사용자 작업을 구분할 수 있다. 별도로 Git 2.55의 합성 reftable 저장소에서 다른 참조의 verify-only 트랜잭션이 열린 동안 일반 git commit은 코드 128과 cannot lock references를 반환했다.

## 선택지

- A (추천) · 기존 격리 승인을 유지하고 worktree Git 내부에 자동 반영의 한시적 복구 기록을 둔다. 절차 ID·작업 참조·기존 및 후보 SHA와 인덱스 지문·소유자·원래 인덱스만 보관한다. 자식 종료 직후와 다음 실행 전에 이 작업의 것이 확인되는 상태만 복구한다. 새 사용자 작업이나 소유를 확인하지 못한 잠금은 건드리지 않고 복구 자료를 남긴다. reftable에서는 검증된 단일 참조 트랜잭션을 쓴다. 정상 자동 마감을 유지하면서 프로세스 종료 후에도 원래 staged 작업을 복원할 수 있다.
- B · 정확한 검증 객체 자동 반영을 현 revision에서 제공하지 않고, 영향을 받는 첫 자동 반영을 중단해 사전 검토한 기존 인덱스·로컬 커밋이 있을 때만 마감을 진행하도록 범위를 조정한다. 변경은 작아지지만 자동 마감 사용법과 계약 근거를 바꾼다.
- 직접 지정 · 범위나 방식 선택을 바꿀 수 있다.

A는 파일/정책의 사용자 원문, 실제 repo outside P009, 운영 전송·병합에는 새 권한을 요구하지 않는다. 변경된 Git 보존·복구 위치와 강제 종료 동작을 승인받고 합성 Git에서 중단 직후와 재호출 복구, 정상 성공, 사용자 인덱스·HEAD 모순 보존, 기존 files/reftable 동작을 대조한다. 권한·데이터가 그대로인 B도 현재 계약 변경 승인 없이는 적용하지 않는다.

전체 검사에서 실패한 대시보드 시험은 같은 후보의 [단독 재실행](r74-dashboard-isolated.txt)에서 1건 통과했다. 전체 실행에서만 실패한 원인은 아직 확인하지 못했다. 강제 종료 지적의 현재 근거는 독립 검토의 모의 주입이며 다음 구현 검증에서 실제 합성 Git 프로세스 종료로 대조한다.
