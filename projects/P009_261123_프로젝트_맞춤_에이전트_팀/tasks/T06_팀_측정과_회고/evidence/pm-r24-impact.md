# R24 보완 판단

공식 R24 fail1/SF2, tester17 fail3/SF1이며 소스35개 지문 불변의 전체1227건(1210통과/17보류)과 집중97 통과는 해당 후보의 기록이다. 목표 미달을 검사 통과로 덮지 않는다. 독립 탐침은 원문을 보존했다.

정상 구현 누락으로 다음을 보완한다. 합의 목적·기준·범위는 바꾸지 않으며 실제 병합·설치·외부 전송을 수행하지 않는다.

- 검증 자료의 Git 결합: 최종 회고/측정 JSON의 실제 근거 참조, 로그·원장·현 팀 정의가 인덱스에 일반 파일로 포함되고 검증한 작업 파일과 동일한지 확인한다. CRLF/LF 차이만 허용한다. ignored·미추적 근거를 강제로 추가하지 않고 이유를 표시해 보류한다.
- 검사 부작용: 새 팀 마감의 검사 뒤 새 staged/unstaged 변경이 있으면 보류하며, 무관한 staged 내용을 마감 커밋에 흡수하지 않는다.
- 기존 파일: 팀 채택 때만 finish 영수증 경로를 관리한다. 기존 다른 용도의 파일은 중간 자동 커밋 전에 충돌을 알린다.
- 승인 대상: 팀 프로젝트의 미리보기가 제시한 전체 SHA를 --yes --commit으로 명시하게 하여 호출 사이에도 승인 대상이 달라지지 않게 한다. 팀 없는 기존 merge 동작은 유지한다. 대상 SHA 제공은 사람 승인 자체를 인증하지 않는다.
- worktree 없는 merge 거부는 main 정본에 실패 로그를 새로 만들지 않는다. 오류 원문은 호출자에게 반환하고 수정 후 깨끗한 main에서 재시도할 수 있게 한다.
- 선언 응답 ID는 최초 요청 이후 응답인지도 대조한다.

정의 변경 영수증의 제안 의미/역할 내용은 사람 검토라는 남은 한계다. 이름 존재는 검사하지만 범용 지문으로 제안의 의미를 자동 인증하지 않는다. 비용·사용자 자료 변경·새 외부 행동은 없으며 PM 자체 판단으로 구현하고 별도 검토로 대조한다.
