# R23–R25 입력 결합 설계 진단

공식 R23 fail3/SF1 → R24 fail1/SF2 → R25 fail1/SF1로 연속 세 번 실패했다. R25 출력의 diagnose 신호 직후 개별 수정과 다음 검토 호출을 멈췄다. 실제 실패 원문과 후보 지문은 그대로 보존한다.

원인 층은 design이다. 검증은 작업 폴더의 집계 결과를 읽는데 Git tree 영수증은 별도 인덱스를 고정한다. R24에서 고정 파일과 refs 목록을 대조했지만, R25에서 집계기가 fallback으로 읽은 TASK-CLOSE가 빠지는 등 수동 입력 목록은 검증의 실제 의존성을 포괄하지 못했다. 반대로 실제 도달 근거로 탈락한 ref도 과도하게 필수로 삼았다. 지적별 파일명을 추가하는 방식은 반복하지 않는다.

근본 조치는 집계/검증기가 실제 사용한 입력을 내부 추적 집합으로 반환하고 최종 인덱스 대조가 그 집합을 소비하게 하는 것이다. 특히 반복 지적 산출의 TASK-CLOSE, 현재 팀 정의, 회고·보조 입력과 실제 채택한 답 영수증의 출처를 연결한다. 공개 legacy JSON/기존 통계 의미는 바꾸지 않고 Git 포함 여부를 강제 추가하거나 원문을 읽어 복사하지 않는다. 제외된 답은 기존 unknown을 유지하며 필요한 입력만 결합한다. 현재 대상과 같은 경로/원장을 이어 전체 목표를 재검토한다.

분류는 PM 결정이다. T06의 측정 장치·회고 강제성과 기존 호환 보존을 채우는 일반 구현 누락이고, 목적·기준·실증 보류 합의를 바꾸지 않는다. 현재 미커밋 후보의 내부 데이터 흐름과 합성 시험만 고치며 사용자 자료·비밀·비용·실제 병합·설치·외부 전송에 새 영향은 없다. 메타데이터의 진위/의미를 자동 인증한다는 주장을 추가하지 않는다. 태스크 마감은 독립 목표/계약 판정과 현재 전체 검사 뒤에만 한다.

사후 보고에는 반복된 입력 누락, 고친 provenance 전달 설계, 추가/제외한 입력, 재검증 결과를 기록한다. 범위 변경/심각한 사용자 영향이 새로 확인되면 수정 전에 결정 요청으로 올린다.

### 상태 경계와 권한

- pre-commit: 보안/감사 전후 전체 입력·인덱스 지문 → 자동 목차 커밋 → rebase → 전체 검사 → 최종 데이터 집계/회고 → 고정 tree/실제 입력 지문 대조. 처음 Team이 없어도 명령 부작용 보호가 적용된다.
- 성공/실패: 기존 src의 finish 시도 ID는 해당 프로젝트/태스크의 성공과 실패만 연결한다. A는 main 판단으로 승인됐으며 [결정/구체안](finish-log-preservation-proposal.md)에 연결한다. 동시 append·실제 실패·다른 시도·식별자 없는 과거 기록을 삭제하지 않는다. 취소된 성공은 Git 완료 메시지 근사로 되살리지 않는다. 전역 잠금 B는 추가하지 않는다.
- post-commit: 이미 생긴 커밋이나 외부 행을 되감지 않는다. merge는 실제 Git 커밋의 tree를 대조하고 승인 SHA를 FF한다. 실제 FF 성공만 실패 기록의 소유를 바꾸며 복구 문구로 오류 원인을 재분류하지 않는다. worker가 실제 P009 merge/설치를 하지는 않는다.
- 호환/원문: legacy 비팀 JSON/텍스트/METRICS 의미는 유지한다. 보안/감사 명령이 만든 변경의 묵시적 커밋은 보호 결함으로 보류한다. private 본문은 로컬에 남고 Git에는 typed metadata만 사용하며 사람/출처/완전성을 인증하지 않는다.

### 중복 대조와 조치

R27 판독/고정 tree/취소 구조는 유지한다. 감사에서 발견한 요청 최초 시각과 owner 방향 신호의 재추론, strict 답 앞의 legacy 파일 존재 검사를 정리한다. 요청 판정기의 결과를 측정에 전달하고, strict 답은 typed 영수증 판정 한 번만 채택한다. 원장 snapshot도 집계와 판정이 공유한다. 반면 기간 안 실제 종류/역할 관측과 최초 요청 코호트는 다른 의미라 합치지 않는다. 새 Markdown 수용 경로는 추가하지 않는다.

### 고정 후보 검증 계획과 현재 증거

기존 R27 집중114 및 추가9·FF 복구1의 원문을 보존하되 최종 후보의 통과로 미리 쓰지 않는다. 위 구조 정리 뒤 후보 하나의 파일 지문을 고정한다. 동일 요청의 log/원장 중복, 참조/시간/구간 모순, 수집 누락/실패의 0·개선 오판을 실제 CLI snapshot→비교→METRICS/회고/finish까지 통과하는 대표 대조로 확인한다. 예시/잘못된 회고 경계는 기존 canonical matrix로, 내용/인덱스 변경·동시 append/취소·pre/post commit·legacy는 실제 임시 Git으로 검증한다. 그 후보의 집중·전체·독립 첫 목표 판단→별도 계약 판정을 회수한 뒤 원인/구조/결과를 한 번에 보고한다.

### 통합 대조에서 정리한 실제 구조

- 요청 판정은 원장 snapshot 하나와 rootAt/ownerSignal 결과를 공유한다. typed 답 판정 앞의 legacy 파일 존재 재검사를 없앴다. 전달도 요청→prepare→terminal 선후를 같은 함수에서 판정하며 모순은 unknown이다. 보고된 실패 관측은 모순 때문에 0으로 지우지 않는다.
- `hasTeamContract`가 작업 폴더·회고 필수성·Git 대상의 채택 정본이다. Git grep 문자열로 start 여부를 추정하지 않고 같은 JSONL 사건 판독을 쓴다. 예시 marker로 legacy 문법을 소급하지 않는다. 공개된 canonical 문법을 늘리지 않았다.
- `InputSnapshot`은 내용 지문뿐 아니라 선택 입력의 부재와 역할/실제 TASK-CLOSE 목록을 기록한다. 반복 의미 판독의 영수증도 같은 trace를 쓰고, 비교 묶음은 같은 원본 bytes에서 값과 지문을 얻는다. 일반 stats도 한 read snapshot을 사용한다. private 원문은 추적/Git 대상으로 추가하지 않는다.
- 최종 tree 대조는 읽은 blob, 없던 입력의 추가, 새 역할/회고 입력의 목록 변화까지 검사한다. 동시 append/새 입력은 보존하고 실패한 finish 시도의 성공만 취소한다. legacy의 안정된 출력/식별자 없는 기록은 기존 의미이며, 전역 기록 잠금은 만들지 않았다.

대표 통합 대조는 실제 CLI의 네 고정 대표 구간에서 동일 요청의 질문 사건2개+원장을 요청1개로 집계하고, 전 도달2→후 도달0·손작업 감소라도 failed-only가 남으면 unknown을 유지한다. 잘못된 답 참조를 추가하면 총량은 null이 되며 같은 snapshot을 비교/METRICS/회고/finish에 연결한다. 추가 대조는 영수증 판독 중 변경, prepare보다 이른 sent/failed, 새 역할/보조 입력/TASK-CLOSE의 늦은 staging, pre/post commit 및 동시 로그 취소다. 초기 receipt fixture의 잘못된 필드는 원문을 보존하고 API의 responseId/responseHash로 고쳤다. 이 설명은 다음 고정 후보의 통과 판정이 아니며 실제 실행 원문과 최종 차수를 연결한다.


### R27 의미 범위 대조

고정 R27은 집중123/전체1253(통과1236·건너뜀17·실패0)이지만 독립 첫 목표 판정 fail blocking3/should_fix2였다. 입력 bytes→tree 결합만으로 증거의 의미 범위는 보장되지 않는다. 공통 원인은 개별 요청 영수증의 전체 수집 승격, 다른 Task의 같은 요청 ID 병합, 완전한 리뷰 한 행의 전체 이력 대체다. 기존 진단의 T-1/T-2/T-5를 아래 정책으로 보완한다.

영수증에는 명시적 purposes를 두고 전체 완료/수집과 개별 요청 답의 주체를 구분한다. 전체 확인은 requestId/decisionReplyId가 없어야 하며 해당 목적과 같은 기간을 요구한다. 기존 무목적 locator는 읽을 수 있지만 총량 권한은 없다. 한 ID에 명시된 Task 둘 이상이면 canonical 판정은 unknown이며 같은 Task 중계와 프로젝트 범위 거울 기록은 중복 제거를 유지한다. 리뷰는 TASK-CLOSE와 사건 원본 수치를 함께 보존하고 겹침이 미확인인 후보 하한은 종류별 max로 삼아 누락/중복 합산을 피한다. 행 형식 완전성을 이력 수집 완전성으로 취급하지 않는다. 일반 검사도 HEAD 변경을 보류하며 검사 스스로 만든 커밋은 보존한다.

분류는 같은 목표의 일반 구현 누락을 채우는 PM 결정이며 범위·실증 합의를 바꾸지 않는다. 신고 purposes도 사람/완전성 인증은 아니다. 실제 사용자 원문/설치/병합은 건드리지 않는다. 다음 고정 후보에는 각 반례가 비교/회고/finish까지 이어지는 대조를 포함하고 같은 원장으로 첫 목표 판정부터 다시 받는다.


### R28 검토 전송 차단

수정 후보41개 파일은 고정했다. 추가4개/기존123개 집중 테스트와 legacy 출력 바이트 대조는 통과했다. 같은 검토 실행 세 번 모두 모델 판정 전에 종료됐으며 원장에는 새 검토 판정이 없다. 세 번째 호출의 실제 stderr에서 입력1,214,321자가 CLI 상한1,048,576자를 넘은 것을 확인했다. 앞의 두 오류는 실행기가 앞300자만 보존해 원인이 직접 드러나지 않는다. 제품 fail이나 모델 판정으로 위장하지 않는다. 원본 patch/이전 검토/원장은 그대로 두고 중복된 실제 delta와 산출물 본문을 지문 있는 파일 참조로 전달하는 실행 래퍼를 준비했다. 이 transport 조치는 제품 코드를 고치거나 기준점을 초기화하지 않으며 코디네이터 결정 전 호출하지 않는다.

### R27~R29 세 번째 실패의 원인 층 재진단

기존 경로를 대조했다. handoff record는 자체 봉투/원문 지문을 원장에 기록하고 project log는 별도의 수동 사건이며 자동 거울 생성이 아니다. 분류는 같은 계약의 측정 누락/검출력 갭을 채우는 PM 결정이다. 새 입력 스키마·실제 저장소 데이터 쓰기·사용자 인증·외부 행동을 추가하지 않는다. 스키마를 확대하거나 기존 증명 범위를 바꿔야 할 근거가 새로 확인되면 먼저 main에 구분해 올린다. 다음 검토는 원장 diagnose 뒤 새 기준 전체 판단이며 R29 실패/고정 후보/검사 결과는 보존한다.

### R30 진단 뒤 새 기준과 PM 분류

새 전체 판단 R30은 fail2/SF1이다. 이전 중계/거울 결합과 호환 대조는 유지한다. 요청 자체의 독립 시작뿐 아니라 로그 답의 태스크 귀속을 같은 판정기에서 확인한다. 태스크가 붙은 로그 답은 확인된 같은 태스크 근원에만 연결한다. 참조가 원장에서 직접 검증된 실제 중계/응답은 원장 분류로 계속 관측한다. 코디네이터 자체 답의 요청 후보도 같은 판정 결과를 받는다. 과거 팀 미채택 review 입력은 옛 파싱을 복구하되 새 품질 집계는 엄격한 같은 수치 대조를 계속한다.

분류는 기존 목표의 일반 구현 갭이다. 보호 우회가 합성 환경에서 재현됐으며 현재 미출시 후보에만 영향이 있다. 실제 사용자 데이터·외부 실행·합의 범위 변경은 없다. R30의 실패를 waiver 처리하지 않는다. 현재 전체 검사는 R30 지문을 다시 확인한 뒤 보존하고, 다음 후보에서 실제 CLI의 사용자/코디네이터 답 대조와 마감 뒤 삭제 커밋, legacy 대조를 함께 검증한다.

R31 fail3/SF2를 실제 원문에 연결한다. 요청 범위의 시간은 ID 전체 최초 시각과 분리해 Task마다 최초 질문 시각으로 결합한다. rebase로 채택이 사라지면 진입 게이트의 사실을 유지하고 최종 검증 누락과 봉인을 보류한다. 역할 관측은 기존 role-observation 목적과 sourceRef 안의 역할/관측 종류를 결합한다. 활동과 관측 없음의 신호를 구별하고 unknown 관측은 수치 확정에 쓰지 않는다. 기존 필드·스키마를 그대로 사용한다. 미채택은 기존 관대한 로그 판독을 따르고 팀 품질만 엄격한 단일 판정/역할을 요구한다. 기존 목적·기준의 구현 보완이며 실제 쓰기·병합·사용자 데이터 영향은 없다. 현재 전체는 R31 고정본에 귀속하고 이후 지문 검증 뒤 제품을 수정한다.

### R31~R33 세 번째 실패의 채택 상태 진단

R31 fail3/SF2 → R32 fail2/SF1 → R33 fail1/SF0으로 원장 diagnose가 발동했다. 이번 실패들은 현재 트리·과거 트리·현재 쓰려고 하는 트리가 같은 채택 신호의 존재 여부를 서로 다른 의미로 읽은 데서 생겼다. R31은 초기 채택 이후 현재 최종 검증을 생략했다. R32는 과거 채택의 원문 문맥 대신 변화한 표지 문자열만 검색했다. R33은 실제 Git blob을 읽으면서 유효한 과거 채택과 이미 사라진 과거 형식 오류를 구분하지 못했다.

기존 현재 표지 판독을 채택/부재/형식 오류의 한 구조 해석으로 유지한다. 현재 입력에서 형식 오류는 의미 오류로 보류한다. 과거의 오류 버전 자체는 유효 채택이 아니므로 다음 선조를 계속 확인한다. 실제 Git 읽기 실패와 올바른 과거 v1·선행 검증된 마감은 계속 엄격하게 처리한다. 유효한 v1 이력, 잠깐 노출됐다 복원된 v2, 현재 미지원 v2, 다른 정상 legacy 프로젝트를 함께 검사한다.

목적·기준은 그대로다. 현재 미출시 구현의 기존 호환성과 관문 오류를 고치며 실제 merge·설치·사용자 자료·외부 실행에 영향이 없다. PM 일반 설계 갭으로 분류하고 새 기준의 전체 독립 검토를 받는다. 과거 오류를 무효 검토/테스트 통과로 바꾸지 않는다.

R47 전체 1299건(1282통과/17건너뜀/0실패)의 소스 지문을 대조했다. R48의 출처 별칭 반례는 수정 전 실패했다. 두 증거 조합을 같은 판정에 넣어 그 응답을 다른 구간에 재사용해도 집계가 보류되고 별개 출처·지문·응답과 기존 실패·정상 답 관측이 보존됐다. 집중 8건과 타입 검사가 통과했다.

### R48 새 전체 판단의 증빙 보존과 검증 순서

### R49 목표 대조 다음 보완

R49 독립 목표 대조는 blocking 2, should_fix 1이다. R49에서 완료 영수증과 비교 파일을 결합했으나, 실제 요청 수집 확인이 없는 과거 stats도 완료 영수증만으로 도달 총량을 주장할 수 있다. 둘은 승인 목적이 다르다. 현행 v1 요청 전용 영수증을 유지하고 stats snapshot에 실제 대조한 입력 지문과 영수증 참조·지문을 담는다. 비교에서 같은 typed 영수증을 대조하고, 근거 없거나 달라진 요청 총량은 관측과 별도로 보류한다. T01과 독립 수기 v1의 의미는 기존 계약을 따른다.

도달의 적격성 판정과 증빙이 어느 요청에 신고됐는지를 별개로 대조한다. 한 원장의 요청 연결 상태 전송 등 비적격 신고도 중복의 상대가 될 수 있다. 비교가 받은 같은 저장소의 여러 표본에는 원문 없이 증빙과 요청 식별 지문을 전달한다. 다른 요청의 같은 증빙이 발견되고 도달을 뒷받침하는 독립 증빙까지 없을 때 해당 표본의 요청 총량과 비교 방향을 보류한다. 별개 답 및 실패 관측은 유지한다. 같은 요청을 여러 번 관측한 경우는 증빙 재사용으로 보지 않는다. 미수집 로그의 코디네이터 요청과 수신 미상은 총량 null로 유지한다. 다른 저장소의 원장을 자동 탐색할 권한이나 실제 서비스·사용자 인증을 추가하지 않는다.

### R50 재검토 뒤 결합 범위 보완

R50의 독립 재검토는 R49 지적의 해소를 확인하고 blocking 2, should_fix 1을 남겼다. 기존 지문은 비공개 수집 자료를 확인하지만 이식된 집계·응답 목록을 같은 자료에서 나온 것으로 대조하지 않았다. 기존 v1 확인 영수증의 hash를 비공개 입력 지문과 공개 스냅샷 요청 집계 간 결합 지문에 사용한다. 공개 결합 범위는 응답 신고 목록, 관측, 확인 시 산출되는 요청 총량과 비교 미해결 수다. 확인자를 서로 다르게 지정하는 기존 규칙과 기간·용도·출처 검증은 유지한다. 별도 영수증 스키마나 사람 인증은 추가하지 않는다. 증빙 목록만 교체하거나 총량/미해결 수만 바꿔도 기존 영수증에 맞지 않는다.

안전한 위치의 비교 영수증은 정규화 파일 바이트 SHA를 먼저 대조한다. 다른 내용이 되면 기존 검증 근거가 없는 관측으로 처리한다. 경로 경계와 나머지 종류의 영수증 검증은 유지한다. 256 KiB를 넘는 정상 응답 목록을 수용하도록 비교 입력에 원장과 같은 32 MiB의 유한 상한을 적용한다. 이 파일 상한은 묶음 표본 수 1~32와 별개로 명시한다.

### R49~R51 design 진단 · 3회 연속 실패

- R49 2/1. 로컬 수집 확인과 원장 한 개의 도달 판정을 이식된 여러 스냅샷에서 이어서 대조할 수 없었다. R50은 기존 v1 요청 전용 영수증을 스냅샷과 비교에서 공유하고, 메시지 및 프로젝트 간 제3자 신고 지문을 전달했다.
- R50 2/1. 로컬 수집 지문은 전달되었으나 공개 수치와 응답 목록이 결합되지 않았고, 손상·용량 경계에서 관측이 사라졌다. R51은 수집·공개 집계 지문을 결합하고 허용된 큰 묶음 및 변경 영수증을 대조했다.
- R51 2/0 및 note 1. 총량 승인과 충돌을 신고하는 근거가 같은 참/거짓으로 줄어, 수집 미확인의 별개 요청이 신고한 같은 응답을 제거했다. 작은 일반 파일 변경은 관측을 보존했지만, 크기 확인이 먼저 실패하는 경우도 있다. 증빙 목록의 손상과 개별 유효 신고까지 같은 방식으로 처리하면 다시 경계가 틀린다.

**원인과 근본 조치.** 비교에는 생성된 수치를 승인하는 증명, 접수한 신고 중 다른 근거와 충돌하는 관측, 잘못된 입력 경로를 독립적으로 판정해야 한다. 완료/수집의 승인 지문은 기존과 같이 같은 표본에 묶는다. 수집 확인이 없거나 목록 일부가 유실되면 그 표본의 요청 총량과 방향을 보류한다. 구조가 유효한 응답 지문은 충돌 대조에 보존한다. 확인 없는 신고의 자체 도달은 승인하지 않으며, 다른 요청에 남은 별개 응답 지원은 보존한다. 요청 수집 영수증의 일반 파일 크기 초과·내용 오류만 한도 안에서 미확인으로 처리한다. 링크·위험 경로·I/O 충돌과 다른 종류 영수증의 경계는 그대로 검증한다.

**영향 분류.** 기존 비교의 관측·총량·출처 범위를 지키는 설계 갭이다. 기존 v1 영수증, T01 원본, 사용자 및 외부 계정, 승인·병합 경계에는 변경이 없다. 실제 외부 응답 없이 소유한 합성 파일로 R49~R51 반례와 정상 경로를 대조한다. 새 전체 목적 검토에서 위쪽 목표와 전체 패치를 다시 확인한다.

### R52 새 전체 검토 뒤 PM 영향 분류와 조치

Blocking 2, should_fix 1이다. 비교에서 요청 수집 영수증 실패와 관측을 분리했으나 stats 초기 입력 검증이 동일한 요청 확인을 일반 필수 증빙으로 먼저 읽어 보류 결과조차 반환하지 않았다. 비교·stats의 요청 수집 확인과 지원 근거는 같은 안전 경로와 제한 판독을 사용한다. 안전한 일반 파일의 누락·손상·초과는 관측을 보존하며 총량을 보류한다. 경로·링크·다른 영수증의 검증은 유지한다.

외부 전송의 적격성은 기존 owner 대상·시각·직접 요청 연결을 유지한다. 증빙 충돌 대조에는 상태 메시지의 선행 data.re 연결을 따라 실제 요청까지 누락 없이 넣는다. 표본에서 성공 근거가 전부 실효되면 도달 및 실패만 남은 요청의 신고 총량을 같이 보류하고 각각의 관측은 유지한다.

합의된 측정·비교·원문 보존·기존 v1 계약 안의 보완이다. 권한·외부 작업·실제 해당 저장소 사용과 T01 원본은 기존 범위를 따른다. 안전한 경로 오류와 증빙의 미수집은 별개로 검증하고 합성 원장으로 중계 연결 및 보존 대조를 실행한다.

### R53 전체 검토 뒤 범위 안 보완

Blocking 3, should_fix 0이다. 제공자가 stats envelope에 적재한 자료는 선택적인 표지 하나로 수기 표본에 재분류하지 않는다. stats 전용 증빙 필드가 남은 잘라낸 snapshot도 같은 확인 규칙을 쓴다. 독립 수기 원본과 T01은 별도의 기존 입력 경로다. 사용자 경로의 시도 및 증빙 충돌 대조는 상태 메시지의 data.re가 해석한 요청을 함께 참조한다. 상태 전달은 결정 요청의 도달 총량을 얻지 못하지만 그 요청의 코디네이터 자체 해결로 미해결을 상쇄할 수도 없다.

최종 Git tree와 검사한 부모를 함께 기록해 병합 후보에서 모두 대조한다. 추가 커밋의 tree가 같아도 검사한 부모를 보존한 마감 커밋이어야 한다. 기존 부모 미기재 영수증은 채택 이력으로 읽고 현재 병합 전 다시 마감한다. 이 조치는 기존 승인 SHA와 팀 채택 관문의 누락을 메우며 실제 문서·계정·저장소 또는 외부 행동을 바꾸지 않는다. 합성 worktree의 정상 검사/빈 커밋 경합으로 재현한다.

### R54 직전 지적 검증과 요청 ID 충돌 보완

직전 blocking 3건의 해소를 확인했다. 새 blocking은 상태 메시지의 명시 ID와 참조가 다를 때 참조를 우선하여, 명시 요청 쪽에서 사용자 경로가 사라지는 문제다. 사실을 덮어쓰는 우선순위 대신 원장의 명시·참조 후보 요청을 함께 보존한다. 두 근거가 다르면 어느 쪽의 도달이나 자체 해결을 추가로 인정하지 않는다. 다른 명확한 답과 실패 관측은 보존한다. 동일 요청 귀속 결과를 소통의 기간 경계·사용자 경로·증빙 중복과 귀속 미확인에서 쓴다. 명시 ID가 생략되고 참조가 하나인 정상 관측을 유지한다. 합의된 요청 지표의 분류 보완이며 원장 형식, 실제 사용자·호스트·외부 전송은 그대로 둔다.

### R53~R55 design 진단 · 3회 연속 실패

R53 3/0은 stats 출처·자체 답·검사 부모 경계를, R54 1/0은 명시 ID와 참조를 하나로 줄이는 문제를 드러냈다. R55는 두 종류의 연결을 보존했으나 긴 참조 계보를 매 상태/전송에 다시 복제했다. 실제 유효한 1,951행·약 0.99 MiB 원장은 212,225개의 증빙과 약 49.2 MiB 배열을 만들어 32 MiB 비교 입력을 넘었다. 단순히 읽기 한도를 늘리면 같은 문제가 더 긴 연쇄에서 반복된다.
