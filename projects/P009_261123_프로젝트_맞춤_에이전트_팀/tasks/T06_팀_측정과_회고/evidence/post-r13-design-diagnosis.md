# R11~R13 반복 실패의 설계 재진단

분류: design · PM 결정. R13 세 번째 fail 신호를 즉시 받아 지적별 수정을 멈췄다. 목적·T06 기준·PRE는 유지하며 외부/사용자 데이터/비밀/돌이킬 수 없는 동작에 닿지 않는다. 합의된 템플릿 형식의 검증을 명확히 하는 구현 보완이고 현장 목표는 사용자 결정대로 T08 보류다.

반복 원인: 원래 요구하지 않은 여러 Markdown 변형(들여쓴 표지·여러 제목 방식)의 수용을 추가하며 일부 구문을 다른 구조로 변환했다. 실제 목록 계층을 보존하지 않은 들여쓰기 허용은 하위 예시를 활성화했고, Setext/HR를 분류하는 근사들은 다른 절을 회고에 포함시켰다. 완전한 Markdown renderer를 런타임 의존성 없이 다시 만드는 방향은 이 태스크의 작은 기계 입력 계약보다 크고 새 경계 오류를 만든다.

근본 조치의 덜어내기: PROJECT의 측정 표지는 원래 템플릿처럼 열0의 최상위 필드로 한정하고 임의 들여쓰기 수용을 제거한다. 하위 목록 예시는 필드가 아니다. 새 팀 회고는 이미 배포하는 ATX 제목/3열 표 계약만 기계 검증한다. 코드/HTML/주석 밖의 bare Setext/가로선은 추측 변환하지 않고 명확한 입력 오류로 보류하여 ATX/빈 줄로 정리하도록 안내한다. 기존 팀 맥락 없는 프로젝트에는 새 회고 문법 검사를 적용하지 않는다. 기존 source/테스트에서 추가로 약속한 기능이 아니라 작업 중 임의 확대한 수용 범위를 덜어내며 기본 템플릿과 실제 source CLI 정상 경로를 유지한다.

도달 누락의 조치: ID 없는 실제 by:user 답은 반드시 미확인으로 남기되 agent 수신 확인을 사용자 요청 누락으로 바꾸지 않는다. ID 있는 orphan도 사용자 답/사용자 전송만 요청 누락 후보로 보존한다. owner/user·역할/프로필의 정의는 바꾸지 않고 같은 사람의 신원 인증을 주장하지 않는다.

현재 별도 tester stage6의 기존 후보 판단을 회수한 뒤 근본 수정을 적용한다. 고유 원문/원장·기존 실패·source 지문을 보존하고 새 단위 반례·정상 템플릿·두 단계 독립 판정 및 현재 전체 검사를 다시 수행한다. 검증 pass나 목표 달성을 미리 선언하지 않는다.
