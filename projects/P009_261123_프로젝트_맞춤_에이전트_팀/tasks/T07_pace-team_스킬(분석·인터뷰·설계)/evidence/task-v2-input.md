# T07 pace-team 스킬(분석·인터뷰·설계)

- 프로젝트: [P009](../../PROJECT.md)
- 상태: 진행
- 사전 검토: v1
- TASK 형식: v2

## 목적

저장소의 실제 업무 단계와 권한을 확인해 필요한 역할·독립 검토·인계 경로를 설계하고, 그 정의를 PACE의 동일한 sync·verify 명령으로 확인할 수 있게 한다. 마감에 쌓인 관측과 미확인 사항을 다음 정의 개선에 연결한다.

## 재료

- BR07의 ①~⑥ 흐름, PROJECT P-4/P-5 및 T08 현장 적용 보류 결정.
- 완료된 BR02/T02, BR04/T04, BR06/T06 및 소통과 공유 자원의 T05/T09 계약.
- [TEAM](../../../../docs/TEAM.md), [TEAM-METRICS](../../../../docs/TEAM-METRICS.md), [HANDOFF](../../../../docs/HANDOFF.md), `templates/team/member.md`, 기존 init/dev 스킬 연결 지점.
- 두 저장소의 실제 Git HEAD 단위 분석과 작업 문서. roblox-studio는 정의서·지침·여덟 단계·기존 역할 정의, ai-sql-client는 설계·지침·백로그·실행 스택과 검토 문서 업무.

## 증명 범위

- 판정 주체: 작업 담당자가 두 저장소의 자료·실행·증거를 대조하고, 작성 세션과 독립된 검토자가 목적과 기준을, 다른 제공자의 실제 세션이 스킬 행동을 판정한다. 권한과 비용 정책에 필요한 결정은 사용자가 내린다.

포함 범위는 두 저장소의 업무와 팀 설계, 확인·인터뷰, 합성 저장소의 원본과 동기화·검증, 그리고 다른 제공자의 스킬 행동이다. 작업 담당자는 자료 분석과 인터뷰에 따라 두 설계를 작성한다. 기존 근거에서 결정된 것은 출처를 제시하고, 미정 정책만 한 번에 하나의 선택지·추천으로 확인한다. 인터뷰 시간·질문 수는 실제 수행 기록에 근거한다. 두 설계의 실제 팀 원본과 동기화 파일은 P009 작업의 합성 임시 Git 저장소에서 생성·검증하며 적용 대상 원본 저장소는 읽기만 한다. 다른 제공자의 실제 세션이 완성 스킬의 순서·역할 선정·승인/회고 행동 시나리오를 판정한다. PM은 코드 기준과 실행, 독립 판단을 대조한다. 범위 밖에는 실제 적용 저장소의 업무 수행, native 역할 유지, Studio 자원, 효과·사용자 회고가 있다. 설치 후 실제 환경이 필요한 이 항목은 사용자 결정에 따라 T08로 인계한다.

## 기준

| # | 완료 기준 |
|---|---|
| T-1 | `pace-team`이 분석→인터뷰→설계→작성·sync→verify→회고를 실행한다. 정의서·AGENTS·백로그·스킬·스택을 분석하고 역할 결정권·병렬·이름/말투·비용/등급을 필요한 만큼 확인한다. 질문은 한 번에 하나이며 추천과 직접 입력을 제공한다. |
| T-2 | 두 실제 저장소를 분석하고 확인/인터뷰와 서로 다른 설계를 기록한다. 각 저장소 필수 업무 담당 누락0, 필요한 별도 역할·제공자 검토 누락0, 예외·역할 합침/분리 이유와 권한을 기록한다. 역할 수의 예시는 합격 기준으로 사용하지 않는다. |
| T-3 | 두 설계를 합성 Git/PACE_HOME에서 `team new`·`team sync`로 작성한다. 원본·두 호스트 설정과 입력 지문을 기록하고 `sync --check --json`, 실제 호스트의 `team verify`로 대조한다. 구조·동기화와 prompt 적재 관측의 경계를 기록한다. |
| T-4 | 리드·서버·UI·QA·리서치·기획·마케팅·경제의 원형과 하지 않는 일 예시가 있다. init의 신규/기존/최신화 분석에서 필요 여부를 판단해 이 스킬로 이어지고, dev 태스크 설계에 담당 역할 선택 안내가 있다. 프로필과 역할의 범위를 구별한다. |
| T-5 | 마감에서 METRICS·팀 회고 입력을 읽고 미사용 후보와 반복 지적의 출처·누락을 대조한다. 변경1~3건 또는 근거 있는 무변경을 제안하고 운영의 적용/승인은 사용자 결정에 맡긴다. 독립 다른 제공자 시나리오가 여섯 단계의 순서 및 역할 수 기준 금지를 검출 가능한 방식으로 확인한다. |

## 접근

- `skills/pace-team/SKILL.md`에는 진입 조건과 실행 선택, 보존할 산출물, 위험 및 회고 규칙을 둔다. 긴 역할 원형은 `references/`로 분리한다. 스킬은 홈 프로필을 설정하지 않으며 팀 원본 수정·적용과 역할 실행은 해당 저장소 계약을 확인한 경우에만 진행한다.
- 두 저장소의 기존 기준·스킬을 파일과 Git 지문으로 인용하고, 팀 로스터마다 필수 업무와 검토 행, 별도 제공자 배정, 결정 주체와 인계 포맷을 기록한다. Claude/Codex는 설치된 호스트와 명시한 운영 제약에서 판정한다.
- PACE 원본은 `team new` 생성 형식·행동 표지를 재사용한다. 권한·요금·실행 모델의 실제 적용을 도구 이름이나 tier에서 추정하지 않는다. 사용자 원문·상세 답·비밀은 설계/시험 증거에 복사하지 않는다.
- 교본 및 기준 문서는 docs/README의 해당 경로와 [SKILLS](../../../../docs/SKILLS.md), 프로젝트 개발 검토·검증 참조를 적용한다. 실제 대상 저장소에 쓰기 전에 T08 사용자가 판단할 경계를 인계 문서에 연결한다.
