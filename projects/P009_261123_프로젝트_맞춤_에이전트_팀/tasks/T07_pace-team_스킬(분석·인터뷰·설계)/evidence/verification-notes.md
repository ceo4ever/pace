# T07 실측과 판단

합성 Git 두 개에서 13개 원본과 두 생성물씩을 실제 CLI로 만들었다. 두 sync dry-run이 차이 0이었다. Claude·Codex별 `team verify`가 총 26개 행을 pass로 판정했다. 보고서의 실행기·모델·원본 지문은 prompt 적재를 확인한다. [전후 경계와 판정표](synthetic-boundary-summary.json)

두 적용 저장소의 HEAD와 깨끗한 상태가 전후 같았다. Claude와 Codex의 기본·활성 설정 파일과 기존 PACE 작업자 설정을 바이트 지문으로 대조했다. 인증 데이터, 일반 CLI 캐시와 세션 로그는 이 확인 범위 밖이다. `PACE_HOME`의 팀 점검은 합성 경로에서 실행했다.

Anthropic의 정상과 압박 2종에서 ①~⑥ 순서, 최소 역할, 재질문 방지와 승인 전 보류를 관측했다. 정상 첫 실행은 의미가 맞는 긴 설명을 enum 값으로 반환해 기계 판정에서 실패했다. 원문을 보존했다. enum과 이유 필드를 분리해 정상만 새 호출했고 원래 압박 두 결과와 함께 통과했다. 별도 음성 대조는 근거 없는 역할, 해결된 질문, 잘못된 단계 순서를 모두 검출했다. [최초 판정](behavior-summary-first.json), [최종 관측](behavior-summary-final.json), [업무 대조](design-negative-controls.json)

Roblox의 상시 후보는 기존 이름을 그대로 복제하기 전에 권한·충돌·단계 경계를 다시 대조했다. 게임 컨셉이나 소규모 문서에는 작성과 필요한 독립 검토만 먼저 배정한다. 출시·가격·공유 Studio 역할은 해당 단계에 선택한다. 초기 조사와 시제품의 판정이 필요한 결정은 argos의 독립 검토 자료로 넘긴다. AI SQL은 대표 문서의 작성·범위 조율을 합쳤고 별도 권한, 인계, 독립 검토의 필요가 있을 때만 다른 역할을 사용한다.

T07 팀 표의 위치는 팀 설계 문서다. 실제 운영 프로젝트에서는 저장소가 지정한 팀 문서나 프로젝트 설계에 결정과 지문을 보존한다. 역할 종류와 실제 제공자의 매핑은 `team new`의 역할 종류 및 `pace project start --agent <도구> --role <이름>`을 배정할 때 지정한다. 역할 이름만으로 제공자를 바꾸거나 권한을 고정하지 않는다.

검증 승인 출처는 [사전 범위 대조](pre-review-disposition.md)에 남겼다. 실제 설치·실행 권한 변경·앱 비용·데이터·Studio 활동은 관측 범위 밖이다.
