# 사전 검토 상세 판정

R1·R2 원문과 TASK 해시를 보존한다. R2 이후 TASK 기준을 바꾸지 않고 아래 실행 세부 판정을 2단계에서 계약과 대조한다.

- SF1: 정의에 키워드가 있어도 0개 적중은 확인 필요를 유지한다. BR04의 의역을 false fail로 만들지 않는 조건 때문이다. 이름은 지시에 노출되므로 그 자체로 읽기 증거가 아니다. 지시 없는 실제 음성은 답의 다른/없는 identity로 fail을 판정하며, 지시 있음+읽기 차단은 확인 필요 또는 fail이고 pass면 결함이다. 둘을 같은 음성 성공으로 합치지 않는다. 이 구분은 미적재 진실성/의미 자동화를 제품이 하지 않는 한계다.
- SF2: 추가 지시 있음/읽기 불가 대조는 TASK 보완 절에 있고 T-4/S-4의 실제 접근 차단 증거와 연결한다. 결과별 기대는 위와 같다. 이것은 BR04의 지시 없는 음성 필수 fail을 느슨하게 만드는 대체 실험이 아니다.
- SF3: 음성 검출 성공은 CLI/모델이 정상 기동해 실제 답을 반환하고 그 답 평가가 기대 상태인 경우만 센다. host 종료/인증/네트워크/중첩 sandbox 실패는 제품에서 fail 상태지만 실험의 적재 판정은 미확인이다. 그것만으로 T-4를 통과시키지 않는다. 실제 읽기 거부/대조 파일 성공도 따로 증명한다.
- SF4: 실측 canary는 vfy- 접두와 짧은 무작위 hex 조각으로 만들며 hasSecret를 통과하고 질문에 없고 원본에만 있는 것을 단위/실측 증거로 확인한다. 문자열의 엔트로피만으로 비밀이라고 하지 않으며 기존 hasSecret 규칙을 적용한다. 기대 표식 추출의 비밀 후보는 제거해 거짓 pass를 만들지 않고 선거부한다.
- SF5: 종료2는 기존 CLI 사용 오류와 확인 필요가 공유하되 기계 구분 경로를 문서/시험에 명시한다. 정상 검사 결과는 stdout 표·고유 JSON report(phase=result, status=확인 필요)를 만들고 사용 조합 오류는 호출/보고서 생성 없이 stderr 진단만 남긴다. 소비자는 exit2만으로 결론내리지 않고 보고서/출력 채널을 확인한다. 자동 완료/의미 승인으로 사용하지 않는다.
- note: 답의 과대는 UTF-8 64KiB 초과다. duties/blocked의 의미는 검사하지 않고 비어 있지 않은 구조만 확인한다. 고정 운영 표식의 예측 가능성·자동 맥락 혼재, 기존 표식 없는 원본 확인 필요, 실제 적용 저장소에 아직 .pace/team이 없어 T08 뒤 검증하는 한계를 문서화한다.
- R1 SF4의 기존팀 실제 실행은 두 대상에 팀 자체가 없으므로 임시 저장소의 이전 T02 템플릿 그대로 실제 호스트에서 확인 필요임을 대조한다. 실제 저장소는 읽기 전용 존재 확인만 했으며 수정/보고서 생성을 하지 않는다.

(b) 이 파일을 TASK의 상세 실행 결정으로 연결하고 실제 계약을 줄이거나 바꾸지 않는다. 2단계에서 (b) 허용 여부를 독립 판단하며 범위/기준 충돌이면 구현 전에 해소한다.

## 2단계 추가 상세

- 삭제 대조는 구성원 이름을 명시한다. 원본 없음/손상·source 파일 안전 거부·설정 오류는 안전한 결과 경로가 있으면 fail 행/보고서/종료1이며 host를 호출하지 않는다. all은 현재 원본 목록만 검사하므로 삭제된 이름까지 보장하지 않는다. orphan은 sync --check로 대조하도록 문서화한다. 빈 목록도 pass가 아닌 fail 보고서다.
- 출력 경로/루트 안전 거부와 CLI 사용 오류는 보고서를 안전하게 쓸 수 없으므로 stderr·종료2·보고서 없음이다. 확인 필요는 stdout 표와 Report: 상대경로, phase=result JSON을 남기므로 소비자는 파일/채널·상태를 함께 검사한다. 제품 실행 거부/선검사 fail과 도구 사용 오류를 이 표로 구분한다.
- 같은 음성 host 응답에 별도 대조 파일에서만 주어진 무작위 control 표식을 읽어 포함하도록 실험 감사 지시를 둔다. 질문의 역할 기대 값은 주지 않는다. actual 도구 읽기 시도/오류와 control 표식을 대조해 중첩 sandbox 때문에 모든 도구가 막힌 실행은 미확인으로 분리한다. 지시 없는 음성에는 구성원 이름/역할 파일 경로도 노출하지 않고 일반 denied-sentinel 경로만 둔다.
- 두 실제 저장소에 없는 것은 새 .pace/team 경로이며 기존 native 팀이 없다는 뜻이 아니다. 실제 도입/이전은 T08이다. 표의 적재 방식은 prompt로 명시하고 native 변조 N/A 이유를 결과에 남긴다. 재실측 원본 지문 변화는 코드/환경 수정과 canary 신규 생성 여부를 따로 기록한다.

## R4 보완 검토 후 실행 상세

R4 pass/blocking0를 보존한다. SF1은 결과·TEAM에 verify Read/Grep/Glob과 실제 Orca 도구 구성 차이, T04가 실제 작업자의 자체 지문 계산 성공을 관측하지 않는다는 한계/T08 인계를 공개한다. SF2 loaded 요청은 고정 질문이 아니라 검증 책임 고지 구역에만 두고 prefix/고지/질문을 분리 캡처한다. 사전 검토 v1은 파일 형식이며 회차는 attempts이므로 변경하지 않는다(2단계 source 대조).

## R5/R6 권고의 최종 연결

정상 재평가 인정은 사용자 결정 전달 원문과 T-4/S-4에 연결했고, Codex native 출처 결합은 사용자 위임 범위의 main 판단 원문에 연결했다. 앞선 external sandbox 구상은 실패 이력이며 최종 호스트별 방법은 TASK 마지막 절과 마감 증거에 명시한다. 위임은 이 프로젝트의 같은 검증 증거 동등성 판단에 사용하며, 목적/필수안전/배포/병합 결정의 대행 권한으로 확대하지 않는다. 명시적 사용자 위임 전달을 보존하며 이전 SF의 추정으로 이를 취소하지 않는다. 종료2 공유 한계는 TEAM 표·문단과 S-3 fake CLI에서 이미 대조한다. v1은 PRE 파일 형식이고 차수는 attempts다.
