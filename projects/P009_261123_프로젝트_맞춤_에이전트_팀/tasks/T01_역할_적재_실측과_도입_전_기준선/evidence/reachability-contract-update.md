# BR09 승인 뒤 BR01 도달 분류 대조

기존 T01 커밋의 로그·원장·판정은 당시 계약의 역사적 스냅숏으로 보존한다. 최신 BR01은 to:captain 행만으로 도달을 인정하지 않는다. 같은 요청을 묶어 캡틴 답→성공 전송→실패 전송만→그 밖 미확인 순으로 판정한다. 이후 T06·T08의 캡틴 개입 비교는 이 정의를 사용해야 한다. 기존 raw stats 사건 수·수신자 행수는 그대로 읽되 도달 지표로 쓰지 않는다.

보존 P002 원장 16개 question에 legacy 요청 ID와 기존 답 근거를 연결한 대조 입력은 baseline-roblox-reachability-v2.json이다. 관측 분류는 캡틴 답 근거 도달10·성공 전송만 도달0·실패 전송만0·미확인6이며 미확인에는 코디네이터 답변4와 수신자 미확인2가 포함된다. 이는 전체 요청의 캡틴 도달 근거 축이다. 기존 수신자 분류10/4/2를 지우거나 두 축을 합산하지 않는다. 실패 기록이 없다고 실제 전송 실패 총량이0이었다고 주장하지 않는다. 병합 승인1은 별도이며 일반 승인8은 해당 질문과 겹쳐 단일 개입 합계에서 다시 더하지 않는다. 손작업 총량은 계속 미확인이다.

ai-sql-client 문서 구간은 보존 원장에 질문 사건이 없어 이 4분류의 관측 후보도0이다. 일반 손작업·직접 대화의 미복원 한계는 기존 null/coverage_spans를 유지한다. 역할 도입 전의 관측 시점·원자료를 바꾸지 않았고 이 문서는 최신 정의에 대한 후속 재분류 위치를 기록한다.

T06은 이 입력과 새 handoffs/project log를 요청 ID로 중복 제거하며 같은 4분류를 시험한다. T08은 동일 정의로 비교하고 미확인에는 추가 표본 계획을 남긴다. T09는 원문·확인된 해석·위임과 실제 전송/응답 연결을 기록해 이후 누락을 줄인다. 이 후속 입력 자체는 T06 장치 실행이나 실제 캡틴 도달을 새로 관측한 증거가 아니다.
