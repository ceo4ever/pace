# T05 사용자 결정 기록 (2026-11-17, 코디네이터 전달)

## 1. 학습 캡처 승인 정책 (사전 검토 1차 지적 5)
- 질문 요약: 자가 학습이 만든 새 기준 캡처를 누가 승인하나 — (A) 코드 검사(가림 사후 검사·maskRequire·추출 대상 가림)로 승인하고 history에 '기준 캡처 사람 확인: 대기'를 남겨 사후 확인, (B) 사람 확인 전 보류.
- 캡틴 답: "A로 진행해 줘". 조건: 가림 fail-closed 유지, 비가역 단계의 캡처 변경은 기존대로 첫 1회 사용자 확인, 대기 목록을 볼 수 있는 출력(`pendingHumanChecks`).

## 2. 구현 후 검토 3차 fail 이후 (blocking 2건 잔여)
- 질문 요약: review-goal-1(7)→review-goal-2(4)→review-goal-3(2) fail. 반영 확인 1회 추가(A) 또는 한계 기록 마감(B).
- 캡틴 답: "모두 권장안대로 진행해 줘" → A. 범위: ① `approvalCheck`가 계정 정보(키) 없는 예전 승인도 거부(테스트 포함) ② review-goal-3의 남은 blocking 2건(driveWithHealing 재개 시 저널 복구·URL 경로 값 후보 노출) 수정 ③ 새 세션(다른 제공자 우선) 반영 확인 1회, 이 3건만 확인. 또 fail이면 멈추고 증거와 함께 올린다.

## 3. 구현 후 검토 4차(반영 확인) fail 이후 — 승인 요청 요약의 경로 원문 (2026-11-17)
- 질문 요약: review-goal-4 — 키 없는 옛 승인 거부·재개 진입 저널 복구는 달성, 남은 blocking 1건은 사용자 확인이 필요한 URL 경로 후보의 승인 요청 요약(summarize)에 경로 원문이 담김(지도·history에는 승인 전 기록 0). 선택: (A) 승인 요약의 원문 허용 + 합의 문서화, (B) 요약에서 값 제거 + 재검토.
- 캡틴 답: "A 승인 요약엔 허용 (권장)". 합의 범위: 승인 요청 요약의 경로 원문 노출은 확인하는 사람에게만 보이며, 지도·history·versions·치유 상태·승인 기록 같은 파일 기록은 승인 뒤에만 한다 — 이 경계(승인 전 파일 기록 0)는 `healer.test.mjs` "검토4 경계"가 단언한다.
