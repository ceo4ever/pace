# T01 운영 결정 대기와 재개 순서

2026-11-19 main이 격리 시험 요약을 확인했다. D1에 대한 캡틴의 명시 승인은 아직 없으므로 운영 반영은 대기한다(main 판단). T01은 진행 상태이고 완료·보류 또는 병합 대기로 바꾸지 않는다. TASK-CLOSE·태스크 완료 커밋은 아직 만들지 않는다.

## 이미 확보한 것

- 독립 anthropic 사전 검토: 1차 fail blocking 1, 같은 세션의 2차 pass blocking 0. 원문·대상 스냅샷·해시는 PRE-REVIEW.json 및 evidence/pre-review-* 참조.
- 설치본 0.1.1의 Windows 수정 포함 및 설치본 모듈 SHA-256: s0-installation.json.
- Claude/p·Codex/p 읽기·쓰기 차단, 실제 파일 변경 양성 대조: isolated-test-summary.md와 연결 JSON.
- 체인 회귀 검사: 27 pass·0 fail. 실제 확정 default 체인 호출은 아직 미실행.
- Git 설정 쓰기 허용 양성 대조는 미확인이다. 성공으로 바꾸거나 전체 쓰기 경로 허용으로 해석하지 않는다.
- 운영 프로필·Telegram·로그온 등록은 변경하지 않았다. 같은 대상·환경의 성공한 격리 시험은 반복하지 않는다.

## 결정 전달 뒤 적용 직전

1. main 답변을 T01 answer 로그와 결정 메모에 기록한다. 실행기·순서·호출 방식·어댑터 설치 여부 및 실제 홈 반영 허용 범위를 구분한다.
2. 설치본 p-executor.ts의 SHA-256을 S-0의 moduleHash와 재대조한다. 달라졌으면 운영 반영을 멈추고 변경 내용과 필요한 재시험 범위를 판정한다. main 체크아웃의 새 변경만을 근거로 이미 검증한 설치본을 교체하지 않는다.
3. `%USERPROFILE%/.pace/profiles/default/agent-chains.json`의 존재·현재 설정을 확인하고 기존 default 및 다른 체인·키의 보존 기준을 로컬에서 확보한다. 인증·시크릿 파일은 읽지 않는다. 운영 프로필 또는 설정 위치가 예상과 다르면 적용하지 않는다.
4. setup은 체인 부재 시 확인 옵션 없이도 파일을 만들 수 있으므로 계획 확인용으로 실제 홈에서 미리 실행하지 않는다. 코드의 감지·계획 API 또는 임시 홈에서 계획을 확인하고, 실제 홈의 setup 실행은 반영 승인 뒤로 한정한다.
5. 실행 시 감지된 후보·방식이 승인 및 시험한 조합과 같은지 확인한다. ACP 또는 새 실행기가 선택되면 미검증 상태로 적용하지 않는다. 새 어댑터 설치는 별도 승인 범위 안에서만 한다.
6. 승인된 setup 적용 뒤 이전 다른 체인·키 보존과 실제 실행기·방식·순서를 대조한다. 설치본 해시를 다시 확인하고 승인된 default 체인으로 합성 읽기를 실행해 실제 선택과 readOnlyEnforced를 연결한다.
7. daemon install은 계획만 실행해 default 체인 없음 오류의 해소 및 다른 남은 오류 목록을 기록한다. `--yes`·`--start`·로그온 등록은 이 태스크에서 실행하지 않는다.
8. 저장소 전체 검사, 코디네이터 제공 새 맥락 tester·reviewer 판정, TASK-CLOSE, project check → done → 메모리·백로그 갱신 → 태스크 커밋 순서로 마감한다. 실제 목표 달성 미확인을 게이트 통과로 대신하지 않는다.

T03·T04에 넘길 것: daemon 환경에서 PATH·인증·실행 파일 동일성, 실제 Telegram 요청 및 승인·복구 흐름. 운영 선택이나 설치본 변경으로 검증 대상이 달라진 경우에만 해당 범위의 재검사를 수행한다.
