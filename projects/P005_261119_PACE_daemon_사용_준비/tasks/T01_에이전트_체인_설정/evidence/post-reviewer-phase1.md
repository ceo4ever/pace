# P005 T01 독립 리뷰 1단계

## 받은 범위와 읽은 범위
- **받은 것:** 메시지에 붙은 9개 관측. s0-installation, readonly-observations, claude/codex-positive-summary, positive-global-guard, chain-unit-check, operational-chain-apply, live-chain-observations, daemon-install-plan입니다.
- **읽은 것:** 위 본문만 봤습니다. 파일 읽기, 검색, 보조 호출(advisor 포함), 파일 변경은 하지 않았습니다. TASK, PROJECT, BR 문서와 작업자 판정도 읽지 않았습니다. 전체 저장소 검사 결과도 반영하지 않았습니다.
- **출력:** 해시와 버전 외에 민감정보는 옮기지 않았습니다.

## 판정: 조건부 달성
T01 범위(기본 체인 준비, 실행기별 읽기 성공과 쓰기 차단 확인)는 이 PC에서 달성된 것으로 봅니다. 다만 아래 한계가 있어 보완이 필요합니다.

## 목표와의 정합
- 체인 준비와 실행기별 읽기·쓰기 검증은 태스크 목표와 직접 맞습니다.
- 데몬 등록은 계획만 출력하고 실제 등록(`--yes`)은 하지 않았습니다. 사람이 확인하는 절차를 지킨 것으로, 범위 위반이 아닙니다.
- Telegram 경로는 이 태스크 범위 밖이라 평가하지 않았습니다.

## 달성 근거
1. **설치본과 소스가 일치합니다.**
   - moduleHash와 mainHash가 같습니다.
   - gitObjectHash와 installedNormalizedHash가 같고 ancestry는 0입니다.
   - 같은 moduleHash(`ccda2773…`)가 체인 적용과 라이브 관측에도 그대로 이어집니다.
   - 관리자 권한 없이 실행했습니다.
2. **체인이 준비됐습니다.**
   - default 프로필 확인됨, 파일 새로 생성(이전에 없음), setup exit 0입니다.
   - 순서는 claude p → codex p입니다.
   - 로그인 호출과 어댑터 설치는 없었습니다. 두 CLI 모두 설치돼 있고 로그인돼 있습니다.
3. **두 실행기 모두 읽기에 성공했습니다.** readExact가 둘 다 true입니다.
4. **쓰기가 차단됐습니다.**
   - 두 실행기 모두 fixture 변경, probe, shellProbe, outsideProbe, git 로컬 변경이 전혀 없습니다.
   - codex는 sandbox read-only, unauthorizedAccess, gitDenied 오류가 원시 출력에 남아 실제로 거부됐다는 증거가 있습니다.
5. **양성 대조가 유효합니다.**
   - 쓰기를 허용한 설정에서는 두 실행기 모두 fixture를 바꾸고 probe와 shellProbe를 만들었습니다.
   - 따라서 위의 음성 결과는 탐지 장치가 원래 둔감해서 나온 결과가 아닙니다.
   - 대조 실험 동안 실제 전역 git 설정 해시는 바뀌지 않았습니다.
6. **라이브 체인이 동작합니다.** exit 0, status ok이고, 1단계 claude가 약 7.2초 만에 성공했습니다. 이때도 readExact true, fixture 변경 없음입니다.
7. **단위 테스트:** 27개 모두 통과했고, S-7(검증 안 된 실행기는 건너뜀)을 포함합니다.

## 한계
1. **claude의 쓰기 차단은 정책 제한입니다.**
   - 근거는 OS 샌드박스가 아니라 `--tools Read,Grep,Glob`(내장 도구 목록 제한)입니다.
   - rawPolicyErrors가 null이라, 쓰기를 시도했다가 거부된 것인지 아예 시도하지 않은 것인지 구분할 수 없습니다.
   - codex는 `--ignore-user-config`를 쓰지만, claude 쪽에는 사용자 설정을 격리했다는 기록이 없습니다. 사용자·프로젝트 MCP 서버, 플러그인, hook이 쓰기 경로가 될 수 있고, 결과가 이 PC의 현재 설정에 좌우됩니다.
2. **claude의 외부 경로 쓰기 탐지는 검증되지 않았습니다.** 양성 대조에서 claude의 outsideProbe가 false였습니다. 그래서 음성 측정의 outsideProbe=false도 claude에 대해서는 근거가 약합니다.
3. **codex로 넘어가는 경로는 실측이 없습니다.** 라이브 실행은 1단계 성공으로 끝났고, 대체 경로 검증은 mock 단위 테스트(S-7)뿐입니다. codex 단독 읽기는 따로 검증됐지만 체인 안에서 전환되는 과정은 보지 못했습니다.
4. **짧은 경로 읽기 실패가 있었습니다.** claude는 처음 짧은 경로(8.3 형식으로 추정)로 읽다 실패하고 긴 정식 경로로 성공했습니다. 데몬 실행 때 경로를 정규화하는지가 확인되지 않았습니다.
5. **codex acp는 읽기 전용이 강제되지 않습니다**(readOnlyEnforced=false). 현재 체인에는 없지만 나중에 추가되면 위험합니다. S-7이 이것을 실제로 막는지는 mock 범위에서만 확인됐습니다.
6. **기타**
   - 라이브 시도에서 model과 effort가 null로 기록돼, 실제 사용 모델이 남지 않았습니다. 별도 관측에 보고된 모델 값은 있습니다.
   - 실행은 각각 한 번씩이라 결과가 매번 같다는 보장이 없습니다.
   - 설정 파일이 처음부터 없었으므로 otherSettingsPreserved=true는 사실상 당연한 값이고, 대상 범위도 불분명합니다.
   - 관측 시각은 단위 테스트에만 있어, 같은 세션에서 나왔다는 연결은 해시로만 가능합니다.
   - 어댑터는 둘 다 쓸 수 없는 상태(adapterUsable false)라 acp 모드는 실사용 경로가 아닙니다.

## 필요한 보완
**필수에 가까운 것**
- **A.** claude 실행에 사용자 설정 격리를 추가하거나, 격리가 필요 없다는 근거를 기록합니다. 예: 엄격한 MCP 설정, 설정 소스 제한.
  - 그다음 claude에게 쓰기를 명시적으로 지시하는 음성 측정을 한 번 해서, 시도했지만 실패한 증거를 남깁니다.
- **B.** claude 외부 경로 쓰기 양성 대조를 다시 설계해서 outsideProbe 탐지가 실제로 작동하는지 확인합니다.

**권장**
- **C.** 1단계를 강제로 실패시켜(예: 사용 불가 표시) codex로 넘어가는 경로를 실측합니다.
- **D.** 짧은 경로가 들어와도 정규화되는지 회귀 테스트를 추가하거나, 데몬 실행 경로에서 확인합니다.
- **E.** readOnlyEnforced=false인 실행기(codex acp)가 체인 설정에 들어오면 거부되는지 검증을 추가합니다.
- **F.** 라이브 시도에 실제 모델과 effort를 기록하고, 관측마다 시각을 남깁니다.
