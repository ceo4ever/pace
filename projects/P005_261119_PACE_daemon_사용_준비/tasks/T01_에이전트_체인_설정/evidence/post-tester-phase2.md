# T01 독립 tester 2단계 판정

## 받은/읽은 범위와 직접 실행 여부
- **받은 것:** 이번 메시지의 TASK, PROJECT, BR01, tester 역할 기준, p-executor·chain 소스 발췌, 저장소 상태, 전체 검사 상태, 코디네이터 직접 관찰, 그리고 1단계 관측 9개.
- **직접 읽은 것:** 작업 폴더 파일 목록만 확인했습니다. 그 폴더에는 검토 하네스 파일만 있고 제품 소스나 evidence 원본은 없습니다. 다른 검토자의 출력 파일은 독립성을 지키려고 열지 않았습니다.
- **실행하지 않은 것:** 명령은 하나도 직접 실행하지 않았습니다. 단위 테스트 27건, S-0 해시, 설치 계획 출력은 모두 관측 요약과 코디네이터 관찰에 기대어 판정했습니다. 전체 검사도 지시대로 다시 돌리지 않았습니다.
- 파일 변경, 다른 세션 호출, 민감정보 출력은 하지 않았습니다.

## 1단계 판단에서 바뀐 점과 이유
| 1단계 지적 | 2단계 결론 | 근거 |
|---|---|---|
| claude는 OS 샌드박스가 아니라 도구 목록 제한 | **합격 범위 안** | S-3 기대 결과가 "CLI 도구 공개 목록에서 쓰기·셸 도구 차단 관찰"을 명시적으로 인정합니다. 소스의 READ_ONLY_PROVEN 주석도 같은 기준입니다. |
| 사용자 MCP 서버로 우회될 수 있음 | **해소** | `claudeP.build`가 항상 `--strict-mcp-config`와 `--disable-slash-commands`를 붙이고, 읽기 전용이면 `--tools` 제한을 겁니다. |
| codex acp는 readOnlyEnforced=false | **해소** | chain.ts가 읽기 전용 요청에서 `readOnlyEnforced !== true`인 단계를 `read_only_unenforceable`로 건너뜁니다. default 체인에도 이 단계가 없습니다. |
| codex 대체 실행이 live로 확인되지 않음 | **blocking 아님 → handoff** | S-4c가 요구하는 것은 "선택된 단계가 검증된 집합에 속함"입니다. codex/p는 S-2~S-3p를 개별로 통과했습니다. live 대체 실행은 합의된 기준 밖의 개선입니다. |
| live attempts의 model이 null | **철회** | 체인 단계에 모델을 지정하지 않았으므로 `step.model ?? null`대로 null이 맞습니다. |
| 버전 차이에 따른 재측정 필요성 | **충족으로 확인** | 소스의 실측 근거는 claude 2.1.322·codex 0.167.1이고 "버전이 바뀌면 재시험"이라고 적혀 있습니다. 이번 시험이 현재 버전(2.1.328·0.170.0)에서 그 재시험 역할을 했습니다. |
| readonly 관측에 moduleHash 없음 | **should_fix로 유지** | S-0은 "실제 시험한 모듈 해시를 남긴다"고 요구합니다. s0·apply·live 관측에는 해시가 있지만 S-2·S-3 관측 각각에는 없습니다. |
| claude 외부 경로 양성 대조 실패 | **should_fix로 유지(아래 T-2)** | |

## blocking / should_fix / handoff
- **blocking: 0.** 전체 검사 결과에 따라 달라질 수 있습니다.
- **should_fix**
  1. S-2와 S-3 관측 각각에 실제 시험한 moduleHash를 남겨 S-0과 직접 묶습니다.
  2. claude 외부 경로 양성 대조가 실패한 사실과 그 원인, 차단 근거가 도구 목록이라는 점을 evidence에 명시합니다.
  3. TASK에는 사전 검토 1차가 fail(blocking 1)이었고 재검토를 요청했다는 기록만 있습니다. 접근 절은 "사전 pass와 PRE-REVIEW.json 확보 전 구현하지 않는다"고 하므로, 운영 반영 전에 재검토 pass가 있었는지 TASK에 연결해야 합니다. 저는 이를 확인하지 못했습니다.
- **handoff**
  - T03·T04:
    - claude가 짧은 경로(8.3)에서 읽기에 실패했습니다. daemon과 워크스페이스 경로에서 긴 경로로 바꾸는지 실측해야 합니다.
    - codex/p 대체 실행이 실제로 일어나는지 한 번 관측합니다.
    - claude p는 사용자 hook과 설정 소스를 제한하지 않습니다. 로그온 환경에서 이 점이 어떻게 작동하는지 확인합니다.
  - 기록 갱신: READ_ONLY_PROVEN 주석의 실측 버전을 현재 버전으로 갱신합니다. 체인 코드 변경은 T01 범위 밖이므로 백로그나 메모리로 넘깁니다.
