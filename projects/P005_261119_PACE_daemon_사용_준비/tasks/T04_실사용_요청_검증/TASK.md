## 목적

등록된 검증용 Git 작업사본에서 Telegram 요청이 실제 default 체인 읽기·승인된 쓰기로 끝까지 실행되고, 거절·만료·이전 기동 승인·중단 쓰기 복구가 안전하게 처리됨을 확인한다(P-4). General /status 같은 결정적 응답을 실제 LLM 작업 성공으로 대체하지 않는다.

## 접근

제품 코드·default 체인·토큰·허용 사용자는 바꾸지 않는다. 권고는 캡틴이 허용한 전용 합성 Git 작업사본을 하나 등록하고, 캡틴이 직접 만든 검증 토픽에서 /bind하는 것이다. 봇 관리자 승격이나 createForumTopic 없이 검증할 수 있다. 기존 토픽이 있으면 그 사용 동의를 확인한다. 운영 실사용 workspace를 선택하는 경우에도 쓰기는 별도 승인한 합성 fixture 파일로 한정한다. 최종 등록 유지/정리 선택도 실행 전에 확인하며 파일·토픽·설정을 임의 삭제하지 않는다.

현재 승인된 장기 기동 상태의 변경은 T04 제한 정지/재기동·비정상 중단/소유 자손 회수 범위를 별도 승인받는다. 기한 있는 독립 감독을 각 시험에 두되 정상 종료 뒤 자동 등록+정상 기동과 기본 read-only를 유지한다. 실패/권한 상태 복원은 main과 정한 범위만 수행하고 사용자 소유 다른 daemon·모델 세션은 건드리지 않는다. Run·런처·device는 변경하지 않는다.

등록은 기존 config를 로컬에서 확인하고 선택 workspace 한 항목만 원자적 병합/설치본 로더 검증한 뒤 승인된 재기동으로 적용한다. 합성 fixture는 canonical 경로의 전용 작업사본에만 만든다. baseline Git HEAD/index·파일 목록/바이트를 보존하고 허용한 결과 파일 외 쓰기나 Git commit/global config 변경을 요청하지 않는다. 외부 서비스·브라우저·서브에이전트를 쓰지 않는 단일 실제 작업을 단계별로 요청한다. P4가 요구하지 않는 동시 모델 두 작업의 추가 부하 시험은 이번 필수 합격 조건에 넣지 않는다.

Telegram은 main을 통해 캡틴과 단계별 준비·새 요청·버튼 시점을 맞춘다. 이전 업데이트를 기준점 전 처리하고 승인된 그룹/사용자/토픽/명령·기한과 새 수신을 RAM에서 연결한다. 읽기/쓰기 요청은 실제 LLM runner를 거쳐야 하며 /status·모사 runner·Gateway 주입으로 대체하지 않는다. 승인 ID·callback·작업 상태는 읽기 관찰만 하고 state.json을 편집해 성공을 만들지 않는다.

관측은 원래 인자/Promise/정책을 바꾸지 않는 설치본 단일 어댑터/API/상태 및 파일/OS 확인으로 한다. 대상 토픽·응답 reply 연결 여부를 boolean으로 남기고 후보 이후 non-getUpdates 메서드별 건수를 기록해 T02/T03의 범위 한계를 보강한다. 원문 본문·토큰·그룹/사람/토픽 식별자는 내보내지 않고 단계 별칭/합성 기대값 일치·건수·해시만 남긴다. 요청의 쓰기 범위와 결과 알림은 캡틴이 직접 확인하고 로컬에서 파일 바이트로 대조한다.

만료는 현재 운영 TTL을 바꾸지 않고 실제 expiresAt 경과를 기다린다. 편의상 줄이려면 별도 config 변경 승인을 받아 재검토하며 현재는 선택하지 않는다. 만료 대기와 전체 검사 한 회를 병행해 같은 검사를 중복하지 않는다. expired 뒤에만 재시작 무효화 시험을 시작해 둘을 혼동하지 않는다.

중단 복구는 승인한 쓰기 요청이 실제 running이고 해당 실행기 프로세스가 생성된 때만 시험한다. 가능한 경우 START 합성 표식도 관측하되 코드/상태를 조작해 실행을 늦추지 않는다. 완료가 먼저 끝나거나 자식 소유를 확인할 수 없으면 임의의 다른 프로세스를 죽이지 않고 미실측으로 main에 보고한다. 강제 중단 전 소유 daemon/자손의 PID·시작시각·명령/계보를 RAM에 고정하고 중단 뒤 동일 소유 자손만 회수한다. Windows 제품 자체의 회수 미확인·quarantine을 그대로 관측하며 기본 reaper를 확인됨으로 주입하지 않는다.

복구 뒤 새 파일/변경·needs_review·승인 무효·자동 재실행 부재와 격리 거절을 연결한다. 회수 확인·결과 검토 없이 release하지 않는다. release를 하더라도 needs_review를 done으로 바꾸지 않고 미검토 작업을 자동 재실행하지 않는다. 회수를 증명하지 못하면 격리 유지와 미해결 문제를 보고해 합의 변경/후속 판단을 받는다.

기준은 AGENTS.md·docs/README.md 보안/환경·PROJECT P-4·BR04다. main이 독립 사전 검토와 새 맥락 tester/reviewer를 제공한다. T04 운영 결정과 사전 pass 전에는 workspace/config/토픽 변경·실제 요청/버튼·모델 실행·기동 중단/재시작을 수행하지 않는다. 현재 자동 등록+정상 기동과 병합 후 재로그온 todo를 보존한다.
