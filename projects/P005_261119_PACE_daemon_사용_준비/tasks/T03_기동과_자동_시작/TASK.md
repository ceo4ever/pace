## 접근

제품 코드는 바꾸지 않고 설치본 CLI를 쓴다. 캡틴은 Windows 로그인 자동 시작·지금 기동을 선택했고 기존 운영 device 및 기동 부수 알림은 승인된 범위로 유지한다. 최초 설계에는 자동 시작 선택 시 실제 재로그온 관측까지 태스크 완료 전제였지만, 2026-11-21 캡틴이 현재 로그아웃하기 어려워 병합 후 시험으로 이관하도록 명시 결정했다. 현재 합격 범위는 정확한 Run/런처 등록·현재 정상 기동·수명주기·단일 인스턴스·검사 병행 관측이며 실제 로그인 자동 기동과 콘솔 비표시를 성공으로 간주하지 않는다.

수동 start도 홈에 숨김 VBS 런처를 생성할 수 있음을 적용 계획에 포함한다. 기존 파일·등록은 먼저 로컬에서 확인하고 다른 값·소유권 불명·legacy 항목이 있으면 자동 삭제/교체하지 않는다. install/uninstall은 사용자 시작 방식 선택과 해당 변경 승인 없이는 실행하지 않는다. 기존 daemon은 시험 소유자로 취급하지 않으며 서비스가 켜져 있으면 중단하고 main에 알린다.

정상 CLI 경로에는 시험용 runtime config를 주입하지 않는다. 기동 전 승인된 운영 config를 설치본 로더로 확인하고 Telegram 연결 대상·허용 목록은 바꾸지 않는다. 실제 봇 사용자 요청·workspace 등록·모델 작업·쓰기 승인 시험은 T04로 남긴다. 자동 연결 메뉴·General 알림 및 재기동 알림은 별도 T03 승인 범위로 명시한다.

필요 시 기동 선택의 검증 프로세스에는 독립 감독의 최대 30분 기한을 두고 기록한 소유 PID/bootId/인스턴스 포트가 그대로인 경우만 stop을 요청한다. 감독과 작업 턴이 중단돼도 동작할 별도 비밀 없는 기한 정지 경로를 기동 전에 준비한다. 정지 실패는 소유 프로세스 회수·에스컬레이션으로 처리하며 다른 프로세스를 정지하지 않는다. 자동 시작을 선택해 실제 상시 기동을 남기는 경우는 캡틴의 최종 상태 선택을 따르며 시험 자동정지와 구분한다.

메모리에는 임의 수치 합격선이나 실행 전 권한 게이트를 두지 않는다. 검사 시작 전과 종료 후를 포함해 가용 물리 메모리(Win32_OperatingSystem FreePhysicalMemory, KiB)·전체 물리 RAM 및 동일 daemon 프로세스 WorkingSet64(bytes)를 목표 5초 간격으로 관측한다. 각 실제 관측 시각·실제 샘플 간격·누락/조회오류를 기록하고 해당 샘플 집합의 최저 가용값·최대 daemon working set과 검사 종료 코드를 보고한다. OS 조회 지연과 샘플 사이의 순간 최저는 관측하지 못하므로 보장하지 않는다. daemon PID/bootId·상태/heartbeat와 프로세스 존재를 검사 전~종료 후 확인해 같은 인스턴스 유지와 중단 여부를 구분한다. 메모리 샘플을 확보하지 못하면 숫자를 추정해 채우지 않고 해당 검증을 미확인으로 남긴다.

OOM은 검사 출력/종료 코드와 daemon 프로세스 연속성에서 관측되는 오류·중단을 우선 확인하고, 가능하면 해당 구간 Windows Resource-Exhaustion-Detector 이벤트 건수도 원문 비출력으로 조회한다. OS 이벤트를 읽지 못하면 한계로 남기며 시스템 전체의 모든 OOM 부재를 단정하지 않는다. 현재 Codex worktree 작업자와 daemon 대기 상태·Windows 기본 동시성4 전체 검사 병행이라는 실제 부하를 기록한다. 실제 daemon 모델 작업 두 개의 부하 시험은 T03 합격 조건에 넣지 않고 T04의 실제 작업 검증에서 필요에 따라 선택한다.

프로필 체인·token·allowedUsers·maxConcurrent·workspace는 이 태스크에서 임의 변경하지 않는다. 실패한 제품 동작은 실제 재현을 기록하고 범위 밖 수정 전에 질문한다. start 종료1은 확인 대기 약10초 안에 준비되지 않은 상태이므로 즉시 프로세스 부재와 동일시하지 않고 실제 상태·로그·소유 프로세스를 확인한다. 자동 시작은 실제 사용자 로그온이 전제이며 재부팅 후 로그인 전에도 실행된다는 의미로 확대하지 않는다. 병합 후 재로그온 인수 실측에는 단일 인스턴스 및 연결 알림·콘솔 비표시를 함께 확인한다.

기준 문서는 AGENTS.md·docs/README.md 보안/환경·PROJECT·BR03이다. main이 새 독립 사전 검토와 사후 tester/reviewer를 제공한다. 사전 pass와 시작 방식·기기표시·외부 알림·감독/최종상태 승인을 확보하기 전에는 실제 기동·Windows 등록·운영 device 변경을 하지 않는다. 상태·로그·실행 증거는 기존 T02의 비밀 제거 경계를 유지한다.

사전 검토 이력: 최초 cross 호출은 timeout6으로 유효 판정이 없었고 원문을 제공받지 못했다. 이후 새 독립 anthropic 세션(보고 claude-opus-5-5, effort low)이 TASK 첫 판단 후 같은 세션에서 PROJECT·BR03·소스를 대조해 fail blocking1을 반환했다. 원문·스냅샷·PRE-REVIEW.json을 보존했고, 승인되지 않은 메모리 수치 게이트를 제거해 원래 P-3/BR03의 관측 요구로 되돌렸다. 같은 reviewer에게 수정분 재검토를 요청한다.

후속 사용자 계약 변경: 독립 2차 사전 pass와 실제 등록/수명주기/검사 병행 관측 후, 캡틴이 실제 로그아웃/로그인 시험을 병합 후로 이관하도록 결정했다. PROJECT P-3·이 태스크 T-4/S-5a·BR03/BACKLOG를 함께 수정하고 현재 TASK 해시로 독립 재검토를 요청한다. 원래 목적·미실측 사실·병합 후 인수 기준과 프로젝트 todo, relogon-checklist 및 기준점을 유지한다. 승인 자체로 실측 성공을 대체하지 않으며 기존 전체 검사·Telegram 시험은 반복하지 않는다.
