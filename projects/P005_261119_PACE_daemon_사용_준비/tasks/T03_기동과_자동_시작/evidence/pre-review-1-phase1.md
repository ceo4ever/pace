# P005 T03 사전 검토 v1 — 첫 판단

**판정: fail (blocking 1)**

## 범위와 한계

- 받은 TASK 본문만 읽었습니다. PROJECT, BR03, T02 기록, 브레인 페이지, 설치본 소스는 지시대로 열지 않았습니다.
- 재료에 적힌 설치본 동작(start exit0 유지, run exit2, 런처 생성과 실패 조건)은 사실 여부를 확인하지 않고 전제로 받았습니다.
- 파일 변경, 명령, 도구, 보조 호출은 하지 않았습니다.

## 상위 목적 정합

- 맞는 점: 기동·정지·재기동, 단일 인스턴스, 검사 병행 시 메모리 여유, 로그온 자동 시작은 "자리에 없어도 Telegram으로 PC의 PACE를 부린다"는 목적의 운영 전제를 다룹니다. 실제 봇 요청과 모델 작업을 T04로 넘긴 경계도 분명합니다.
- 한계(non-blocking, 기록 권고): HKCU Run은 사용자가 로그온해야 실행됩니다. 정전이나 업데이트로 재부팅된 뒤 로그온하지 않으면 daemon이 뜨지 않습니다. 자동 시작을 골라도 "자리에 없는" 상황 전체를 덮지는 못한다는 점을 캡틴 선택 자료에 넣는 것이 좋습니다.

## 실현 가능성

- 실현 가능합니다. 승인 전 무변경 원칙, 기존 등록이 있으면 중단, 강제 로그오프 금지, 30분 기한 정지와 소유 PID/bootId 확인이 일관되게 정해져 있습니다.
- 자동 시작의 재로그온과 콘솔 미표시는 사람이 직접 봐야 한다는 점을 반영했습니다.

## 관측·판정 결함

**Blocking**
1. **S-4/T-3의 메모리 판정 방법이 정해지지 않았습니다.** 통과 기준은 "최저 가용 물리 메모리 ≥ max(2GiB, RAM 10%)"인데, 샘플링은 "주기적"이라고만 되어 있습니다. 간격(예: ≤2초), 측정 지표(Windows Available MB 등), 샘플 구간(검사 시작 전부터 종료 후까지)이 없으면 순간적인 최저값을 놓칠 수 있어 같은 실측에서도 판정이 달라질 수 있습니다. 또 "실제 동시 모델 작업 2개 시험을 구분"이라는 문구만 있어, 이 시험이 T03 통과 조건에 들어가는지 T04로 넘기는지 분명하지 않습니다.

**Non-blocking 권고**
- S-5a: 재로그온 뒤 기대 결과가 running true와 콘솔 없음뿐입니다. 단일 인스턴스(lock 소유자 1개)와 Telegram 연결 알림(poller 연결)도 확인하면 상위 목적에 맞는 증거가 됩니다.
- S-3: "추가 연결 알림 없음"을 어떤 수단으로, 어느 시간 창에서 확인할지 정해 두는 것이 좋습니다.
- S-4: "이 worktree 세션"이 병행 부하로서 무엇을 뜻하는지(어떤 프로세스인지, 활성 상태인지) 한 줄로 밝히면 재현성이 좋아집니다.

**pass 조건:** S-4에 샘플 간격, 측정 지표, 샘플 구간을 정하고, 동시 모델 작업이 T03 기준에 들어가는지 명시하면 됩니다.
