## 받은 범위와 세션 연속성

- **받은 자료:** 현재 TASK, PROJECT, BR03, BACKLOG, 병합 후 재로그온 체크리스트, 후속 todo 원문.
- **받지 않은 자료:** `human-relogon-baseline.json`, 실행 증거 원문, 감사 스크립트, 커밋. 그래서 "전체 검사 exit 0, 991 pass·0 fail·9 skipped", 등록 정확성, 현재 기동 결과는 문서에 적힌 주장으로만 받았고 직접 확인하지 않았습니다.
- **연속성:** 이 세션의 1단계, 2단계(fail, B1), 2회차(pass) 판단을 그대로 유지합니다. 메모리 관측 계약은 바뀌지 않았으므로 B1 해소 판단도 유효합니다.
- 파일 변경, 명령, 도구, 보조 호출은 하지 않았습니다.

## 사람 실측을 성공으로 간주하는지: 간주하지 않음

- TASK T-4와 접근 절, PROJECT P-3, BR03, BACKLOG, 체크리스트, todo가 모두 같은 내용을 담고 있습니다: 실제 재로그온 자동 기동과 콘솔 비표시는 실측하지 않았고, 승인했다고 해서 성공으로 대체하지 않는다.
- 캡틴의 실제 발언("머지 후에 테스트")과 맞게, 미룬 것은 재로그온·콘솔 확인의 시점뿐입니다. 등록, 정확한 런처, 현재 기동, 수명주기, 단일 인스턴스, 메모리 관측은 병합 전 요구로 남아 있습니다.
- 콘솔 표시 여부는 사람이 본 결과로만 기록하고 VBS 창 스타일로 대신 통과시키지 않습니다. 확인하지 못하면 미확인으로 유지합니다. 둘 다 적절합니다.

## 마감 가능한 범위

T03은 병합 전 범위로 마감할 수 있습니다. 범위는 다음과 같습니다.
- Run·런처 정확 등록
- 현재 정상 기동
- start/stop/재기동
- 단일 인스턴스
- 검사 병행 관측
- 후속 인수 조건과 todo 보존

실제 로그인 자동 기동과 콘솔 비표시는 이번 마감에 들어가지 않습니다. 상위 목적인 "자리에 없어도"는 재로그온 인수를 마칠 때까지 일부만 검증된 상태로 남습니다.

## 권고 (non-blocking)

1. **todo 문구:** "기준점을 갱신한 뒤 수행"은 기존 기준점을 덮어쓰는 것으로 읽힐 수 있습니다. 체크리스트처럼 "별도 새 기준점, T03 기준점 보존"으로 맞추는 것이 좋습니다.
2. **후속 인수 표시:** 이 인수를 추적하는 곳은 사실상 todo 하나뿐입니다. P005나 BR03이 완료로 바뀐 뒤에도 보이도록 BACKLOG 진행 현황의 BR03 비고에 "재로그온 인수 미완"을 남기는 것이 좋습니다. BR03 상태 "대기"와 T03 "진행"이 서로 맞지 않는 문제도 아직 남아 있습니다.
3. **헤더 버전:** "사전 검토: v1" 표기가 계약 변경 뒤에도 그대로입니다.
