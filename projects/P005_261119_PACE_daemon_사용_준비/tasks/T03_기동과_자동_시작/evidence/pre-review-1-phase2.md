# P005 T03 사전 검토 — 2단계 재판정

**판정: fail (blocking 1)**

## 범위와 한계

- 1단계 판단(blocking 1: S-4 메모리 판정 방법이 정해지지 않음)은 그대로 두고, 이번 턴에 받은 자료와 대조했습니다.
- 받은 자료: PROJECT 전문, BR03 전문, 소스 발췌(`startDaemonNow`, `startDaemon`, `runDaemon`/`acquireInstance` 앞부분, `adapter.connect`).
- 받지 않은 자료: install/uninstall 소스, 런처 내용, `isRunning`과 status의 종료 코드 구현, T02 기록, 사용자 대화 원문. 이 부분은 확인하지 않았습니다.
- 파일 변경, 명령, 도구, 보조 호출, 민감값 출력은 하지 않았습니다.
- 지금 판단할 수 있는 것은 계획이 맞는지뿐입니다. 실제 기동, 재로그온, 지속 운영은 아직 관측되지 않았습니다.

## 목표·범위 일치

| 항목 | 대조 결과 |
|---|---|
| T-1 start/status/stop/재기동 | BR03 완료 기준, P-3과 일치 |
| T-2 단일 인스턴스 | BR03은 "두 번째 기동이 거절되는지 확인"을 요구합니다. 소스상 `start`는 이미 실행 중이면 종료 0으로 기존 인스턴스를 그대로 두고, 직접 run만 `InstanceBusyError`로 종료 2를 냅니다. TASK가 이 두 경우를 나눠 기대 결과를 둔 것은 소스와 맞습니다. |
| T-4 자동 시작 | P-3, BR03과 일치합니다(선택한 경우에만 로그오프·로그온 뒤 running true와 콘솔 없음 확인). 등록 항목 이름 "PACE Daemon"은 BR03에 근거가 있습니다. install 소스를 받지 못해 실제 등록값은 확인하지 못했습니다. |
| 수동 start의 런처 생성 | 소스상 런처가 없으면 파일을 쓰고, 내용이 다르면 실행을 거부합니다. TASK S-5m과 접근 절의 설명이 이와 맞습니다. |
| 기동 알림 | `connect`는 기동할 때마다 General에 `기기 ${device} 연결됨`을 보냅니다. TASK가 device 노출과 알림을 따로 승인받도록 한 것은 근거가 있고 꼭 필요합니다. |
| 미결 사항 | 시작 방식과 운영 변경은 PROJECT 결정 메모에 아직 승인 기록이 없습니다. "선택·승인 전 실행하지 않음"으로 둔 TASK는 이 상태와 맞습니다. |
| T04 경계 | 모델 작업, 쓰기, workspace 등록을 넘긴 것은 P-4와 맞습니다. |

## 메모리 수치 대조

- BR03은 "메모리 여유를 본다"는 관찰만 요구합니다. P-3의 확인 방법도 "병행 시 메모리 여유 확인"뿐입니다. 두 문서 모두 수치 합격선이 없습니다.
- PROJECT 결정 메모에도 max(2GiB, RAM 10%)를 사용자가 승인한 기록은 없습니다. 이 수치는 TASK가 스스로 정한 시험 기준입니다(접근 절도 "이번 시험 기준으로 정했다"고 적고 있습니다).
- 따라서 이 수치를 T-3의 합격 게이트로 쓰는 것은 승인 근거가 없는 임의 게이트입니다. 승인된 요구는 관찰과 기록입니다.

## Blocking (1)

**B1. T-3/S-4의 메모리 판정이 정의되지 않았고, 승인되지 않은 게이트가 섞여 있습니다.** 1단계 지적을 이어받아 보강한 것입니다.
- 다음 둘 중 하나로 정해야 합니다.
  - (a) 수치 없이 관찰 기준으로 둡니다: 검사 종료 0, daemon 유지, 프로세스 중단 없음, 최저 가용 메모리와 daemon 메모리를 기록.
  - (b) 2GiB/10%를 합격선으로 쓰려면 캡틴이나 main의 승인을 받고 결정 메모에 남깁니다. 미달하면 실패가 아니라 질문이라는 현재 처리도 함께 적습니다.
- 어느 쪽이든 샘플 간격, 측정 지표, 구간(검사 전부터 종료 후까지)을 정해야 합니다.
- "동시 모델 작업 2개" 시험이 T03 기준에 들어가는지, T04로 넘기는지 밝혀야 합니다. P-4의 경계로 보면 T04로 넘기는 쪽이 자연스럽습니다.

## Non-blocking

- 재로그온 뒤 확인할 증거로 단일 인스턴스와 General 연결 알림을 추가하면 좋습니다. `connect`가 매번 알림을 보내므로 쉽게 관측할 수 있습니다.
- HKCU Run은 사용자가 로그온해야 동작합니다. 재부팅 뒤 로그온하지 않으면 daemon이 뜨지 않는다는 점을 기록하고, "지속 운영"으로 과장하지 않아야 합니다.
- `startDaemon`은 약 10초(20회 × 500ms) 안에 응답이 없으면 종료 1을 냅니다. S-2에서 이 종료 1을 기동 실패와 구분해 기록하면 좋습니다.
- BR03의 상태가 아직 "대기"인데 T03은 "진행"입니다. 문서 동기화가 필요합니다.

**pass 조건:** B1을 (a) 또는 (b)로 정리하고 샘플링 방법과 동시 모델 작업의 범위를 명시하면 됩니다.
