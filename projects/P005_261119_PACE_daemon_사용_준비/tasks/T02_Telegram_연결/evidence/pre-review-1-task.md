## 목적

포럼 그룹에서 허용 사용자가 이 PC의 PACE에 메시지를 보내고 답을 받는 통로를 연결하고, 허용 밖 사용자는 실행·응답 없이 거절됨을 실제로 확인한다(P-2). T01 승인은 이 작업의 Telegram 설정·전송을 포함하지 않으므로 별도 결정 전에는 계획과 읽기 전용 조사만 한다.

## 접근

제품 코드와 Telegram 어댑터는 변경하지 않는다. 설치본을 시험·운영 대상으로 고정하고 운영 선택과 토큰 입력 경로, 실제 전송·제한된 시험 기동/정지 허용 범위를 코디네이터에게 먼저 확인한다. 봇 생성·BotFather 대화·그룹 초대·권한 설정은 캡틴이 정하며 에이전트가 임의 외부 전송하지 않는다. 토큰은 질문·argv·문서·로그·커밋에 넣지 않는다.

설정은 설치 마법사의 숨김 입력 또는 telegram init의 stdin을 사용하되 Windows 로그온 등록을 함께 수행하는 install --yes는 사용하지 않는다. 기존 설정이 생겼으면 대상과 현재 값을 로컬에서 먼저 확인하고 승인 범위만 병합·원자적 갱신한다. 폴링 충돌이나 webhook이 확인되면 자동 해제하지 않고 질문한다. 허용 목록은 거부 기본이며 workspace·쓰기 권한·maxConcurrent 변경은 이 태스크의 별도 승인 없이 수행하지 않는다.

T02의 실제 응답 검증에 필요한 제한 기동/정지는 별도 승인받는다. T03의 상시 기동·자동 시작 선택은 이후 태스크다. 불허 사용자의 무응답만으로 통과하지 않는다. 설치본 runDaemon과 동일 TelegramAdapter 인스턴스에서 권한 분기나 수신 결과를 바꾸지 않는 통계 관찰을 사용한다. 기존 daemon이 실행 중이면 중복 poller를 만들지 않는다. 실제 불허 시험 계정이 없으면 허용 사용자를 임시 제외하는 대체 절차를 사용자에게 먼저 확인하며, 합성 ID나 mock을 실사용 거절 증거로 대체하지 않는다.

기준 문서는 AGENTS.md·docs/README.md의 민감 경로·PROJECT·BR02다. 코디네이터가 별도 독립 사전 및 사후 검토를 제공한다. 사전 pass·운영 결정 전에는 Telegram 시크릿 변경·API 호출·메시지 전송·daemon 기동을 수행하지 않는다. 증거는 허용/거절/원문 일치 여부와 건수만 남기고 사용자·채팅 ID·응답 본문·토큰을 저장하지 않는다. 상태·로그 원문은 필요할 때 저장소 밖에서 비밀 제거 후 관측하며, 실제 토큰을 송신해 검증하지 않는다.
