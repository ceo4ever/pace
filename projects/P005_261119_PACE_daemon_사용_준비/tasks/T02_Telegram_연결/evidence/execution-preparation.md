# T02 승인 전 로컬 준비

## 사전 검토와 로컬 계측 확인

사전 검토는 별도 anthropic Claude 세션(보고 모델 claude-opus-5-5)에서 TASK 첫 판단 후 같은 세션의 PROJECT·BR02·소스 대조로 진행했다. 최초 fail blocking 1은 마법사의 자동 시작 부작용 때문이었고 계획에서 해당 경로를 완전히 배제했다. 같은 세션의 2차는 pass blocking 0이며 원문·TASK 스냅샷·해시는 PRE-REVIEW.json 및 pre-review-1/2 파일에 연결했다. `사전 검토: v1`은 회차가 아니라 기록 형식 버전이다.

운영 파일 내용·토큰을 읽지 않고 설치본 소스 모듈만 import했다. TelegramAdapter.prototype.connect 및 TelegramApi.prototype.call은 둘 다 함수이며 writable/configurable=true이고 runDaemon이 export되어 있다. 모듈 원본 SHA-256과 관측 범위는 local-observer-preflight.json에 기록했다. 실제 인스턴스 생성·prototype 교체·API 호출·운영 설정·기동은 수행하지 않았다. 이 결과는 실제 송신 계측 성공이나 T-2/T-3 달성을 입증하지 않는다.

## 2차 검토 지적 처리

- **R-1:** call 관찰 가능성도 위 로컬 확인에 포함했다. 승인 뒤 실제 API params/응답 관측을 확보하지 못하면 T-3은 미확인으로 남기고 마감하지 않는다. 실제 수신 거절을 계측할 수 없으면 TASK 규칙대로 T-2 미달이다.
- **R-2:** device는 config의 기기 표기이며 연결 알림·상태에 드러난다. 비민감 별칭의 실제 설정은 별도 명시 승인과 PROJECT 결정 기록 전에는 하지 않는다. 새로운 config이면 기존 기기 관련 상태와 충돌하는지 승인 뒤 로더·상태를 대조한다.
- **R-3:** 기존 daemon이나 다른 poller가 확인되면 운영 파일을 변경하거나 기존 프로세스를 정지하지 않고 main에 보고한다. 승인 전 로컬 프로세스 명령 이름 패턴 검사에서는 PACE daemon 후보 0개를 관측했다. 임의 시험 wrapper로 이미 기동된 프로세스나 다른 기기의 poller까지 배제한 증거는 아니며 실제 실행 직전에 다시 확인한다.
- **R-4:** 승인된 config를 원자적 갱신한 뒤 기동 전에 설치본 loadConfig로 검증한다. 검증 실패면 기동하지 않고 원래 설정 복원 또는 승인된 복구 절차 후 main에 보고한다. 승인 전에는 운영 config를 읽거나 생성하지 않았다.
- **R-5:** v1 마커를 유지한다. 각 검토 차수·정규화 해시·continuity는 PRE-REVIEW.json에서 추적한다.

## 사용자 입력 준비 절차

1. 캡틴이 사용할 봇·포럼 그룹과 허용/불허 시험 사용자, 비민감 기기 별칭을 확정한다. 토큰은 main이나 작업자 채팅에 전달하지 않는다.
2. main은 Telegram API 조회·chat-scoped 명령 메뉴 변경·General 연결 알림·시험 명령/응답·재기동 알림 및 제한 기동/정지·권한 원상복원 범위를 명시 승인받는다. 별도 불허 계정이 없다면 임시 제외 절차까지 따로 승인받는다.
3. 실제 입력은 사용자의 로컬 PowerShell에서 `Read-Host -AsSecureString`으로 받는다. 명령 리터럴 파이프나 화면에 에코되는 표준 입력 타이핑을 사용하지 않는다. 토큰을 인자·환경변수·입력 중계 파일에 넣지 않는다.
4. 실행 전 설치본 해시·대상 경로·저장 위치 ACL·기존 파일을 확인한 뒤 ProcessStartInfo로 고정된 설치 CLI와 숫자 chat id 인자만 전달한다. SecureString을 메모리에서만 변환해 RedirectStandardInput으로 한 번 전달하고 stdin을 닫는다. 사용자 조작이 필요하므로 main이 입력 가능한 로컬 경로를 준비한다. 아직 이 입력 절차를 실행하지 않았다.
5. finally에서 BSTR 제로화·SecureString 해제를 수행하고 오류/출력은 고정된 결과나 토큰 일치 여부만 남긴다. 관리 문자열의 즉시 메모리 소거는 보장하지 않는다. chat id는 CLI argv/로컬 기록에 존재할 수 있으나 저장소 증거로 복제하지 않는다.
6. token 문자열이 필요한 로컬 비교는 RAM에서만 수행하고 상태·로그·송신 관측·셸 기록의 원문 일치 건수만 기록한다. 실제 토큰을 Telegram에 보내서 검증하지 않는다. 시크릿의 제품 저장은 설치본의 원자적 저장을 사용하며 입력 중계 파일과 구별한다.

## 대기 상태

봇·그룹·사용자·입력 경로 및 실제 외부 동작 허용은 아직 전달받지 못했다. Telegram API·메시지·시크릿 변경·운영 config 변경·daemon 기동 없이 대기한다. T02는 진행 상태이며 목표 달성은 미확인이다. T01 결과와 전체 프로젝트 완료를 혼동하지 않는다.
