# T02 실제 Telegram 관측

## 승인·설정과 입력 보호

캡틴의 별도 승인으로 확정된 포럼 그룹과 허용자 한 명을 연결했다. 입력 출처는 캡틴이 선택한 ACL 제한 로컬 .env이며 토큰을 RAM에서 설치 CLI 자식 stdin으로만 전달했다. 설치 마법사·autostart·워크스페이스 등록은 실행하지 않았다. 입력 파일은 그대로 유지했다.

초기 S-1에서 운영 secrets 폴더의 예상 밖 상속 FullControl 권한을 발견해 저장 전에 멈췄다. main이 새 secrets 폴더만 사용자/SYSTEM/Administrators로 제한하고 입력 하위 폴더·파일 SDDL 보존을 확인했다. 이후 작업자가 저장 전 폴더 및 저장 후 실제 시크릿 파일의 ACL을 비식별로 확인했다. 다른 계정이나 부모 .pace 권한을 작업자가 바꾸지 않았다.

Bot API 읽기 조회로 승인 봇·포럼·실제 그룹 멤버십·webhook 부재를 확인했다. 봇은 관리자가 아니므로 최초 준비 스크립트의 과도한 관리자·토픽관리 조건이 실패했다. main이 소스로 General status에 해당 승격이 불필요함을 확인해 멤버십만 검사하도록 수정했다. 실패 때 설정·토큰 저장이나 기동은 없었다. 권한 승격·토픽 생성은 하지 않았다.

설치 CLI telegram init 이후 allowedUsers.telegram만 원자적으로 병합하고 설치본 loadConfig로 검증했다. 기존 device 및 그 외 설정은 보존했다. 실제 기동에는 config의 메모리 사본으로 device=pace-pc를 전달했고, 불허 단계도 메모리 사본에서만 허용자를 제외했다. 운영 config 파일은 세 단계 내내 같은 SHA-256이다. 근거: operational-setup.json 및 final-runtime-restoration.json.

## 실제 새 요청 세 단계

각 단계는 별도 설치본 runDaemon 프로세스다. connect는 단일 어댑터 참조만 잡고, call은 원래 인자·Promise·반환/예외를 바꾸지 않고 RAM 관측만 덧붙였다. 기존 update 처리 후 빈 poll·진행 송신 없음 기준점을 확보한 뒤 ready를 main에 알렸다. 캡틴은 이후 General에서 봇을 멘션한 status를 각 한 번 전송했다고 main에 답했다. 그룹·사용자·General·명령·준비 이후 시각과 일치하는 요청을 RAM에서 대조했다. 원문·식별자·update id는 저장하지 않았다.

| 단계 | 새 요청 | 거절 증가 | 상태 응답 | 새 작업 | 토큰 일치 | 혼선 | 결과 |
|---|---:|---:|---:|---:|---:|---:|---|
| 최초 허용 | 1 | 0 | 1 | 0 | 0 | 0 | pass |
| 메모리 임시 제외 | 1 | 1 | 0 | 0 | 0 | 0 | pass |
| 정상 허용 복원 | 1 | 0 | 1 | 0 | 0 | 0 | pass |

근거: live-allow-initial.json, live-deny.json, live-allow-restored.json. 허용은 성공한 송신 API 응답 이후 최소 3초, 불허는 수신 이후 최소 8초 관측한 시점의 결과다. 불허는 무응답만으로 통과하지 않았고 동일 새 요청 한 건과 rejectedUsers 증가 한 건·작업 부재·송신 부재를 함께 확인했다. /status는 LLM을 호출하지 않으므로 실제 체인 요청·쓰기 승인은 T04로 남는다.

각 프로세스에는 10분 자체기한·소유 PID 확인 정지·부모 감독 소멸 확인이 있고 별도 감독 프로세스에도 정지/회수 기한이 있었다. 실제 세 단계 모두 관측 완료 뒤 정상 정지 exit 0이었다. 초기·불허 단계의 상태 stopped·lock 부재·인스턴스 포트 획득 확인 후만 다음 정상 단계를 시작했다.

진행 중 불허 결과 파일 생성·정지 확인보다 앞서 복원 기동을 한 번 시도한 작업자 순서 오류가 있었다. 설치본 acquireInstance가 exit 2로 차단해 두 번째 어댑터나 poller, 추가 메뉴·연결 알림은 생성되지 않았다. 이를 로그에 남겼고 실제 정지·포트 해제 확인 후 정상 복원 단계를 새로 기동했다. 성공한 불허 시험은 반복하지 않았다. 조기 실패 상태 파일은 관측 성공 증거로 사용하지 않았다.

## 복원과 비밀 검사

최종 상태 stopped·lock 부재·인스턴스 포트 해제를 확인했다. 디스크의 허용자 한 명·원래 device·전체 config 해시가 보존됐고 설치본 모듈 해시도 로컬 사전 점검과 일치한다. .env는 캡틴 소유 입력으로 유지한다. 시험 중 메뉴 갱신과 연결/재기동 알림은 승인 범위에서 발생했으며 외부 메시지를 삭제하지 않았다.

상태·전체 daemon 로그·상태 저장 파일·Telegram offset 파일·로컬 PowerShell 셸 기록 및 설치 CLI status/logs 출력에서 토큰 원문 일치 0을 확인했다. 각 단계의 API params/응답도 RAM에서 검사했다. 인증에 필요한 HTTPS Bot API URL의 토큰을 전체 네트워크 비노출로 주장하지 않는다. 실제 토큰을 Telegram 메시지로 전송해 시험하지 않았다. 사용자/그룹 식별자는 저장소 증거로 내보내지 않았다.

최종 로컬 검사에서 daemon status는 정지 상태의 정상 계약인 exit 3이다. 처음 검사 스크립트가 exit 0만 허용해 실패했으나 제품 소스 확인 후 정지의 기대 코드 3으로 고쳐 로컬 조회만 재실행했다. 실제 메시지 시험은 반복하지 않았다. 근거: secret-observations.json.

## 감사용 실행 소스

execution-common.mjs, execution-apply.mjs, execution-runtime.mjs, execution-supervisor.mjs는 실제 비밀 없는 실행 소스의 감사 사본이다. execution-source-hashes.json에 원문·LF 정규화 해시를 남겼다. common 감사 사본은 선언 비밀 검사가 멤버접근 대입을 코드로 구분하도록 공백 한 곳을 추가했으며 실제 실행 원본과 감사본 해시를 구분한다. 로컬 기록 검사 감사 사본에도 같은 성격의 공백 변환이 한 곳 있다. 실제 실행 원본은 변하지 않았다. 사본 안 상대 import는 실행 당시의 원래 pace-p005-t02-* 파일명을 유지하며, 감사 사본을 그대로 운영 실행하는 도구로 제공하지 않는다. 원본 실행 경로에는 토큰·그룹/사용자 ID를 소스 리터럴로 쓰지 않았다.

전체 검사와 독립 사후 판정은 별도로 진행한다. 이 기록은 T02 실제 연결·허용/거절 시험의 관측이며 프로젝트 전체 완료 판정이 아니다.
