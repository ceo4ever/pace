## B2(정지 증거와 상태·로그 토큰 검사 소스 미수신): 해소

**정지 확인(initial-stop, deny-stop)**
- 두 스크립트는 정지를 다음 세 가지로 확인합니다.
  - `acquireInstance(home)`에 성공해야 합니다. 다른 daemon이 인스턴스를 잡고 있으면 실패하므로, 실패하면 여기서 중단합니다.
  - status 파일의 상태가 `stopped`여야 합니다.
  - 잠금 정보가 `null`이어야 합니다.
- 셋 중 하나라도 어긋나면 throw로 끝나고 증거 파일을 저장하지 않습니다. 증거의 true 값들은 이 확인을 모두 통과했을 때만 기록됩니다.
- 두 결과 파일의 해시가 같은 것은 내용이 같은 고정 출력이라 정상입니다.
- 결과 수정 시각은 소스 수정 시각보다 뒤입니다(10:43:02.212 → .375, 10:46:10 → 10:46:58). 실행 순서와 맞습니다.

**최종 확인(final-local-check)**
- 정지 대기: allow-restored 상태가 `stopped`이면서 exit 0이 될 때까지 기다립니다.
  - 조기 시도는 exit 2였으므로 이 조건을 통과할 수 없습니다. 조기 시도와 정상 복원이 구분됩니다.
- 이후 다음을 단언합니다.
  - `live-allow-restored`의 passed
  - 인스턴스 획득, stopped, 잠금 없음
  - config 해시가 operational-setup 기준값과 같음
  - 허용 사용자가 입력값과 같음
  - 모듈 해시와 시크릿 파일 ACL
- `deviceDiskUntouched`는 고정 true로 기록되지만, device가 들어 있는 config 전체 해시가 같다는 단언이 뒷받침합니다.

**토큰 검사**
- daemon 파일 4개와 PSReadLine `ConsoleHost_history.txt` 전체를 UTF-8로 읽어 원문 일치를 봅니다.
- CLI `status`와 `logs`의 stdout+stderr도 검사하며, 종료 코드를 각각 3과 0으로 단언합니다.
- 일치가 하나라도 나오면 증거를 저장하기 전에 throw합니다. 따라서 0건 결과는 실제로 일치가 없을 때만 만들어집니다.

**버전 일치**
- 결과(10:50:05.714, :06.256)가 보존된 소스 수정 시각(10:50:05.232) 직후에 생성됐습니다. exit 3을 기대하도록 고친 버전이 실제로 증거를 만든 버전이라는 서술과 맞습니다.
- 잘못된 exit 0 전용 버전은 덮어써져 원문이 없다는 한계는 처리 기록에 정직하게 남아 있습니다. 그 버전은 증거를 만들지 않았으므로 판정에 영향이 없습니다.

**저장소 기록 검사(record-scan)**
- T02 폴더 전체(재귀), PROJECT, log.jsonl, 프로젝트 메모리, BACKLOG, BR02, 대시보드를 대상으로 실제 token·chat·user 값을 비교했습니다. 103개 파일에서 일치 0건입니다.
- 저장소 상태의 변경·미추적 경로를 모두 포함하므로, 직전 지적 중 "`save()`를 거치지 않은 기록"의 공백이 메워졌습니다.
- 선언된 비밀 검사(`node scripts/secret-scan.ts`)는 exit 0, 2,688개 파일입니다. 제외 목록은 기존 제품 목록 그대로입니다.

**감사 사본의 공백 변환**
- common과 record-scan 감사 사본은 원본과 바이트가 다릅니다. 원본 해시와 감사본 해시, 변환 사유가 따로 기록돼 있습니다.
- "공백 한 곳 추가, 동작 변경 없음"이라는 주장은 원본 바이트를 받지 못해 직접 diff로 확인하지 못했습니다. 기록된 출처를 근거로 수용합니다.

**남는 한계**(blocking 아님, TASK-CLOSE 기록 대상)
- 로테이션된 로그 파일(`daemon.log.*`)이 있는지와 그 파일의 검사 여부를 알 수 없습니다.
- 셸 기록은 PowerShell ConsoleHost 하나만 검사했습니다.
- chat ID는 원문 문자열로만 비교했습니다. `-100` 접두어를 뗀 형태로 남은 경우는 잡지 못합니다.
- 이 보완 검토의 증거 파일처럼 이후 추가되는 파일은 마감 전에 다시 검사해야 합니다(작업자도 명시함).

## 남은 blocking과 최종 판정

**판정: pass (blocking 0)**
- 독립 목표 대조: **맞음.** 1단계 첫 판단과 2단계 대조는 바뀌지 않았습니다.
- 목표 달성: **T-1~T-3 달성**(관측 범위 안). B2가 해소돼 T-3과 복원의 근거가 감사 가능한 상태가 됐습니다.

**마감은 보류**합니다. 이유는 기능 결함이 아니라 마감 조건(S-6)이 아직 채워지지 않았기 때문입니다.
- 선언 비밀 검사(exit 0)와 기록 비노출 검사(0건)는 받았습니다.
- **태스크 선언 전체 검사(`npm run check`) 결과는 아직 없습니다.** 결과를 추정하지 않습니다.
- 제품 코드 변경이 없으므로 전체 검사 결과가 T02 기능 판정을 뒤집을 가능성은 낮습니다. 그래도 S-6 기준상 원문 결과를 받기 전에는 마감할 수 없습니다.
- 마감 전 남은 일:
  1. 전체 검사 원문을 확인합니다.
  2. 이후 추가된 증거 파일을 포함해 기록 비노출 검사를 다시 실행합니다.
  3. PM이 F5 로그 항목을 직접 확인합니다.
