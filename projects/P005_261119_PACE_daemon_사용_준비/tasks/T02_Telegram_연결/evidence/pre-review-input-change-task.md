## 목적

## 접근

제품 코드와 Telegram 어댑터는 변경하지 않는다. 설치본을 시험·운영 대상으로 고정하고 운영 선택과 토큰 입력 경로, 실제 전송·제한된 시험 기동/정지 허용 범위를 코디네이터에게 먼저 확인한다. 봇 생성·BotFather 대화·그룹 초대·권한 설정은 캡틴이 정하며 에이전트가 임의 외부 전송하지 않는다. 토큰은 질문·argv·문서·로그·커밋에 넣지 않는다.

설치 마법사·daemon install은 대화형 실행까지 모두 배제하고, 설치 CLI telegram init의 stdin만 사용한다. 사용자가 로컬 PowerShell에서 Read-Host -AsSecureString으로 입력하고, ProcessStartInfo의 RedirectStandardInput으로 기동한 설치 CLI에 메모리에서만 변환·전달한 뒤 즉시 stdin을 닫는다. 토큰은 리터럴·argv·환경변수·입력 중계 임시 파일에 넣지 않고, 오류도 고정된 결과만 출력한다. SecureString과 BSTR은 finally에서 해제·제로화하며 관리 문자열의 즉시 메모리 소거까지 보장하지는 않는다. chat id는 CLI argv에 필요하므로 로컬 기록에 존재할 수 있으나 저장소 증거로 복제하지 않는다. 셸 기록 검사는 원문을 출력하지 않고 토큰 일치 여부만 확인한다.

기존 설정이 생겼으면 대상과 현재 값을 로컬에서 먼저 확인하고 승인 범위만 병합·원자적 갱신한다. 시크릿 저장은 설치본 writeTelegramSecret의 원자적 쓰기·chmod 0600을 따르되 Windows ACL 보장은 별도 확인한다. 저장 폴더·파일의 ACL이 의도한 사용자/SYSTEM/관리자 밖으로 넓으면 저장·기동을 멈추고 질문한다. 허용 ID는 Telegram actorOf가 생성하는 숫자 문자열과 같은 형식인지 확인한다. 폴링 충돌이나 webhook이 확인되면 자동 해제하지 않고 질문한다. 허용 목록은 거부 기본이며 workspace·쓰기 권한·maxConcurrent 변경은 승인 없이 수행하지 않는다. 기동 알림에 실제 device가 포함되므로 비민감 별칭(예: pace-pc)을 별도 승인받아 설정하며 임의 컴퓨터 이름을 송신하지 않는다.

T02의 제한 기동/정지는 별도 승인받는다. 기동 시 chat-scoped setMyCommands와 General의 기기 연결 알림, 필요한 getMe/getUpdates 및 승인된 /status 응답까지 실제 외부 동작 범위를 알리고 확인받는다. 재기동할 때도 연결 알림이 재발송될 수 있다. T03의 상시 기동·자동 시작 선택은 이후 태스크다. 기존 daemon 또는 다른 서비스의 poller가 있으면 새 poller를 시작하지 않는다.

계측은 설치본 TelegramAdapter.prototype.connect만 감싸 동일 인스턴스 참조를 잡고 원래 메서드에 같은 this·인자를 전달하며 원래 Promise와 반환·예외를 그대로 돌려준다. stats를 읽을 뿐 값·권한 판정·sink·수신 분기는 바꾸지 않는다. o.adapters에 두 번째 TelegramAdapter를 넣지 않는다. 모듈 원본 해시는 계측 전후 동일해야 하고 프로토타입은 시험 프로세스에만 존재한다. 송신 관측은 설치본 TelegramApi.call의 인자·반환·예외를 바꾸지 않는 관찰 래퍼로 API params/응답의 실제 토큰 일치 여부만 RAM에서 검사한다. token이 포함될 수 있는 URL·본문·응답 원문은 기록하지 않는다. 계측이 불가능하면 T-2 미달로 두고 태스크를 닫지 않는다.

불허 계정이 없으면 S-4r의 임시 제외 승인을 먼저 받는다. 정상 완료·오류·중단 시 finally에서 이 시험이 소유한 daemon을 정상 정지하고 원래 허용 목록을 원자적으로 복원한다. 복원 후 재기동과 허용 응답 확인까지 해야 성공이다. 설정 복원이 실패하면 정지 상태를 유지하고 main에 올린다. 기존 daemon은 소유한 것으로 가정해 정지하지 않는다. 실패 시 기존 config/시크릿은 RAM에 보관한 원래 바이트로 승인 범위 안에서 원자적 복원한다. 원래 없던 파일은 임의 삭제하지 않고 소유 검증 후 접근 제한된 PACE 홈 내부 복구 위치로 이동해 원래 경로를 비운다. 외부 송신된 메뉴·메시지는 로컬 복원으로 취소되지 않으며 무단 삭제하지 않는다. 복원·재기동 범위와 부수 알림도 실행 전 승인받는다.

실제 거절은 통계 증가·요청 작업 부재·응답 부재를 함께 본다. 합성 ID나 mock을 실사용 거절 증거로 대체하지 않는다. GROUP privacy mode로 메시지가 수신되지 않은 경우도 거절 성공이 아니다.

기준 문서는 AGENTS.md·docs/README.md의 민감 경로·PROJECT·BR02다. 코디네이터가 별도 독립 사전 및 사후 검토를 제공한다. 사전 pass·운영 결정 전에는 Telegram 시크릿 변경·API 호출·메시지 전송·daemon 기동을 수행하지 않는다. 증거는 허용/거절/원문 일치 여부와 건수만 남기고 사용자·채팅 ID·응답 본문·토큰을 저장하지 않는다. 상태·로그 원문은 필요할 때 저장소 밖에서 비밀 제거 후 관측하며, 실제 토큰을 송신해 검증하지 않는다.

## 캡틴 승인 반영과 현재 실행 상세

2026-11-20 main이 캡틴의 “진행해줘” 승인을 전달했다. 확정 그룹·허용자1명에 Telegram 연결·봇 메뉴 갱신·General 연결/재기동 알림·/status 응답·해당 사용자의 임시 제외/즉시 복원을 허용한다. 워크스페이스 등록·작업/승인 실행·상시 기동·Windows 등록은 제외다. 승인 출처 및 위에 달라진 선택은 프로젝트 사용자 결정 로그로 남겼다. 아래는 앞서 적은 숨김 입력·device 설정·디스크 임시 제외 절차를 대체하며 기준 T-1~T-3은 유지한다.

입력은 `%USERPROFILE%/.pace/secrets/telegram-setup/.env`에서 메모리로만 읽는다. 캡틴이 직접 지정한 파일이며 새 토큰 중계 파일·환경변수·argv는 만들지 않는다. ACL 확인 결과 setup 폴더는 보호 DACL이고 파일은 해당 폴더에서 상속하며 사용자/SYSTEM/관리자 밖 allow ACE는 0건이었다. 형식·중복 키 검사에서 토큰1개·그룹 형식 정상·허용 사용자1명임을 값 출력 없이 확인했다. 입력 출처가 바뀌었으므로 초기 검토의 SecureString 입력은 현재 실행 방식이 아니다.

운영 config는 승인된 allowedUsers.telegram만 병합하고 설치본 로더로 검증한다. 기존 device 값은 보존한다. 새 config인 경우 기존 값은 설치본 기본값으로 판단하며 그 값을 보존하되 Telegram 시험에는 노출하지 않는다. 실제 기동 config 사본에만 device=pace-pc를 사용한다. 불허 시험은 같은 사본의 telegram 허용 목록만 빈 배열로 만들며 운영 파일을 덮어쓰지 않는다. 정상·거절·복원 각 단계에서 운영 config 해시가 같아야 한다. 이는 사용자의 임시 제외/복원 목적을 디스크 권한 변경 없이 달성하는 실행 선택이다.

각 시험은 설치본 runDaemon을 실행하는 별도 로컬 Node 프로세스다. connect와 call 관찰은 기존 계획대로 단일 인스턴스에서 인자·원래 Promise/예외를 보존한다. 10분 기한을 각 실행 프로세스 자체에 두고 소유 PID/상태가 일치할 때만 정상 stop-request를 쓴다. 별도 비밀 없는 감독 프로세스도 기한과 자식 종료를 관리해 부모 작업 턴 종료·감독 중단 시 시험 런타임의 자체 기한이 남는다. 정상 정지 뒤 종료를 확인하고만 다음 단계를 시작한다. 정지 실패 시 소유 자식 프로세스만 회수하고 main에 올리며 기존 daemon은 건드리지 않는다. 임시 권한은 RAM 사본이므로 강제 종료돼도 디스크에 남지 않는다.

실제 첫 허용·불허·복원 요청은 각 단계 준비 상태를 main에 알리고 캡틴과 맞춰 전송받는다. 준비가 아닌 동안 보낸 메시지를 새 시험 요청으로 추정하지 않는다. 실제 전송 전 기존 poller/webhook·부수 알림 범위를 다시 확인하며 충돌이면 기동하지 않는다. API call 관측에 실패하면 T-3 미확인, 거절 계측 실패면 T-2 미달로 유지한다. 현재는 ACL·형식의 로컬 확인까지만 수행했고 새 운영 설정·Bot API·기동은 변경된 상세 재검토 전 수행하지 않았다.
