# P005 T02 독립 tester 1단계 판정 (비식별 관측만 사용)

## 받은 범위와 읽은 범위
- **받은 자료:** 메시지에 붙여 넣은 JSON 9개입니다(operational-setup, live-allow-initial, live-deny, live-allow-restored, allow-initial-stop, deny-stop, final-runtime-restoration, secret-observations).
- **읽은 범위:** 이 9개뿐입니다. 파일 열람, 명령 실행, 보조 호출(advisor 포함)은 하지 않았습니다. TASK·PROJECT·BR 문서와 작업자 결론은 열지 않았습니다.
- **자료의 성격:** 모두 실행 측이 만든 boolean과 카운트입니다. 식별자와 원문은 없어서 값을 원본과 대조할 수는 없습니다. 아래 판정은 이 수치가 사실이라는 전제 위에 있습니다.

## 1. 목표 정합: 적합
관측 항목이 태스크 목표 네 가지(포럼 연결 구성, 허용 사용자 응답, 불허 사용자 거절, 토큰 비노출)에 모두 대응합니다. 응답 → 거절 → 허용 복원 순서로 세 단계를 나눈 것도 목표에 맞습니다.

## 2. 달성: 조건부 달성

| 목표 | 근거 | 판정 |
|---|---|---|
| 포럼 연결 구성 | 봇·포럼·봇 멤버 확인이 모두 true, 웹훅 없음, configLoaderPass, userCount 1. 사용한 API는 조회용 4종(getMe·getChat·getWebhookInfo·getChatMember)뿐 | 충족 |
| 허용 사용자 응답 | 처음과 복원 후 모두 요청 1건에 status 응답 1건, 발신 1건, 거절 증가 0, apiFailures·interference 0 | 충족 |
| 불허 사용자 거절 | 요청 1건에 거절 증가 1, 응답·발신 0, 새 작업 없음 | 조건부 충족 (한계 ① 참조) |
| 토큰 비노출 | 세 단계 모두 API 파라미터 31건·응답 30건에서 일치 0건. daemon 파일 4개, 셸 기록, CLI status·logs 출력에서도 일치 0건. 자식 프로세스 출력에도 토큰 없음 | 관측 범위 안에서 충족 |
| 원상 복구 | 각 단계 뒤 데몬이 멈췄고, lock이 없고, 포트를 다시 잡을 수 있음. config 해시와 모듈 5개 해시가 시작 때와 끝에서 같음. 허용 사용자 복원, 디바이스 파일 미변경 | 충족 |

## 3. 한계
1. **거절 시험은 실제 다른 계정이 아닙니다.** 거절 단계만 `runtimeExclusionOnly: true`입니다. 허용 계정을 실행 중에 허용 목록에서 빼고 시험한 것으로 보입니다. 허용 목록 판정 로직은 확인되지만, 등록되지 않은 실제 제3자 계정의 메시지는 관측되지 않았습니다.
2. **거절은 무응답 방식입니다.** 거절 시 발신이 0건입니다. 거절 안내 메시지가 필요한지는 목표 문구만으로 판단할 수 없습니다.
3. **포럼 토픽 경로를 확인한 boolean이 없습니다.** 응답이 요청이 온 토픽(또는 General)으로 갔는지 보여 주는 값이 없습니다. `topicCreationNotRequired`이므로 토픽 생성 권한도 확인하지 않았습니다.
4. **표본이 작습니다.** 단계마다 요청이 1건씩이고, 명령도 status 한 종류입니다.
5. **토큰 검사 방식을 알 수 없습니다.** 원문과 똑같은 문자열만 찾았는지, URL 인코딩이나 일부만 포함된 경우도 찾았는지 나와 있지 않습니다. API 요청 URL 경로가 검사 대상에 들어갔는지도 불명확합니다. Windows 이벤트 로그, 임시 파일, 크래시 덤프는 검사 대상이 아니었습니다.
6. **ACL 상속이 막혀 있지 않습니다.** 원본 env와 파일 ACL이 `protected: false`이고 디렉터리만 true입니다. 지금은 예상 밖 허용이 0이지만, 상위 폴더 권한이 바뀌면 그대로 따라 바뀔 수 있습니다.
7. **상위 목적 기준으로는 빈칸이 있습니다(T02 범위 밖).** `workspaceCount 0`이고 자동 시작도 설정하지 않았습니다(`automaticStartupTouched false`). 작업 위임과 자리를 비운 동안의 상시 가동은 아직 검증되지 않았습니다.

## 4. 보완 권고
- 등록되지 않은 실제 두 번째 Telegram 계정으로 거절을 다시 확인해야 합니다. 이번 시험에서 가장 큰 공백입니다.
- 응답이 요청과 같은 포럼 토픽으로 가는지 boolean으로 관측해야 합니다.
- 토큰 검사 범위를 명시하고 넓혀야 합니다. 인코딩되거나 일부만 포함된 형태까지 찾고, 요청 URL 경로를 제외했다면 그 사실을 기록해야 합니다.
- 원본 env 파일과 시크릿 파일 ACL의 상속을 차단할지 검토해야 합니다.
- 상위 목적을 위해 작업 위임과 자동 시작은 별도 태스크에서 검증해야 합니다.

## 결론
네 가지 목표 모두 주어진 관측 범위 안에서는 근거가 있습니다. 판정은 **조건부 통과**입니다. 다만 불허 사용자 거절은 실제 다른 계정이 아닌, 같은 계정을 실행 중에 허용 목록에서 빼서 시험했다는 한계가 있습니다. 이 판정은 별도로 실행 중인 전체 검사 결과와 함께 봐야 합니다.
