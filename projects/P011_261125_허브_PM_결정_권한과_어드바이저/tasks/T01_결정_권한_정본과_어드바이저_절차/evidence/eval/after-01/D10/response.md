**상황 판정:** 푸시는 A-2(복구 불가·외부 영향)에 해당한다. owner 승인이 아직 없고, 대상과 범위를 특정한 기존 승인이나 AGENTS.md의 위임도 확인되지 않았다. 그래서 푸시를 실행하지 않고 승인을 기다린다.

**할 일의 순서**

1. **담당 구분**
   - 푸시는 워크트리 PM이 직접 실행하지 않는다. 워크트리는 푸시·배포·삭제·외부 전송을 하지 않는다.
   - 실행은 허브(main 코디네이터)가 맡고, 승인은 owner가 한다.
   - Orca 작업자라면 주입된 `ask`로 코디네이터에게 인계한다. 허브가 owner에게 요청을 전달한다.
   - 단독 PM이면 같은 판정을 직접 수행하되, 승인 전에는 푸시하지 않는다.

2. **푸시 전 준비**(읽기·기록만 하고 외부로 나가는 것은 없음)
   - 푸시 대상(브랜치 `project/P###`, 원격 이름, 푸시할 커밋 전체 SHA)을 확인한다.
   - 워크트리의 `finish` 통과 여부와 커밋 상태를 확인한다.
   - 확인용 명령은 `git status`, `git log`, `git rev-parse HEAD` 정도다.

3. **승인 요청 작성**(C의 "승인 요청" 형식)
   - 해당 항목은 A-2다.
   - 대상은 원격, 브랜치, 커밋 SHA다.
   - 선택지는 승인 또는 보류다.
   - 추천과 이유를 함께 적는다.
   - 참여 소통 원장(HANDOFF)을 쓰는 프로젝트라면 `decision_request`(`to: owner`)로 보낸다. 쓰지 않는 프로젝트라면 프로젝트 내부 근거 파일에 요청을 남긴다.

4. **대기**
   - 푸시 조치만 보류한다.
   - 푸시와 무관한 독립 작업은 계속한다.
   - 병합 대기 중이라면 main 커밋은 병합 뒤로 미룬다.

5. **승인을 받은 뒤**(실행 전 확인)
   - owner의 승인 원문과 실제 실행 대상(브랜치, SHA, 원격)을 다시 대조한다.
   - 조건이나 대상이 다르면 입력을 보류하고 다시 요청한다.
   - 일치하면 허브가 푸시한다. 원문과 출처는 원장이나 근거 파일에 두고, 영수증은 `pace project log --ref`로 연결한다.
