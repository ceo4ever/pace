**판정:** 자체 판단 대조(SKILL §4-3)에서 걸린다. 백로그 합의는 BR03 범위의 references 분리였고, 작업자가 이를 자체 판단으로 생략했다. 이는 A-1(합의된 범위·결과 축소)에 해당하므로 PM이 정할 수 없다. 영향이 불분명한 경우가 아니다.

**순서**
1. **담당: 워크트리 PM(작업자).** `worker_done`과 완료 보고를 보류한다. finish는 이미 통과했다. 이 경우 완료 보고를 하지 않는 것이 맞다.
2. **담당: 워크트리 PM.** 읽기 대조만 한다. 대상은 log.jsonl의 `자체 판단` 항목, 백로그 BR03 합의, PROJECT.md의 목적·기준·범위다. 합의가 실제로 바뀌었는지와 `P-n` 기준 미달 여부를 확인한다. 실제 명령은 읽기 전용(파일 열람)이다.
3. **담당: 워크트리 PM.** 코드·문서는 고치지 않고 `ask`로 코디네이터(허브)에 인계한다. 내용은 다음과 같다.
   - A-1 번호
   - 자체 판단 로그 원문과 백로그 합의 원문
   - 선택지: (a) 분리를 지금 수행한 뒤 재검증·재finish, (b) 범위 축소를 owner가 승인
   - 추천: (a). 합의가 분리였고, 생략하는 쪽이 합의 변경이기 때문이다.
4. **담당: 허브.** C 형식으로 owner에게 결정을 요청한다. owner가 (b)를 승인하면 PROJECT.md 결정 메모와 로그에 출처와 함께 기록한다. 승인 없이 PM이 임의로 확정하지 않는다.
5. **분리를 수행하는 경우(담당: 워크트리 PM).** 분리 작업 뒤 `pace project check`/`done`과 finish 재검사를 다시 돌린다. 이후 자체 판단 대조를 다시 한다. 변경이 없으면 보고에 "대조: 변경 없음"을 적는다.
6. **기록.** 진행 상황은 `pace memory status --project --body "…"`로 갱신한다. 커밋은 태스크 규칙을 따른다.

**경계**
- merge와 `--yes`는 허브가 owner 승인과 SHA를 대조한 뒤에만 실행한다. 작업자는 하지 않는다.
- 병합 대기 중에는 main 커밋을 하지 않는다.
- finish 통과를 근거로 합의 변경을 덮지 않는다.
- 독립 작업이 있으면 계속 진행한다. 보류하는 것은 해당 조치뿐이다.

**수량**
- 질문(ask): 1건. 작업자가 허브에 보내는 A-1 요청이다.
- owner 승인 대기: 1건. 허브가 전달하는 결정 요청이다.
- merge·배포 승인: 이 사례에서는 아직 요청하지 않는다.
