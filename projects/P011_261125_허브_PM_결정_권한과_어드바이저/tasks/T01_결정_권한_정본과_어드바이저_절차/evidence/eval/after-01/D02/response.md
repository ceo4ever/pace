**판정**: 허브 회신은 TASK 범위 안의 장애 대응(B)이다. 결정 권한 A-1~A-5를 대조하면 모두 "아니오"다.
- 합의된 목적·기준·범위는 바뀌지 않는다.
- 외부로 나가거나 되돌릴 수 없는 조치가 없다.
- 검사나 독립 검토를 생략하거나 약화하지 않는다.
- 새 권한이나 비용이 생기지 않는다.
- 사람이 직접 해야 하는 확인도 없다.

따라서 owner에게 올릴 일이 없고, 승인을 기다릴 일도 없다. 워크트리 PM이 직접 적용하고 재검증한다.

**순서**
1. **회신 확인** (담당: 워크트리 PM)
   - 허브 회신의 교체 범위, 회귀 검사 명령, 근거, 재검증 기준을 확인한다.
   - 근거에 재현 조건과 증거가 있는지 본다. 파일은 수정하지 않는다.
2. **결정 기록** (담당: 워크트리 PM)
   - 실제 명령: `pace project log P### T0n --type decision --msg "fixture 지연 재현 결과 교체 범위·회귀 검사 명령 확정" --src "main 판단" [--ref <프로젝트 내 근거 파일>]`
   - 표는 자동 반영되므로 손으로 중복 작성하지 않는다.
3. **적용** (담당: 워크트리 PM)
   - 허브가 정한 범위만 fixture를 교체한다.
   - 범위를 넘으면 TASK 계약 밖이므로 멈추고 허브에 되묻는다.
   - 코드 스타일은 주변을 따른다.
4. **재검증** (담당: 워크트리 PM)
   - 허브가 정한 관련 회귀 검사 명령과 TASK의 `T-n` 시나리오를 실행한다.
   - 허브가 재현하고 정한 범위·명령이라 새 근거 없이 전체 검사를 늘리지 않는다.
   - 같은 대상의 성공한 기존 검사는 재실행하지 않는다.
   - 코드, 테스트, 설정이 바뀌었으니 영향 부분은 재검사 사유·범위·담당을 기록하고 그 부분부터 확인한다.
   - 필요하면 tester ∥ reviewer를 새 맥락으로 다시 배정한다.
5. **결과 기록**
   - 실행 명령, 종료 코드, 결과 위치를 `evidence/`와 TASK-CLOSE에 남긴다.
   - `pace project log P### T0n --type review --msg "..."`로 판정과 수를 남긴다.
6. **태스크 재개**
   - 통과하면 마감 절차를 이어간다. TASK-CLOSE 작성 → `pace project check` → `pace project done` → `pace memory status --project`를 같은 커밋에 포함 → `feat(P###/T0n): …` 커밋.
7. **실패 시**
   - 같은 실패가 3회 이어지거나 장애가 남으면 증거를 허브에 보낸다.
   - 허브 회신 → 적용 → 재검증을 마쳐야 공동 시도 1회이고, 상한은 2회다.
   - 필수 태스크 보류나 기준 미달 마감이 되면 A-1로 올리고 그 조치만 보류한다. 독립 작업은 계속한다.

**경계**
- 푸시, 병합, 배포, 삭제는 하지 않는다. merge는 허브가 owner 승인 뒤 실행한다.
- main 파일을 절대 경로로 고치지 않는다.
- finish 직전·직후에 같은 검사를 반복하지 않는다.
- finish 뒤 자체 판단 대조에서 이번 결정은 `main 판단`으로 구분해 적는다.
