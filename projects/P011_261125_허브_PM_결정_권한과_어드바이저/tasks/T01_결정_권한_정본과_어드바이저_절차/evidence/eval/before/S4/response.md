**판단:** 지금은 메모리를 갱신하지 않고, 사용자에게 먼저 묻는다.

근거는 SKILL.md §4의 "병합 대기 중 main 커밋 금지"(71행)다. main 세션은 P031이 `finish`로 `병합 대기`인 동안 메모리를 포함한 어떤 커밋도 main에 하지 않는다. 프로젝트 메모리(`.pace/`)는 저장소에 커밋되는 파일이다(§7, 94행). main에 커밋하면 fast-forward가 깨져서 P031의 `finish`를 다시 돌려야 한다.

**순서**
1. **상태 확인(읽기 전용):** `pace project list`로 P031이 실제로 `병합 대기`인지, 다른 프로젝트·태스크 상태는 어떤지 확인한다. 이 명령은 파일을 바꾸지 않는다.
2. **갱신 보류:** `pace memory status --project --body ...`는 실행하지 않는다. 이 명령은 `.pace/`에 쓰고, 그 결과가 main 커밋 대상이 되기 때문이다. `git commit`도 하지 않는다.
3. **사용자에게 질문:** 선택지와 권고를 붙여 짧게 묻는다.
   - (a) **권고:** P031을 `pace project merge P031`으로 먼저 병합한다. 병합은 사람 승인 뒤 `--yes`로 한다. 병합이 끝난 뒤 메모리를 갱신하고 커밋한다.
   - (b) 지금 갱신이 꼭 필요하면, 사용자가 위험을 알고 승인했을 때만 진행한다. 이 경우 P031의 `finish`를 다시 돌려야 할 수 있다.
4. **대기:** 사용자 답이 오기 전에는 쓰기·커밋·병합을 하지 않는다. merge도 승인 전에는 실행하지 않는다.
5. **병합 뒤(승인될 때):** `pace memory status --project --body "<어디까지 · 다음 할 일 · 막힌 것>"`으로 갱신한다. 원본 문서를 직접 편집했다면 `pace backlog refresh`를 실행한 뒤 커밋한다.

**담당·기록·대기**
- **담당:** main 세션(허브 PM)이다. 메모리 갱신은 merge 뒤에 한다. P031 worktree 세션은 건드리지 않는다.
- **실제 명령:** 지금 실행하는 것은 `pace project list` 하나다. 쓰기 명령은 0개다.
- **기록:** 지금은 하지 않는다. merge 뒤에 `pace memory status --project`로 남긴다.
- **질문:** 1개(병합 먼저 vs 지금 갱신).
- **승인 대기:** 2개. 하나는 갱신 시점에 대한 답이고, 다른 하나는 `pace project merge P031 --yes` 승인이다.
