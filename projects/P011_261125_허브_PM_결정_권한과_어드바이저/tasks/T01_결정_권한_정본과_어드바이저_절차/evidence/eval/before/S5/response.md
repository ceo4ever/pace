**상황 판단:** `finish`는 통과했지만, SKILL.md §4-3의 **자체 판단 대조** 단계가 아직 남아 있습니다. 이 단계는 `worker_done`이나 완료 보고 전에 해야 합니다. log.jsonl의 "BR03 범위의 references 분리 생략"은 백로그 합의(분리)를 바꾼 범위 변경입니다. 그래서 §6 첫 번째 멈춤 조건(계약 변경)에 해당합니다. 작업자가 혼자 정할 수 없고, "대조: 변경 없음"이라고 보고하면 안 됩니다.

**순서**

1. **담당: worktree 작업자(PM)**. 읽기만 합니다.
   - log.jsonl의 `자체 판단` 항목을 PROJECT.md 목적·기준·범위, 그리고 BR03 백로그 합의와 대조합니다.
   - 대조 결과, 분리 생략은 합의된 범위를 줄이는 변경으로 확인됩니다.
2. **담당: worktree 작업자**. 되돌릴 수 있는 기록만 남깁니다.
   - 필요하면 `pace project log P### --type question --by agent --to coordinator --msg "BR03 references 분리 생략 — 합의 변경 여부"`를 실행합니다.
   - Orca 작업자이면 이어서 주입된 `orca orchestration ask`로 코디네이터에게 질문합니다. Orca 밖이면 사용자에게 대화로 묻습니다.
   - 질문은 선택지와 권고·이유를 붙여 짧게 씁니다.
     - A. 분리를 지금 수행합니다. 이 경우 태스크를 추가하거나 되돌려 구현하고, 다시 check·done·finish를 거칩니다. **권고 A**: 백로그 합의가 분리였고, 생략 사유가 자체 판단뿐입니다.
     - B. 생략을 합의 변경으로 승인합니다. 이 경우 PROJECT.md 기준·범위와 백로그를 갱신하고, 결정 메모를 `사용자 결정` 또는 `main 판단`으로 남깁니다. 생략분은 후속 BR로 넘깁니다.
   - **질문 1건, 승인 대기 1건**입니다. 답이 올 때까지 진행을 멈춥니다.
3. **답을 받은 뒤** 작업자가 처리합니다.
   - 답을 받으면 같은 범위로 `--type answer --by agent`를 기록합니다.
   - A이면 분리를 구현하고 검사를 다시 돈 뒤 `finish`를 다시 실행합니다.
   - B이면 문서와 log를 합의에 맞게 고치고 필요하면 `pace backlog refresh`를 실행합니다. 그다음 `finish`를 다시 돌려 통과를 확인합니다. 끝나면 "대조: 합의 변경 승인 후 반영"이라고 보고합니다.
4. **마무리**
   - 보고에 `pace project stats` 지표와 남은 일을 포함합니다.
   - 작업자는 `worker_done`으로 끝냅니다.

**경계**

- `pace project merge`는 실행하지 않습니다. merge는 main에서 사람이 승인하는 단계이고, worktree 세션은 하지 않습니다.
- 푸시와 배포도 하지 않습니다.
- main에서 worktree 파일을 고치지 않습니다.
- 답을 받기 전에는 `worker_done`을 보내지 않습니다.
- 이번 시나리오에서는 실제 명령, 수정, 질문, 메모리 기록, 커밋, 전송을 하나도 실행하지 않았습니다. 위 명령은 계획일 뿐입니다.

**읽은 범위**

- 자동 첨부는 받았습니다. 첨부 내용은 사용자 이메일 컨텍스트입니다.

- 전체 바이트는 도구로 확인하지 않았으므로 적지 않습니다.
