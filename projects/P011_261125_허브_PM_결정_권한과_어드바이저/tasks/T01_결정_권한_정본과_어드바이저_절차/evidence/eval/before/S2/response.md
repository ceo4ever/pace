**사례: "BL261109_03 착수해 줘" (백로그 확정, Orca 밖)**

규모는 L 프로젝트로 본다. 이 사례는 BL 출처의 백로그 착수라서 §1에서 규모를 다시 따지지 않는다. 승인 답은 기다리지 않는다. §2-4에서 백로그 지시가 곧 착수 결정이기 때문이다.

**담당**
- 글쓰기(PROJECT.md 내용과 결정 메모)는 에이전트인 내가 한다.
- 번호·폴더·worktree·형식 확인은 `pace project` 명령이 한다.
- 착수 뒤 프로젝트는 worktree의 새 세션이 맡는다. 이 main 세션은 worktree 파일을 절대 경로로 고치지 않는다.

**순서와 실제 명령 또는 기록**
1. `pace project new "<백로그 이름>" --from BL261109_03`을 실행한다. 앞부분이 모호하면 명령이 거부하므로 BL 폴더명을 확인해 다시 쓴다. 브리프(BR) 파일은 출처로 쓸 수 없다.
2. 분석 단계다. BACKLOG.md, 코드 위치(`file:line`), 지금 동작을 읽는다. `new`가 넣은 "- 브레인:" 후보 중 관련 없는 줄은 지운다. 부족하면 `pace brain search`를 쓴다.
3. 설계 단계다. 목표를 한 단계 위 목적에 대조한 뒤 PROJECT.md에 목적, 기준 `P-n`, 설계·보안 영향, 바꿀 정본 목록, 태스크 표를 쓴다. 기준 문서는 §5·standards.md로 고른다.
4. 결정 메모에 목적, 기준, 태스크, 출처(백로그 확정)를 기록한다.
5. `pace project start P###`를 실행한다. 이 명령이 정의 커밋, worktree(`../<저장소>.wt/P###`, 브랜치 `project/P###`), 준비 명령을 처리한다. 작업자 도구는 `--agent` > PROJECT.md `- 작업자:` > 정의서 > 현재 세션 도구 순으로 정해진다. 모델과 effort는 필요할 때만 `--model`·`--effort`로 준다.
6. Orca 밖이므로 코디네이터를 띄우지 않는다. start가 출력한 명령으로 worktree에서 새 세션을 열도록 사용자에게 안내한다.
7. 원본 문서를 직접 편집했다면 커밋 전에 `pace backlog refresh`를 실행한다.
8. 멈추기 전에 `pace memory status --project --body "…"`로 진행을 기록한다.

**경계**
- 이 세션에서 하지 않는 일은 태스크 수행, merge, 배포, push다. 태스크(분석, 설계, 구현, 테스트, 마감)와 finish는 worktree 세션이 한다.
- merge는 사람이 main에서 `pace project merge P###`로 승인한 뒤 `--yes`로 한다.
- 백로그가 큰 산출물이면 작성자와 다른 제공자의 독립 검토(cross-verify)를 고려한다.
- 기준·범위 변경, 보안·비용 문제, 같은 실패 3회가 생기면 선택지와 권고를 붙여 사용자에게 묻는다.

**질문·승인 대기 수**
- 착수 단계의 질문은 0건이다.
- 승인 대기도 0건이다.
- 나중에 승인이 필요한 것은 merge와 배포이고, 모두 이 착수 범위 밖이다.

**자동 첨부와 읽은 범위**
- 자동 첨부는 받았다. 사용자 이메일 컨텍스트이고, 사용하지 않았으며 외부로 보내지 않았다.
- 읽은 파일은 다음과 같다.
  - `skills/pace-project-dev/SKILL.md`: 1–98줄 전체
  - `references/backlog.md`: 1–23줄 전체
  - `references/project-define.md`: 1–6줄 전체
- 전체 바이트 수는 도구로 확인하지 않았으므로 적지 않는다.
- 아무것도 실행하거나 수정하지 않았다.
