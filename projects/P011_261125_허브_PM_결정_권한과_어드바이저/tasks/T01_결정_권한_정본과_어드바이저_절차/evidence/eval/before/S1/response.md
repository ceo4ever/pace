**판정: 작은 일** (SKILL.md §1). 오타 한 글자라서 diff를 한 문장으로 말할 수 있습니다. 프로젝트(P###)와 태스크는 만들지 않습니다.

## 할 일 순서

| # | 담당 | 실제 명령 또는 기록 |
|---|---|---|
| 1 | 에이전트 | Grep으로 `memory list`의 도움말 문자열 위치를 찾고 Read로 해당 부분만 확인합니다. 오타가 한 곳인지, 같은 문구가 다른 곳(문서·테스트 스냅샷)에도 있는지 봅니다. |
| 2 | 에이전트 | Edit로 그 한 글자만 고칩니다. 같은 오타가 도움말 정본과 사본에 함께 있으면 정본까지만 고치고 나머지는 보고합니다. |
| 3 | 에이전트 | 저장소의 검사 명령을 실행합니다. 정확한 명령은 저장소의 `AGENTS.md`나 설정에서 찾습니다. 도움말 출력을 검사하는 테스트가 있으면 그 기대값도 함께 맞춥니다. |
| 4 | 에이전트 | 검사를 통과하면 커밋합니다. 이 작업 디렉터리는 git 저장소가 아니라서, 실제 저장소라면 커밋하고 여기서는 불가능하다고 보고합니다. |
| 5 | 에이전트 | `pace memory status --project`는 세션을 멈추거나 태스크를 끝낼 때 쓰는 기록이라 이 작업에는 필요 없습니다. 쓰더라도 커밋 전에 갱신해 같은 커밋에 넣습니다. |

## 경계

- `pace project new`, `start`, `task`, `finish`, `merge`는 쓰지 않습니다.
- 도움말 문구 말고 기준이나 범위를 바꿔야 하면(예: 명령 이름이나 동작 변경) 멈추고 묻습니다. 푸시·배포도 승인 없이는 하지 않습니다.
- 검사가 세 번 연속 실패해도 멈추고 묻습니다.
- 백로그나 프로젝트 원본 문서를 직접 편집하게 되면 커밋 전에 `pace backlog refresh`를 실행합니다.
- 도움말 문자열이 없거나 여러 후보라서 "한 글자"를 특정할 수 없을 때만 사용자에게 질문합니다. 이 경우 선택지와 권고를 붙여 짧게 묻습니다.

## 수

- 질문: 기본 0개. 위 경우에만 1개입니다.
- 승인 대기: 0개. 커밋은 SKILL.md 흐름에 포함되어 있습니다. 푸시·병합은 하지 않으므로 승인 대기도 없습니다.

- 읽은 파일: `skills/pace-project-dev/SKILL.md` 하나입니다. 읽은 범위는 1–98줄(전체)입니다. `references/`는 이 사례에 필요하지 않아 열지 않았습니다.
- 전체 바이트: 바이트 수를 확인하는 도구를 쓰지 않아 적지 않습니다.
