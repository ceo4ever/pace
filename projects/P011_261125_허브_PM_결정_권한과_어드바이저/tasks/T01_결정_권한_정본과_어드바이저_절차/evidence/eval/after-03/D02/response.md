**판단:** 허브 회신은 TASK 범위 안의 B 조치(허브 회신 → 워크트리 적용 → 재검증)다. A-1~A-5에는 모두 "아니오"다. 합의와 기준 `P-n`은 바뀌지 않고, 외부 영향이나 안전 기준 약화도 없고, 새 권한이나 사람 승인도 필요 없다. 그래서 owner에게 묻지 않고 승인도 기다리지 않는다.

**순서**
1. **회신 대조 (워크트리 PM)**: 회신의 교체 범위, 관련 회귀 검사 명령, 재현 근거가 현재 TASK.md의 기준 `T-n`과 테스트 표 안에 있는지 확인한다. 범위나 기준이 바뀌면 A-1로 보고 `ask`로 허브에 올린다. 이번 사례는 해당하지 않는다.
2. **기록 (워크트리 PM)**: `pace project log P### T0n --type decision --msg "fixture 지연 재현 결과에 따라 교체 범위·회귀 검사 확정" --src "main 판단" [--ref <프로젝트 내 근거 파일>]`을 실행한다. 허브의 근거 원문은 복제하지 않고 참조만 남긴다. 로그가 PROJECT.md 표에 자동 반영되므로 표는 손으로 고치지 않는다.
3. **적용 (워크트리 PM)**: 회신이 정한 범위만 worktree에서 교체한다. 범위 밖은 건드리지 않는다. 필요하면 TASK.md 테스트 표에 회귀 검사 명령을 한 줄 반영한다.
4. **재검증 (워크트리 PM)**: 허브가 지정한 회귀 검사 명령과 저장소 검사 명령을 실행하고 종료 코드와 결과 위치를 기록한다. 같은 대상에서 이미 성공한 검사는 반복하지 않고, 바뀐 범위부터 다시 본다. tester와 reviewer는 새 맥락으로 다시 배정하고 둘 다 다시 돈다. 결과는 `--type review`로 남긴다.
5. **재개와 마감 (워크트리 PM)**: 통과하면 TASK-CLOSE.md를 작성하고, `pace project check P### T0n`, `pace project done P### T0n` 순서로 실행한다. 이어서 `pace memory status --project --body "…"`를 갱신하고, 같은 커밋에 `feat(P###/T0n): …`로 커밋한다.
6. **실패 시**: 공동 시도는 최대 2회다. 2회 뒤에도 풀리지 않으면 되돌릴 수 있는 차선(선택 태스크 보류, 이슈 기록)을 고른다. 필수 태스크 보류나 기준 미달 마감이 되면 A-1로 허브에 `ask`한다.

**경계**
- 푸시, 병합, 배포는 하지 않는다. 병합은 허브가 owner 승인 뒤에 실행한다.
- 도구나 하네스 수정은 허브 담당이다. 워크트리 PM은 main을 고치지 않는다.
- 병합 대기 중이면 main 커밋은 병합 뒤로 미룬다.

**집계**
- 질문: 0건
- 승인 대기: 0건
- 허브로 `ask`: 0건 (범위 이탈 시에만)
- 실제 실행한 명령과 기록: 없음. 읽기 전용 시험이라 위는 계획이다.
