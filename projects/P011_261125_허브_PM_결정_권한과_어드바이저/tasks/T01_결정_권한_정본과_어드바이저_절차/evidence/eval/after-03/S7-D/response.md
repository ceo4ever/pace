상황 문장이 "진단을 기록한 직후"에서 끊겨 있어서, 진단 기록 뒤의 표준 경로(reviewer.md 「반복 실패」·decision-rights.md)로 답한다. 이 경로가 아닌 상황이라면 다시 알려 달라.

## 전제
- 같은 대상(TASK.md 등)을 `pace agent verify`로 3번 연속 fail했다. 3번째 호출에서 `escalation.stage: diagnose`가 나왔다.
- 워크트리 PM인 내가 근거와 진단을 허브에 보내 B로 근본 조치를 정했다. 진단 증거에는 층(structure·planning·design·other)을 적었다.
- 진단은 `pace agent review-note --target <대상> --diagnosis --layer <층> --summary … --file <진단 증거>`로 기록했다.

## 진단 기록 직후 순서

1. **근본 조치 직전, 영향을 분류한다.**
   - 담당은 워크트리 PM이다. 실제 조치를 A-1~A-5로 대조한다.
   - 이미 승인된 구체적 조치는 다시 승인받지 않는다. 새 영향이 생기면 다시 분류한다.
   - A에 걸리면 해당 조치만 보류하고 독립 작업은 이어간다. 걸리지 않으면 PM이 결정한다.
2. **A에 걸리는 경우 (owner 결정 필요).**
   - 허브를 거쳐 수정 전에 요청한다. 요청에는 A 번호와 6요소(대상·실패 추이·진단과 고친 층·남은 지적 성격·선택지·추천과 이유)를 넣는다.
   - 승인 원문이 오면 현재 대상·해시와 대조한 뒤 `review-note --decision --by user --choice … --file <영수증>`로 기록한다.
   - 사전 검토에서 "고치고 구현 진행"을 고르면, 수정 후 TASK 해시를 확인하고 PRE-REVIEW `waiver`를 붙인다.
3. **A에 걸리지 않는 경우 (PM 결정).**
   - `evidence/`에 분류 이유와 근본 조치를 적고 `review-note --decision --by pm …`을 기록한다. PM 결정은 waiver가 아니다.
4. **근본 조치를 적용한다.**
   - 지적별 땜질은 하지 않는다. 도구 결함이면 허브가 B로 고친다.
   - 병합 대기 중이면 main 커밋은 병합 뒤로 미룬다.
5. **`pace agent verify`를 다시 호출한다.**
   - 진단 뒤 첫 verify는 새 기준의 **전체 검토**다. 이전 지적으로 purpose를 좁히지 않는다.
   - 경로를 바꾸지 않고 `verify`를 쓴다. 미실행(종료 10)이면 reviewer.md의 규칙대로 다른 제공자를 다시 확인한다. 안 되면 `--allow-same-provider`(`cross: false`)로 원장을 잇는다.
   - 차수 원문은 `review-records/`에 보존한다.
6. **결과별 처리.**
   - pass(blocking 0): 사전 검토면 `PRE-REVIEW.json`에 원장을 옮겨 적는다. 진단 뒤 전체 검토는 `changed`로 기록하고 reason은 "진단 뒤 새 기준 전체 검토"다.
   - fail: 진단 뒤 첫 fail이므로 `ask_user` 단계다. 위 1~3의 결정 기록을 먼저 남기고 다시 검토한다. 같은 영역이 또 지적되면 원인 층을 다시 진단한다.
7. **보고.**
   - PM 경로는 4요소(무엇이 반복됐는지·고친 층·채우거나 덜어낸 것·재검증 결과)를 TASK-CLOSE 리뷰 절과 사후 요약에 남긴다.
   - 사용자 경로는 6요소를 수정 전에 보고하고, 결정 원문·승인 직전 대상 해시·승인 뒤 첫 수정 기록을 연결한다.
8. **계약 목표가 미달·미확인이면 done하지 않는다.** `판정: 막힘`으로 두고 보완을 요청한다. 검토 pass는 목표 달성을 대신하지 않는다.

## 경계
- 이 시험에서는 실제 명령, 수정, 질문, 메모리 기록, 커밋, 전송을 하지 않았다.
- 승인 대기는 A에 걸릴 때만 생기며 최대 1건이다. 걸리지 않으면 0건이다. 이 사례의 실제 분류는 전제에 없으므로 확정하지 않는다.
- 사용자 결정을 PM이나 자동 검사가 대신하지 않는다. waiver는 사용자만 줄 수 있다.
- 병합·배포는 허브가 수행하며 이 단계에 해당하지 않는다.
