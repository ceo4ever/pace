**전제.** 사례 C의 본문은 읽지 않았다. 아래는 "반복 검토에서 진단 결과 합의된 목적·기준·범위를 바꿔야 하는 경우"로 해석해 답한 것이다.

## 순서

1. **멈춘 지점 확인 (워크트리 PM)**
   - `verify`가 낸 `escalation` 단계를 먼저 읽는다. 세 번째 fail이면 `diagnose`, 진단 뒤 첫 fail이면 `ask_user`다.
   - 아직 기록되지 않은 단계에서 다시 `verify`를 호출하면 종료 16으로 차단되므로 호출하지 않는다.
   - 재검토를 더 돌리지 않는다.

2. **진단 정리 (워크트리 PM)**
   - 차수별 blocking 원문을 모아 원인 층(structure, planning, design, other)을 가린다.
   - 이 사례의 층은 planning이거나 design일 가능성이 크다. 근거는 증거 원문으로 확인한다.
   - 근본 조치를 합의 문서와 대조한다. PROJECT.md의 `P-n`, 범위, 백로그 브리프가 대상이다.

3. **분류**
   - 조치가 목적·목표·범위·기준을 실질적으로 바꾸거나, 필수 태스크 보류나 기준 미달 마감이면 **A-1 = 예**다.
   - 이때 PM 단독 결정(`--by pm`)은 불가하다. waiver로 덮는 것도 불가하다.
   - 계약 목표가 미달이거나 미확인이면 `done`하지 않고 `판정: 막힘`으로 둔다.

4. **허브에 인계 (`ask`)**
   - 작업자는 owner에게 직접 묻지 않고 허브에 `ask`로 넘긴다. 허브가 C 형식으로 owner에게 요청한다.
   - 요청에는 A-1 번호와 6요소를 붙인다. 6요소는 대상, 실패 추이, 진단과 고친 층, 남은 지적 성격, 선택지, 추천과 이유다.
   - 원장을 쓰면 `decision_request`(`to: owner`)로 보낸다. 쓰지 않으면 `evidence/`의 근거 파일로 남긴다.
   - 선택지는 범위 조정(A-1로 처리), 고치고 다시 검토, 기준 유지 후 보완 관측 등이다.
   - 추천은 근거와 함께 하나만 낸다.

5. **회신 전까지 (보류와 독립 작업)**
   - 합의를 바꾸는 해당 조치만 보류한다. 코드와 문서의 수정 직전 분류도 계속 적용한다.
   - 독립 작업은 이어간다.
   - 진단 근거는 `pace agent review-note --target <대상> --diagnosis --layer <층> --summary … --file <진단 증거>`로 기록한다. 이것은 `diagnose` 단계일 때만 가능하다.
   - 이 단계에서 `decision`은 기록하지 않는다. 승인 원문 위치나 영수증을 진단 증거에 연결한다.

6. **회신 후**
   - 워크트리 PM이 승인 원문과 현재 대상(해시)을 대조한다. 일치하면 `review-note --decision --by user --choice … --file <승인 근거>`로 기록한다.
   - PROJECT.md나 TASK.md의 합의를 갱신하고 결정 메모에 출처를 적는다.
   - 수정한 뒤 **전체 재검토**를 한다. 사전 검토 단계라면 TASK 해시에 대해 pass를 받거나 사용자 waiver를 받는다.
   - 승인 전에는 수정하지 않는다.

7. **기록과 보고**
   - 사용자 경로이므로 수정 전에 6요소를 보고한다.
   - TASK-CLOSE 리뷰 절에 결정 원문, 승인 직전 해시, 승인 뒤 첫 수정 기록을 연결한다.
   - `pace memory status --project --body "<어디까지 · 다음 할 일 · 막힌 것>"`을 갱신한다.
   - finish 뒤에는 자체 판단 대조를 하고, 합의를 바꾼 것이 있으면 보고 전에 §6으로 올린다.

## 기록 위치

- 진단: `review-note --diagnosis`와 `evidence/` 진단 파일
- 결정: `review-note --decision --by user`와 승인 근거 파일
- 로그: `pace project log`에 근거 참조

## 질문과 승인 대기 수

- **질문**: 1건. 허브를 거친 owner A-1 결정 요청 하나로 묶는다.
- **승인 대기**: 1건(합의 변경). 병합, 푸시, 배포는 이 단계에 없다. 병합은 이후 별도 승인이 필요하다.
- **추가 반복 검토**: 0회. 합의가 바뀌기 전까지 돌리지 않는다.

## 경계

- 이 시험에서는 어떤 파일도 수정하지 않았다.
- 질문, 메모리 기록, 커밋, 전송도 하지 않았다.
- owner 결정을 PM이 대행하지 않는다.
