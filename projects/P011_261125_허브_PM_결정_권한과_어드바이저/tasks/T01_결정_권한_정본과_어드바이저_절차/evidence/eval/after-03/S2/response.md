**사례: "BL261109_03 착수해 줘" (백로그 확정, Orca 밖)**

**담당**
- 이 세션이 main 허브 PM과 프로젝트 정의를 맡는다.
- 구현은 start가 만드는 worktree의 새 세션이 맡는다.
- Orca 밖이라 코디네이터로 전환하지 않고 worktree 작업자를 띄우지도 않는다.

**순서와 명령 (SKILL §2, backlog.md)**
1. **규모 확인.** BL 단위 백로그라 작은 일은 아니다. 태스크 없는 프로젝트인지 L 프로젝트인지는 BACKLOG.md의 BR 수로 가린다.
   - 이 판단을 하려면 `backlogs/` 아래 BL261109_03 폴더와 BACKLOG.md를 먼저 읽어야 한다.
   - 앞부분이 모호하거나 BR 파일을 직접 가리키면 `new`가 거부한다.
2. **프로젝트 생성.** `pace project new "<백로그 이름>" --from BL261109_03`을 실행한다. 번호, 폴더, PROJECT.md가 만들어진다.
3. **분석.** 백로그, 코드 위치, 현재 동작을 모은다. `new`가 넣은 "- 브레인:" 후보 중 관련 없는 줄은 지운다.
4. **설계.** 목표를 한 단계 위 목적에 대조한 뒤 PROJECT.md에 목적, 기준 `P-n`, 설계·보안 영향, 바꿀 정본 목록, 태스크 표를 쓴다. BR01은 T01에 대응한다.
5. **착수 결정 기록.** 백로그 확정이 곧 착수 결정이다. 목적, 기준, 태스크와 출처(BL261109_03)를 PROJECT.md 결정 메모에 적는다. 승인 답은 기다리지 않는다.
6. **백로그 독립 검토.** 큰 산출물이므로 작성자와 다른 제공자의 에이전트가 독립 검토한다(cross-verify.md). 제공자 호출이 불가능하면 이유와 미실행을 기록하고 `--allow-same-provider`로 같은 제공자의 새 세션에서 검토한다(`cross: false`). 검토를 아예 생략하면 A-3에 해당해 owner에게 요청한다.
7. **원본 편집 후 갱신.** 백로그나 프로젝트 원본을 직접 고쳤다면 커밋 전에 `pace backlog refresh`를 실행한다.
8. **착수.** `pace project start P###`를 실행한다.
   - 정의 커밋, worktree(`../<저장소>.wt/P###`), 브랜치 `project/P###`, 준비 명령이 만들어진다.
   - 작업자 도구는 `--agent` > PROJECT.md `- 작업자:` > 정의서 `작업자 도구:` > 현재 세션 도구 순으로 고른다. 받을 수 없는 이름이면 worktree 생성 전에 거부된다.
   - 모델·effort는 필요할 때만 `--model`·`--effort`로 준다.
   - start가 성공하면 BACKLOG.md 상태가 `진행`으로 바뀐다.
9. **인계.** start 출력의 명령으로 worktree에서 새 세션을 연다. 이후 태스크(분석 → 설계 → 구현 → 테스트 → 마감)는 그 세션이 맡는다.
10. **기록.** `pace memory status --project --body "<어디까지 · 다음 할 일 · 막힌 것>"`을 남긴다.

**경계**
- main에서 worktree 파일을 절대 경로로 수정하지 않는다.
- finish, merge, 배포는 이번 범위가 아니다. merge는 owner 승인 원문과 미리보기 SHA를 대조한 뒤에만 허브가 실행한다.
- 진행 중 목적, 기준, 범위가 바뀌면 A-1로 owner에게 묻는다.
- 작은 일로 다룰 수 없다고 판단되면 프로젝트 없이 바로 고치지 않는다.

**질문·승인 대기 수**
- 착수 질문: 0건
- 승인 대기: 0건
- 백로그 확정이 착수 결정이므로 owner 승인은 기다리지 않는다. 병합과 배포 승인은 이후 단계의 몫이라 지금은 세지 않는다.
- A 항목에 걸리는 일이 생길 때만 질문한다.
