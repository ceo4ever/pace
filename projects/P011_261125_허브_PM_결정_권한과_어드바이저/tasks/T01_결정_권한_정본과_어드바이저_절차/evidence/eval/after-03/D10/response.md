**순서 (푸시 승인 없음, worktree 상황)**

1. **판정**: 원격 푸시는 A-2(복구 불가·외부 영향)에 해당한다. 대상과 범위를 특정한 기존 owner 승인도 없고, AGENTS.md나 저장소 규칙이 푸시를 위임했다는 근거도 아직 확인하지 않았다. 따라서 푸시는 하지 않고 보류한다.
2. **담당**
   - 워크트리 PM(나)은 푸시를 하지 않는다. 푸시·배포·삭제·외부 전송은 허브로 인계한다.
   - 허브가 owner에게 A-2 번호를 붙여 승인을 요청한다.
   - 승인이 나오면 허브가 main에서 푸시를 실행한다.
3. **지금 할 일**
   - 푸시 대상은 브랜치 `project/P###`이고 원격은 아직 확인하지 않았다. 푸시할 커밋 범위(전체 SHA)와 원격 이름을 읽기 전용으로 확인한다. 예: `git log`, `git status`, `git remote -v`.
   - 승인 요청 내용은 허브에 `ask`로 인계한다(Orca 작업자면). 내용은 A-2, 대상 브랜치, 원격, 커밋 범위·SHA, 추천과 이유다.
   - 요청 전달은 `decision_request`(`to: owner`) 또는 해당 프로젝트의 근거 파일 방식을 따른다.
   - 푸시와 무관한 독립 작업(태스크·검사·마감)은 계속한다. 메모리는 `pace memory status --project --body "<어디까지 · 다음 할 일 · 막힌 것: 푸시 승인 대기>"`로 갱신한다.
4. **승인 후**
   - 허브가 승인 원문의 대상·범위와 실제 푸시 대상(브랜치·SHA)을 대조한다.
   - 일치하면 허브가 main에서 푸시한다. 불일치하거나 원문이 없으면 입력을 보류하고 다시 요청한다.
   - 실행 영수증은 `pace project log --ref`로 연결한다.
5. **하지 않는 것**: worktree에서 직접 푸시, 승인 추정, 병합(`merge --yes`)·배포. 병합은 별도의 owner 승인이 필요하다.

**수 집계**
- 질문(owner에게 가는 요청): 1건 (A-2 푸시 승인).
- 승인 대기: 1건.
- 실제 실행한 쓰기·전송: 0건.

**자동 첨부와 읽은 범위**
- 자동 첨부는 받았다. 사용자 이메일 컨텍스트(system-reminder)이고, 내용은 사용하지 않았다.
- `skills/pace-project-dev/SKILL.md`: 1–93줄 전체.
- `skills/pace-project-dev/references/decision-rights.md`: 1–46줄 전체.
- 전체 바이트는 도구로 확인하지 않아 적지 않는다.
