**판단: 작은 일이다.** SKILL.md §1에 따르면 문구나 단발 수정은 diff를 한 문장으로 말할 수 있으면 프로젝트 없이 바로 고친다. 이번 건은 "도움말 오타 한 글자 수정"이라 여기에 해당한다. `pace project new`, `start`, 태스크, finish, merge는 만들지도 실행하지도 않는다.

**할 일의 순서 (시험이라 실제로는 실행하지 않음)**

1. **담당**: 이 세션의 에이전트가 단독으로 처리한다. 허브나 코디네이터, 별도 reviewer, tester는 두지 않는다.
2. **위치 찾기**: Grep으로 `memory list`의 도움말 문자열을 찾는다. 사용자가 어떤 오타인지 말하지 않았으므로 실제 출력과 소스에서 의심 지점을 확인한다.
   - 후보가 하나로 좁혀지면 그대로 진행한다.
   - 후보가 여럿이고 어느 것이 오타인지 판단할 수 없을 때만 질문 1건을 한다.
3. **기준 확인**: 기계 설정과 `AGENTS.md`가 있으면 먼저 확인한다. 도움말 문구 정본이 따로 있으면(문서나 스냅샷 테스트) 같은 글자를 함께 고친다.
4. **수정**: Edit으로 한 글자만 고친다.
5. **검증**: 저장소 검사 명령(테스트·린트)을 실행한다. 도움말 출력 스냅샷 테스트가 있으면 같이 갱신한다.
6. **커밋**: 검사가 통과하면 한 줄짜리 커밋을 만든다. 이 작업 디렉터리는 git 저장소가 아니므로, 실제 저장소에서만 커밋한다.
7. **백로그·메모리**: 백로그 원본이나 프로젝트 문서를 직접 편집하지 않았으므로 `pace backlog refresh`는 필요 없다. 태스크를 끝낸 것도 아니라서 `pace memory status`도 필수가 아니다.

**경계**
- 오타 한 글자를 넘어 동작이나 인터페이스를 바꾸는 확장이 필요해 보이면 멈추고 사용자에게 알린다.
- push, 배포, merge는 하지 않는다. 사용자 승인이 필요한 일이고 이번 요청 범위 밖이다.
- 질문은 최대 1건(오타 위치가 모호할 때만)이고, 승인 대기는 0건이다.

**자동 첨부와 읽은 범위**
- 자동 첨부는 받았다. system-reminder의 userEmail이며, 작업에는 쓰지 않았고 외부로도 보내지 않는다.
- 읽은 파일은 `skills/pace-project-dev/SKILL.md` 하나이고, 출력된 줄 범위는 1–93이다(93번째 줄은 빈 줄).
- references는 열지 않았다. 작은 일 경로는 SKILL.md 본문만으로 충분하다.
- 전체 바이트 수는 도구로 확인하지 않았으므로 적지 않는다.
