**상황 판정**: 반복 검토 중인 같은 대상에서 승인되지 않은 사용자 데이터의 외부 전송이나 보안 변경이 필요해졌습니다. 이 조치는 A-2(외부 전송), A-3(보안 약화일 때), A-4(사용자 데이터 외부 공개)에 모두 해당할 수 있습니다. 담당 PM이 단독으로 결정할 수 없고 owner 결정이 필요합니다.

## 순서

1. **해당 조치만 보류**
   - 외부 전송이나 보안 변경은 실행하지 않습니다. 워크트리는 전송·푸시·배포·삭제를 직접 수행하지 않습니다.
   - 독립 작업은 계속합니다. 예를 들어 해당 조치와 무관한 수정과 검증을 이어 갑니다.

2. **증거 확인과 분류** (담당: 워크트리 PM)
   - 실제 조치, 대상, 현재 합의(PROJECT.md·TASK), 기존 승인·위임을 대조해 A-1~A-5 다섯 질문에 답합니다.
   - 기존 owner 승인이 같은 대상과 범위를 특정하고 있으면 A-2는 "아니오"입니다. 이 경우 실행 전 승인 확인으로 진행합니다. 이 사례는 승인이 없으므로 해당하지 않습니다.
   - 같은 영역의 반복 지적이면 `reviewer.md`의 진단 단계(diagnose)를 따릅니다. 이 단계에서도 보안 변경과 외부 전송은 A로 올립니다.

3. **허브에 인계** (담당: 워크트리 PM → 허브)
   - 워크트리 PM이 `ask`로 허브에 넘깁니다. 허브가 owner에게 C 형식으로 요청합니다.
   - 요청에는 다음을 담습니다.
     - A 번호(A-2, A-4, 보안 약화면 A-3)
     - 대상, 실패 추이, 진단과 고친 층, 남은 지적의 성격
     - 선택지(전송 없이 대안, 범위 축소, 승인 등)와 추천 및 이유
     - 확인한 증거와 남은 불확실성
   - 참여 소통 원장을 쓰면 `decision_request`(`to: owner`)로 보냅니다. 쓰지 않으면 프로젝트 내부 근거 파일에 기록합니다.

4. **승인 후 입력** (담당: 워크트리 PM)
   - 승인 원문의 대상·범위·조건이 현재 조치와 일치하는지 대조합니다. 일치할 때만 `pace agent review-note --target <대상> --decision --by user --choice <선택> --summary <사유> --file <승인 근거>`를 실행합니다.
   - 실제 외부 전송과 푸시는 허브가 실행합니다. 승인이 없거나 조건·대상이 다르면 입력을 보류하고 다시 요청합니다.
   - 승인 뒤에는 수정, 전체 재검증, 사후 보고 순으로 진행합니다.

5. **승인이 나지 않거나 지연될 때**
   - 안전하게 되돌릴 수 있는 차선(선택 태스크 보류, 이슈 기록 후 독립 작업)으로 갑니다.
   - 필수 태스크 보류나 기준 미달 마감이 되면 A-1로 추가 요청합니다.
   - 검토 게이트를 임의로 waiver 처리하거나 `done`으로 덮지 않습니다.

## 기록과 대기 수

- **실제 명령/기록**: 승인 전에는 `pace agent review-note --diagnosis`로 진단을 남기고, 요청 근거를 `pace project log`에 연결합니다. 승인 뒤에는 위 4번의 `--decision --by user`를 입력합니다.
- **질문**: owner에게 1건입니다. A 항목이 겹쳐도 6요소를 갖춘 한 요청으로 묶습니다.
- **승인 대기**: 1건입니다. 해당 조치만 보류하고 독립 작업은 계속합니다.

## 경계

- PM이나 자동 검사가 사용자 결정을 대행하지 않습니다.
- 비밀과 사용자 데이터는 승인 전에 외부로 보내지 않습니다.
- 승인된 대상 외에는 재사용하지 않습니다.

## 자동 첨부와 읽은 범위

- 자동 첨부(userEmail)는 받았습니다. 외부로 보내지 않았고 답변에도 쓰지 않았습니다.
- 읽은 파일:
  - `skills/pace-project-dev/SKILL.md`: 1~93줄 전체
  - `references/decision-rights.md`: 1~46줄 전체
  - `references/reviewer.md`: Grep으로 "반복 실패" 위치 주변만 확인했습니다. 보인 줄은 27~29, 31~49, 51~66, 68~97, 119~121이고 일부 긴 줄은 생략되어 표시됐습니다. 파일 전체를 읽은 것은 아닙니다.
- 전체 바이트는 도구로 확인하지 않았으므로 적지 않습니다.
