**사례: worktree 작업자 세션, 태스크 표에 T01 `대기`**

**담당**
- 담당은 워크트리 PM(작업자)이다. 태스크 계약 안의 실행은 자율로 하고, 합의 변경이나 외부 영향이 걸리는 결정만 허브로 올린다. (SKILL §3, §6)
- main에서 worktree 파일을 절대 경로로 고치지 않는다. 이 세션이 그 worktree의 세션이다.

**순서**
1. 시작 점검 (읽기만 한다)
   - `pace project list`로 P###와 T01 상태를 확인한다. 원본은 PROJECT.md의 태스크 표다.
   - PROJECT.md의 목적과 기준 `P-n`을 읽는다.
   - 앞 태스크가 없으므로 "남긴 것"은 읽을 대상이 없다.
   - `.pace/` 프로젝트 메모리가 있으면 읽는다.
2. 분석
   - `pace project task P### "<표의 T01 이름 그대로>"`를 실행한다.
   - 이름이 표의 `대기` 행과 같으면 T01로 열리고 상태가 `진행`이 된다. 이름이 다르면 새 번호가 생기므로 이름을 정확히 맞춘다.
   - TASK.md에 목적과 재료를 쓴다.
3. 설계
   - 기준 `T-n`, 테스트 표(기준마다 시나리오 한 줄 이상), 접근을 쓴다.
   - 새 형식 TASK는 사전 검토 전에 증명 범위와 판정 주체를 먼저 쓴다.
   - 기준 문서는 `standards.md`에서 고른다. 코드를 바꾸면 언어 색인의 안티패턴을 대조한다.
4. 구현 전 검토 (게이트)
   - 작성 PM과 다른 제공자의 reviewer에게 `pace agent verify`로 TASK.md를 검토받는다.
   - pass(blocking 0)이거나 사용자 결정 waiver일 때만 구현한다.
   - 다른 제공자를 호출할 수 없으면 사유와 미실행을 기록하고 같은 제공자 새 세션으로 검토한다(`cross: false`, B1).
   - 양쪽 모두 미실행이면 A-3으로 허브에 `ask`하고 이 관문만 보류한다.
   - 검토한 내용이 구현 전에 실질적으로 바뀌면 다시 검토받는다.
5. 구현
   - 기존 코드 스타일을 따른다. 버그라면 실패하는 테스트(RED)부터 쓴다.
6. 테스트
   - 저장소 검사 명령과 E2E를 직접 수행한다.
   - 새 맥락의 tester와 reviewer를 병렬로 배정하고 회수·판정한다.
   - 출력에 `escalation`이 있으면 먼저 따르고, 없으면 fail·blocking을 고친 뒤 둘 다 다시 돈다.
   - TASK-CLOSE "리뷰"에 차수마다 한 줄과 교본 대조 한 줄을 적는다.
7. 마감
   - TASK-CLOSE.md를 쓴다.
   - `pace project check P### T01`로 통과를 확인한 뒤 `pace project done P### T01`을 실행한다.
   - `pace memory status --project --body "<어디까지 · 다음 할 일 · 막힌 것>"`로 진행 상황을 갱신한다.
   - TASK-CLOSE, 상태, 메모리를 같은 커밋 `feat(P###/T01): …`에 넣는다.
   - 백로그나 프로젝트 원본 문서를 직접 편집했다면 커밋 전에 `pace backlog refresh`를 실행한다.
8. 다음 `대기` 태스크로 넘어간다. 모두 `완료`(또는 `보류`)이면 PROJECT-CLOSE.md를 쓰고 `pace project finish P###`를 실행한다. 이어서 자체 판단 대조를 하고 `worker_done`으로 끝낸다.

**경계**
- merge, push, 배포는 하지 않는다. 허브가 main에서 owner 승인 원문을 대조한 뒤 실행한다. 작업자는 `worker_done`까지만 한다.
- 합의된 목적·기준·범위를 바꾸는 일, 필수 태스크 보류, 보안·검토 생략, 새 권한·비용, 사람 확인이 필요한 일은 `ask`로 허브에 올린다. 해당 조치만 보류하고 독립 작업은 계속한다.
- 장애나 같은 실패 3회는 근거와 함께 허브에 보낸다.

**질문·승인 대기 수**
- 지금 시점의 질문은 0개, 승인 대기는 0개다. T01 착수에는 승인이 필요 없다.
- 이 시험에서 실제로 실행한 명령은 없다. 위 명령은 모두 실제 상황에서 할 일이다.

**자동 첨부와 읽은 범위**
- 자동 첨부는 받았다. userEmail 컨텍스트 한 건이다.
- 읽은 파일과 줄 범위는 다음과 같다.
  - `skills/pace-project-dev/SKILL.md` 1–92행
  - `references/task-steps.md` 1–11행
  - `references/decision-rights.md` 1–45행
- `reviewer.md`, `commands.md` 등 나머지 references는 열지 않았다. 사전 검토의 세부 형식은 실제 수행 때 `reviewer.md`에서 확인해야 한다.
- 전체 바이트 수는 도구로 확인하지 않았으므로 적지 않는다.
