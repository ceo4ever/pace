**공통**
- 담당은 워크트리 PM이다. 사용자 결정 입력자도 워크트리 PM이다. owner 요청은 허브가 전달하며, 허브가 main에서 실행할 일은 이 사례에 없다.
- 수정 전에 owner 답의 원문과 출처를 현재 대상과 해시에 대조한다.
  - 원문이 조치와 범위에 맞아야 한다. 실제 사용자 데이터 전송이 필요한 조치라면, 승인 범위에 그 전송이 들어 있는지 확인한다.
  - 맞지 않으면 입력을 보류하고, 6요소와 A-4를 붙인 요청을 허브에 다시 보낸다. 해당 조치만 보류하고 독립 작업은 계속한다.
- 근거 파일은 `evidence/`에 둔다. 원장을 쓰면 답 ID·지문·출처를 담은 영수증을 넣는다. 원문은 로컬 원장에 둔다.
- 그다음 `pace agent review-note --target <대상> --decision --by user --choice <선택> --summary <사유> --file <승인 근거>`를 실행한다. 이 입력은 `ask_user` 단계가 열린 뒤에만 가능하다. 지금이 그 단계다.
- 승인 직전 대상 해시, 결정 원문, 승인 뒤 첫 수정 기록을 `pace project log --ref`로 연결한다. 커밋 시각만으로 승인 전 수정 여부를 주장하지 않는다.
- 수정 전에 허브에 6요소(대상·실패 추이·진단과 고친 층·남은 지적 성격·선택지·추천과 이유)를 보고한다.
- 질문과 승인 대기는 0건이다. owner가 이미 답했고, 원문이 대조를 통과했다는 전제다. 대조가 어긋나면 1건이 생긴다.

**① 고치고 다시 검토**
1. user decision을 기록한다.
2. 수정한다.
3. `pace agent verify`로 전체 검토를 돌린다.
4. 통과하면 이후 흐름은 그대로 간다. 다시 fail이면 같은 영역인지 보고 원인 층을 다시 진단한다.
5. 회신: 허브에 결정 반영과 재검증 결과를 보고한다.
6. waiver는 쓰지 않는다.

**② 고치고 구현 진행(사전 검토)**
1. user decision을 기록한다.
2. 수정한다.
3. 고친 뒤의 TASK 해시가 승인 대상인지 확인한다. 아니면 승인 대상 해시가 다르다는 사유로 재요청한다.
4. `PRE-REVIEW.json` 최상위에 `waiver`를 붙이며, 이전 시도 이력은 그대로 둔다.
   - 값은 `by: user`, `date: 2026-11-25`, `reason`, `evidence`(승인 근거), `hash`(고친 뒤 TASK 해시)다.
5. 이후 TASK가 바뀌면 waiver가 무효가 된다. 그러면 재검토나 재승인이 필요하다.
6. 구현 진입 전 `pace project check`로 게이트를 확인한다.
7. 회신: 허브에 보고한다.

**③ 이슈로 남기고 마감(구현 후)**
1. user decision을 기록한다. 이 경로는 waiver가 아니다.
2. 결정 원문을 TASK-CLOSE 리뷰 절에 연결한다.
3. 남긴 blocking을 이슈와 "남긴 것"에 기록한다.
4. 계약 목표가 미달이거나 미확인이면 done하지 않고 `판정: 막힘`으로 둔다. 필수 기준 미달 마감이면 A-1로 요청한다.
5. 목표 달성이 확인되면 `pace project check` → `done` → `pace memory status --project` 갱신 → 커밋 `feat(P###/T0n)`을 같은 커밋으로 처리한다.
6. 사후 보고에는 반복된 것, 고친 층, 채우거나 덜어낸 것, 재검증 결과의 4요소를 TASK-CLOSE와 허브 보고에 남긴다.

**읽은 범위와 확인 상태**
- 첨부는 자동 첨부였다. 이메일 형태의 계정 정보가 자동으로 붙었고, 값은 쓰지 않았다.
- `SKILL.md` 1–93줄 전체를 읽었다.
- `decision-rights.md` 1–46줄 전체를 읽었다.
- `reviewer.md`는 40–125줄만 읽었다. 1–39줄은 읽지 않았다.
- references 전체를 grep으로 검색했다. 그 결과로 `coordinator.md`, `task-steps.md`, `tools.md`의 해당 줄을 봤고, 파일 전체는 열지 않았다.
- 전체 바이트는 확인하지 않았다.
- 다른 사례의 응답·평가표·TASK·마감 문서는 읽지 않았다. 수정, 질문, 메모리 기록, 커밋, 전송도 하지 않았다.
