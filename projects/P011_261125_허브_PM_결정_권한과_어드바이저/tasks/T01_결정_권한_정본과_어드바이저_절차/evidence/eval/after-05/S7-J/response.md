**판정: 수정 전에 멈추고 owner 결정을 요청한다. 질문 1건, 승인 대기 1건이다.**

근거는 `reviewer.md:101`이다. 재검증의 normal 단계에서 새 지적을 해결하려면 미승인 실제 사용자 데이터 전송이 필요할 때, 수정 전에 owner 결정을 먼저 받는다. 그 뒤 승인 원문의 근거를 `pace project log`에 연결하고 normal 단계 검증을 잇는다.

**순서**
1. **분류 (담당: 워크트리 PM).**
   - 해당 항목은 A-2(외부 전송)와 A-4(사용자 데이터 외부 공개)다.
   - 합성 데이터로 바꾸면 합의 기준 `P-n`을 못 채운다. 그래서 A-1(합의 변경)과 A-3(필수 증거 약화)도 걸린다. 합성 데이터 대체는 PM이 단독으로 택하지 않는다.
   - 이 지적에 대해 기존 승인이나 위임은 없다.
2. **보류.**
   - 전송과 그 수정만 보류한다. 데이터는 보내지 않는다.
   - 이 단계는 normal이므로 `review-note --decision`과 `--diagnosis`는 쓰지 않는다. `waiver`도 쓰지 않는다.
   - 독립 작업은 계속한다.
3. **허브에 `ask`로 인계 (담당: 워크트리 PM).**
   - 허브가 owner에게 `decision_request`를 보낸다. 원장을 쓰지 않는 프로젝트는 프로젝트 내부 근거 파일에 기록한다.
   - 요청에는 아래를 담는다.
     - A-2, A-4, A-1, A-3 번호
     - 대상과 전송 범위
     - 증거와 남은 불확실성
     - 선택지: ① 범위를 특정한 전송 승인 ② 합의 변경 (합성 데이터 허용 또는 기준 조정, A-1) ③ 해당 기준을 보류하되 미달 처리
     - 추천안과 그 이유
4. **회신 대기.** 회신 전에는 수정·전송·커밋을 하지 않는다.
5. **회신 후 (담당: 워크트리 PM).**
   - 승인 원문과 현재 대상·범위를 대조한다. 다르면 입력하지 않고 다시 요청한다.
   - 맞으면 `pace project log --ref <승인 근거>`로 연결한 뒤 수정한다.
   - 이어서 `pace agent verify`로 전체 재검증을 한다.
   - 승인 범위를 넘는 전송은 허브로 인계한다. 워크트리는 직접 전송하지 않는다.
6. **거절 시.**
   - 합성 데이터로 바꾸면 기준 미달이다. 그 경우 `판정: 막힘`으로 두고 done하지 않으며, 합의 변경은 A-1로 다시 요청한다.
   - 기준 미달이거나 목표 달성이 미확인이면 `check`나 `done`으로 덮지 않는다.
7. **마감 보고.** 승인 대기 중 수정 전 기록과 사후 요약 4요소(반복된 것, 고친 층, 채우거나 덜어낸 것, 재검증 결과)를 TASK-CLOSE와 C의 사후 요약에 남긴다.
