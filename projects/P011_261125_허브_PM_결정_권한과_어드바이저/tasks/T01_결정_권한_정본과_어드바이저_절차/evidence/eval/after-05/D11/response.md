**답변 (읽기 전용 시험 — 실제 실행·기록·질문·메모리·커밋·전송은 하지 않았다)**

**읽은 범위**
- 자동 첨부: 있음. 사용자 계정 정보(이메일)가 자동 첨부됐고, 값은 쓰지 않는다.
- `skills/pace-project-dev/SKILL.md` 1–93줄 전체.
- `references/decision-rights.md` 1–46줄 전체.
- `references/commands.md`는 grep으로 1–15줄 근처 일부만 확인했다.
- `docs/HANDOFF.md`는 이 작업 디렉터리에 없었다(Glob 결과 없음). 그래서 원장 세부 형식은 직접 읽지 못했다.
- 전체 바이트는 도구로 확인하지 못했으므로 적지 않는다.

**판정**
- 담당은 허브 PM이다. 푸시는 A-2(복구·외부 영향)에 해당한다.
- 다만 이번에는 대상과 범위를 특정한 기존 owner 승인이 이미 있다. 원문과 출처를 대조했고 원격·브랜치·커밋도 일치한다. 따라서 A-2는 "아니오"다.
- 새 owner 요청은 만들지 않는다. 질문 0건, 승인 대기 0건이다.

**순서**
1. 푸시 직전에 한 번 더 대조한다. 로컬 원장 본문의 owner 답 원문·출처가 실행할 원격, 브랜치, 커밋 전체 SHA와 같은지 확인한다. 조건이나 대상이 하나라도 다르면 푸시를 보류하고 해당 A-2 승인 요청을 보낸다. 지금 전제로는 모두 일치한다.
2. 허브가 main에서 푸시를 직접 실행한다. 워크트리 작업자는 푸시하지 않는다.
3. 실행 뒤 영수증을 남긴다. 영수증에는 답 ID·요청 지문·출처를 담고 원문은 복제하지 않는다. 명령은 `pace project log P### --type decision --msg "푸시 실행: <원격>/<브랜치> <전체 SHA>, owner 승인 대조 일치" --src "main 판단" --ref <영수증 파일>`이다.
4. 소통 원장을 쓰는 프로젝트라면 `decision_request`와 `decision_reply`가 같은 요청·제안 지문으로 묶여 있는지 확인한다. 검토 게이트의 근거 파일이 필요하면 같은 영수증을 연결한다.
5. 병합 대기 중이라면 main 커밋은 병합 뒤로 미룬다. 영수증 파일 때문에 커밋이 필요하면 그 시점까지 미룬다. 푸시 자체는 새 커밋이 아니므로 가능하다.

**회신·보고**
- 워크트리 작업자가 푸시를 요청했다면 허브가 실행 결과(대상·SHA·영수증 참조)를 짧게 회신한다.
- owner에게는 사후 요약 한 줄이면 충분하다: "기존 승인(답 ID)에 따라 `<원격>/<브랜치> <SHA>` 푸시 완료". 별도 승인 요청은 없다.

**경계**
- 병합(`merge --yes`)과 배포는 이 승인에 포함되지 않는다. 병합은 미리보기 커밋 전체 SHA와 별도 owner 승인 원문을 대조해야 하고, 배포는 별도 승인이 필요하다.
- 질문 0건, 승인 대기 0건이다.
