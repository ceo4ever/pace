**읽은 범위와 첨부:** 자동 첨부는 사용자 이메일 컨텍스트 하나다. 값은 쓰지 않으며 이 작업에는 쓰지 않았다. 아래 파일은 도구로 직접 읽었다.
- `SKILL.md` 1–93줄 전체
- `references/cross-verify.md` 1–10줄 전체
- `references/task-steps.md` 1–12줄 전체

- `commands.md`·`backlog.md`·`reviewer.md`는 Grep으로 일부 줄만 확인했다. 전체를 읽지는 않았다.

전체 바이트 수는 확인하지 않았다. 다른 사례의 응답·평가표·TASK·마감 문서는 읽지 않았고 수정·질문·커밋·전송도 하지 않았다.

## 사례 1: 다른 제공자 불가, 같은 제공자 새 세션 가능

**TASK 검토 (구현 전)**
- 담당: 워크트리 PM이다. reviewer는 같은 제공자의 별도 새 세션이다.
- 순서
  1. 먼저 다른 제공자를 시도한다. 시도했지만 불가했다.
  2. 미실행 사유를 기록한다.
  3. `pace agent verify --allow-same-provider`로 TASK.md를 새 세션에서 검토받는다. 호스트의 별도 새 세션을 써도 된다.
  4. `PRE-REVIEW.json`의 attempt에 `cross: false`를 적고 제공자·결과와 검토 원문(`evidence/`)을 보존한다.
  5. blocking은 수정한 뒤 `verify`를 다시 호출한다. pass(blocking 0)이면 구현한다.
- 기록: 태스크 기록에 대상, 판정, 지적 처리, 검토 방식(`cross: false`)을 남긴다.
- 회신·보고: 지적마다 반영 여부와 이유를 남긴다. 사용자에게 먼저 묻지 않는다. 사후 요약이나 완료 보고에 "교차 검토 미실행 → 같은 제공자 대체"를 한 줄 적는다.
- 질문·승인 대기: 0건이다. B1이 이미 위임한 조치이므로 A-3 해당이 없다.

**백로그 검토**
- 담당: 작성자 PM(main)이다. 같은 방식으로 다른 제공자를 먼저 시도한다.
- 순서: 불가하면 사유를 기록한다. 상위 목적 글(`--purpose-file`)과 함께 `pace agent verify --author-agent <claude|codex> --target <BACKLOG> --purpose-file <목적 글> --out <기록> --allow-same-provider`를 실행한다. 결과에 `cross: false`를 적는다.
- 기록·회신: blocking·should_fix·note 항목마다 반영 여부와 이유를 남긴다. 목표·전략 이견은 A-1로 판정한다. 백로그 원본을 직접 고쳤다면 커밋 전에 `pace backlog refresh`를 실행한다.
- 질문·승인 대기: 0건이다.

**주의**
- 다른 제공자가 실행돼 fail이 나왔다면 같은 제공자 폴백으로 대체할 수 없다. 이 경우는 위 상황이 아니다.
- 같은 제공자로 몰래 대체하지 않는다. 제공자는 결과의 모델 출처로 확인한다.

## 사례 2: 둘 다 호출 불가

- 담당: 워크트리 PM이 작업하고, 허브가 owner에게 A-3 결정 요청을 전달한다. 독립 검토 생략이나 두 경로 모두 미실행은 A-3 '예'이기 때문이다.
- 순서
  1. 두 경로의 미실행 사유와 시도 기록을 남긴다.
  2. 해당 관문만 보류한다. TASK의 사전 검토 관문이 보류되므로 구현은 시작하지 않는다. 백로그 검토가 걸린 착수도 보류한다.
  3. 독립 작업은 계속한다.
  4. 허브가 C 형식으로 요청을 보낸다. 내용은 A-3 번호, 대상과 근거, 선택지, 추천과 이유다. 원장을 쓰면 `decision_request`(`to: owner`)를 쓴다.
- 기록: `pace project log P### [T##] --type decision --msg "..." --src "main 판단"`에 근거 파일을 `--ref`로 연결한다.
- 주의: 검토가 한 번도 실행되지 않았으므로 PRE-REVIEW `waiver`의 근거가 성립하지 않는다. owner가 답해도 waiver로 덮지 않는다. 필수 결과가 미확인이면 보완 관측이나 적법하게 바뀐 계약으로 다시 판정한다. 사용자의 waiver 승인 원문이 있고 대상 해시가 일치할 때만 입력자(워크트리 PM)가 입력한다.
- 질문·승인 대기: 결정 요청 1건을 보내고 회신을 기다린다. 해당 관문만 보류한다.
