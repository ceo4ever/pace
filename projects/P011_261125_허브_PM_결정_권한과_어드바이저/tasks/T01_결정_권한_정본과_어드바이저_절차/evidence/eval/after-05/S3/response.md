**시나리오: worktree 작업자 세션, 태스크 표에 T01이 `대기`**

**전제 확인**
- 이 시험에서는 아무것도 실행하지 않았다. 아래는 실제로 하게 될 순서다.
- 자동 첨부는 있었다. 사용자 이메일이 첨부됐고 값은 적지 않는다. 식별 용도로만 쓰고 외부 전송은 하지 않는다.
- 직접 읽은 파일은 세 개다.
  - `skills/pace-project-dev/SKILL.md` 1–92줄(전체)
  - `references/task-steps.md` 1–11줄(전체)
  - `references/decision-rights.md` 1–45줄(전체)
- 전체 바이트 수는 도구로 확인하지 않아 적지 않는다.
- 다른 사례의 응답·평가표·TASK·마감 문서는 읽지 않았다.

**담당**
- 담당은 worktree PM인 이 작업자 세션이다. 태스크 계약 안의 실행은 이 세션이 맡는다.
- 허브(main 코디네이터)는 merge, 푸시, 배포, owner 요청 전달을 맡는다.
- main에서 worktree 파일을 절대 경로로 고치지 않는다. 이 세션은 worktree 안에서만 작업한다.

**순서 (SKILL §3, T01은 표의 맨 앞 `대기`)**
1. **분석**
   - 실제 명령은 `pace project task P### "<표의 T01 이름 그대로>"`이다.
   - 이름이 `대기` 행과 같으면 T01 번호로 열린다. TASK.md가 생기고 표 상태가 `진행`이 된다.
   - TASK.md에 목적과 재료를 쓴다.
   - T01은 첫 태스크라 읽을 앞 태스크 TASK-CLOSE는 없다.
2. **설계**
   - TASK.md에 기준 `T-n`, 테스트 표(기준마다 시나리오 한 줄 이상), 접근을 쓴다.
   - 새 형식이면 증명 범위·판정 주체를 먼저 쓴다.
   - 기준 문서는 `standards.md`로 고른다.
   - **구현 전 검토**
     - 작성 PM과 다른 제공자의 reviewer에게 `pace agent verify`로 TASK.md를 맡긴다.
     - blocking 0인 pass이거나 사용자 결정 waiver일 때만 구현한다.
     - 다른 제공자를 호출할 수 없으면 사유와 미실행을 기록하고 같은 제공자의 새 세션으로 검토한다. 이때는 `cross: false`로 기록한다. 둘 다 미실행이면 A-3으로 `ask`를 보낸다.
     - 검토 대상, 판정, 지적 처리, 방식을 태스크 기록에 남긴다.
3. **구현**
   - 기존 코드 스타일을 따르고 안티패턴과 대조한다.
   - 버그는 실패하는 테스트(RED)부터 쓴다.
4. **테스트**
   - 저장소 검사 명령과 E2E를 돌린다.
   - 새 맥락으로 tester ∥ reviewer를 배정하고 회수·판정한다.
   - 출력에 `escalation`이 있으면 먼저 따른다. 없으면 fail과 blocking을 고치고 둘 다 다시 돈다.
   - TASK-CLOSE 리뷰에는 차수별 한 줄과 교본 대조 한 줄을 적는다.
5. **마감**
   1. TASK-CLOSE.md를 쓴다.
   2. `pace project check P### T01`을 돌려 통과시킨다.
   3. `pace project done P### T01`을 실행한다.
   4. `pace memory status --project --body "<어디까지 · 다음 할 일 · 막힌 것>"`으로 진행 상황을 갱신한다.
   5. 커밋 `feat(P###/T01): …`를 만든다. TASK-CLOSE, 상태, 메모리를 같은 커밋에 넣는다.
- 다음 `대기` 태스크가 있으면 이어서 진행한다.
- 모든 태스크가 `완료` 또는 `보류`가 되면 §4(PROJECT-CLOSE, `finish`)로 간다.
- 백로그나 프로젝트 원본 문서를 직접 편집했다면 커밋 전에 `pace backlog refresh`를 실행한다.

**필요한 회신·보고**
- 허브에 줄 정기 회신은 없다.
- 장애나 같은 실패 3회는 근거와 함께 허브에 보낸다. 허브 회신은 `(main 판단)`으로 기록한다.
- 합의 변경(A-1), 외부 영향(A-2), 안전 기준 약화(A-3), 사용자 자산(A-4), 사람 수행(A-5)에 걸리면 `ask`로 허브에 인계한다. 허브가 owner에게 요청하고, 그동안 해당 조치만 보류하고 독립 작업은 이어간다.
- A 밖의 되돌릴 수 있는 결정은 근거를 기록하고 PM이 직접 정한다. 사후 요약에 모아 완료 보고에 붙인다.
- 푸시, 배포, 외부 전송은 worktree에서 하지 않고 허브로 넘긴다.
- merge는 허브의 일이다. finish 통과 뒤 `worker_done`으로 끝낸다. 그 전에 자체 판단을 합의와 대조하고, 완료 보고에 결과를 적는다. 바뀐 게 없으면 "대조: 변경 없음"이라고 적는다.

**질문·승인 대기 수**
- 지금 시점에는 질문 0건, 승인 대기 0건이다.
- 착수 결정은 이미 확정된 것으로 보고 승인 답을 기다리지 않는다. T01 수행에도 owner 승인은 필요 없다.
- 위 A 항목이 실제로 발생할 때만 `ask`를 한다.
