## 읽은 범위
- 자동 첨부: 있음. 사용자 계정 식별 정보가 첨부됐고 값은 적지 않는다. 이 시험에는 쓰지 않았다.
- 읽은 파일:
  - `skills/pace-project-dev/SKILL.md` 1–93줄 전체
  - `references/decision-rights.md` 1–46줄 전체
  - `references/verification.md` 1–19줄 전체
- 열지 않은 파일: `commands.md`, `reviewer.md`, `task-steps.md`. 그래서 `pace project log`의 정확한 인자 형식은 확인하지 못했다.
- 전체 바이트 수: 도구로 확인하지 않았으므로 적지 않는다.

## 공통
공동 시도(허브 회신 → 워크트리 적용 → 재검증)를 2회 마쳤다. 이는 상한(decision-rights B-4)이므로 세 번째 시도는 하지 않는다. 같은 대상의 성공한 검사를 불필요하게 반복하지도 않는다.

## 옵션 1: 선택 태스크 보류 (계약에 명시됨)
- **담당**: 워크트리 PM이 직접 결정한다. A-1~A-5에 모두 해당하지 않으므로 owner 승인은 필요 없다.
- **행동**:
  1. 안전하게 되돌릴 수 있는 차선으로 선택 태스크를 보류한다. PROJECT.md 태스크 표 상태를 `보류`로 바꾸고 이슈로 기록한다.
  2. 남은 독립 태스크를 이어서 수행한다.
- **기록**:
  - 결정과 근거를 `pace project log`로 남긴다. 허브 결정은 "(main 판단)"으로 표기한다.
  - 진행 메모리(`pace memory status --project`)를 갱신한다.
- **보고**: 사후 요약(C)에 보류 사실과 실제 결과를 한 줄로 담아 다음 대화나 완료 보고에 붙인다. 별도 요청은 보내지 않는다.
- **재개**: 도구 수정, 환경 복구, 결정 증거처럼 원인이 풀렸다는 근거가 생기면 보류를 풀고 재개한다.
- **대기**: 질문 0, 승인 대기 0.

## 옵션 2: 필수 태스크 보류 후 필수 결과 없이 마감
- **담당**: 필수 태스크 보류와 기준 미달 마감은 A-1에 해당한다. PM이 단독으로 결정할 수 없고 owner가 결정한다.
- **행동**:
  1. 워크트리 작업자가 `ask`로 허브에 인계한다.
  2. 허브가 owner에게 결정 요청(C)을 보낸다. 요청에는 A-1 번호, 대상과 근거(두 차례 시도와 실패 증거), 선택지, 추천과 이유를 담는다. 원장을 쓰는 프로젝트라면 `decision_request`를 `to: owner`로 보낸다.
  3. 회신이 올 때까지 해당 조치(필수 태스크 보류와 필수 결과 없는 마감)만 멈춘다. 마감·finish·merge를 진행하지 않는다. 독립 태스크가 있으면 계속한다.
- **회신 뒤**:
  - owner 회신(`decision_reply`)은 같은 요청 지문으로 묶어 기록하고, 원문을 근거 파일에 연결한다.
  - 그다음 게이트 요건과 현재 계약을 다시 확인한다. 필수 결과가 여전히 미확인이면 보완 관측하거나, 적법하게 변경된 계약으로 다시 판정한다.
  - 마감 조치는 이 회신으로만 진행한다.
- **대기**: 질문 1(A-1 owner 결정 요청), 승인 대기 1(owner 회신).
