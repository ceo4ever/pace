**판단**: 허브 회신은 B-3의 "허브 결정·근거·재검증 기준" 회신이다. TASK 범위 안이고 A-1~A-5 어디에도 해당하지 않으므로 owner에게 묻지 않는다. 질문 0건, 승인 대기 0건이다.

**담당과 순서 (워크트리 PM)**
1. 회신의 교체 범위, 근거, 회귀 검사 명령이 TASK 계약과 맞는지만 대조한다. 범위 밖 항목이 섞여 있으면 그 부분만 보류하고 허브에 `ask`한다.
2. 허브가 정한 범위 안에서만 fixture를 교체한다. 범위 밖 파일은 건드리지 않는다.
3. 회신에 적힌 관련 회귀 검사 명령을 그대로 실행해 종료 코드와 결과 위치를 확인한다. 이 재검사는 verification.md의 "관련 코드·테스트 변경" 사유에 해당한다. 사유, 범위, 담당을 기록하고 해당 부분부터 확인한다. 통과가 확인된 기존 검사는 로그가 부족하다는 이유만으로 반복하지 않는다.
4. 기록 명령은 다음과 같다.
   - `pace project log P### T0n --type decision --msg "fixture 지연 재현 기반 교체 범위·회귀 검사 확정" --src "main 판단" --ref <프로젝트 내 근거 파일>`
   - 재검사 결과는 `--type review` 또는 `--type change`로 남긴다. 원문 출력, 세션, 비밀은 복제하지 않는다.
5. 필요하면 TASK.md와 TASK-CLOSE의 테스트 표, 기준 대조, 남긴 것을 갱신한다. 이어서 `pace project check`, `pace project done` 순으로 진행하고 `pace memory status --project --body "…"`를 같은 커밋에 넣는다.
6. 검증 대상이 달라졌다면 tester와 reviewer를 새 맥락으로 다시 돌린다. 이때 `escalation`을 먼저 따른다.
7. 푸시, 병합, 배포는 하지 않는다. 필요해지면 허브에 인계한다. `finish` 직전·직후에는 같은 검사를 반복하지 않는다.

**회신·보고 (허브로)**
- 적용 결과와 재검증 결과(명령, 종료 코드, 결과 위치)를 보고한다.
- 막혔던 태스크를 재개했다고 알리고, 결정은 "(main 판단)"으로 기록했다고 적는다.
- 같은 실패가 반복되면 B-4에 따라 공동 시도는 2회가 상한이다.

**자동 첨부와 읽은 범위**
- 자동 첨부된 것은 사용자 계정 정보 컨텍스트 1건이다. 값은 쓰지 않았고 사용하지도 않았다.
- 읽은 파일은 `skills/pace-project-dev/SKILL.md` 1~93줄(전체), `references/decision-rights.md` 1~46줄(전체), `references/verification.md` 1~19줄(전체), `references/commands.md` 1~16줄(전체)이다.
- 전체 바이트는 도구로 확인하지 않아 적지 않는다.
- 다른 사례의 응답, 평가표, TASK, 마감 문서는 읽지 않았다.
