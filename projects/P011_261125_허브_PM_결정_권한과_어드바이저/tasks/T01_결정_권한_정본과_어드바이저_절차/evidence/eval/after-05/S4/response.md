**사례: main 세션, P031 `병합 대기`, 사용자가 "진행 상황 메모리 갱신해 줘"라고 요청**

**담당**
- main 세션(허브)이 맡는다. P031 worktree에 들어가 수정하지 않는다.
- 이 요청은 메모리 파일 갱신만 다룬다. merge 승인은 이 요청에 들어 있지 않다.

**실제 명령 또는 기록**
1. `pace project list`로 P031 상태를 확인한다. 진행 상태의 원본은 PROJECT.md 태스크 표다.
2. `pace memory status --project --body "<어디까지: P031 finish 통과, 병합 대기 · 다음 할 일: owner 승인 뒤 허브가 merge · 막힌 것: 없음 또는 승인 대기>"`를 실행한다. 이 명령으로 `.pace/` 메모리 파일만 갱신한다.
3. **그 메모리 변경은 커밋하지 않는다.** SKILL §4 ✋ 규정에 따라 병합 대기 중 main 커밋은 병합 뒤로 미룬다. B의 도구 수정 커밋도 같다.
4. 백로그·프로젝트 원본 문서는 편집하지 않으므로 `pace backlog refresh`는 필요 없다.
5. `pace project merge`와 `--yes`는 실행하지 않는다.

**필요한 회신·보고**
- 메모리 파일은 갱신했고, 커밋은 P031 병합 뒤로 미뤘다고 알린다.
- merge는 별도로 owner 승인 원문과 미리보기 대상을 대조한 뒤 허브가 실행한다고 알린다.
- 배포가 있으면 별도 승인이 필요하다는 것도 알린다.

**질문·승인 대기 수**
- 질문 0건.
- 승인 대기는 이 요청 안에서 0건이다. 이후 merge 승인(배포가 있으면 배포 승인도)은 따로 필요하다.

**자동 첨부와 읽은 범위**
- 자동 첨부된 것은 사용자 이메일 컨텍스트 하나다. 값은 쓰지 않는다. 외부로 보내지도 않는다.
- 직접 읽은 파일은 `skills/pace-project-dev/SKILL.md` 1–93줄 전체다.
- `references/`는 Grep으로 "memory|메모리"만 검색했다. 파일을 열어 읽지는 않았고, 일치한 줄(`finish.md` 17·21줄, `goal-review.md` 21줄)만 봤다.
- `decision-rights.md`와 `commands.md`는 열지 않았다. 위 판단은 SKILL.md 본문만 근거로 한다.
- 전체 바이트 수는 도구로 확인하지 않아 적지 않는다.
