**판단:** 이번 사례는 `ask_user` 단계다. 남은 지적을 해결하려면 미승인 사용자 데이터 외부 전송과 보안 변경이 필요하다. 이는 A-2(외부 전송)와 A-4(사용자 데이터 외부 공개)에 해당한다. 보안 검사나 검토를 약화하는 변경이면 A-3도 해당한다. 따라서 담당은 PM 단독이 아니라 owner 결정이다. 워크트리 PM은 허브에 `ask`로 인계하고, 허브가 owner에게 요청한다.

**순서 (실제 실행은 하지 않았고 계획만 적는다)**
1. **담당:** 워크트리 PM이 `escalation`(`ask_user`, 종료 0)을 확인한다. 이번 차수의 최초 판정 원문은 `review-records/`에 보존하고 비밀·민감정보를 검사한다.
2. **분류:** 남은 지적을 A 항목으로 나눈다.
   - A 밖의 독립 지적은 PM이 결정한다. 근거 파일을 남기고 `pace agent review-note --decision --by pm ...`으로 기록한다.
   - 외부 전송·보안 변경 조치만 보류한다.
3. **회신·보고:** 워크트리 PM이 허브에 `ask`를 보낸다. 담는 내용은 A 번호, 대상, 실패 추이, 진단과 고친 층, 남은 지적의 성격, 선택지, 추천과 이유의 6요소다. 허브가 이를 C의 결정 요청으로 owner에게 전한다. 워크트리는 전송·푸시·배포를 직접 하지 않는다.
4. **승인 후:** 승인 원문과 현재 대상(해시)이 일치하는지 대조한다. 일치하면 아래를 순서대로 한다.
   - 근거 영수증을 연결해 `review-note --decision --by user --choice ... --file ...`로 기록한다.
   - `pace project log --ref`로도 연결한다.
   - 수정한다.
   - `pace agent verify`로 전체 검토를 받는다.
   - 승인 원문이 없거나 대상이 다르면 입력하지 않고 다시 요청한다.
5. **마감 경계:** 사용자 결정이 있어도 계약 목표가 미달이거나 미확인이면 `done`하지 않고 `막힘`으로 둔다. 사전 검토가 아니므로 waiver는 쓰지 않는다. 승인 전에는 외부 전송도 보안 변경도 하지 않는다. `worker_done`, 병합, 커밋도 하지 않는다. 사후 보고는 4요소(반복된 것, 고친 층, 채우거나 덜어낸 것, 재검증 결과)를 TASK-CLOSE와 C의 사후 요약에 남긴다.
