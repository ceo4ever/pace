**사례: `pace memory list` 도움말 오타 한 글자 수정**

**판정:** SKILL.md §1의 "작은 일"에 해당한다. 문구 수정이고 diff를 한 문장으로 말할 수 있다. 프로젝트(P###), 태스크, `start`, worktree, 코디네이터는 만들지 않는다.

**담당:** 이 세션의 에이전트가 단독으로 처리한다. 허브 인계, 독립 reviewer, tester는 쓰지 않는다.

**순서(실제로는 실행하지 않고 계획만 적는다):**
1. Grep으로 `memory list` 도움말 문자열이 정의된 곳을 찾고, 해당 파일의 그 부분만 Read로 연다. 오타인지 확인한 뒤 Edit으로 한 글자만 고친다.
2. 도움말 문구가 테스트 스냅샷이나 문서에도 복제돼 있는지 Grep으로 확인한다. 있으면 같이 맞춘다.
3. 저장소의 검사 명령(`AGENTS.md`나 설정에 적힌 것)을 실행한다.
4. 통과하면 커밋한다. 작은 일이라 `feat(P###/T0n)` 형식이 아니라 일반 문구 수정 커밋 메시지를 쓴다. 현재 디렉터리는 git 저장소가 아니므로, 실제 환경에서 저장소가 아니면 커밋은 못 한다고 보고한다.

**기록과 명령:**
- `pace project …` 명령은 하나도 쓰지 않는다.
- `pace memory status`는 세션을 멈추거나 태스크를 끝낼 때만 쓰는 규칙이라 이번엔 해당 없다.
- 백로그나 프로젝트 원본 문서를 편집하지 않으므로 `pace backlog refresh`도 필요 없다.

**회신·보고:** 사용자에게 한국어로 짧게 보고한다. 내용은 수정한 파일과 줄, 오타 전후 문구, 검사 명령 결과, 커밋 여부다. 검사가 실패했거나 건너뛴 부분이 있으면 그대로 적는다.

**질문과 승인 대기:** 0건. 범위가 명확하고 A 조건(기준·범위 변경, 병합, 배포)에 걸리지 않는다. merge와 배포도 없다.

**경계:**
- 한 글자 이상으로 번지거나 도움말 구조를 바꾸게 되면 작은 일이 아니므로 규모를 다시 판단한다.
- 같은 검사가 3회 실패하면 근거와 함께 허브에 보낸다.

**자동 첨부와 읽은 범위:**
- 자동 첨부된 컨텍스트는 사용자 계정 정보 1건이다. 값은 적지 않는다.
- 읽은 파일은 `skills/pace-project-dev/SKILL.md` 하나뿐이다. 줄 1~93 전체이고, 출력에 보인 마지막 내용은 92줄이다.
- references는 이 사례에서 필요하지 않아 열지 않았다.
- 전체 바이트는 도구로 확인하지 않아 적지 않는다.
