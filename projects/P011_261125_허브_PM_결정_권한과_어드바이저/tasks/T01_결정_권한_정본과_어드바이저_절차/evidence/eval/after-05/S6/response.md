# 시나리오 답안 (읽기 전용, 실제 실행 없음)

## 공통 사항
- **자동 첨부**: 사용자 계정 정보(이메일)가 시스템 컨텍스트로 자동 첨부됐습니다. 값은 적지 않으며, 외부 전송에도 쓰지 않습니다.
- **읽은 파일**: 없습니다. 읽은 줄 범위도 없습니다. 스킬은 프롬프트에 적힌 이름과 설명만으로 골랐고 SKILL 본문은 열지 않았습니다.
- **전체 바이트**: 도구로 확인하지 않았으므로 적지 않습니다.
- **수정·질문·메모리·커밋·전송**: 모두 하지 않았습니다.
- **참고**: 작업 디렉터리는 git 저장소가 아닙니다. 그래서 worktree나 merge가 필요한 사례(③④⑥)는 착수 전에 이 점을 보고해야 합니다.

## 사례별 순서

| # | 담당 스킬 | 실제 명령·기록 | 회신·보고 | 질문 / 승인 대기 |
|---|---|---|---|---|
| ① "이걸로 서비스 기획해 줘" | **pace-intent** ("서비스 기획"이 트리거 문구) | 스킬 호출 → 프로젝트 맥락으로 "이것"이 가리키는 대상을 먼저 확인합니다. 부족한 부분은 한 번에 한 질문씩 인터뷰합니다. 빈틈 없는 기획안을 만든 뒤 인계 형태(프롬프트·문서·프로젝트·백로그)를 정합니다. | 기획안과 인계 방식을 보고합니다. | 질문은 한 번에 1개씩이고, 승인 대기는 0입니다. 인계 형태는 마지막에 확인합니다. |
| ② "프로젝트 문서 최신화해 줘" | **pace-project-init** (최신화 모드) | 스킬 호출 → 현재 상태를 분석한 뒤 AGENTS.md, docs/README.md 정의서, 유형별 문서, 프로젝트 메모리, 백로그를 현재 상태에 맞게 갱신합니다. | 변경한 문서 목록과 근거를 보고합니다. | 질문 0, 승인 대기 0 (요청 자체가 갱신 지시). |
| ③ "BL261109_03 착수해 줘" | **pace-project-dev** (백로그 단계 착수) | 스킬 호출 → 백로그 항목을 읽고 규모를 판단합니다. 필요하면 projects/P### 를 발의하고 분석·설계·계약 → 태스크 순으로 진행합니다. | 규모 판단 결과와 착수 상태를 보고합니다. | 질문 0, 승인 대기 0. 항목이 모호하거나 스킬의 승인 관문이 있으면 그때 1건씩 묻습니다. |
| ④ "확정된 목차대로 제안서 작성·검증을 프로젝트로 진행해 줘" | **pace-project-dev** | 스킬 호출 → 확정된 목차를 계약으로 삼아 작성 태스크와 검증 태스크로 나눕니다. 이후 finish → merge 순으로 진행합니다. | 작성·검증 결과를 보고합니다. | 질문 0, 승인 대기 0. |
| ⑤ "PRD 써 줘" (내용·독자 미정) | **pace-intent** (독자와 목적이 중요한 문서) | 스킬 호출 → 독자와 목적부터 한 질문씩 인터뷰합니다. 빈틈을 메운 뒤 PRD 문서로 인계합니다. 확정 뒤 작성·검증 단계는 pace-project-dev가 이어받습니다. | 확정한 목적, 독자, 목차를 보고합니다. | 질문은 한 번에 1개씩이고, 첫 질문은 독자·목적입니다. 승인 대기는 0입니다. |
| ⑥ "확정된 목차대로 제안서 작성하고 검증해 줘" | **pace-project-dev** (설명에 "확정된 목차대로 작성·검증은 문서여도 처음부터 이 스킬"이라고 명시) | ④와 같습니다. "프로젝트로"라는 말이 없어도 이 스킬이 맡습니다. | ④와 같습니다. | 질문 0, 승인 대기 0. |

## 구분 기준
- 내용이나 독자가 정해지지 않았으면 pace-intent로 갑니다 (①⑤).
- 정의서와 문서의 최신화는 pace-project-init이 맡습니다 (②).
- 계획이나 목차가 확정되어 실행과 검증만 남았으면 pace-project-dev입니다 (③④⑥).
