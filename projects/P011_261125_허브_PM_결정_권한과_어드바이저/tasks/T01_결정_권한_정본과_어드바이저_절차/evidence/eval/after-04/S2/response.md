**사례: "BL261109_03 착수해 줘" (백로그 확정, Orca 밖)**

**담당**
- 이 세션의 PM이 허브와 워크트리 PM 역할을 겸하는 단독 PM이다.
- main에서 정의와 start까지 맡는다. 그 뒤 프로젝트는 worktree에서 새로 연 세션이 맡는다.
- main에서 worktree 파일을 절대 경로로 고치지 않는다.

**순서와 실제 명령**
1. **규모 판단.** BL 폴더와 BACKLOG.md, BR 파일을 읽는다. 단계가 여럿이면 L 프로젝트로 보고 BR 번호와 같은 번호의 태스크로 나눈다. 한 번에 끝나는 일이면 태스크 없는 프로젝트로 둔다.
2. **프로젝트 생성.** `pace project new "<이름>" --from BL261109_03`을 실행한다. 앞부분이 모호하거나 BR 파일을 출처로 주면 거부되므로, 그때는 BL 폴더명을 쓴다. 이 명령이 번호, 폴더, PROJECT.md를 만든다.
3. **분석.**
   - 백로그, 코드 위치, 지금 동작을 확인한다.
   - `new`가 넣은 "- 브레인:" 후보 중 관련 없는 줄을 지운다.
4. **설계.**
   - 목표를 한 단계 위 목적에 대조한다.
   - 목적, 기준 `P-n`, 설계·보안 영향, 바꿀 정본 목록, 태스크 표를 쓴다.
   - 세부는 `project-define.md`를 따른다.
   - 보안 영향이 있으면 `security.md`를 연다.
5. **착수 결정 기록.** 백로그 확정이 곧 착수 결정이다. 목적, 기준, 태스크와 출처를 PROJECT.md 결정 메모에 적는다. 승인 답을 기다리지 않는다.
6. **백로그 확정 방식 확인.** 이 확정이 백로그 지시 수준인지 확인한다. 큰 산출물이면 작성자와 다른 제공자가 독립 검토한다(`cross-verify.md`).
7. **원본 편집 시 대시보드 갱신.** 백로그나 프로젝트 원본을 직접 고쳤다면 커밋 전에 `pace backlog refresh`를 실행한다.
8. **start.** `pace project start P### [--agent … --model … --effort …]`를 실행한다.
   - 이 명령이 정의 커밋, worktree(`../<저장소>.wt/P###`, 브랜치 `project/P###`), 준비 명령을 처리한다.
   - 작업자 도구는 `--agent`, PROJECT.md `- 작업자:`, 정의서, 지금 세션 도구 순으로 고른다. 받을 수 없는 이름이면 worktree를 만들기 전에 거부된다.
   - BACKLOG.md 전체 상태는 start가 성공하면 진행으로 바뀐다.
9. **Orca 밖 처리.** 코디네이터 세션은 띄우지 않는다. start 출력에 나온 명령으로 worktree에서 새 세션을 연다.

**회신과 보고**
- 사용자에게 알릴 내용은 다음과 같다.
  - 생성한 P### 번호
  - 규모 판단
  - 기준과 태스크 요약
  - worktree 경로
  - 새 세션을 여는 명령
- 되돌릴 수 있는 PM 판단은 근거를 기록해 두었다가 사후 요약에 한 줄씩 붙인다.
- 세션을 멈출 때는 `pace memory status --project --body "<어디까지 · 다음 할 일 · 막힌 것>"`으로 기록한다.

**경계**
- 아래 조치는 하지 않는다.
  - 병합
  - 푸시
  - 배포
- 이런 조치는 owner 승인 뒤에만 한다. 입력자는 허브이며, 병합은 미리보기 SHA와 승인 원문을 대조한 뒤 `--yes`를 입력한다.
- 진행 중 기준이나 범위가 바뀌면 A-1로 owner에게 묻는다.
- 아래 상황이 생기면 A-3이나 A-4로 보고 멈춘다.
  - 검토 생략
  - 필수 증거 미확인
  - 새 권한이나 비용 필요
- 같은 실패가 3회 반복되면 B 절차(원인 조사, 필요하면 두 번째 의견)로 처리한다.

**대기 수**
- 질문 0개, 승인 대기 0개다. 착수 단계에서는 막을 항목이 없다.
- 병합과 배포 승인은 이후 단계에서 따로 생긴다.
