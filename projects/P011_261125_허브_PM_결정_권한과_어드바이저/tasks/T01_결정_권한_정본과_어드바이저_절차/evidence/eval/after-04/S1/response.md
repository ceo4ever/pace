**읽은 범위**
- `skills/pace-project-dev/SKILL.md` 1–93줄을 모두 읽었습니다.
- references는 열지 않았습니다. 이 사례는 §1의 "작은 일"에 해당하고, SKILL.md 본문만으로 절차가 정해집니다.
- 전체 바이트 수는 도구로 확인하지 않았으므로 적지 않습니다.
- 사용자 이메일이 시스템 컨텍스트로 자동 첨부되었습니다. 값은 적지 않으며, 이번 작업에는 쓰지 않습니다.

**판단 (§1)**
- 오타 한 글자 수정은 diff를 한 문장으로 말할 수 있는 단발 문구 수정이므로 "작은 일"입니다.
- 따라서 프로젝트(`projects/P###`)도 태스크도 만들지 않고, `pace project new`나 `start`도 쓰지 않습니다.
- 담당은 이 세션의 에이전트 한 명입니다. 허브나 worktree 작업자, reviewer는 배정하지 않습니다.

**순서**
1. `Grep`으로 `memory list` 도움말 문자열이 정의된 소스 위치를 찾고, 오타가 있는 줄을 `Read`로 확인합니다.
2. 같은 오타가 다른 곳(문서나 테스트의 기대 출력)에 있는지 `Grep`으로 확인합니다. 도움말 문자열을 검증하는 테스트가 있으면 기대값도 함께 고칩니다.
3. `Edit`으로 한 글자를 고칩니다.
4. 저장소의 검사 명령을 실행합니다. 이 명령은 저장소의 `AGENTS.md`나 설정에서 확인하고, 추측하지 않습니다. 가능하면 `pace memory list --help` 출력도 확인합니다.
5. 검사가 통과하면 커밋합니다. 이 디렉터리는 git 저장소가 아니므로 실제 환경에서는 저장소 여부를 먼저 확인합니다.

**기록과 보고**
- `pace project log`는 쓰지 않습니다. 프로젝트가 없기 때문입니다.
- 진행 기록(`pace memory status --project`)은 §7에서 세션을 멈추거나 태스크를 끝낼 때 쓰라고 한 것입니다. 오타 수정 한 건이면 보통 필요하지 않습니다.
- `pace backlog refresh`는 백로그나 프로젝트 원본 문서를 직접 편집했을 때만 실행합니다. 이번 작업은 해당하지 않습니다.
- 사용자에게는 고친 위치(`파일:줄`), 전과 후 문구, 검사 결과를 짧게 알립니다. 검사가 실패하면 출력을 그대로 보고합니다.

**멈춤과 승인**
- 질문 0건, 승인 대기 0건입니다. 범위와 기준이 명확해서 A 조건(§6)에 걸리지 않습니다.
- merge나 배포 단계가 없어서 ✋ 승인 게이트도 없습니다.
- 경계: 도움말 오타가 아니라 명령 동작이나 옵션 이름까지 바꿔야 하는 일이라면 작은 일이 아닙니다. 그 경우에는 규모를 다시 판단합니다.
