# 읽은 범위와 자동 첨부

- **자동 첨부**: 시스템 알림으로 사용자 계정 식별 정보가 자동 첨부됐습니다. 값은 적지 않으며 사용하지 않았습니다.
- **읽은 파일**
  - `skills/pace-project-dev/SKILL.md` 1–93줄(전체)
  - `references/decision-rights.md` 1–46줄(전체)
  - `references/verification.md` 1–19줄(전체)
- **읽지 않은 파일**: `commands.md`와 `reviewer.md`는 열지 않았습니다. `pace project log`의 정확한 형식은 확인하지 못했습니다.
- **전체 바이트**: 도구로 확인하지 않았으므로 적지 않습니다.
- **근거**: `decision-rights.md` B-4는 허브 회신, 워크트리 적용, 재검증을 한 번의 공동 시도로 셉니다. 상한은 2회이고 둘 다 실패했으므로 상한에 도달했습니다. 추가 시도는 하지 않습니다.

# 옵션 1: 선택 태스크 보류, 독립 태스크 남음

- **담당**: 워크트리 PM이 실행합니다. 허브는 사후 요약을 owner에게 전달합니다.
- **판정**: A-1에 해당하지 않습니다. 계약에 명시된 선택 태스크의 보류는 합의를 바꾸지 않기 때문입니다. PM이 결정하며 owner의 승인은 기다리지 않습니다.
- **기록**
  - 보류 근거와 공동 시도 2회의 결과를 이슈로 남깁니다.
  - 태스크 표 상태를 `보류`로 바꿉니다.
  - `pace project log`에 허브 회신을 "(main 판단)"으로 적고, 보류 결정과 근거도 함께 적습니다.
  - `pace memory status --project --body "<어디까지 · 다음 할 일 · 막힌 것>"`으로 진행 상황을 갱신합니다.
- **다음 행동**
  - 독립 태스크의 `대기` 중 맨 앞부터 계속 진행합니다.
  - 같은 장애를 세 번째로 재시도하지 않습니다.
  - 도구 수정, 환경 복구, 새 결정 증거가 생기면 보류 태스크를 재개합니다.
- **회신·보고**: 사후 요약에 "선택 태스크 보류, 결과 한 줄"을 담아 다음 대화나 완료 보고에 붙입니다. 원장을 쓰면 `status`로 보냅니다.
- **질문·승인 대기**: 0건입니다.

# 옵션 2: 필수 태스크 보류, 필수 결과 없이 마감

- **담당**: 워크트리 PM이 `ask`로 허브에 인계하고, 허브가 owner에게 요청을 보냅니다.
- **판정**: A-1에 해당합니다. 필수 태스크 보류와 기준 미달 마감은 합의 변경입니다.
- **보류할 조치**
  - 필수 결과 없는 마감인 `done`, `finish`, PROJECT-CLOSE 확정을 모두 보류합니다.
  - 목표 미달·미확인을 게이트 통과로 덮지 않습니다.
  - `waiver`나 `review-note --by user`도 owner 원문 없이 입력하지 않습니다.
- **요청 내용**: 항목 번호 A-1, 대상(필수 태스크와 영향받는 `P-n`), 근거(공동 시도 2회의 실패 증거), 선택지, 추천과 이유를 담습니다. 선택지 예시는 다음과 같습니다.
  - 기준·범위를 변경하고 합의한 뒤 마감
  - 원인이 풀릴 때까지 대기
- **계속할 일**: 이 필수 태스크에 의존하지 않는 독립 작업은 이어갑니다. `pace memory status --project`에 막힌 이유를 기록합니다.
- **owner 회신 뒤**: 회신 원문과 출처를 근거로 연결합니다. 바뀐 계약이나 요건에 맞춰 다시 판정하며, 보완 관측이 필요하면 그것을 먼저 합니다.
- **질문·승인 대기**: 1건(A-1)입니다.

# 두 옵션의 차이

| 구분 | 옵션 1 | 옵션 2 |
|---|---|---|
| 판정 | 이슈 기록 후 PM이 결정 | A-1, owner 결정 필요 |
| 질문·승인 대기 | 0건 | 1건 |
| 마감·finish | 독립 태스크 계속 | 해당 조치 보류 |
| owner 보고 | 사후 요약 | 결정 요청 |
