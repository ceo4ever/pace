# 행동 평가 실행 근거

작성자는 Codex/OpenAI다. 사례 실행은 `pace agent run --agent claude --mode p --model sonnet --effort medium --prompt-file <프롬프트> --raw-dir <로컬 경로>`로 호출했고, 응답에서 Claude Sonnet 5.5/Anthropic을 보고했다. 사례마다 새 맥락이며 역할을 왕복하는 D01·D02도 별개 호출이다. S6는 이름과 설명만 사용했다. S7 기준선은 한 응답에 독립 하위 사례를 모두 받았다. 이후 S7-A~J는 하위 사례별 새 세션으로 분리했다.

격리된 PACE_HOME과 Claude 안전 모드·세션 비저장을 사용했다. 호출 작업 폴더에는 검증할 스킬·참조만 복사했고 테스트 기준표·프로젝트·백로그·이전 응답은 복사하지 않았다. 응답에서 계정 맥락의 자동 첨부가 관측됐다. 커밋하는 응답 한 건의 첨부 계정 값만 가렸고, 그 원문과 전체 호스트 스트림은 로컬 권한 제한 자료에 보존했다. 답변은 앞으로 할 행동의 서술이다.

`snapshot.json`은 입력 스킬 파일의 바이트와 SHA-256을 직접 측정한 값이다. 읽은 줄은 모델 응답의 자체 보고를 유지했다. `rubric.sha256`은 사례와 필수·금지 행동을 실행 전 고정한 기준표의 지문이다. 기준선은 착수 커밋의 기존 기준표를 사용했다. 각 사례 하위 폴더의 `prompt.txt`·`response.md`·`result.json`은 실제 입력·응답·관측 실행 결과다.

| 차수 | 범위와 변경 |
|---|---|
| before | 원래 스킬에서 S1~S7 실행. 초기 비교용 원응답 보존. |
| after-01 | 변경 후 S1~S7과 D01~D15 전체 실행. 메모리 갱신과 커밋만 미루는 차이를 명확히 하고, 필수 검사 생략안의 결정 주체를 답하도록 상황을 분명히 했다. 여분의 `ID`는 표 머리의 오해석으로 발생한 실행이며 판정 대상 사례가 아니다. |
| after-02 | S7 하위 사례 분리. 중단 이력만 있는 normal 단계에서 전체 검토가 열리는 경계를 명확히 했다. |
| after-03 | 전체 사례 실행과 독립 채점. 내부 선택·선택 태스크 보류의 사후 요약과 병합 대기 중 우회, normal 단계에서 실제 데이터 전송이 필요한 수정의 처리에 보완이 필요했다. |
| after-04 | 사후 요약과 병합 대기 우회, 진단 직후 normal에서 전체 검토를 먼저 하는 경계를 명시했다. 독립 입력이 부족한 S7 하위 사례에 상황을 완결해 전체를 다시 실행했다. |
| after-05 | 합의된 대상 환경에 다른 환경의 설계를 적용한 원인을 design으로 판별하도록 명확히 했다. B1 범위를 기존 태스크의 구현 전·후 및 백로그 검토로 명시하고 전체를 재실행했다. 결정 권한 15건, 기존 회귀 17건이 독립 채점에서 통과했다. |

합성 시나리오는 실제 사람 승인 증명과 별개이며 실제 Orca 왕복은 병합 후 인수의 관측 대상이다.
