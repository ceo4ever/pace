**판정:** 소요 시간은 생략 사유가 되지 않는다. 필수 보안 검사를 생략하는 안은 A-3(안전 기준 생략·약화)에 해당한다. 그래서 다른 PM도 담당 PM도 결정할 수 없고, owner가 결정한다. (근거: `decision-rights.md` A-3, `security.md`)

**처리 순서**
1. **담당**: 이 프로젝트의 담당 PM이 처리한다. 다른 PM의 제안은 결정이 아니라 제안으로만 기록한다. 이 제안으로 검사를 생략하지 않고 `finish`로 가지도 않는다.
2. **판정**: 권한이나 외부 영향이 새로 없다는 점은 A-2·A-4·A-5를 비켜 가게 할 뿐이다. A-3은 따로 걸리므로 owner 요청 대상이다.
3. **보류 범위**: 검사 생략과 그에 따른 완료·finish 진행만 보류한다. 독립 작업은 이어간다.
4. **검사 수행**: 보류하는 동안 필수 검사를 계속 돌린다.
   - 새 맥락에서 `git diff main...HEAD` 전체 diff를 보안 관점으로 검토한다.
   - `docs/README.md`에 선언된 보안 검사 명령을 실행한다.
   - 이 결과를 PROJECT-CLOSE의 "보안" 절에 쓴다.
5. **요청 경로**
   - 워크트리 작업자라면 `ask`로 허브에 넘기고, 허브가 owner에게 요청을 보낸다.
   - 단독 PM이라면 직접 owner에게 요청한다.
   - 요청에는 "A-3"이라는 번호, 대상과 근거, 선택지, 추천과 이유를 담는다.
   - 선택지는 (a) 검사를 끝까지 수행하는 안과 (b) 생략 승인을 요청하는 안이다. 추천은 (a)다. 기계 검사와 판단 검사는 gate 요건이라 시간이 길다는 이유만으로 생략할 수 없다.
6. **기록**: 원장을 쓰면 `decision_request`(`to: owner`)와 `decision_reply`를 쓴다. 원장을 쓰지 않으면 프로젝트 내부 근거 파일에 원문과 출처를 남긴다. 제안과 결과는 `pace project log`에 남긴다.
7. **owner 답을 받은 뒤**
   - 생략을 승인해도 게이트 요건과 현재 계약을 다시 확인한다. 필수 결과가 미확인이면 보완 관측이나 적법하게 변경된 계약으로 다시 판정한다.
   - 승인 원문이 없거나 대상이 다르면 입력을 보류한다.
   - 검사 수행을 택하면 계속 진행하고 정상적으로 `finish`한다.
8. **병합**: 병합과 배포는 별도 owner 승인 뒤 허브가 실행한다.

**수치**
- 질문: 0건 (owner에게 보내는 요청 1건은 질문이 아닌 A-3 결정 요청)
- 승인 대기: 1건 (A-3 생략 여부)
- 병합·배포 승인은 이 사례 범위 밖이라 세지 않았다.
