이 시험은 읽기 전용이라 실제 명령은 하나도 실행하지 않았다. 아래는 사용자가 E′에서 고른 선택지별로 할 일의 순서다.

**전제:** 세 선택지 모두 사용자의 결정이다. 이 결정은 A 항목(A-3 안전 기준, 남은 blocking을 안고 진행하는 조치)에 해당하므로 PM이 대신 내릴 수 없다. 그래서 "사용자 승인 원문"이 먼저 있어야 한다. 원문이 없거나 조건·대상이 다르면 입력을 보류하고 허브를 거쳐 질문한다. 이번 사례는 사용자가 이미 선택했으므로 추가 질문은 0개다. 단, 아래 대조에서 불일치가 나오면 그때만 1개를 허브에 올린다.

## ① 고치고 다시 검토
- **담당:** 워크트리 PM이 기록하고 수정한다. 재검토는 `pace agent verify`로 받는 별도 reviewer가 한다. 호스트 reviewer는 원장에 남지 않으므로 쓰지 않는다.
- **순서:**
  1. 사용자 답 원문과 현재 대상(TASK 해시)을 대조한다.
  2. `pace agent review-note --target <대상> --decision --by user --choice <선택> --summary <사유> --file <승인 근거 영수증>`으로 user decision을 기록한다.
  3. 수정 직전에 영향을 분류한다. 합의된 목적·기준·범위를 바꾸는 수정이면 A-1로 먼저 올리고, 아니면 PM이 수정한다.
  4. 수정한다.
  5. `pace agent verify`를 다시 호출해 이전 지적으로 범위를 좁히지 않는 **전체 검토**를 받는다.
- **대기:** 승인 대기 0개. 새 위험이 나오면 수정 전에 다시 분류한다.

## ② 고치고 구현 진행 (사전 검토)
- **담당:** 워크트리 PM이 한다. `waiver`의 `by: user`는 PM이 입력하지만, 승인 주체는 사용자다.
- **순서:**
  1. 사용자 decision을 기록한다(①과 같은 명령).
  2. 수정한다.
  3. 고친 뒤 TASK 해시를 Node 명령으로 계산한다. 그 해시가 사용자가 승인한 대상인지 확인한다.
  4. 해시가 승인 대상과 같을 때만 `PRE-REVIEW.json` 최상위에 `waiver`를 추가한다. 내용은 `{by:"user", date:"2026-11-25", reason, evidence:"evidence/<승인 근거>.md", hash:<고친 뒤 해시>}`다.
  5. 기존 시도 이력은 그대로 둔다.
  6. 구현 단계로 진행한다.
- **주의:** 해시가 승인 대상과 다르면 waiver를 입력하지 않고 보류한다. TASK가 더 바뀌면 waiver는 무효가 되어 다시 검토받는다. 마커 제거나 pass 위장은 하지 않는다.
- **대기:** 승인 대기 0개(해시가 다르면 1개).

## ③ 이슈로 남기고 마감 (구현 후)
- **담당:** 워크트리 PM이 한다. waiver는 구현 후 검토에는 쓰지 않는다.
- **순서:**
  1. user decision과 원문을 TASK-CLOSE 리뷰 절에 연결한다.
  2. 남은 blocking을 TASK-CLOSE의 이슈·"남긴 것"에 기록한다.
  3. 반복된 것, 고친 층, 채우거나 덜어낸 것, 재검증 결과를 담은 사후 보고를 쓴다.
  4. 계약 목표 달성 여부를 goal-review로 판정한다.
- **분기:**
  - 목표가 **미달·미확인**이면 done하지 않고 `판정: 막힘`으로 둔다. 보완을 요청하거나 A-1로 올린다.
  - 목표가 **달성**이면 `pace project check P### T0n`, `pace project done P### T0n`을 차례로 실행한다. 이어서 `pace memory status --project --body …`로 진행 상황을 갱신하고 `feat(P###/T0n): …` 커밋(TASK-CLOSE·상태·메모리 같은 커밋)을 만든다.
- **대기:** 승인 대기 0개. push·merge는 하지 않고 finish 뒤 허브에 넘긴다.

## 공통 경계
- 사용자의 결정을 PM이나 자동 검사가 대신하지 않는다.
- 승인 전 수정 여부를 커밋 시각만으로 주장하지 않는다. 승인 직전 해시와 승인 뒤 첫 수정 기록을 연결한다.
- 병합·배포·푸시는 하지 않는다.
