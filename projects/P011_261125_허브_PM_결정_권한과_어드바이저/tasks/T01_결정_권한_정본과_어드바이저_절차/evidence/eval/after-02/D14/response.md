**사례: 하네스 도구의 작은 결함. 허브가 재현했고, AGENTS.md가 작은 수정 main 커밋과 main 설치를 위임했으며, 병합 대기 프로젝트는 없다.**

**판정 근거**
- SKILL §6과 decision-rights A-2에 따르면, 하네스 장애를 푸는 작은 도구 수정을 허브가 main에서 고치고 커밋하며 필요하면 재설치하는 것은 이미 위임된 조치다. 따라서 A-2는 "아니오"다.
- A-1은 아니오다. 목적·기준·범위가 바뀌지 않는다.
- A-3은 아니오다. 검사나 검토를 생략하거나 약화하지 않는다.
- A-4는 아니오다. 새 권한이나 새 비용이 없다.
- A-5는 아니오다. 사람만 할 수 있는 확인이 필요하지 않다.
- 병합 대기 프로젝트가 없으므로 "main 커밋은 병합 뒤로 미룬다"는 보류 조건(§4 ✋)이 걸리지 않는다. 지금 바로 커밋할 수 있다.

**담당과 순서**
1. **담당: 허브 PM.** 작업자에게 넘기지 않고, 프로젝트도 만들지 않는다. §1의 "작은 일"에 해당하며 diff를 한 문장으로 말할 수 있다.
2. 허브가 main에서 결함 파일을 고친다. 버그이므로 실패하는 테스트(RED)를 먼저 둔다. 수정하는 경로의 기준 문서는 standards.md에서 고른다.
3. 저장소 검사 명령을 실행해 통과를 확인한다. 실제 명령은 저장소의 검사 정의에서 찾는다. 이 작업 디렉터리에서는 AGENTS.md가 Glob으로 검색되지 않았다. 그래서 검사 명령과 설치 명령의 정확한 문자열은 확정하지 못했고, 추측해서 적지 않는다.
4. main에 커밋한다. 메시지는 도구 수정이 드러나게 쓰고 `P###` 접두사는 쓰지 않는다.
5. AGENTS.md가 정한 main 설치 명령으로 재설치한다. 설치 뒤 원래 재현 조건을 다시 돌려 해결을 확인한다.
6. 원인과 해결 결과를 `pace project log`에 "(main 판단)"으로 기록한다. 작업자가 있으면 결정, 근거, 재검증 기준을 회신하고, 작업자는 적용 뒤 재검증해 태스크를 재개한다. 장애가 풀렸으므로 보류된 태스크가 있으면 재개한다.
7. 진행 상태는 `pace memory status --project --body "…"`로 남긴다. 사후 요약은 다음 대화나 완료 보고에 한 줄로 붙인다.
8. 백로그나 프로젝트 원본 문서를 직접 고쳤다면 커밋 전에 `pace backlog refresh`를 실행한다. 고치지 않았다면 필요 없다.

**하지 않을 것**
- 푸시, 병합, 배포는 하지 않는다. 위임 범위 밖이므로 필요해지면 별도 승인을 받는다.
- worktree 파일을 main에서 절대 경로로 고치지 않는다.

**질문과 승인 대기: 0건.** 요청할 owner 결정이 없고, 승인을 기다리는 단계도 없다.
