**판정: 작은 일** (SKILL.md §1). 오타 한 글자라서 diff를 한 문장으로 말할 수 있다. 그래서 프로젝트, 태스크, `pace project new/start`, 백로그, 코디네이터 없이 바로 고친다.

## 할 일의 순서

1. **위치 찾기**: `Grep`으로 `memory list` 도움말 문자열을 찾는다. 오타가 어느 단어인지 확인하고, 같은 문자열이 테스트나 문서에 있는지도 본다.
2. **기준 확인**: 주변 코드 스타일과 `AGENTS.md`를 따른다. 이번 변경은 도움말 문구 한 글자라 교본이나 보안 문서는 필요 없다.
3. **수정**: `Edit`으로 한 글자만 고친다. 같은 오타가 테스트 기대값이나 문서에 있으면 함께 맞춘다.
4. **검증**: 저장소의 검사 명령을 실행한다. 가능하면 `pace memory list --help` 출력도 확인한다.
5. **커밋**: 검사가 통과하면 커밋한다. 메시지는 예를 들어 `fix: memory list 도움말 오타 수정`이다. 이 세션은 `git`이 없는 디렉터리라 실제 커밋은 불가능하다. 저장소 안에서 할 때만 해당한다.
6. **마무리**: 위 5단계로 끝난다. 프로젝트 문서가 없으므로 `pace backlog refresh`와 `pace memory status`는 필요 없다.

## 담당, 기록, 대기

- **담당**: 이 세션의 에이전트 한 명이 전부 한다. reviewer나 tester 배정은 없다.
- **기록**: `pace project log`나 PROJECT 문서 기록은 없다. 커밋 메시지만 남긴다.
- **질문**: 0건.
- **승인 대기**: 0건. 병합과 배포가 없고 A 조건(기준이나 범위 변경)에도 걸리지 않는다.
- **경계**: 오타 수정을 넘어 도움말 구조나 동작을 바꾸고 싶어지면 멈추고 규모를 다시 판단한다.
