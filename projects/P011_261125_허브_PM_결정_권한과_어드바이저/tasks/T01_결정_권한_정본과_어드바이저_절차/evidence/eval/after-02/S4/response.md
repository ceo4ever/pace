**사례: main 세션, P031 `병합 대기`, 사용자 요청 "진행 상황 메모리 갱신해 줘"**

**담당**
- 메모리 갱신은 main 세션이 직접 맡는다. 근거는 SKILL §7과 §4의 ✋ 항목이다.
- worktree 작업자나 허브에 넘기지 않는다.
- merge는 허브의 일이다. 이번 요청에는 merge가 포함되지 않는다.

**순서**
1. `pace project list`로 P031과 태스크의 현재 상태를 확인한다. 진행 상태의 원본은 PROJECT.md 태스크 표다. 읽기 전용이다.
2. `pace memory status --project --body "<어디까지: P031 finish 통과, 병합 대기 · 다음 할 일: 허브의 owner 승인 확인 후 merge, 이후 완료 기록 확인 · 막힌 것: owner 병합 승인 대기>"`를 실행한다. 메모리 파일 갱신은 병합 대기 중에도 허용된다.
3. **커밋하지 않는다.** 병합 대기 중 main 커밋은 병합 뒤로 미룬다. 갱신된 `.pace/` 파일은 워킹트리에 uncommitted로 남기고, 병합 뒤 커밋할 항목으로 사용자에게 알린다.
4. 사용자에게는 "메모리 갱신함, 커밋은 병합 뒤로 보류"라고 보고한다.

**하지 않는 것**
- `pace project merge`와 `--yes`는 실행하지 않는다. owner 승인 원문 대조가 선행돼야 한다.
- 배포는 하지 않는다.
- worktree 파일은 절대 경로로 고치지 않는다.
- B의 도구 수정 커밋도 하지 않는다.
- 백로그나 PROJECT.md 원본은 편집하지 않는다. 편집했다면 커밋 전에 `pace backlog refresh`가 필요하지만, 이번에는 해당이 없다.

**수치**
- 질문: 0개
- 승인 대기: 0개. 메모리 갱신은 A 항목에 걸리지 않는다. 병합 승인은 별개의 후속 건이다.
- 실제 명령: `pace project list`, `pace memory status --project --body ...`
- 커밋: 0개
