# T06 독립 검토에서 확인한 경계

| 관측 | 적용 |
|---|---|
| 같은 ID를 둔 채 구현 후 기준 문구가 달라져도, 최초 구현은 이전 기준의 응답을 셌다. | 넘길 때 기준 ID와 내용의 지문을 기록한다. 제출 시 현재 기준 및 원래 대상·직전 검토를 비교하고 바뀌었으면 원문만 보존한다. |
| 자동 생성이 현재 조건과 맞지 않는 사용자 결정을 지웠다. | 결정 원문을 `inactive_waiver`에 보존한다. 실제 사용자·근거·최신 실패와 현재 지문에 모두 맞을 때 활성 기록으로 유지한다. |
| 두 상한이 한 번에 닿는 시험은 호출 한도 변경만으로 실패하지 않았다. | 판정 없이 4회 고정하는 별도 반례를 추가했다. 다른 단계에서 열린 상위 조치는 원래 단계의 판정이 1회인 상태로 확인한다. |
| 원문은 기록됐으나 마지막 원장 행이 누락되는 중단과 오래된 결과는 별도 검증이 필요했다. | 복구도 실제 고정 원문의 예약 지문·대상·스냅숏과 형식을 맞춘다. 완전한 판정, stale, 변조 및 pending 중단을 비교했다. |
| 처음 미확인 근거와 T05의 허용 줄 diff가 외부 검토에도 필요하다. | 두 호출 모두 같은 증거를 프롬프트로 넘긴다. 구현 후 기준과 허용 수정의 실제 입력을 시험에서 확인했다. |
| 외부 출처는 원래부터 입력자가 확인하는 정보다. | 판정 원문과 PRE에 외부 제출 출처를 표시한다. 실제 독립 검토와 작성자 확인은 합의된 BR06과 기존 수기 절차의 책임을 적용한다. |
| 옛 동일 제공자 대체 기록에 교차 제공자가 드러나지 않을 수 있다. | 보존된 교차 미실행 정보가 있을 때만 생성한다. 기존 두 실행기의 기록은 해당 교차 제공자를 사용하며 다른 옛 제공자의 이유·정체를 추정하지 않는다. |

P013 자체의 실제 독립 검토는 PROJECT.md의 기존 main 판단에 따라 최초 기준 실행본을 사용했다. 이 브랜치의 새 예산·구조화·외부 입구는 실제 작업본 CLI와 임시 저장소 시험으로 증명했다.
