# T02 상위 근본 검토와 분할

2026-11-26 허브 전달 독립 검토 요약 원문이다.

- 주원인은 계약의 상태 조합 폭발(허가 유형 7종 × 국면·단계 × B1)과 태스크 도중 허브 해석이 계약에 누적된 것. 함수 통합은 이미 됐으나 입력이 여러 곳에서 따로 만들어져 틈이 계속 난다.
- 순서 문제: 판정 질문·범위 밖 지적 하향(BR03·T03)보다 BR02를 먼저 해 T02가 상한 없는 옛 방식으로 자기 검토를 받고 있다.

허브는 T02a에서 일반 예산과 공동 시도, 소진 보고, 실제 A-3 요청 및 승인 회차만 다루도록 결정했다. B1은 시도에 교차 미실행 사유와 함께 기록한다. T02b를 T03 뒤에 배치해 한정 수정 확인과 진단 문턱, 재실패의 상위 검토를 다룬다.

## T02b 설계 입력

- 원장 진단과 수정 확인 진단을 같은 진단 기록으로 통합한다. 진단 후 독립 실패에서 `upper_review`가 기존 `ask_user` 자리를 잇는다. owner에게는 근본 검토 결과가 A-1 합의 변경이나 A-3에 해당할 때 요청한다.
- 상위 근본 검토는 공동 시도나 총 상한에 세지 않는다. 근본 검토 결과로 계약이 실제 변경되면 해당 계약의 예산을 새로 시작한다.
- 작성자가 아닌 새 맥락 독립 검토자가 맡는다. 전문가 호출 연결은 BL261125_01 BR02가 맡는다.

## T02b 인수 정합

단계 예산(1+1) → 공동 시도(단위 합산 2회) → 수정 확인(지적당 1회·단위 2회와 사후 보고) → 문턱의 허브 진단 → 수정 확인 1회 → 실패 시 `upper_review` 순서다. 상위 검토는 상한에 닿아도 발동하며 공동 시도·호출 상한에 세지 않는다. 계약이 바뀌면 단계 일반 예산만 다시 시작하고 공동 시도·수정 확인 합산은 유지한다. 전문가 자동 호출 절차 연결은 BL261125_01 BR04를 따른다. 상한 도달 뒤 상위 검토 인수 사례를 시험한다. BR09는 P013 작업본에서 관리한다.

## T09 상위 검토 종료점

허브 공동 시도 1의 결정이다. 첫 `upper_review` 해결안을 적용해 독립 재검증 1회를 수행하고 사후 보고한다. 실패하면 두 번째 새 맥락 상위 검토가 계약·백로그 자체를 대조하고 독립 재검증 1회를 수행한다. 여전히 실패하면 A-1에서 조정·보류를 요청한다. 상위 검토와 후속 확인은 공동·수정 확인 누적에 넣지 않는다.
