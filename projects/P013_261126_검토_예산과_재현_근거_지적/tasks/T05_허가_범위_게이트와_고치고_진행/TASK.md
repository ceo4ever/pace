## 목적

통과가 허용하는 검토 대상과 변경 범위를 고정하고 check·done·commit-msg에서 같은 기준을 적용한다. 승인된 위치의 작은 지적 반영은 허가 범위와 통과 근거를 지킬 때 계속 진행하며 실제 diff를 다음 검토의 증거로 남긴다.

## 재료

- BR05의 허가 범위와 허용되는 사후 수정, T03 구조화 지적 위치, T04 관측 기준과 옛 기록 호환.
- 프로젝트 check·done·commit-msg와 PRE-REVIEW 기록·후보 Git 읽기. [민감 경로](../../../../docs/SECURITY.md)
- BL261118_02 BR04와 겹치는 해시·세션 기록 관문. T06은 이번 형식을 그대로 기록한다.

## 증명 범위

- 판정 주체: 고정 검토 기록과 Git의 실제 후보 파일·diff를 비교하는 도구, 임시 저장소 시험과 보안 reviewer·tester. 검토 권한과 원문의 진위는 사람·독립 검토가 확인한다.
- 포함: 통과의 대상 해시·허가 범위·근거/허용 위치, 누락·과거 기록과 실제 파일·줄 범위 대조, check·done·commit-msg 후보, 허용 diff와 다음 검토 입력, 보안 검사.
- 범위 밖: 외부 검토 저장과 PRE-REVIEW 자동 생성은 T06, 스킬·정본 문서의 전반 정리는 T08, OS 파일 쓰기 제한은 BL261124_02에서 다룬다.

## 기준

| # | 완료 기준 |
|---|---|
| T-1 | 새 pass를 검토 대상 지문과 도구가 기록한 Git 기준 커밋에 묶는다. 기계 판정 허가의 수준은 탐침(probe) 또는 구현(implementation)이며 정규화한 경로와 보호 줄을 함께 기록한다. 알 수 없는 수준·자유 문구·잘못된 경로는 범위 재검토를 요구한다. 허가 입력을 실제 원장·PRE-REVIEW에서 같은 입력으로 확인한다. 검토 기록의 해시가 확인된 원문 스냅숏으로 근거 위치와 should_fix·note 허용 위치의 원래 줄을 대조한다. 수동 전사는 독립 원장과 일치해야 한다. |
| T-2 | 탐침 범위 등으로 한정된 pass에서 범위를 넘은 코드 변경은 check·done·실제 commit-msg가 모두 거부한다. 게이트가 검사하는 실제 index·Git 후보·작업본과 허가 시점의 기준 커밋을 구별하고 중간 커밋도 범위에 포함한다. 그 결과가 불일치·경로 오류·링크·검사 실패에서 상태를 전진시키지 않는다. 기존 사용자 훅은 보존한다. |
| T-3 | 최신 pass의 보호 위치·허가 범위를 건드리지 않고 실제 변경 줄이 허용된 should_fix·note 안에 모두 들어 있으면 현재 지문이 달라도 진행한다. 허용된 실제 diff와 원래·현재 지문을 다음 구현 후 검토의 입력으로 보존한다. |
| T-4 | 승인 해시가 다르거나 위치 밖·통과 근거·허가 범위 변경이 있거나 대조할 수 없으면 BR01 예산으로 범위 재검토를 요구한다. 일반 파일의 줄 대조가 없는 rename·mode 변경·링크·binary·추가/삭제는 작은 수정으로 처리하지 않는다. 보호와 허용 위치가 겹치면 보호가 우선한다. 이전 허가 필드 없는 PRE-REVIEW의 기존 게이트와 승인 원문 조건을 보존한다. |
| T-5 | 부정 경로의 이전 구현 실패와 새 구현 통과, 임시 저장소·실제 커밋 훅, 독립 tester·보안 reviewer, 선언 전체 및 보안 검사를 통과한다. 기존 pre-review·project-dev-skill·project-role 회귀를 유지하며 BL261118_02 BR04에 형식 연결을 기록한다. |

## 접근

- 검토된 기준과 허가 범위를 원장과 승인 기록으로 한 번 표현한다. 정상 게이트와 Git 후보 모두 같은 경로·해시·범위를 검증한다.
- diff의 실제 변경 줄과 보호/허용 위치를 원문 기준으로 대조한다. 비교할 수 없는 상태는 범위 재검토 요청을 보낸다.
- 민감 경로의 보안 관점을 먼저 검토한다. 테스트는 검토/허가 자료, 실제 index/candidate, 링크와 파일 권한의 실패 조건을 증거로 보존한다.
