# T05 독립 검토 지적과 대응

| 검토 근거 | 관측 | 적용 |
|---|---|---|
| 다른 제공자 보안 1차 | 새 도구가 모든 사전 시도에 허가 형식 표지를 기록해 기존 owner 예외가 막혔다. | 최신 실행 fail의 원장·원문과 현재 TASK 해시의 사용자 예외를 대조한다. 승인 근거의 진위는 입력자가 확인한다. 앞선 독립 pass가 기록한 Git 허가를 함께 적용하며, 더 넓은 범위는 기존 검토 예산에서 새 pass를 확인한다. |
| 다른 제공자 보안 1차 | 허가 필드 수동 누락의 다음 행동과 원장의 필드가 빠졌을 때의 판정이 부족했다. | 도구는 원문 기록의 별도 허가 표지도 확인한다. 사본이 빠지면 최신 결과의 `review.permission`을 옮길 위치를 알려 준다. T06이 생성으로 연결한다. |
| 다른 제공자 보안 재검증 | 앞선 탐침 경계를 유지하는 사용자 예외의 범위 재검토 안내가 필요했다. | 범위 오류에 적용되는 기존 허가와 범위 재검토를 명시한다. 최신 판정이 미확인이면 보완 관측을 안내한다. |
| 최초 tester 세션 | 읽기 전용 실행에서 셸 도구가 노출되지 않았고, 후속 Anthropic 실행에서도 시험 명령에 승인이 필요해 실행되지 않았다. | 실행이 가능한 격리 Codex 세션에서 같은 대상의 실제 시험을 회수했다. 첫 두 응답은 시험 실행 근거로 집계하지 않았다. |
| 최초 정적 tester | 독립 검증 세션 기록 BR04에서 기존 사전 허가와 새 구현 후 검증을 구별할 필요가 있었다. | BR04는 커밋 훅의 기존 사전 TASK 허가 및 done·finish의 새 구현 후 reviewer·tester 기록을 구별한다. |

작업본과 index의 순변경 및 기준 커밋 이후 완료 커밋까지의 변경을 비교한다. 작은 수정은 원문에 줄 위치가 있는 교체 hunk로 제한한다. 불완전하거나 모호한 줄은 통상 예산의 범위 재검토로 보낸다. 이 관문은 저장소에 기록된 원문과 Git 후보의 불일치를 찾는다. 검토 독립성과 사용자 결정 원문의 진위는 작업자가 확인한다.
