# T05 보안과 관측 기준

- 민감 경로인 check·done·commit-msg의 판정 입력만 바꾼다. 기존 훅 설치·사용자 훅 보존·외부 행동은 기존 절차를 따른다. 이 변경은 Git과 기록에 남은 허가를 대조하는 도구 관문이며 독립성, 원문의 진위와 OS 쓰기 권한은 별도다.
- 검토 시 Git 기준 커밋, 검토 대상 해시, probe 또는 implementation, 허용 저장소 상대 경로 목록, 통과의 보호 줄 범위를 연결한다. probe는 허가 목록의 정확한 일반 파일 경로만 허용한다. 구현 수준에 명시 경로가 있으면 같은 목록을 적용한다.
- check·done은 실제 작업본과 index의 순변경을 확인한다. commit-msg는 Git이 넘긴 실제 index를 읽으며 finish는 후보 커밋을 읽는다. 기준 커밋은 후보의 조상이어야 하고 중간 커밋의 남은 변경을 차감할 수 없다. 실패하면 TASK·PROJECT·BACKLOG·근거 및 HEAD·브랜치가 전진하지 않는다.
- 새 허가가 있는 원장의 PRE 필드 탈락·불일치, 경로 역행·외부·링크·대소문자, 모드 변경과 꼬인 줄 범위, 정본 및 보호 위치 변경을 반례로 확인한다. 중간 커밋·작업본과 index의 양방향 반례, 사용자 훅의 실제 성공·거부, 기준 지문과 승인 텍스트의 변경을 임시 저장소에서 비교한다.
