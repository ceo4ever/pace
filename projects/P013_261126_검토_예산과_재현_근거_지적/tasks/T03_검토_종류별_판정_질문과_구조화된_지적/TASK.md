## 목적

검토 종류마다 판정 질문을 하나로 고정하고 구조화된 지적의 유효 blocking에서 판정을 계산한다. 판정 질문 밖의 설계·구현 지적은 맡을 단계로 보내고, 항목별 위치·실패 시나리오·재현이 관문에 들어갈 조건을 입증한다.

## 재료

- P013의 현재 프로젝트 기준, BR03와 owner의 Q1·Q2 원문
- T01의 단위·검토 단계와 원장, T02a의 단계 예산·공동 시도·owner 결정 및 B1 기록
- verify 프롬프트와 기록, reviewer·tester·cross-verify 정본

## 증명 범위

- 판정 주체: 가짜 실행기의 명령 경로, 원장 스냅숏·판정, 다른 제공자의 실제 응답, 독립 tester·reviewer. 구조 판독은 재현 주장의 진실성까지 자동 확인하지 않는다.
- 포함: 검토 단계별 질문과 응답 스키마, 판정 계산·강등·차이 기록, 판정 없는 출력, 이전 기록과 T02a 후속 시도의 호환, 문서 및 문구 시험.
- 범위 밖: 증거 상태·영향 문턱과 안전 예외는 T04, 허가 범위는 T05, 외부 검토 기록 및 자동 사전 기록은 T06.

## 기준

| # | 완료 기준 |
|---|---|
| T-1 | 백로그, 태스크 사전, 구현 후 프롬프트에는 해당 단계 고유 판정 질문과 하위 확인만 표시된다. tester 질문은 문서에서 독립적으로 고정한다. 관리 단위 밖의 기존 목표 대조는 유지한다. |
| T-2 | 구조화된 지적은 ID·등급·판정 질문과의 연결·위치·실패 시나리오·재현·확신도를 보존한다. 질문 밖 지적을 note로 보내며 사전 구현 및 백로그 설계·구현의 인계가 표시된다. 연결된 지적의 재현 정보가 빠졌으면 should_fix다. |
| T-3 | 판정은 구조화 결과의 blocking으로 결정된다. 검토자의 마지막 단어와 차이를 보존하고 판독 불가·모순된 구조는 unknown으로 기록한다. 원장·재검토·고아 복구는 같은 근거와 기계 판정을 읽는다. |
| T-4 | 옛 원장·관리 밖 검토와 T02a 공동·승인 회차를 유지한다. 질문별 최종 판정은 같은 예산·원장에 귀속되고 B1의 조사 사유를 계속 보존한다. 수정 확인의 연결은 T09가 맡는다. |
| T-5 | 실제 다른 제공자 응답과 도구 판정을 별개로 보존하고, 명령 집중 시험과 선언된 전체 검사를 통과한다. |

## 접근

- T01 단계 값을 판정 질문의 키로 재사용한다. 새 JSON 응답의 형식·근거를 해석하는 변환을 한 곳에 두어 명령 경로와 복구가 같은 판정으로 수렴한다.
- 판정 질문과 무관한 지적을 방어적으로 낮추되 원래 등급을 보존한다. 파싱되지 않은 결과는 검토 완료로 사용하지 않는다. 기존 기록은 명시된 새 형식으로 재판정하지 않는다.
- T02a 원장과 직전 판정에서 고친 범위를 유지한다. 형식이 바뀐 원장은 기계가 유효하다고 남긴 지적과 원래 출력 양쪽을 다음 검토에 연결한다.
