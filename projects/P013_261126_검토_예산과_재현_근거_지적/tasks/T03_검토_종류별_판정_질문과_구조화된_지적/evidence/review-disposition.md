# T03 사전 검토 처리

- 질문 밖의 명시된 유형은 note다. 빠지거나 잘못된 하위 확인 ID는 판정 미확인으로 기록하고 호출 수만 사용한다.
- 구현·설계 인계와 유효 blocking의 판정은 독립 입력별로 시험한다. 위치·실패 조건·재현 수단의 각 누락과 원문 다름을 따로 검증한다.
- 문서·도구는 note 등급으로 맞췄다. 검토 방식은 관리 단위에서만 새 구조를 적용하며, 기준 실행본용 실제 독립 검토와 작업본 CLI의 실제 교차 관측은 자료를 따로 남긴다.
- T04의 영향 및 보안 예외, T09의 수정 확인과 상위 검토는 분할한 계약에 따라 후속 작업이 맡는다. 프로젝트 병합은 전체 완료 뒤 main 승인으로 진행한다.

## 구현 검토 반영

- 첫 독립 검토의 줄 범위 사례를 보완했다. 여러 위치 및 행·열 범위가 있는 blocking 지적은 입력에 담긴 근거를 유지한다. 중복 JSON 키는 이스케이프 표기를 포함해 미확인으로 판정한다. 원문과 도구 판정이 다를 때 응답에서 표시한다. [첫 reviewer](review-records/R1.json) [첫 tester](tester-first.md)
- 두 번째 tester가 구조화 단계 표지를 잃은 고아 기록이 원문의 pass로 복구되는 경로를 재현했다. 구조화 원문 또는 평가 흔적이 있는데 단계가 누락된 기록은 고아 복구와 재검토 기준점에서 모두 거부한다. 재검토 기준점의 원장 판정을 구조로 다시 계산하는 회귀 시험을 추가했다. [두 번째 reviewer](review-records/R2.json) [재현](tester-r2.md)
- 목표 검토와 도구 안내의 양쪽 제공자 미실행 절을 결정 권한 정본에 맞췄다. 허브가 관문을 보류하고 검토를 복구하며, 관문 생략·완화나 증거 공백 수용을 제안하는 경우 A-3으로 묻는다.
