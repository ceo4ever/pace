# T01 검토 지적 처리

사전 검토는 작성자와 다른 제공자(Anthropic)의 읽기 전용 verify로 첫 판정을 받은 뒤 같은 세션에 PROJECT·BR01·결정 권한 A를 전달했다. 두 단계 모두 blocking 0이다. 1단계는 프롬프트에 포함된 TASK를 읽었고 2단계는 전달한 저장소 원문 사본을 읽었다. 현재 TASK 지문과 첫 판정의 스냅숏은 PRE-REVIEW에 연결했다.

| 지적 | 처리와 근거 |
|---|---|
| 범위 재검토 입력과 pass 뒤 처리 | 직전 유효 판정 원문과 스냅숏 대비 줄 변경을 전달한다. 직전 pass면 앞선 blocking이 없다고 명시한다. 주입 실행기 프롬프트 시험으로 확인했다. |
| 옛 원장과 기준점 누락 | 정본 두 원장의 실행 이력을 소급 집계한다. 범위 재검토에 필요한 옛 스냅숏 또는 원문이 유실됐으면 거부한다. 하위 원장 중 확인된 저장소 사례는 P008·P012의 증거 픽스처다. |
| 단계 식별과 변경 | 실제 태스크 폴더의 루트 TASK.md가 사전 검토다. 구현 결과를 다른 Markdown·evidence/TASK.md로 옮겨 종류를 바꿔도 사전 예산으로 열 수 없다. 백로그는 전달한 종류와 무관하게 동일 단계다. |
| 동시 진입과 복구 | 공유 잠금 보유 중에는 다른 원장의 실행기 호출이 0이다. 소유 프로세스가 사라진 잠금 복구를 별도 표지로 직렬화한다. 복구 자체가 다시 중단되어 표지가 잔류하면 해당 표지와 프로세스를 확인한 뒤 정리해야 한다. |
| 원장 위변조·단위 밖 복사 | Git으로 관리하는 원장 보존을 전제로 한다. 고의 편집과 원장이 없는 다른 단위로의 물리 복제는 BR01의 정본 범위 밖이다. |
| 호출과 폴백 | 공통 계수는 verify 요청 및 검토 고정 예약 요청이다. B1 폴백이 유효 판정을 반환하면 회차에 포함한다. 검토기 내부에서 제공자를 확인하지 못한 응답은 독립 판정으로 인정되지 않는다. |
| 검토 실행 전 거부도 호출 소진 | 입력을 갖춰 예산 확인까지 온 요청은 판정 유무와 관계없이 호출로 센다. BR01이 명시한 verify 호출과 공통 예약 호출을 같은 계수에 모은다. |
| 측정과 표기 | 원장 토큰은 보고되지 않았으면 null로 저장한다. 표시명은 판정 증거 `미확인`과 구분해 `미보고`를 선택하고 후속 BL261125_01 BR03에 연결했다. |
| 소진 뒤 품질 경로 | reviewer 2단계에서 차단·상태 전달이 BR01의 경계임을 확인했다. 공동 시도와 owner 결정 경로를 BR02가 이어서 붙인다. |
| 사전 검토의 구조 누락 | 초기 구현에서 구조만 판정하고 이후 평가에서 목표·안전이 빠질 수 있음을 tester가 재현했다. 예산 대상의 구조 오류는 실행 전 거부해 첫 판정이 목적·안전을 볼 수 있게 했다. 옛 구조 전용 판정은 원문과 스냅숏 지문 확인 뒤 호출로만 세고, 이어서 첫 전체 판정과 범위 재검토를 각각 검증했다. 예산 단위 밖 중단은 P007의 기존 진단 흐름을 유지한다. |
