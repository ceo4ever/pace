# T01 공동 시도 두 회 대조

작업본의 독립 reviewer 호출은 사후 검토 2회에서 차단됐다. 허브는 BR01 범위와 검증 기준을 유지한 채 프로젝트 초기 기준 실행본의 격리 사본으로 공동 재검증을 허용했다. 기준본 원장은 R1·R2의 판정 행과 원문을 입력으로 썼다. 새 호출 예약 행은 작업본에 보존하고 기준본 입력에서만 뺐다. 결과 R3·R4 원문과 실제 판정 행은 지문을 대조한 뒤 태스크 원장에 연결했다.

| 공동 시도 | 적용과 판정 | 실제 결과와 처리 |
|---|---|---|
| 1 | 옛 구조 전용 판정과 기존 일반 진단 회귀 보완. 기준 실행본 R3 첫 판정 pass, 독립 tester fail | 다른 Markdown 경로와 `--kind task`로 구현 후 결과를 사전 예산에 올릴 수 있었다. 새 호출의 판정 단계는 실제 태스크 루트 TASK.md로 고정했다. [reviewer R3](review-records/R3.json) [tester](tester-joint1-stage2.md) |
| 2 | 단계 구분 고정과 Markdown 사본 시험. 기준 실행본 R4 첫 판정 pass, 독립 tester fail | 옛 `evidence/TASK.md`의 goal 판정 두 건이 사전 예산을 막고 구현 후 예산이 다시 열렸다. 옛 행과 고아 기록의 복구도 원장의 루트·증거 위치를 판정에 반영하도록 고쳤다. [reviewer R4](review-records/R4.json) [tester](tester-joint2-stage2.md) |

원인은 동일한 `TASK.md` 이름을 가진 기록의 단계 식별을 대상 이름과 원장 출처에 다르게 적용한 설계다. 실제 명령으로 옛 goal 원장 두 건과 중단 복구를 함께 구성해 루트 사전 검토는 실행되고 구현 후는 종료 16인지 단언했다. 추가 시험은 수정 전 실패, 수정 후 통과했다. 집중 검사 55건이 통과했다.
