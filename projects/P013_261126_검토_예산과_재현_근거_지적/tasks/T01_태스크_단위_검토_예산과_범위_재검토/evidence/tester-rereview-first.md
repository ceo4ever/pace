**1단계 잠정 평가: 목표에 부합하는 검토 상한을 도입했지만, 변경만으로는 한도 준수와 독립 검토 품질 유지를 확인하기 어렵습니다.**

태스크의 사전·구현 후 검토와 백로그 검토에 단계별 판정 2회, 호출 4회 상한을 둡니다. 실행 전에 호출을 원장에 예약하고, `unknown`·무효·중단은 판정에서 제외하면서 호출에는 남깁니다. 태스크 루트와 `evidence/`가 잠금과 예산을 공유하므로, 두 위치 사이에서 대상을 바꾸거나 동시에 호출해도 같은 한도를 적용하는 구조입니다. 첫 사전 검토의 구조 오류를 실행 전에 처리하고, 후속 판정에 직전 독립 검토 원문과 변경분을 제공하는 점도 목표와 맞습니다.

1. **대상 경로에 따라 기존 검토가 예산에서 빠질 수 있습니다.** 기존 구현은 대상 파일이 있는 폴더에 원장을 썼습니다. 새 구현은 태스크 루트와 `evidence/`의 원장 두 개만 읽습니다. 예를 들어 기존 `evidence/sub/change.patch`의 검토가 `evidence/sub/REVIEW-LOG.jsonl`에 남아 있다면 새 집계에서 빠지고, 같은 단계에서 추가 전체 검토가 열릴 수 있습니다.
2. **서로 다른 산출물에도 범위 재검토를 적용합니다.** 같은 단계라는 이유로 이전 대상의 판정과 스냅숏을 가져오지만, 두 대상이 같은 산출물의 개정본인지 확인하지 않습니다. 제공된 테스트도 `BACKLOG.md`에서 별도 `BR02` 문서로 넘어갈 때 범위 재검토를 기대합니다. 이전 문서의 blocking이 새 문서에도 적용되는지, 우연히 일치해 변경분에서 빠진 내용이 새 문서에서도 유효한지 확인할 근거가 부족합니다.
3. **일반 산출물의 반복 중단에는 기존 정지 조건이 약해집니다.** 중단을 연속 실패에서 제외하는 변경은 예산 적용 여부와 무관합니다. 새 호출 상한이 적용되지 않는 경로에서는 중단만 반복될 경우 기존 진단 단계도, 새 예산 차단도 열리지 않습니다.

가짜 실행기 기반 테스트에는 공유 상한, 동시 호출, 미실행 폴백 등을 확인하는 단언이 추가됐습니다. 실제 실행 결과와 외부 검토 경로의 예약 적용 여부는 이번 변경만으로 확인할 수 없습니다. 제공된 diff만 검토했으며 명령 실행과 파일 수정은 없었습니다.
