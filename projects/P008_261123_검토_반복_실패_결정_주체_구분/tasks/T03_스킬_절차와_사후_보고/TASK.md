- 판정 주체: 정책 내용은 다른 제공자 reviewer, 행동은 실제 다른 제공자의 새 맥락 응답, 원장·승인 전후 파일 불변과 수정 순서는 소스 CLI 실행 증거 및 독립 tester가 대조한다. 사람 승인의 진위는 도구가 대신 판정하지 않는다.
- 포함: 매 수정 전 영향 확인·두 결정 경로·두 보고 형식·정본 링크 일치, S7 일반갭/보안·범위변경/애매함 해소/재검증 새 위험 사례, 소스 CLI 종료0 즉시 단계·16 차단·pm/user 및 diagnose 단계 승인 경로.
- 범위 밖: 실제 위험한 서비스·사용자 데이터·배포는 다루지 않는다. CLI 단계·승인 시나리오는 명시적 합성 fixture로 실행한다. 행동 에이전트는 스킬을 읽고 순서를 제시하며 구현·실제 위험 행동을 하지 않는다. 설치본 인수는 병합 뒤 main 재설치 후 코디네이터가 맡는다.

## 접근

스킬 정본의 분류는 자동화하지 않는다. 매 수정 전 목적·범위와 조치가 닿는 파일·동작·데이터·외부를 확인한다. 일반 갭에 해법이 여러 개라는 이유로 묻지 않고 근본 조치로 채우거나 덜어낸다. 같은 영역 재지적은 해당 설계를 다시 진단한다. 이미 승인된 구체적 조치를 재확인하지 않되 새로운 심각 오류·보안·합의 변경·외부 영향은 사전에 올린다. diagnose에서 발견한 위험은 승인 원문을 진단 증거에 연결하고 ask_user에서 발견하면 --decision --by user에 연결한다. normal 단계의 새 위험은 일반 승인 증거·project log로 남기며 열린 단계 없이 review-note 단계를 위조하지 않는다. PM 기록은 --by pm, waiver는 사용자만 유지한다. raw CLI 통합 fixture는 PATH의 가짜 claude p 응답을 쓰며 실제 독립 모델 검토라고 주장하지 않는다. 별도의 행동 호출은 실제 Anthropic으로 하고 evals 정답표·TASK·마감은 노출하지 않는다. 승인 파일은 합성 시나리오 입력임을 표시하고 실제 승인처럼 보고하지 않는다. 정책·브레인·프로필 외 경로를 바꾸지 않으며 보안·회귀 기준은 기존 문서와 교본 verification 색인에 대조한다.
