- 사전 검토 R1·R2 모두 Anthropic Claude Opus 5.5, blocking 0. R1의 생성 템플릿 검사·표지 오류·구조 선검사·원장 분리·⑤ 분리·표지 우회 문서화를 TASK에 반영하여 R2 전체 검토를 받았다. R2의 재검토 조건·주석 빈 값·실측 원문 보존·승인 원문 fixture를 구현·증거에 반영했다. 기준선 비교는 합의 범위 밖 제안으로 남겼다.

- 근본 진단(structure): 일반 등급 안내와 특별한 범위 확대 등급 규칙이 떨어져 있고 문구가 모호했다. 목적·기준을 이미 충분히 입증하는 범위의 확대 요구라는 조건을 풀어 쓰고, should_fix가 승인·반영 의무가 아님을 분리했다. 특별 규칙을 최종 판정 지시 직후에 두고 cases-run3 전체를 다시 실행했다. ② R1은 확대 요구를 should_fix로 명시, TASK는 blocking 0/pass였다. 다른 유형도 기대 판정을 유지했다. ⑤는 권한 대체와 안전 제외를 분리해 각각 검출했다.
- tester 1단계는 fenced 코드의 HTML 주석 표지 때문에 정상 절이 지워지는 결함을 재현했다. 실패 테스트(parser-red)를 먼저 남기고 fence/주석 상태를 순차 처리하여 고쳤다. 이후 인라인 코드 재현도 RED→GREEN으로 고쳤다. 기존 tester의 EPERM 제한은 별도 원문으로 보존하고 실행 가능한 호스트 독립 tester에 인계했다.
- reviewer 구현 검토 R3 F1: 구조 누락만 한 건 지적하면 다음의 제한 재검토가 아직 평가하지 않은 안전 기준을 숨길 수 있었다. 실패 테스트(scope-red) 뒤 직전 TASK 스냅숏 구조 오류가 있으면 다음을 전체 검토로 열도록 고쳤다. rereview_of는 null이고 fail 집계는 유지한다. R4는 F1 해소 pass였다. R4 N1은 단건 억제의 빈 값을 게이트의 구조 누락으로 한정하여 의미상 미정/TBD의 나머지 평가를 막지 않게 명확히 했다.
- 구현 검토 R2는 호출 목적 인자를 잘못 작성한 실행을 작업자가 중단한 기록이다. 실제 지적이 아니며 다음 호출이 interrupted로 자동 복구했다. 원장을 고치거나 실제 blocking으로 보고하지 않았다.
