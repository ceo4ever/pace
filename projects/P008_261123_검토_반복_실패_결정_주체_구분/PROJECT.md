## 목적

구현 전 TASK에 증명 범위와 판정 주체를 먼저 적어 합의된 목적을 입증하는 데 필요한 지적에 검토를 집중한다. 반복 실패가 남으면 PM이 갭을 근본 조치하고 재검증 뒤 보고한다. 심각한 오류·보안·합의 변경을 다루는 조치는 변경 전에 사용자 결정을 받는다.

## 설계

T01 → T02 → T03 순서로 진행한다. TASK 형식 표지는 게이트·프롬프트·수동 검토가 같은 버전으로 해석한다. 원장의 단계 계산과 종료 계약을 유지하고, 결정 주체 기록과 안내에 PM/사용자 경로를 반영한다.

보안 영향은 `src/project/pre-review.ts`의 계약 게이트와 `review-note` 결정 근거 검사다. 필수 안전 기준을 증명 범위 밖으로 빼거나 PM 결정으로 waiver를 쓰면 거부한다. 기존 근거 파일 검증을 유지하고 시험과 증거에 비밀·사용자 데이터를 넣지 않는다. 마감 전에 선언된 보안 검사와 전체 검사를 수행한다.

worktree의 소스 CLI와 정본 스킬로 완료를 입증한다. 승인·병합 뒤 main에서 재설치하고 코디네이터가 설치본을 확인한다. bubble-catch의 통과 회차는 설치 뒤 운영 지표로 남긴다.
