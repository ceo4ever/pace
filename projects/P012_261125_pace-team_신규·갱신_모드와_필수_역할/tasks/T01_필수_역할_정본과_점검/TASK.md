## 증명 범위

- 판정 주체: reviewer는 BR01과 문서 의미를 대조하고, 독립 tester는 고정 입력과 별도 맥락의 원응답으로 행동·음성 대조를 판정한다. PM은 owner 결정 A의 출처와 점검 증거를 확인한다.
- 포함: 두 필수 원형 자리와 등록 표, 합의 원문 대조와 정의 대조, 신규·갱신의 추가·개선 제안, 요건 버전 및 선행 장치 보류, 요건 미등록 분기, 요건 단일 정본과 재실행 가능한 스킬 시나리오.
- 범위 밖: 측정·표지(T02), 갱신 및 이전 흐름과 세 분기 통합 평가(T03), 기획자 실제 등록·적용(T04), 허브 위임(T05)과 실제 요건 ID 등록 뒤 참조 재검사(T04·T05), 문제 해결자 등록·판정(BL261125_01). T01의 동작은 시험 요건으로 검증한다.

## 기준

| # | 완료 기준 |
|---|---|
| T-1 | 두 필수 원형의 이름·필수 표시·등록 위치·담당과 요건 ID, 요건 문장, 근거, 선행 장치, 요건 버전, 고정/권고 형식을 정본에서 찾을 수 있다. 정본은 BR01의 요건 범주, 결정 권한 참조, owner 결정값과 저장소별 권고값의 차이를 다룬다. 재실행 시나리오를 `skills/pace-team/evals/scenarios.md`에 정의한다. |
| T-2 | 합의 원문에 있으나 등록되지 않은 요건과 등록됐으나 정의가 충족하지 않은 요건을 서로 다른 표에서 식별한다. 스킬·팀 원본·BR05 대상 문서의 해당 참조에 요건 본문 중복이 없고 등록 뒤에는 요건 ID를 사용한다. |
| T-3 | 시험 요건을 등록한 원형에 대해 정의가 없으면 저장소 분석에 근거한 맞춤 정의를 제안한다. 기존 정의가 불완전하거나 새 버전의 요건이 빠지면 해당 요건을 개선 제안하고 완전한 정의에는 수정 제안을 하지 않는다. 요건 ID마다 충족·누락·보류(선행 미병합)·해당 없음 중 결과와 근거를 남긴다. |
| T-4 | 선행 장치가 없으면 해당 등록 요건을 보류(선행 미병합)로 남기고 낮춘 정의를 제안하지 않는다. 문제 해결자는 요건 미등록(BL261125_01 담당)으로 표시하고 요건 누락이나 추가·임의 정의를 제안하지 않는다. |

## 접근

스킬 ①과 ③에서 정본의 합의 원문 대조 및 팀 정의 대조로 연결한다. `required-roles.md`에 두 원형 자리, 공통 요건 표 형식, 비교 순서와 결과 형식을 둔다. 역할 후보와 팀 문서에는 정본을 연결하고 `skills/pace-team/evals/scenarios.md`에 고정 입력과 필수·금지 행동을 둔다. 외부 제공자의 새 맥락에는 필요한 스킬과 시험 사본만 제공한다. 평가 기준과 정답을 격리 입력에서 제외하고 프롬프트·픽스처·원응답·독립 판정을 근거에 보존한다.
