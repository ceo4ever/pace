## 목적

허브 쪽·조건부 필수 역할의 비참여가 프로젝트 회고 신고를 매번 강제하지 않게 하고, 실제 참여와 소통 원장은 계속 정상 집계한다. 호출 기록이 생기는 후속 프로젝트에서 호출 수집과 팀 채택을 독립적으로 유지한다. [BR02](../../../../backlogs/BL261125_02_pace-team_신규·갱신_모드와_필수_역할/BR02_필수_역할_측정_분류.md)

## 재료

## 증명 범위

- 판정 주체: 실제 소스 CLI의 stats·finish·merge 시험, 원본 판독기 구판 동작을 테스트가 확인한다. 독립 tester가 실제 실행·검출력을, reviewer가 호환성·보안·계약과 nonparticipation 증거 경계를 판정한다.
- 포함: 허브 쪽·조건부 역할 표지, 세 비참여 상태, 기존 기록과 실제 활동 우선, 회고 관문, 과거 설치 원본 판독, 미채택 프로젝트의 호출 기록 분리 규칙.
- 범위 밖: 필수 역할 실제 원본·등록(T04와 BL261125_01), 새 호출 기록 형식과 지표 코드는 BL261125_01 BR03에서 이 규칙으로 구현한다. 팀 채택 계약의 기존 입력은 이 태스크에서 유지한다.

## 접근

- 기존 회고의 `unconfirmed`만 쓰는 방법은 코드가 없어도 임시로 작동하지만 매 프로젝트에서 무관한 신고를 요구한다. 저장소 측정이 분류하는 방법을 선택한다. 원본 frontmatter 형식은 닫혀 있으므로 팀 폴더에 버전이 있는 선택 JSON 표지를 둔다. 프로젝트 채택 판단과 기존 일반 역할을 유지한다.
- 이미 측정에 쓰이는 안전한 metadata JSON, 링크/UTF-8/크기·비밀 검사와 검증 대상 Git 스냅숏 경계를 쓴다. 표지로 호출 가능 위치·조건만 안다. 실제 구간 내 근거가 없으면 기록 부족이다. 역할·기간과 결합된 영수증에 조건 미발생 또는 관측된 미사용을 적고, 참여 선언·역할 관측이 있으면 두 비참여 판정을 적용하지 않는다. 기존 로그의 note/src/ref를 써서 옛 판독기의 구조를 유지한다.
- 측정 도구는 채택된 프로젝트에서만 새 분류를 추가한다. 호출 telemetry를 소통 또는 팀 채택 필드와 분리한다. 호출 기록만 있는 상태를 기존 팀 투입·소통 신호로 오인하지 않는 조건을 후속 역할에 문서로 넘긴다.
