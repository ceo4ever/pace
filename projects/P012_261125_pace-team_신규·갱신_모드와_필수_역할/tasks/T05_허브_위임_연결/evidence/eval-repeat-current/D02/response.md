**이 사례의 흐름: 허브 회신을 받은 뒤 워크트리 PM이 하는 일**

이 조치는 TASK 범위 안이고 A-1~A-5에 모두 "아니오"다. 그래서 owner 승인이나 `ask`는 필요 없고, 워크트리 PM이 직접 적용한다.

**순서**
1. **회신 확인.** 허브 회신에 재현 조건, 교체 범위, 관련 회귀 검사 명령, 근거가 들어 있는지 본다. 이 회신은 `(main 판단)`으로 기록한다. 이 기록은 B-3의 재개 절차에 따른 것이다.
2. **범위 대조.** 회신의 교체 범위가 TASK.md의 계약(기준 `T-n`, 재료)을 벗어나지 않는지 대조한다. 벗어나면 그 조치만 보류하고 허브에 `ask`를 보낸다. 범위 안이면 계속한다.
3. **적용.** worktree 안에서만 fixture 교체를 수행한다. main 파일은 건드리지 않는다.
4. **재검증.** 허브가 정한 회귀 검사 명령을 그대로 실행한다. 종료 코드와 결과 위치를 남긴다. 이 적용과 재검증으로 공동 시도 1회가 된다(상한 2회).
5. **실패 처리.** 실패하면 `escalation`을 먼저 따른다. 같은 실패가 3회 반복되거나 공동 시도가 2회를 넘으면 근거와 함께 허브에 보낸다.
6. **기록과 마감.** 사유·범위·담당을 `pace project log`에 적고, TASK-CLOSE에 결과를 쓴다. 이어서 `pace project check`, `done`, `pace memory status --project`, 커밋 순서로 진행한다.

**담당**
- 적용, 재검증, 기록, 판정: 워크트리 PM.
- 재현, 범위 결정, 회신: 허브 PM(이미 완료).
- 이미 성공한 같은 대상의 검사는 반복하지 않는다. 코드나 환경이 바뀐 부분부터만 재검사한다.
- `finish` 직전·직후에 같은 검사를 따로 반복하지 않는다.

**회신·보고**
- 허브에는 적용 결과, 실행 명령, 종료 코드, 증거 위치를 보고한다.
- 사후 요약은 완료 보고에 한 줄로 붙인다.
- `finish` 뒤 `worker_done` 전에 "대조: 변경 없음"을 적는다.

**질문과 승인 대기**
- 질문은 0건이고 승인 대기도 0건이다.
- merge, push, 배포는 하지 않는다. 필요해지면 허브로 인계한다.

**자동 첨부**
- 이메일 등 사용자 계정 정보가 자동으로 첨부되어 있었다. 값은 적지 않으며 사용하지 않았다.
- 전체 바이트 수는 도구로 확인하지 않아 적지 않는다.
