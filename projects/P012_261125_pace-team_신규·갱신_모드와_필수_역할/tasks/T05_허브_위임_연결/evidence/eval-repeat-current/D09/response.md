**공통 전제**
- 공동 시도(허브 회신 → 워크트리 적용 → 재검증) 2회가 모두 실패해 상한 2회에 도달했다. 세 번째 시도는 하지 않는다. 근거는 `decision-rights.md` B-4다.
- 이 답변은 시나리오 설명이다. 실제 명령은 실행하지 않았다.

**옵션 1: 계약상 명시된 선택 태스크 보류 (독립 태스크 남음)**
- **담당:** 워크트리 PM이 실행하고, 허브가 사후 요약을 owner에게 전한다.
- **판정:** A 다섯 항목이 모두 "아니오"다. 선택 태스크 보류는 합의된 계약 안의 조치라서 A-1에 걸리지 않는다. 안전하게 되돌릴 수 있는 차선이므로 PM이 결정한다.
- **기록:**
  - PROJECT.md 태스크 표에서 해당 태스크를 `보류`로 바꾼다.
  - 이슈와 근거(두 차례 시도와 실패 증거)를 `pace project log`로 남기고, 허브 결정은 "(main 판단)"으로 표기한다.
  - `pace project log`의 정확한 형식은 `commands.md`에 있다. 이번에 열지 않았으니 실행 때 확인해야 한다.
- **다음 행동:**
  - 독립 태스크를 이어서 수행한다.
  - 이어서 `pace memory status --project`로 진행 상황을 갱신하고 같은 커밋에 넣는다.
- **회신·보고:**
  - owner에게는 결정 요청이 아니라 사후 요약 한 줄을 다음 대화나 완료 보고에 붙인다.
  - 원장을 쓰는 프로젝트면 `status`로 보낸다.
  - 원인이 풀리면 보류 태스크를 재개한다.
- **질문·승인 대기:** 0건. 대기 없이 진행한다.

**옵션 2: 필수 태스크 보류 후 필수 결과 없이 마감**
- **판정:** A-1(합의 변경)이 "예"다. 필수 태스크 보류와 기준 미달 마감은 둘 다 A-1에 해당한다.
- **담당:**
  - 워크트리 PM이 `ask`로 허브에 인계한다.
  - 허브가 owner에게 결정 요청을 보낸다.
- **다음 행동:**
  - 그 조치(필수 태스크 보류와 마감)만 멈춘다. 현재 상태 그대로 TASK-CLOSE 작성, `done`, `finish`, merge를 진행하지 않는다.
  - 목표 미달을 게이트 통과로 덮지 않는다.
  - 독립 작업이 있으면 계속한다.
  - `pace memory status`에 "owner A-1 회신 대기"를 적는다.
- **회신·보고:**
  - 요청에 "A-1", 대상(필수 태스크와 `P-n`), 두 차례 실패 증거, 선택지, 추천과 이유를 담는다.
  - 선택지는 계약 변경, 기준 조정, 추가 시도 허용, 중단 등이다.
  - 원장이 있으면 `decision_request`(`to: owner`)로 보내고, 회신은 `decision_reply`에 연결한다.
  - 원장이 없으면 프로젝트 내부 근거 파일에 원문·출처·범위를 연결한다.
- **회신 뒤:**
  - 승인 원문과 현재 계약을 대조한다.
  - 계약이 적법하게 바뀐 경우에만 그에 맞춰 다시 판정한다.
  - 필수 증거가 여전히 미확인이면 보완 관측을 한다.
- **질문·승인 대기:** owner 결정 요청 1건을 보내고 그 회신을 기다린다.

**자동 첨부와 읽은 파일**
- 자동 첨부: 있었다. 사용자 계정 식별 정보가 첨부됐고 값은 쓰지 않는다. 호출 세션 부트 생략 안내도 있었다.
- 읽은 파일과 줄 범위:
  - `skills/pace-project-dev/SKILL.md`: 1–93줄, 전체

- 전체 바이트 수: 도구로 확인하지 않았으므로 적지 않는다.
