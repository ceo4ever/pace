**순서** (근거: `reviewer.md` 지적 등급 절의 재검토 규칙, 49줄)
1. **원문 보존.**
   - 2차 재검토 원문과 바뀐 줄 목록을 차수별 고유 증거 경로(`review-records/`)에 보존한다.
   - 보존 전에 비밀·민감정보를 검사한다.
   - TASK-CLOSE와 review 로그에 증거 경로를 연결한다.
   - 원문이 없거나 복사할 수 없으면 추정 복원하지 않고 한계를 적는다.
2. **등급 부여.** 원문에 등급이 없으므로 PM이 `blocking`·`should_fix`·`handoff` 기준으로 직접 매긴다. 불확실한 결함은 낮추지 않는다.
   - **지적 1(해소):** 해소로 기록한다.
   - **지적 2(부분 해소):** 남은 부분은 직전 등급을 유지한다. 직전이 blocking이었다면 아직 blocking이다.
   - **고친 줄에서 생긴 새 문제:** 재검토 범위 안이다. 결함이면 blocking이고, 이름·문구 수준이면 should_fix다.
   - **바뀌지 않은 절의 새 지적:** 재검토 범위 밖이다. `note`로만 남기고 이번 판정·수정 대상에 넣지 않는다.
3. **판정.** blocking이 하나라도 남으면 `fail`이다. 지적 2의 잔여분이나 새 문제가 blocking이면 fail이다. note는 판정에 영향을 주지 않는다.
4. **수정 전 대조.** 수정 직전에 합의된 목적·범위에 조치가 영향을 주는지 A-1로 대조한다. 영향이 없으면 PM이 결정하고 근거를 `pace project log`에 남긴다. 영향이 있으면 `ask`로 허브에 인계하고 해당 조치만 보류한다.
5. **수정과 재검증.** 지적 2 잔여분과 새 문제를 고친 뒤 `pace agent verify`를 다시 호출해 자동 재검토를 받는다.
   - 도구 밖 reviewer로 경로를 바꾸지 않는다.
   - purpose에는 내 대응이나 자체 판정을 넣지 않는다.
   - 출력에 `escalation`이 있으면 그 단계(진단·결정)를 먼저 따른다.
6. **기록과 보고.**
   - 지적마다 등급, 근거, 반영 여부와 이유, 수정 위치, 재검토 결과를 연결해 TASK-CLOSE에 적는다.
   - 허브에 보내는 회신은 "1 해소 / 2 부분 해소(잔여 등급) / 새 문제 등급 / note 1건(범위 밖) / 다음 verify" 정도의 요약이다.
   - note는 TASK-CLOSE의 "남긴 것"으로 넘긴다.

**경계**
- 바뀌지 않은 절의 새 지적을 이번 차수에 고치지 않는다.
- 이번 차수는 도구 절차 문제가 아니므로 B 이관은 하지 않는다. 같은 절차·열람 지적이 두 번 이어질 때만 B로 이관한다.
- 수정, 커밋, 메모리 기록은 이 시험에서 하지 않았다.
