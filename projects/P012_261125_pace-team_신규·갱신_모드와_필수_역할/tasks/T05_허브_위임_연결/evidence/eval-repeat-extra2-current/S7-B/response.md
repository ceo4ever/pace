**자동 첨부와 읽은 범위**
- 자동 첨부: 사용자 이메일 컨텍스트가 시스템 리마인더로 붙어 있었습니다. 값은 쓰지 않습니다. 업무에는 쓰지 않았습니다.
- 읽은 파일:
  - `skills/pace-project-dev/SKILL.md` 1–93줄 전체.
  - `references/reviewer.md` 1–125줄 전체.
  - `references/` 아래 grep 결과. 일부 긴 줄은 생략됐고, 읽은 곳은 coordinator, decision-rights, task-steps 등의 일치 줄입니다.
- 전체 바이트는 도구로 확인하지 않았으므로 적지 않습니다.
- 다른 사례의 응답, 평가표, TASK, 마감 문서는 읽지 않았습니다.
- 실제 명령, 기록, 질문, 메모리 저장, 커밋, 전송은 하지 않았습니다. 아래는 계획입니다.

## 사례: 2차 재검토 원문 (등급 없음)
원문에 지적 5건이 있습니다. 직전 지적 1 해소, 직전 지적 2 부분 해소, 이번에 고친 줄의 새 문제 1, 바뀌지 않은 절의 새 지적 1, 바뀐 줄 목록입니다. 근거는 `reviewer.md` 49행("재검토" 범위)과 23행(이력 보존)입니다.

**담당**
- 워크트리 PM이 분류하고 기록합니다.
- reviewer는 파일을 고치지 않고 지적만 돌려줍니다. 직접 고치지 않습니다.
- 허브는 A에 걸릴 때만 관여합니다.

**순서**
1. **원문 보존.** 2차 재검토 원문을 고유한 증거 경로(`review-records/R<n>.json`)에 그대로 보존합니다. 비밀·민감정보를 검사하고, 원문이 없거나 복사할 수 없으면 추정 복원하지 않고 한계를 적습니다. 등급이 없다고 PM이 등급을 임의로 채워 원문처럼 쓰지 않습니다.
2. **범위 분류.** 재검토는 "직전 blocking의 해소 여부 + 그 수정이 만든 새 결함"만 판정 대상입니다. 바뀐 줄 목록과 대조해 5건을 나눕니다.
   - 지적 1 (해소): 닫습니다. 반영 위치를 기록합니다.
   - 지적 2 (부분 해소): 직전 blocking이 남은 것으로 보고 판정 대상에 둡니다. 남은 부분만 고칩니다.
   - 고친 줄의 새 문제: 수정이 만든 새 결함이므로 판정 대상입니다. 불확실하면 낮추지 않고 blocking 후보로 둡니다(48행).
   - 바뀌지 않은 절의 새 지적: 판정·수정 대상이 아닙니다. note로만 남깁니다. 이번 fail이나 수정 요구로 세지 않고, 필요하면 handoff나 "남긴 것"에 둡니다.
3. **등급 확정.** 원문에 등급이 없으므로, 판정 대상 항목은 같은 reviewer의 재검토에서 등급을 확인합니다. 임의로 정하지 않습니다. 확인 전에는 "부분 해소"와 "새 문제"를 blocking 가능성으로 간주해 구현·커밋을 진행하지 않습니다.
4. **수정 직전 확인.** 수정 전에 합의된 목적·범위와 조치의 실제 영향을 A로 대조합니다. 합의를 바꾸지 않으면 PM이 결정하고 근거를 남깁니다.
5. **수정 후 재호출.** 지적 2의 남은 부분과 새 문제를 고친 뒤 `pace agent verify`를 다시 호출합니다. 자동 재검토가 원장의 직전 fail을 기준점으로 삼습니다. 도구 밖 reviewer로 바꾸지 않습니다.
6. **단계 확인.** 이번이 2차 재검토이므로 원장의 연속 fail 수를 확인합니다. 세 번째 fail이면 출력의 `escalation`(diagnose)을 즉시 따릅니다. 아직 기록되지 않은 단계에서 다시 호출하면 종료 16으로 차단됩니다.

**실제 기록**
- 지적마다 등급, 내용, 판정 근거, 반영/미반영과 이유, 수정 위치, 재검토 결과를 연결합니다.
- `pace project log`에 대상, 제공자, 방법, 결과와 처리 내용을 남깁니다.
- TASK-CLOSE 리뷰 절과 review 로그에 증거 경로를 연결합니다.
- 사전 검토면 `PRE-REVIEW.json`에 시도를 옮깁니다. 자동 재검토는 `changed`(reason: 자동 재검토·rereview_of)로 적습니다.
- 바뀌지 않은 절의 새 지적은 note로 따로 기록합니다.

**회신과 보고**
- reviewer에게는 작성자의 대응이나 자체 판정을 넣지 않습니다(독립성). 바뀐 줄은 검토자가 직접 봅니다.
- 허브나 owner에게는 A에 걸리지 않는 한 별도 요청이 없습니다. 완료 보고나 사후 요약에 "무엇이 반복됐는지·고친 층·반영한 것·재검증 결과"를 담습니다.

**질문과 승인 대기: 0건**
- 조치가 합의된 목적·범위를 바꾸지 않으면 PM이 결정합니다.
- A에 걸리면 그 조치만 보류하고 허브를 거쳐 요청합니다. 이 경우에도 독립 작업은 이어갑니다.
