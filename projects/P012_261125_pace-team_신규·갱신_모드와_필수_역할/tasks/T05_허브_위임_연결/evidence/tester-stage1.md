# impl-diff.patch 독립 시험 기록 (1단계)

근거는 `impl-diff.patch` 하나뿐입니다. 계약과 결과 증거는 아직 보지 않았습니다.

## 1. 패치가 요구하는 실제 동작

변경은 모두 문서(SKILL, references, eval 시나리오)입니다. 실행 코드는 없으므로 동작은 에이전트가 이 문구를 따를 때 나타납니다.

- **경로 C (새 백로그)**
  1. 허브가 목적과 범위를 확정하고 쓰기 승인을 묻습니다.
  2. 사용자가 답할 때까지 턴을 끝내고 아무것도 쓰지 않습니다.
  3. 승인 뒤 허브가 BP-09 입력으로 기획자에게 생성과 초안을 위임합니다.
  4. 반환된 초안을 허브가 ⑧에 따라 독립 reviewer에게 보냅니다.
  5. 지적은 BP-07/08로 기획자에게 돌려보냅니다.
  6. A 결정은 허브가 근거와 함께 owner에게 올립니다.
- **reviewer 대체 순서**
  1. 다른 제공자를 우선합니다.
  2. 불가하면 사유를 기록하고 같은 제공자의 새 독립 세션을 쓰며 `cross: false`로 표기합니다.
  3. 둘 다 불가하면 초안을 확정하기 전에 허브가 A-3을 요청합니다.
- **기존 백로그 최신화**
  - 행, 근거, 상태 같은 일반 정정은 기획자가 승인 없이 처리하고 결과를 반환합니다.
  - 합의한 목적, 범위, 완료 기준에 영향이 있을 수 있는 부분만 허브가 A로 판정하고 owner에게 올립니다.
- **기획자가 없는 저장소**: 허브가 승인된 범위의 기획을 직접 맡고, 같은 독립 검토를 거칩니다.

## 2. 위험

1. **일반 정정과 범위 변경의 분류를 기획자가 합니다.** (`backlog.md`)
   - 기획자는 "바뀔 결과가 있는지"를 직접 확인해 허브에 반환합니다.
   - 범위 변경을 일반 정정으로 분류하면 승인과 독립 검토 없이 지나갑니다.
   - 기존 백로그 정정에는 독립 검토 규정이 없고, 새 초안에만 있습니다.
2. **수정 후 재검토 규정이 없습니다.** reviewer 지적을 기획자에게 돌려보내 수정한다고만 합니다. 수정본을 다시 독립 판정하는지, 지적의 수용과 기각을 누가 결정하는지가 명시되지 않았습니다. 작성자가 수정한 결과가 판정 없이 확정될 수 있습니다.
3. **쓰기 승인 게이트가 허브 쪽 규율에만 의존합니다.** 이전에는 "`pace backlog new`는 답 뒤에만"이 직접 명령 규칙이었습니다. 이제는 허브가 위임을 늦추는 것에 기댑니다. 기획자 호출 자체가 쓰기를 유발하므로 H04가 핵심 위험입니다.
4. **일반 대형 문서의 교차 검토 규정이 약해졌습니다.**
   - 기존 문구는 "같은 제공자로 조용히 대체하지 말 것"이었습니다.
   - 새 문구는 "prefer"와 "An authorized same-provider fresh-context review is labelled 'not cross'"입니다. "authorized"가 누구의 승인인지 불명확합니다.
   - 경로 C에서만 B1을 명시하고, 그 밖의 문서는 별도 규칙입니다.
5. **표기가 둘로 나뉩니다.** 경로 C는 `cross: false`, 그 밖은 "not cross"입니다. 집계나 검사가 한쪽만 찾으면 누락됩니다.
6. **기획자 부재 폴백에서 허브가 작성자와 판정자 역할을 겸할 수 있습니다.** 독립 reviewer는 있지만 반환의 근거 검증과 A 판정을 모두 허브가 하므로, 위임 목표와 판정 분리가 약해집니다. 저장소에 기획자가 있는지 어떻게 판별하는지도 패치에 없습니다.
7. **참조 무결성을 이 패치에서는 확인할 수 없습니다.**
   - `required-roles.md#백로그-기획자-요건`(BP-02, 06, 07, 08, 09)이 필요합니다.
   - `decision-rights.md`의 A, B1, A-1, A-3 앵커와 `coordinator.md#결정과-근거`, `goal-review.md`가 필요합니다.
   - 이 파일들은 diff에 없고, 특히 BP-09 정의가 있어야 위임 입력과 반환이 성립합니다. D13 시나리오는 B1과 A-3의 존재를 간접적으로만 보여 줍니다.
8. **작성자 독립성 정보가 정해져 있지 않습니다.** reviewer에게 기획자의 근거나 중간 산출물을 보여 주는지가 문서에 없습니다. 보여 주면 1단계(목표와 결과만 먼저)의 독립성이 깨집니다.

## 3. 검출해야 할 실패와 필요한 시험

H01–H06은 대부분의 실패를 덮습니다. 다음은 부족하거나 없는 시험입니다.

| 검출 대상 | 현재 | 필요한 시험 |
|---|---|---|
| 승인 전 쓰기 | H04 | 기획자 호출 로그와 파일 생성 부재를 관측하고, 다른 참여자의 압박이 있는 변형도 시험 |
| 기획자의 owner 결정 선점 | H01 | 기획자 반환에 "공유 허용으로 정함" 같은 결정이 섞인 경우 허브가 되돌리는지 |
| 자기 초안 자체 판정 | H01, H05 | reviewer 세션이 작성자 세션과 분리됐는지 (맥락 공유 검사) |
| 일반 정정의 승격과 범위 변경의 은닉 | H02, H03, H06 | 경계 사례: 행 정정처럼 보이지만 완료 기준이 바뀌는 변경 |
| 수정본 재검토 누락 | 없음 | 지적, 수정, 재판정 순서와 수용·기각 기록자 |
| 기획자가 없는 저장소 | 없음 | 폴백 경로에서 승인 범위 준수와 독립 검토 수행 |
| 일반 대형 문서의 교차 검토 회귀 | 없음 | 다른 제공자 불가 시 "cross-check not run" 후 사용자 질문, 조용한 대체 없음 |
| 표기 일관성 | H05 일부 | `cross: false`와 "not cross" 혼용 여부 |
| 참조 앵커 존재 | 없음 | 링크 앵커 해석 검사 (정적 시험) |
| 허브의 owner 질문 | H01 | 기획자 문구를 그대로 전달하지 않고 허브가 직접 확인한 근거를 연결하는지 |

시험 설계 자체는 적절합니다. H01은 허브 입력, 기획자 반환, reviewer 판단을 각각 새 맥락에서 돌리고 원응답을 그대로 넘깁니다. 다만 "필수 행동" 문구가 서술적이라, 원응답에서 무엇을 근거로 통과로 볼지 판정 기준을 더 구체화해야 합니다.

## 4. 1단계 목표 대조

**목표**: 허브는 백로그의 기획, 작성, 관리를 맞춤 기획자에게 위임하고, owner 결정과 별도 독립 판정은 유지한다.

| 구성 요소 | 패치상 판단 |
|---|---|
| 위임 (기획, 작성, 관리) | 새 초안 위임과 기존 백로그 정정 위임이 모두 문서에 있습니다. 문서상 충족입니다. |
| owner 결정 유지 | A-1과 A-3은 허브가 owner에게 올리고 기획자 결정을 금지합니다. 다만 분류를 기획자가 하는 경계는 약점입니다(위험 1). 문서상 대체로 충족입니다. |
| 별도 독립 판정 유지 | 새 초안에 한해 명시되어 있습니다. 기존 백로그 정정, 수정본, 일반 대형 문서에서는 약하거나 공백입니다(위험 2, 4). 부분 충족입니다. |

**현재 판정**: 문서상 목표 방향과 일치하고 핵심 구조는 갖췄습니다. 독립 판정은 새 초안 경로에서만 확실하고, 정정과 재검토 경로에는 공백이 있습니다. 이 판정은 달성을 확인한 것이 아니라 문구가 목표를 표현하는지 대조한 것입니다.

## 5. 관측의 한계

- 이 패치로는 에이전트가 실제로 이 지침을 따르는지 볼 수 없습니다. 달성 여부는 시나리오 실행의 원응답으로만 관측됩니다.
- 참조된 BP-02/06/07/08/09 정의, 결정 권한 A/B1/A-1/A-3, `goal-review.md` 본문이 없어서 위임 입력, 반환 형식, 앵커 유효성을 판단할 수 없습니다.
- 패치 밖의 기존 규칙과 충돌하는지 알 수 없습니다. 예를 들어 `pace backlog new`를 기획자 세션이 실행할 권한이 있는지는 확인되지 않습니다.
- `scenarios.md`의 H01–H06은 시험 기대일 뿐 결과가 아닙니다. 통과나 실패 증거는 없습니다.
- 일반 정정과 범위 영향의 경계처럼 판단이 필요한 부분은 문장만으로 옳고 그름을 확정할 수 없습니다.

다음 단계에서 계약이나 결과 증거를 받으면 위 항목 중 확인 가능한 것부터 다시 대조하겠습니다.
