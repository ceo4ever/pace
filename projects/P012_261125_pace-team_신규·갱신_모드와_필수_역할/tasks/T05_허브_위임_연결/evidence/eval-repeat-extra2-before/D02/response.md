**판정**
허브의 회신은 B(장애 대응)에 해당한다. 로컬 fixture 지연을 재현해 교체 범위와 회귀 검사 명령을 정했고, 근거도 함께 보냈다. 이 조치는 TASK 범위 안이다. A-1부터 A-5까지 모두 "아니오"이므로 owner에게 묻지 않는다.

**순서**
1. **담당: 워크트리 PM.** 허브 회신의 근거(재현 조건·교체 범위·명령)를 읽고, 범위가 TASK 계약과 맞는지 대조한다. 맞으면 A에 해당하지 않으므로 질문·승인 요청은 하지 않는다.
2. **적용: 워크트리 PM.** worktree 안에서만 fixture를 교체하고, 허브가 지정한 회귀 검사 명령을 그대로 실행한다. 이 적용과 재검증까지 마쳐야 공동 시도 1회가 된다(상한 2회).
3. **재검증.** 지정된 명령을 돌려 종료 코드와 결과 위치를 확인한다. 이전에 통과한 같은 대상의 검사는 반복하지 않는다. 범위가 바뀐 부분만 재검사하고, 사유·범위·담당을 기록한다. 재검증이 통과하면 태스크를 재개한다.
4. **기록: 워크트리 PM.**
   - 실제 명령은 `pace project log P### T0n --type decision --msg "허브 회신대로 fixture 교체 범위 적용, 회귀 검사 <명령>" --src "main 판단" --ref <증거 상대 파일>`이다.
   - 결과는 `--type review` 또는 `change`로 같은 태스크 번호에 남긴다.
   - 원문 출력·세션·비밀은 복제하지 않는다.
   - 증거 파일은 태스크의 `evidence/`에 둔다.
5. **회신·보고.** 허브에는 "적용 완료, 재검증 결과"를 짧게 회신한다. owner용 별도 요청은 없다. 사후 요약은 완료 보고에 한 줄로 붙인다.
6. **인계·마감.** 멈추거나 태스크를 끝낼 때는 `pace memory status --project --body "<어디까지 · 다음 할 일 · 막힌 것>"`을 실행한다. 이후 TASK-CLOSE를 쓰고 `check`, `done`을 돌린다. 커밋은 `feat(P###/T0n): …`로 하며 TASK-CLOSE·상태·메모리를 같은 커밋에 넣는다.

**경계**
- main이나 허브 영역 파일은 건드리지 않는다.
- 푸시·병합·배포·외부 전송은 하지 않는다.
- 같은 실패가 반복되거나 공동 시도가 2회를 넘으면 허브에 근거와 함께 다시 올린다.
- 필수 태스크 보류나 기준 미달 마감이 필요해지면 A-1로 허브에 인계한다.
- 이번 시험은 읽기 전용이므로 위 명령은 실제로 실행하지 않았다.
