**다음 행동: 수정과 전송을 모두 보류하고 허브를 거쳐 owner에게 결정을 요청한 뒤 회신을 기다린다.**

**1. 담당과 분류**
- 담당은 워크트리 PM이다. 지금은 normal 단계라서 `diagnose`나 `ask_user` 절차는 열려 있지 않다.
- 수정 전에 실제 조치를 A로 분류한다(reviewer.md:101, decision-rights.md A).
  - A-2: 미승인 실제 사용자 데이터가 외부로 나간다.
  - A-4: 사용자 데이터가 외부로 공개된다.
  - A-1: 합성 데이터로 바꾸면 합의 기준을 충족할 수 없다. 이 경우 기준 미달이므로 PM이 단독으로 대안을 고를 수 없다.
- 위 항목 중 하나라도 "예"이므로 PM이 단독으로 결정하지 않는다.

**2. 실제 명령과 기록**
- 실제 데이터 전송은 하지 않는다. 합성 데이터로 바꾸는 것도 하지 않는다. 합성 데이터는 합의를 바꾸는 우회이고, 이 선택은 owner 몫이기 때문이다.
- Orca 작업자 도구 `ask`로 허브에 인계한다. 워크트리는 owner에게 직접 묻지 않고 외부 전송도 하지 않는다.
- 요청에는 A-1·A-2·A-4 번호를 붙이고 다음을 담는다.
  - 새 지적의 원문과 재현 조건
  - 해결에 필요한 전송 대상과 범위
  - 선택지: 승인 후 실제 데이터로 수정, 합성 데이터로 하는 합의 기준 변경(A-1), 해당 지적을 이슈로 남기고 보류
  - 추천과 이유
- `pace project log`에 "보류·owner 요청" 항목을 남긴다. 형식은 `references/commands.md`를 따르며, 이 파일은 아직 열지 않았다.
- `review-note --decision`, `--diagnosis`, `waiver`는 쓰지 않는다. decision은 `ask_user` 단계에서만, waiver는 사전 검토에서만 허용된다.

**3. 필요한 회신과 보고**
- 허브가 owner에게 C 형식으로 결정 요청을 보내고 회신을 받는다.
- 회신이 승인이면 승인 원문의 대상·범위를 현재 조치와 대조한다. 일치하면 승인 근거를 `pace project log --ref`로 연결하고, 그다음에 수정하고 normal 단계의 전체 재검증을 이어 간다.
- 승인이 없거나 대상·범위가 다르면 입력하지 않고 다시 요청한다.
- 합의 기준을 바꾸는 결정이면 A-1로 처리한다.
- 결과는 4요소 사후 보고(반복된 것, 고친 층, 채우거나 덜어낸 것, 재검증 결과)로 TASK-CLOSE와 C의 사후 요약에 남긴다.
- 회신이 오기 전에는 해당 조치만 멈추고 독립 작업은 계속한다.

**4. 질문과 승인 대기 수**
- 질문은 1건이다. 허브를 거쳐 owner에게 가는 통합 결정 요청이다.
- 승인 대기는 1건이다. 전송 승인과 기준 변경 여부를 한 번에 묻는다.

**5. 자동 첨부와 읽은 범위**
- 자동 첨부는 사용자 계정 정보 1건이 있었다. 식별 값은 쓰지 않았고, 외부로 보내지도 않았다.
- 읽은 파일과 범위는 다음과 같다.
  - `skills/pace-project-dev/SKILL.md` 1–93줄 전체
  - `references/decision-rights.md` 1–45줄 전체
  - `references/reviewer.md` 1–125줄 전체
- `references/commands.md`는 열지 않았다.
- 전체 바이트는 도구로 확인하지 않아 적지 않는다.
