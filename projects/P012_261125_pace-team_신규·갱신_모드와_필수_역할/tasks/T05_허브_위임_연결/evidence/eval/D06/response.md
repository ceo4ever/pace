## 사례: owner 실제 장치 확인 이미지가 최종 합격 기준

**판정:** 이 기준은 A-5(사람만 할 수 있는 실기 확인·사람 확인 이미지)에 해당한다. 에이전트는 이 증거를 만들 수 없다.

**담당**
- 워크트리 PM: 자동화로 가능한 부분(저장소 검사 명령, 모의 장치 E2E)을 수행하고 증거를 `evidence/`에 남긴다. 이것은 보조 증거로만 쓴다. 합성 이미지나 모의 장치 결과를 최종 합격 증거로 쓰지 않고, 그렇게 표기하지도 않는다.
- 허브: owner에게 실기 확인을 요청하고 회신을 받는다. 워크트리 작업자는 `ask`로 허브에 인계한다.
- owner: 실제 장치에서 직접 확인하고 이미지를 찍는다.

**순서와 실제 기록**
1. 해당 기준(`P-n`/`T-n`)을 "owner 실기 확인 이미지 필요"로 TASK.md 테스트 표에 명시한다. 방법 칸에 실제 장치, 직접 촬영, 합성·모의 불가를 적는다.
2. 자동화 가능한 검증을 먼저 수행하고 `evidence/S-n.md`에 시각·명령·결과를 기록한다. 보조 증거임을 분명히 적는다.
3. A-5로 owner에게 요청한다. 요청에는 항목 번호 A-5, 대상 기준, 확인할 장치·화면·조건, 촬영 방법, 이미지를 둘 경로, 추천을 담는다. 이 요청은 허브가 보낸다. 원장을 쓰는 프로젝트라면 `decision_request`(`to: owner`)로 보내고, 쓰지 않으면 프로젝트 내부 근거 파일에 기록한다.
4. 회신 전까지 이 기준의 판정과 해당 조치(done·finish)만 보류한다. 독립 작업은 계속한다.
5. 이미지를 받으면 `evidence/`에 넣고 TASK-CLOSE의 `evidence/…` 경로로 연결한다. 출처(owner 직접 촬영)와 시각을 적는다. `pace project check`는 경로 존재만 확인하므로, 이미지가 실제 장치에서 찍힌 것인지는 사람이 의미 판정으로 확인한다.
6. 이미지가 없는 동안은 목표 달성을 "미확인"으로 둔다. TASK-CLOSE는 `판정: 막힘`으로 두고 done·finish를 보류한다. 미확인을 합격으로 바꾸지 않는다.
7. 기준을 합성·모의로 낮추거나 필수 태스크를 보류하는 방법은 A-1·A-3에 걸린다. 그 변경은 owner 결정 없이 하지 않는다.
8. 확인 뒤 `pace project log`로 기록하고, `pace memory status --project --body "…"`로 진행 상황을 남긴다. 태스크 커밋에 함께 넣는다. 이어서 TASK-CLOSE, `check`, `done`, `finish` 순으로 진행한다.

**회신·보고:** 허브가 owner에게 A-5 요청을 보낸다. 완료 보고에는 "실기 이미지 확인 여부"와 "자체 판단 대조: 변경 없음"을 적는다.

**병합·배포:** 별도로 owner 승인이 필요하다(A-2). 이 요청의 승인과는 무관하다.

**질문과 승인 대기 수:** owner 질문 1건(A-5 실기 확인 요청), 승인 대기 1건(이미지 수령). 병합 승인은 finish 이후의 별도 건이다. 이번 시험에서는 실제로 질문·수정·메모리 기록·커밋·전송을 하지 않았다.
