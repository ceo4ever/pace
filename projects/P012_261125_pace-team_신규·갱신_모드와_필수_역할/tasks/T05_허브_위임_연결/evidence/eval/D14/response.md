**사례: 허브가 재현한 하네스 도구의 작은 결함 (병합 대기 프로젝트 없음)**

**담당**
- 허브 PM이 main에서 처리한다. 근거는 decision-rights B-3, A-2의 S1 위임, AGENTS.md의 위임이다.
- 워크트리 작업자는 수정하지 않는다. 막힌 조치만 보류하고 독립 작업은 이어간다.

**순서**
1. 수정 전에 A-1~A-5를 대조한다. 합의 변경, 외부 영향, 안전 기준 약화(A-3, 보안 검사·테스트·검토를 약화하는 수정인지 포함), 사용자 자산, 사람 수행 필요 여부다. 모두 "아니오"여야 owner 질문 없이 진행한다.
2. 재현 조건과 증거를 확인한다. 허브가 이미 재현했으므로 이를 근거로 쓴다.
3. 작은 수정이면(diff를 한 문장으로 말할 수 있으면) 프로젝트 없이 main에서 바로 고친다.
4. 저장소 검사 명령을 실행하고 통과하면 main에 커밋한다. 병합 대기 프로젝트가 없으므로 커밋을 미루지 않는다.
5. 필요하면 main에서 재설치한다. AGENTS.md에 위임돼 있으므로 이 재설치도 승인 없이 한다.
6. 수정 뒤 재현 조건으로 재검증한다.
7. 백로그나 프로젝트 원본 문서를 직접 편집했다면 커밋 전에 `pace backlog refresh`를 실행한다.

**기록과 회신**
- 작업자에게 결정, 근거, 재검증 기준을 회신한다. 작업자는 이를 "(main 판단)"으로 기록하고, 적용 뒤 재검증해서 태스크를 재개한다.
- 허브 결정은 "(main 판단)"으로 기록한다. `pace project log`를 쓸 때는 `references/commands.md`의 형식을 따른다. 이 파일은 읽지 않았다.
- 허브 회신, 워크트리 적용, 재검증을 마치면 공동 시도 1회다. 상한은 2회다. 2회가 지나도 풀리지 않으면 안전하게 되돌릴 수 있는 차선을 고른다. 필수 태스크 보류나 기준 미달 마감이 되면 A-1로 owner에게 요청한다.
- owner에게는 사후 요약 한 줄만 다음 대화나 완료 보고에 붙인다.
- 진행 상황은 `pace memory status --project --body ...`로 갱신한다.

**질문·승인 대기**
- 질문은 0건, 승인 대기도 0건이다.
- push, merge, 배포는 이 사례에 포함되지 않는다. 필요해지면 허브가 owner 승인을 받고 실행 전 확인을 거친다.
- 수정이 A에 걸리면 해당 조치만 보류하고 owner에게 A 번호를 붙여 요청한다.

**자동 첨부와 읽은 범위**
- 자동 첨부된 것은 사용자 계정 정보를 담은 system-reminder 컨텍스트와 PACE-BOOT 훅 안내다. 식별 값은 쓰지 않는다.
- 직접 읽은 파일은 두 개다.
  - `skills/pace-project-dev/SKILL.md` 1~93줄, 전체.
  - `skills/pace-project-dev/references/decision-rights.md` 1~46줄, 전체.
- 전체 바이트는 도구로 확인하지 않았으므로 적지 않는다.
- 다른 사례의 응답, 평가표, TASK, 마감 문서는 읽지 않았다.
- 수정, 질문, 메모리 기록, 커밋, 전송은 하지 않았다.
