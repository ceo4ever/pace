## 사례: finish 통과 뒤 `자체 판단`이 백로그 합의와 어긋남

**담당**
- 대조는 worktree PM(작업자)이 맡는다. 근거는 SKILL §4-3이다.
- 결정은 owner가 한다. A-1(합의 변경)에 해당한다. 백로그 합의는 "분리"인데 "BR03 범위의 references 분리 생략"은 결과 축소이기 때문이다.
- 작업자는 owner에게 직접 묻지 않고 `ask`로 허브에 인계한다. 허브가 C 형식으로 owner에게 요청한다.

**순서**
1. `worker_done`과 완료 보고 전에 log.jsonl의 `자체 판단` 항목들을 읽는다. 이것을 백로그와 PROJECT.md의 목적·기준 `P-n`·범위와 대조한다.
2. 이 생략 항목은 합의를 바꾼 것으로 판정한다. 같은 판단이라도 PM이 단독 결정하면 안 된다.
3. 허브에 `ask`를 보낸다. 내용은 다음과 같다.
   - A-1 번호
   - 대상: BR03 references 분리 생략
   - 근거: 백로그 합의는 분리, log의 `자체 판단`은 생략
   - 선택지: (a) 분리를 수행한다. (b) owner가 범위 축소를 승인한다.
   - 추천: (a). 합의가 분리이고, 되돌릴 수 있는 쪽이며, 승인 없이 줄이면 안 된다.
4. 이 조치(완료 보고·`worker_done`)만 보류하고, 독립 작업이 있으면 계속한다.
5. 회신에 따라 진행한다.
   - (a)면 분리를 구현한다. 그 뒤 `pace project finish P###`를 다시 돌리고, §4-3 대조를 다시 한 뒤 보고한다.
   - (b)면 승인 원문과 출처를 프로젝트 근거 파일에 연결한다. 결정 메모에 기록하고 `pace project log`로 남긴다. 그 뒤 보고한다.
6. 보고에는 대조 결과, owner 회신, 해당 사후 요약을 적는다. 합의를 바꾼 것이 없었을 때만 "대조: 변경 없음"이라고 쓸 수 있다. 이번에는 그 문구를 쓸 수 없다.

**실제 명령·기록**
- `ask`(허브 인계)
- (a)인 경우 `pace project finish P###` 재실행
- `pace project log`
- `pace memory status --project --body …`

**경계**
- merge와 `--yes`는 허브가 owner 승인 뒤에 한다. 작업자는 하지 않는다.
- 병합 대기 중에는 main 커밋을 병합 뒤로 미룬다.
- finish가 통과했다는 이유로 합의 위반을 덮지 않는다.

**대기 수**
- 질문 1건(허브 경유 owner A-1 요청)
- 승인 대기 1건(그 회신)
- 이후 merge 승인은 별도로 있다.
