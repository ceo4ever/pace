## 공통 전제
- 공동 시도 2회(허브 회신 → 워크트리 적용 → 재검증)가 모두 실패했으므로 상한에 도달했다. 근거는 `decision-rights.md` B-4다.
- 이 답변은 읽기 전용이다. 아래 명령과 기록은 실제로 실행하지 않았다.

## 옵션 1: 계약상 명시된 선택 태스크 보류 (독립 태스크 남음)
- **담당:** 허브가 맡고 워크트리 PM이 같이 처리한다. A-1~A-5 어디에도 해당하지 않으므로 PM이 결정한다.
- **실제 행동:**
  1. 해당 선택 태스크만 `보류`로 둔다.
  2. 장애는 이슈로 기록한다.
  3. 근거를 `pace project log`로 남긴다. 허브 결정은 "(main 판단)"으로 적는다. 정확한 형식은 `commands.md`에 있는데, 이번에는 열지 않았다.
  4. 남은 독립 태스크를 표의 맨 앞 `대기`부터 이어서 수행한다.
- **회신·보고:** owner에게 사전 질문은 하지 않는다. C의 사후 요약에 "선택 태스크 보류, 근거, 실제 결과"를 한 줄로 붙인다. 이 요약은 다음 대화나 완료 보고에 넣는다.
- **재개 조건:** 도구 수정, 환경 복구, 결정 증거 중 하나가 생기면 보류 태스크를 재개한다.
- **대기 수:** 질문 0, 승인 대기 0.

## 옵션 2: 필수 태스크 보류 후 필수 결과 없이 마감
- **담당:** 작업자가 `ask`로 허브에 넘기고, 허브가 owner에게 요청을 보낸다.
- **판정:** A-1(합의 변경)에 해당한다. 필수 태스크 보류와 기준 미달 마감이 모두 '예'다.
- **실제 행동:**
  1. 마감과 `finish`를 진행하지 않는다. 이 조치만 보류한다.
  2. 독립 작업이 있으면 계속한다.
  3. 필수 결과가 미확인이면 보완 관측으로 먼저 증거를 확인한다.
  4. 마감 판단 전에 `PROJECT.md`와 실제 결과를 대조한다.
- **회신·보고:** 허브가 C 형식으로 `decision_request`(`to: owner`)를 보낸다. 내용은 다음과 같다.
  - A-1 번호
  - 대상과 근거 (두 차례의 시도 기록과 증거)
  - 선택지 (필수 태스크 보류, 기준 변경, 다른 해결책)
  - 추천안과 그 이유
- **회신 이후:** 원장을 쓰면 `decision_reply`를 같은 지문으로 연결한다. 원장을 쓰지 않으면 프로젝트 내부 근거 파일에 원문과 출처를 남긴다. 회신 뒤에는 게이트 요건과 현재 계약을 다시 확인하고 그에 맞게 진행한다. 원인이 풀리면 태스크를 재개한다.
- **대기 수:** 질문 1(owner에게), 승인 대기 1(A-1 회신).
