**시험 답안: worktree 작업자, 태스크 표에 T01 `대기`**

**담당**: 이 세션이 worktree 작업자 겸 PM이다. 태스크 계약 안의 실행은 이 세션이 맡는다. 허브와 owner 몫인 병합, 푸시, 배포, A 항목 결정은 하지 않는다. 부트 hook은 pace agent가 호출한 자식 세션이라 부트를 생략한다.

**순서와 실제 명령·기록**
1. **분석**
   - 표의 `대기` 중 맨 앞인 T01을 잡는다.
   - `pace project task P### "<표의 이름 그대로>"`를 실행한다. 이 명령이 `tasks/T01_<이름>/TASK.md`를 만들고 표 상태를 `진행`으로 바꾼다.
   - TASK.md에 목적과 재료를 쓴다. T01이 첫 태스크라 앞 TASK-CLOSE의 "남긴 것"은 없다.
2. **설계**
   - TASK.md에 증명 범위·판정 주체, 기준 `T-n`, 테스트 표(기준마다 시나리오 한 줄 이상), 접근을 쓴다.
   - 기준 문서는 standards.md로 고른다.
   - 코드를 바꾸면 언어 색인의 안티패턴을 테스트 표와 접근에 대조한다.
3. **구현 전 검토**
   - 작성 PM과 다른 제공자의 reviewer에게 `pace agent verify`로 TASK.md를 검토받는다.
   - blocking은 고친 뒤 `verify`를 다시 불러 pass(blocking 0)를 받는다. 사용자 결정 waiver가 있어도 통과한다.
   - 대상, 판정, 지적 처리, 검토 방식을 태스크 기록에 남는다.
   - 다른 제공자를 호출할 수 없으면 이유와 미실행을 기록하고 `--allow-same-provider`로 진행한다. 이 검토는 `cross: false`로 기록한다.
   - 양쪽 다 미실행이면 A-3이므로 `ask`로 허브에 인계하고 이 관문만 보류한다.
   - 이 단계가 끝나기 전에는 구현하지 않는다.
4. **구현**
   - 주변 코드 스타일을 따른다.
   - 버그면 실패하는 테스트(RED)부터 쓴다.
5. **테스트**
   - 저장소 검사 명령과 E2E를 수행한다.
   - tester와 reviewer를 새 맥락으로 병렬 배정한다. reviewer는 사전 검토와 별도로 연다.
   - 출력에 `escalation`이 있으면 먼저 따른다. 없으면 fail·blocking을 고치고 둘 다 다시 돈다.
6. **마감**
   - TASK-CLOSE.md를 쓴다. "리뷰"에는 차수별 한 줄과 교본 대조 한 줄을 넣는다.
   - `pace project check P### T01`을 통과시킨 뒤 `pace project done P### T01`을 실행한다.
   - `pace memory status --project --body "<어디까지 · 다음 할 일 · 막힌 것>"`을 실행한다.
   - 커밋 `feat(P###/T01): …`에 TASK-CLOSE, 상태, 메모리를 같은 커밋으로 넣는다.
   - 원본 문서를 직접 편집했다면 커밋 전에 `pace backlog refresh`를 실행한다.
7. 다음 `대기` 태스크로 넘어간다. 모두 `완료`거나 `보류`면 PROJECT-CLOSE.md(목표 달성 판정 포함)를 쓰고 `pace project finish P###`를 실행한다. 이어서 자체 판단 대조를 하고 `worker_done`으로 끝낸다.

**필요한 회신·보고**
- 허브에는 막힌 결정이나 장애만 `ask`나 `escalation`으로 보낸다. 같은 실패가 3회 나거나 A 항목에 걸릴 때가 해당한다.
- 허브 회신은 "(main 판단)"으로 기록하고 재검증 뒤 재개한다.
- A 밖의 결정은 PM이 근거를 기록하고, 완료 보고의 사후 요약에 한 줄씩 담는다.
- 완료 보고에는 "대조: 변경 없음" 또는 변경 내용을 적는다.

**경계**
- main에서 worktree 파일을 절대 경로로 고치지 않는다.
- merge, 푸시, 배포는 허브가 owner 승인 뒤에 하고, 이 세션은 하지 않는다.
- 병합 대기 중에는 main 커밋을 미룬다.
- 기준 `P-n`, 목적, 범위를 바꾸는 일은 A-1이므로 `ask`로 올린다.

**질문 수와 승인 대기 수**
- 지금 시점의 사용자 질문은 0건, 승인 대기는 0건이다. 착수 결정은 이미 끝났고 start도 끝났다.
- 구현 전 reviewer pass는 게이트이지 사용자 승인 대기가 아니다.

**자동 첨부와 읽은 범위**
- 자동 첨부는 있었다. 사용자 계정 정보가 담긴 system-reminder이며, 값은 적지 않는다. 이번 판단에는 쓰지 않았다.
- 읽은 파일과 줄 범위는 다음과 같다.
  - `skills/pace-project-dev/SKILL.md` 1–93줄
  - `references/task-steps.md` 1–11줄
  - `references/decision-rights.md` 1–45줄
- 전체 바이트는 도구로 확인하지 않아 적지 않는다.
- 다른 사례의 응답, 평가표, TASK, 마감 문서는 읽지 않았다.
