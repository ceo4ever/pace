## 공통 사항

- **담당**: 워크트리 PM이 입력자입니다. `review-note --by user`와 `waiver`는 워크트리 PM이 입력합니다. owner에게 다시 묻는 일은 허브가 전달합니다. 이번에는 owner가 이미 답했으므로 추가 질문은 없습니다.
- **입력 전 대조**: 입력하기 전에 owner 답변 원문과 현재 대상(경로·해시)을 대조합니다. 원문이 없거나 조건·대상이 다르면 입력을 보류하고 해당 A 번호로 다시 요청합니다.
- **근거 파일**: 근거는 `evidence/<승인 근거>.md`에 영수증으로 둡니다. 영수증에는 답 ID·지문·출처를 담습니다.
- **추가 승인 조건**: 수정에 미승인 실제 사용자 데이터 전송이 필요하면 그 승인을 먼저 받습니다. 승인 원문 근거는 `pace project log --ref`로 연결합니다.
- **질문·승인 대기**: 세 경로 모두 0건입니다. 단, 원문이나 대상이 맞지 않으면 1건이 생깁니다.

## ① 고치고 다시 검토

1. 수정 직전의 대상 해시 또는 "diff 없음"을 기록합니다.
2. `pace agent review-note --target <대상> --decision --by user --choice "고치고 다시 검토" --summary <사유> --file <영수증>`을 실행합니다.
3. 수정합니다. 수정 전에 실제 조치를 A로 한 번 더 분류합니다.
4. `pace agent verify`로 **전체 검토**를 받습니다. 직전 지적으로 purpose를 좁히지 않습니다.
5. **보고**: 6요소 보고는 수정 전에 이미 나갔어야 합니다. 이번에는 결정 원문, 승인 직전 해시, 승인 뒤 첫 수정 기록을 연결합니다.
6. 같은 영역이 또 지적되면 원인 층을 다시 진단합니다.

## ② 고치고 구현 진행 (사전 검토)

1. user decision을 기록합니다. 명령은 ①과 같고 `--choice`만 "고치고 구현 진행"으로 바꿉니다.
2. TASK.md를 수정합니다.
3. 안내된 node 명령으로 수정 후 TASK 해시를 구합니다. 그 해시가 owner가 승인한 대상인지 확인합니다. 승인 범위를 벗어났으면 재요청합니다.
4. `PRE-REVIEW.json` 최상위에 `waiver`를 추가합니다.
   - 값은 `{"by":"user","date":"2026-11-25","reason":…,"evidence":…,"hash":<수정 후 해시>}`입니다.
   - 원장에서 옮겨 적은 attempts 이력은 그대로 둡니다.
5. 실행된 검토(pass·fail)가 하나라도 있어야 waiver가 성립합니다. 이번에는 fail이 있었으므로 충족합니다.
6. waiver 이후 TASK를 바꾸면 waiver는 무효입니다. 바꿨다면 재검토를 받습니다.
7. 구현으로 진행합니다. 기준과 안전 항목은 이후 구현 후 검토와 테스트에서 다시 확인합니다.
8. **보고**: 6요소 보고와 승인 원문 연결은 ①과 같습니다. 사후 요약은 TASK-CLOSE 리뷰 절에 남깁니다.

## ③ 이슈로 남기고 마감 (구현 후)

1. user decision을 기록합니다. 명령은 ①과 같고 `--choice`만 "이슈로 남기고 마감"으로 바꿉니다.
2. waiver는 쓰지 않습니다. waiver는 사전 검토 게이트 전용입니다.
3. TASK-CLOSE 리뷰 절에 decision과 원문을 연결합니다. 남은 blocking은 이슈와 "남긴 것"에 기록합니다. 사용자 데이터 취급은 필수 안전 항목이므로 내용과 영향을 구체적으로 적습니다.
4. **계약 목표**: 목표가 미달이거나 미확인이면 `판정: 막힘`으로 두고 done하지 않습니다. 보완 관측이나 수정을 요청하고, 범위를 바꿔야 하면 A-1로 처리합니다. 목표가 달성돼 있으면 `pace project check P### T0n`, `pace project done P### T0n`, `pace memory status --project`, 커밋 `feat(P###/T0n): …` 순으로 진행합니다.
5. **보고**: 사후 요약 4요소(무엇이 반복됐는지, 고친 층, 채우거나 덜어낸 것, 재검증 결과)를 TASK-CLOSE와 C의 사후 요약에 남깁니다. 아직 고치지 않은 부분은 "미재검증"으로 밝힙니다.

## 자동 첨부와 읽은 범위

- **자동 첨부**: 사용자 계정 정보(이메일)가 시스템 컨텍스트로 자동 첨부됐습니다. 값은 쓰지 않았고 어떤 외부 요청에도 넣지 않았습니다.
- **읽은 파일**: 모두 `skills/pace-project-dev/` 아래 파일입니다.
  - `SKILL.md` 1–93줄 전체
  - `references/reviewer.md` 1–125줄 전체
  - `references/decision-rights.md` 1–45줄 전체
- **읽지 않은 것**: 다른 사례의 응답·평가표·TASK·마감 문서는 읽지 않았습니다.
- **전체 바이트**: 도구로 확인하지 않아 적지 않습니다.
- **실행한 행동**: 수정·질문·메모리·커밋·전송은 하지 않았습니다.
