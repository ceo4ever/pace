**순서 (진단 기록 직후, normal 단계)**

1. **담당**: 워크트리 PM이 직접 진행한다. 허브 인계나 사용자 질문은 하지 않는다. 진단 단계의 근본 조치는 이미 A 분류와 B 허브 결정을 거쳐 확정됐다.
2. **조치 적용**: 확정된 근본 조치를 적용한다. 수정 직전에 합의된 목적·범위와 조치의 실제 영향을 한 번 확인한다. 이미 승인된 구체적 조치는 다시 승인받지 않는다. 새 영향이 생기면 그때 A로 다시 분류한다.
3. **`review-note --decision`은 입력하지 않는다.** decision은 다음 verify가 fail로 끝나 `ask_user` 단계가 열린 뒤에만 쓴다.
4. **검증 명령**: `pace agent verify` (구현 전 TASK 검토면 `--kind task`)를 같은 대상 경로로 실행한다. 진단 뒤 첫 verify는 새 기준 전체 검토다.
   - `purpose`에는 합의된 상위 목적과 판정 기준만 넣는다.
   - 이전 지적으로 purpose를 좁히지 않는다.
   - 작성자의 대응이나 자체 판정은 넣지 않는다.
   - 구현 후 검토라면 `evidence/impl-diff.patch`를 같은 경로에서 갱신한다.
5. **결과에 따른 분기**
   - pass(blocking 0): 이어서 진행한다. 사전 검토라면 원장에서 PRE-REVIEW.json으로 옮겨 적는다. 이때 continuity는 `changed`(사유: 진단 뒤 새 기준 전체 검토)로 적는다.
   - fail: 출력의 `escalation`을 따른다. 진단 뒤 첫 fail이면 `ask_user`이므로 그때 분류하고 decision을 기록한다.
   - 종료 10(미실행): 다른 제공자를 다시 확인한다. 안 되면 `--allow-same-provider`로 원장을 잇는다. 주기 중간에 경로를 섞지 않는다.
6. **기록**: 진단 증거 원문과 `review-records/R<n>.json`을 연결해 `pace project log`에 남긴다.
