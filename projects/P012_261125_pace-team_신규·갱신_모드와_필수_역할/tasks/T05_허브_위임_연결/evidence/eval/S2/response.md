**착수 시나리오: "BL261109_03 착수해 줘" (백로그 확정, Orca 밖)**

**읽은 파일**
- `skills/pace-project-dev/SKILL.md`: 전체 1~93줄.
- `references/backlog.md`: 전체 1~28줄.
- 자동 첨부는 있었다. 사용자 계정 정보가 system-reminder로 붙었고, 그 값은 적지 않는다.
- 전체 바이트 수는 도구로 확인하지 않았으므로 적지 않는다.

**담당**
- 이 세션은 main의 PM이다. 규모는 L 프로젝트(백로그 폴더 하나가 프로젝트가 되고, 브리프가 같은 번호의 태스크가 된다)로 본다.
- main에서는 프로젝트 정의와 start까지만 맡는다.
- 이후 프로젝트 수행은 worktree에서 새로 연 세션이 맡는다. 이 세션은 코디네이터가 아니다.

**순서와 실제 명령**
1. `pace project new "<이름>" --from BL261109_03`
   - 번호, 폴더, PROJECT.md가 만들어진다.
   - 앞부분이 모호하거나 브리프 파일을 출처로 주면 거부되므로, 그때는 멈추고 BL 폴더명으로 다시 지정한다.
2. 분석
   - 백로그, 코드 위치, 현재 동작을 읽는다.
   - `new`가 넣은 "- 브레인:" 후보 중 관련 없는 줄은 지운다.
3. 설계
   - 목표를 한 단계 위 목적에 대조한다.
   - PROJECT.md에 목적, 기준 `P-n`, 설계·보안 영향, 바꿀 정본 목록, 태스크 표를 쓴다.
   - 세부는 `references/project-define.md`를 열어 따른다.
4. 착수 결정
   - 백로그 확정이 곧 착수 결정이다.
   - 목적, 기준, 태스크, 출처를 PROJECT.md 결정 메모에 적는다.
   - 승인 답은 기다리지 않는다.
5. 백로그 원본을 직접 편집했다면 커밋 전에 `pace backlog refresh`를 실행한다. 대시보드가 없으면 건너뛴다.
6. `pace project start P###`
   - 정의 커밋, worktree(`../<저장소>.wt/P###`, 브랜치 `project/P###`), 준비 명령이 만들어진다.
   - 작업자 도구는 `--agent` > PROJECT.md `- 작업자:` > 정의서 > 현재 세션 도구 순으로 고른다.
   - 받을 수 없는 이름이면 worktree를 만들기 전에 거부된다.
7. Orca 밖이므로 start 출력에 나온 명령으로 worktree에서 새 세션을 열도록 안내한다. 이 세션이 태스크를 직접 수행하지 않는다.

**경계**
- main에서 worktree 파일을 절대 경로로 고치지 않는다.
- 백로그처럼 큰 산출물은 작성자와 다른 제공자의 에이전트가 독립 검토한다(`cross-verify.md`). 이 사례는 확정된 백로그를 실행하므로, 검토 필요 여부는 설계 단계에서 판단해 기록한다. 이 부분은 참조 문서를 열어 보지 않아 불확실하다.
- merge와 배포는 하지 않는다. 사람 승인 뒤에 허브가 수행한다.
- 이번 시험은 읽기 전용이라 위 명령을 실제로 실행하지 않는다.

**회신·보고**
- 사용자에게 한 번 보고한다. 담을 내용은 프로젝트 번호, 결정 메모 요약, worktree 경로, 새 세션을 열 명령이다.
- 보고에는 "승인 대기 없음"을 명시한다.

**질문·승인 대기 수**
- 질문 0건, 승인 대기 0건이다.
- 이후 기준이나 범위가 바뀌거나 결정 권한 A에 걸리면 그때 묻는다.
