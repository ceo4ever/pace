**역할: main 허브**입니다. 아래는 `skills/pace-intent/SKILL.md`를 읽고 정리한 내용이며, 실제로 실행한 작업은 없습니다.

## 판단

**1. 지금은 폴더를 만들지 않습니다.**
- ⑨의 근거는 "propose a route with a one-line reason, wait for confirmation, then create. Nothing is written before the user confirms."입니다.
- C 경로 행에도 "Once purpose and scope are fixed, ask for the write and end the turn. After the user's reply, the hub delegates…"라고 적혀 있습니다.
- C 경로와 초안 목적·범위는 사용자와 합의했습니다. 하지만 저장소에 쓰는 것은 별도 확인 대상이고, 사용자가 아직 답하지 않았습니다.
- 다른 참여자의 "시간을 아끼자"는 요청은 사용자의 확인이 아닙니다. 폴더 생성도 쓰기이므로 "Nothing is written" 규칙에 해당합니다.
- 다른 저장소에 쓰는 경우라면 Edge cases의 "Writing into another repository: confirm with the user first"도 적용됩니다.

**2. 허브가 직접 초안을 쓰지도 않습니다.**
- 사용자가 확인한 뒤에는 허브가 저장소의 백로그 기획자에게 생성과 초안 작성을 위임합니다(BP-09).
- 저장소에 기획자가 없을 때만 허브가 승인된 초안을 직접 처리하고, 같은 검토를 적용합니다.
- 지금은 그 이전 단계입니다.

**3. ⑧ 교차 검토도 아직 시작하지 않습니다.**
- ⑧은 "after the route and its write are confirmed" 이후에, 기획자가 돌려준 초안을 검토하는 단계입니다.
- 쓰기 확인이 없으면 초안이 없으므로 검토할 대상도 없습니다.
- 확인 후에는 허브가 독립 검토자를 배정하고, 결과를 받아 기획자에게 수정을 라우팅합니다.
- 다른 provider를 쓸 수 없으면 그 사유를 기록하고, 새 독립 same-provider 세션을 `cross: false`로 표시해 씁니다.
- 둘 다 불가능하면 초안을 받아들이기 전에 허브가 A-3 결정을 요청합니다.

## 도구 적용

- 사용자에게는 ④의 형식에 맞춰 질문 하나만 합니다.
  - 도구 UI에서는 `AskUserQuestion`에 질문 1개를 넣습니다. 일반 텍스트라면 마지막 선택지를 `직접 입력`으로 둡니다.
  - 선택지는 2~4개이고, 첫 번째에 `(추천)`과 한 줄 이유를 붙입니다.
  - 이 답이 무엇을 바꾸는지 한 줄로 적습니다.
  - 선택지 예시는 다음과 같습니다.
    1. "C 백로그 초안을 저장소에 작성 (추천)": 합의한 목적·범위가 확정됐고, 승인해야 기획자에게 위임할 수 있습니다.
    2. "작성 전에 범위 수정"
    3. "직접 입력"
  - 선택 옵션 외에 "있으면 같이 적어 주세요" 같은 추가 요청은 넣지 않습니다.
- 질문을 한 뒤에는 그 턴을 끝내고 답을 기다립니다.
- 다른 참여자에게는 "저장소 쓰기는 사용자 확인 후에 진행한다"고 짧게 알립니다.
- 이 단계에서 쓰는 도구는 읽기 전용(Read/Glob/Grep)뿐입니다. 쓰기·`pace` 명령·위임 호출은 사용하지 않습니다.

## 사용자가 답한 뒤의 순서

- **승인:** 백로그 기획자에게 생성과 초안 작성을 위임합니다. 이어서 ⑧에 따라 독립 검토를 진행합니다.
- **범위 수정:** 합의 내용을 고친 뒤 다시 확인을 요청합니다.
- **거절 또는 보류:** 아무것도 쓰지 않습니다.
