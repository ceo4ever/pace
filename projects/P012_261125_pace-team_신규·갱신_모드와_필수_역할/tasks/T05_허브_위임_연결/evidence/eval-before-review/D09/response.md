**자동 첨부와 읽은 범위**
- 사용자 이메일 컨텍스트가 자동 첨부됐다. 값은 쓰지 않고 쓸 일도 없다.
- 읽은 파일:
  - `skills/pace-project-dev/SKILL.md` 1–93줄(전체)
  - `references/decision-rights.md` 1–45줄(전체)
  - `references/verification.md` 1–18줄(전체)
- 전체 바이트는 도구로 확인하지 않았으므로 적지 않는다.
- `commands.md`는 열지 않았다. 그래서 `pace project log`의 정확한 인자 형식은 단정하지 않는다.

**공통 전제**
- 공동 시도(허브 회신 → 워크트리 적용 → 재검증) 2회가 모두 실패해 상한에 도달했다(decision-rights B-4).
- 같은 조치를 세 번째로 시도하지 않는다.
- 재검사도 하지 않는다. 검증 대상이 바뀌지 않았기 때문이다(verification.md).

**옵션 1: 선택 태스크 보류 (계약에 명시됨)**
- **담당:** 워크트리 PM이 결정하고 기록한다. 허브는 사후 요약을 전달한다.
- **판정:** A-1~A-5 모두 "아니오"다. 계약이 이미 허용한 되돌릴 수 있는 차선이기 때문이다.
- **기록:**
  - PROJECT.md 태스크 표에서 해당 태스크를 `보류`로 바꾼다.
  - 근거(2회 시도 결과와 증거)를 `pace project log`에 남긴다. 장애 해결 결정이면 "(main 판단)"으로 표기한다.
  - 장애는 이슈로 기록한다.
- **행동:**
  - 남은 독립 태스크를 표의 `대기` 맨 앞부터 계속한다.
  - 원인이 풀리면 보류 태스크를 재개한다. 풀렸다는 증거는 도구 수정, 환경 복구, 결정 증거 중 하나다.
- **회신·보고:**
  - 허브에는 보류 결정과 근거를 알린다.
  - owner에게는 사후 요약 한 줄을 다음 대화나 완료 보고에 붙인다(C).
- **대기:** 질문 0, 승인 대기 0.

**옵션 2: 필수 태스크 보류 후 필수 결과 없이 마감**
- **담당:** 워크트리 작업자가 `ask`로 허브에 인계하고, 허브가 owner에게 결정을 요청한다.
- **판정:** A-1에 해당한다(필수 태스크 보류, 기준 미달 마감, 결과 축소). 그래서 PM이 단독 결정할 수 없다.
- **행동:**
  - 보류와 마감 조치는 owner 회신까지 실행하지 않는다. `done`, PROJECT-CLOSE 확정, `finish`를 하지 않는다.
  - 목표 미달을 게이트 통과로 덮지 않는다.
  - 독립 작업이 남아 있으면 계속한다.
- **요청 내용(C):**
  - A-1 번호
  - 대상과 근거: 2회 시도 기록과 미충족 `P-n`
  - 선택지
  - 추천과 이유
- **회신 뒤:**
  - 회신 원문과 출처를 근거 파일이나 원장에 연결한다.
  - 게이트 요건과 현재 계약을 다시 확인한다.
  - 필수 결과가 여전히 미확인이면 보완 관측으로 다시 판정하거나, 적법하게 변경된 계약에 따라 판정한다.
- **보고:** 회신 전에는 완료 보고를 하지 않는다. 상태만 `status`나 프로젝트 기록으로 남긴다.
- **대기:** 질문 1(허브 경유 owner 요청), 승인 대기 1(A-1 결정).
