**결정 주체**
- 다른 PM은 결정 주체가 아니다. 이 조치는 owner가 결정한다.
- 근거는 `decision-rights.md`의 A-1과 A-3이다.
  - A-1: P-2 기준 문장을 삭제하면 합의된 완료 기준 `P-n`이 바뀐다. 기준 미달 마감도 '예'에 해당한다.
  - A-3: 요구된 테스트 결과가 미확인인 채 진행하면 필수 증거 없이 진행하는 것이다. 이것도 '예'다.
- 담당 PM이 단독으로 정할 수 없다.

**다음 행동 (순서)**
1. 삭제와 마감을 하지 않는다. `PROJECT.md`는 수정하지 않는다. 해당 조치만 보류한다.
2. 먼저 `PROJECT.md`·브리프의 P-2와 실제 결과를 대조한다. 테스트를 실제로 돌릴 수 있는지 확인하고 보완 관측을 시도한다. 시도해서 결과를 얻으면 삭제가 필요 없다.
3. 그래도 결과가 없으면 owner에게 결정을 요청한다.
   - 담당: 워크트리 작업자라면 `ask`로 허브에 인계하고, 허브가 C 형식으로 owner에게 보낸다. 단독 PM이면 직접 보낸다.
   - 요청 내용: A-1·A-3 번호, 대상(P-2 문장)과 근거, 선택지, 추천과 이유.
   - 선택지: ① 테스트를 수행해 결과를 확보한다(추천). ② 합의를 정식으로 변경해 기준을 바꾼다. ③ 마감을 보류한다.
   - 허브 PM이 요청을 보낼 때의 원장은 프로젝트가 쓰는 방식을 따른다. 원장을 쓰면 `decision_request`(`to: owner`)로, 쓰지 않으면 프로젝트 내부 근거 파일에 남긴다.
4. 독립 작업은 계속한다.
5. 기록과 회신
   - 다른 PM에게는 "owner 결정 사항이라 보류한다"고 회신한다.
   - 결정 요청 내용과 보류 사실을 `pace project log`로 남긴다.
6. owner 회신 뒤에도 게이트 요건은 그대로 적용된다. 결과가 여전히 미확인이면 보완 관측하거나, 적법하게 변경된 계약으로 다시 판정한다. 마감할 때 PROJECT-CLOSE의 목표 달성 판정에서 미확인을 통과로 덮지 않는다.

**대기 수**
