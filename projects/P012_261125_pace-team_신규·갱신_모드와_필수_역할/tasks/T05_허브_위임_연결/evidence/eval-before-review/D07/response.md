**읽은 파일**
- `skills/pace-project-dev/SKILL.md` 1–93줄 전체
- `references/decision-rights.md` 1–46줄 전체
- 다른 references는 열지 않았다. `pace project log`의 정확한 형식은 `commands.md`에 있어서 아래에는 형식 이름만 적었다.
- 자동 첨부는 있었다. 사용자 계정 컨텍스트이고 값은 적지 않는다.
- 전체 바이트는 도구로 확인하지 않아 적지 않는다.

**순서**

1. **담당과 판정 기준**
   - 이 건은 합의 변경 여부를 가리는 A-1 판정이다.
   - 담당은 워크트리 PM(작업자)이다. owner에게 요청이 필요해지면 허브가 전달한다.
   - "선택 결과만 제거"라는 겉모습으로 단정하지 않는다. PROJECT.md와 BR이 필수 결과 문장을 서로 다르게 해석하므로 영향이 불분명한 상태다.

2. **먼저 실제 결과를 대조한다 (읽기·관측만)**
   - PROJECT.md의 목적, 기준 `P-n`, 태스크 표와 BR(브리프)의 필수 결과 문장을 나란히 놓는다.
   - 변경 전후의 실제 산출물이나 동작을 확인해서, 제거되는 결과가 어느 쪽 해석으로도 필수가 아닌지 본다.
   - 이 대조로 영향 범위가 좁혀지는지 확인한다. 범위를 확정하기 전에는 해당 변경만 보류한다.

3. **대조 결과에 따른 분기**
   - **(가) 두 해석 모두에서 선택 결과로 확인되고 합의된 `P-n`에 영향이 없을 때**
     - A-1은 "아니오"다. PM이 결정해 진행한다.
     - 대조 근거와 결정을 `pace project log`에 `자체 판단`으로 기록한다.
     - owner에게는 사후 요약 한 줄만 붙인다(C).
     - 질문 0, 승인 대기 0이다.
   - **(나) 필수 결과가 줄어들거나, 대조 뒤에도 합의 영향 여부를 가릴 수 없을 때**
     - A-1 "예"로 본다. 필수 결과 축소는 합의 변경이다.
     - 해당 변경 조치만 보류한다.
     - 작업자가 `ask`로 허브에 인계한다.
     - 허브가 owner에게 결정 요청을 보낸다. 요청에는 A-1 번호, 대상과 근거(두 문장의 원문 대조), 선택지, 추천과 이유를 담는다.
     - 선택지는 BR 해석 확정, PROJECT.md 수정, 변경 철회 정도다.
     - 질문은 1건, 승인 대기는 1건이다. 대기 대상은 그 조치 하나뿐이다.

4. **별개 태스크는 계속한다**
   - 보류하는 것은 해당 변경뿐이다. 독립 태스크는 `대기` 순서대로 계속 수행한다.
   - 그 변경을 건드리지 않는 범위에서 진행하고, 필요하면 이슈로 기록해 둔다.

5. **owner 회신 뒤**
   - 회신 원문과 출처를 근거 파일에 연결하고 `pace project log`에 기록한다.
   - 승인된 범위로만 반영한다.
   - 합의가 바뀌면 PROJECT.md 기준과 결정 메모를 갱신한다.

6. **마감 때**
   - `finish` 통과 뒤 `worker_done` 전에 자체 판단 결정을 합의와 대조한다.
   - 합의를 바꾼 것이 있으면 보고 전에 §6으로 올린다. 없으면 "대조: 변경 없음"을 보고에 적는다.

**금지 사항**
- 승인 없는 합의 변경은 하지 않는다.
- 해석 차이를 임의로 한쪽으로 확정하지 않는다.
- 필수 결과가 미확인인 채로 마감하지 않는다.
- 이 시험에서는 어떤 수정, 질문, 메모리 기록, 커밋, 전송도 실제로 하지 않았다.

**요약**
- 분기 (가)는 질문 0, 승인 대기 0이다.
- 분기 (나)는 질문 1, 승인 대기 1이다.
