**시험 답변 (읽기 전용, 실행 없음)**

**읽은 범위와 첨부**
- 자동 첨부된 것은 사용자 이메일 컨텍스트 하나입니다. 값은 적지 않으며 외부로 보내지도 않습니다.
- `skills/pace-project-dev/SKILL.md`는 1–93줄 전체를 읽었습니다.
- `references/decision-rights.md`는 1–46줄 전체를 읽었습니다.
- `references/commands.md`는 `--ref` 검색에서 나온 14줄만 봤습니다.
- `docs/HANDOFF.md`는 열지 못했습니다. 검색에 걸리지 않았고 직접 읽지도 않았습니다. 원장 필드의 세부 형식은 확인하지 못했습니다.
- 전체 바이트 수는 도구로 확인하지 않았으므로 적지 않습니다.

**담당**
- 푸시는 A-2(외부 영향) 조치입니다. 승인은 owner가 하고, 입력과 실행은 허브 PM인 제가 main에서 합니다. 워크트리는 푸시하지 않습니다.

**할 일 순서**
1. 승인 원문과 현재 실행 대상을 한 번 더 대조합니다. 원장의 로컬 본문에 있는 owner 답 원문과 출처를 `decision_request`/`decision_reply`의 같은 요청·제안 지문과 맞춥니다. 원격, 브랜치, 커밋(전체 SHA), 범위도 함께 맞춥니다. 상황 설명대로 모두 일치하므로 이 승인을 재사용합니다. 새 owner 요청은 만들지 않습니다.
2. 푸시를 실행합니다. 허브가 main에서 입력하며, 승인된 원격·브랜치·커밋 그대로만 올립니다. 병합이나 배포는 이 승인에 포함되지 않아 따로 하지 않습니다.
3. 영수증을 남깁니다. 답 ID, 지문, 출처를 담은 짧은 영수증을 만들어 `pace project log P### --type decision --msg "<푸시 한 줄>" --src "main 판단" --ref <프로젝트 내 상대파일>`로 연결합니다. 원문은 원장의 로컬 본문에만 두고 로그에는 요약과 참조만 적습니다. 위임이 있다면 `delegate`의 basis는 `approved`로 씁니다.
4. 병합 대기 중이면 main 커밋은 병합 뒤로 미룹니다. 이 경우 메모리 파일은 갱신하되 커밋은 미룹니다.

**필요한 회신·보고**
- owner에게는 사후 요약 한 줄이면 됩니다: "기존 승인 답 <ID>로 <원격/브랜치/SHA> 푸시 완료". 원장을 쓰므로 상태 안내 `status`로 보냅니다.
- 이 푸시를 요청한 작업자가 있다면 완료만 회신합니다.

**멈춤 조건**
- 대조 중 원문이 없거나 조건·대상·범위가 하나라도 다르면 입력을 보류하고, A-2 번호를 붙여 `decision_request`(`to: owner`)를 보냅니다. 독립 작업은 계속합니다.

**질문·승인 대기 수**
- 질문 0, 승인 대기 0. 이미 일치하는 승인이 있어 추가로 기다릴 것이 없습니다.
