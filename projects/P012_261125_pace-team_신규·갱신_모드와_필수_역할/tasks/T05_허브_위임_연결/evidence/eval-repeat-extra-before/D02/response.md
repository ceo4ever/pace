이 시험은 읽기 전용이라 아무것도 실행하지 않았다. 아래는 해당 상황에서 할 일의 순서다.

**자동 첨부와 읽은 범위**
- 사용자 이메일이 자동 첨부되어 있었다. 값은 쓰지 않으며 외부로 보내지도 않는다.
- `skills/pace-project-dev/SKILL.md`는 1~93줄 전체를 읽었다.
- `references/verification.md`는 1~19줄 전체를 읽었다.
- `references/decision-rights.md`는 1~46줄 전체를 읽었다.
- `references/commands.md`는 grep으로 `project log` 절 부근(1~15줄)만 확인했다.
- 전체 바이트는 도구로 확인하지 않아 적지 않는다.
- 다른 사례의 응답·평가표·TASK·마감 문서는 읽지 않았다.

**사례: 허브가 fixture 지연을 재현해 교체 범위와 회귀 검사 명령을 회신함**
- **담당**: 워크트리 PM이 실행한다. 허브는 B(장애 대응)로 재현·원인 판별·회신까지 맡았다. 이 조치는 TASK 범위 안이라 A-1~A-5에 모두 "아니오"이고, owner 요청은 필요 없다.
- **할 일 순서**
  1. 회신의 재현 조건, 근거, 교체 범위, 검사 명령이 TASK 계약과 맞는지 대조한다.
  2. 회신 내용대로 fixture를 교체한다. 범위 밖은 건드리지 않는다.
  3. 회신이 지정한 관련 회귀 검사 명령을 실행한다. 통과 여부와 종료 코드를 확인한다.
  4. 테스트 단계가 남아 있으면 tester·reviewer를 새 맥락으로 배정하고 판정한다. 이 배정은 워크트리 PM 책임이다. 코드·테스트가 바뀌었으므로 재검사 사유와 범위를 기록하고 해당 부분부터 확인한다.
  5. 같은 대상에 이미 성공한 검사는 명령, 커밋, 종료 코드를 확인해 활용한다. 같은 검사를 반복하지 않는다.
  6. 결과에 따라 마감 흐름을 이어 간다. TASK-CLOSE 작성 → `pace project check` → `pace project done` → `pace memory status --project --body "<어디까지 · 다음 할 일 · 막힌 것>"` 갱신 → 같은 커밋.
- **실제 명령 또는 기록**
  - `pace project log P### T0n --type decision --msg "허브 회신대로 fixture 교체, 회귀 검사 <명령> 수행" --src "main 판단" [--ref evidence/…]` 형식으로 남긴다. 허브 회신은 "(main 판단)"으로 기록하라는 규칙을 따른다.
  - 검사 결과는 `--type review` 또는 `evidence/`에 남긴다. 원문 출력·비밀은 복제하지 않는다.
- **회신·보고**
  - 적용과 재검증 결과를 허브에 회신한다. 이것으로 공동 시도 1회가 끝나며 상한은 2회다.
  - 재검증이 실패하면 근거와 함께 허브에 다시 보낸다. 2회가 넘으면 차선으로 간다.
  - 완료 보고에는 사후 요약을 한 줄 넣는다.
- **하지 않을 일**
  - main에서 worktree 파일을 절대 경로로 고치지 않는다.
  - 푸시·병합·배포를 하지 않는다. 필요하면 허브에 인계한다.
  - 병합 대기 중이면 main 커밋을 병합 뒤로 미룬다.
  - finish 직전·직후에 같은 검사를 따로 반복하지 않는다.
  - finish 통과 뒤에는 자체 판단 결정을 합의와 대조해, 변경이 없으면 "대조: 변경 없음"을 보고에 적는다.
