이 시험은 읽기 전용이라 실제로 실행한 것은 없다. 아래는 순서만 적은 것이다.

**읽은 파일**
- 자동 첨부: 사용자 이메일 컨텍스트가 있었다. 값은 쓰지 않으며 사용하지 않는다.
- `skills/pace-project-dev/SKILL.md` 1–93줄 전체를 읽었다.
- `references/decision-rights.md` 1–46줄 전체를 읽었다.
- `references/verification.md` 1–19줄 전체를 읽었다.
- `references/commands.md`는 Grep으로 `pace project log` 관련 줄(1–15줄 부근)만 확인했다. 전체 바이트는 도구로 확인하지 않았으므로 적지 않는다.
- 다른 사례의 문서는 읽지 않았다.

**사례: 허브가 지연을 재현하고 교체 범위와 회귀 검사 명령을 회신한 경우**
1. **담당**
   - 장애 재현, 원인 판별, 회신은 허브 PM이 이미 끝냈다 (B-1~3).
   - 허브의 회신을 적용하고 재검증한 뒤 태스크를 재개하는 일은 워크트리 PM인 내가 맡는다.
2. **A 판정**
   - 이 조치는 TASK 범위 안이다. 합의, 외부 영향, 안전 기준, 사용자 자산, 사람 수행에 해당하는지 보는 A-1~A-5에 모두 "아니오"다.
   - 그래서 owner에게 요청하지 않는다. 질문 0건, 승인 대기 0건이다.
   - 예외: 교체 범위가 기준 `P-n`을 바꾸거나 검증을 약화하는 것으로 드러나면 그 조치만 보류하고 `ask`로 허브에 인계한다.
3. **기록**
   - 명령: `pace project log P### T0n --type decision --msg "fixture 지연 → 교체 범위·회귀 명령 적용" --src "main 판단" [--ref <프로젝트 내 근거 파일>]`
   - 허브가 전한 근거를 `--ref`로 연결하고 원문이나 비밀은 복제하지 않는다.
   - 표는 손으로 중복 작성하지 않는다.
4. **적용과 재검증**
   - 허브가 정한 교체 범위만 고친다. 범위를 넓히지 않는다.
   - 허브가 지정한 관련 회귀 검사 명령을 그대로 실행한다. 종료 코드와 결과 위치를 확인한다.
   - 변경 범위가 달라졌으므로 재검사 사유, 범위, 담당을 기록한다. 같은 대상의 성공한 검사를 불필요하게 반복하지는 않는다.
   - 이 한 번이 공동 시도 1회다. 상한은 2회다.
   - 결과를 `pace project log … --type review` 등으로 남긴다.
5. **회신·보고**
   - 허브에는 적용 범위, 실행한 명령, 결과, 재개 여부를 짧게 회신한다.
   - 재검증이 실패하면 근거와 함께 허브에 다시 보낸다.
   - 태스크를 재개하고 마감 단계에서 TASK-CLOSE, `check`, `done`을 진행한다.
   - 세션을 멈추거나 태스크를 끝낼 때는 `pace memory status --project`로 진행 기록을 남기고, 같은 커밋에 넣는다.
6. **하지 않는 일**
   - push, merge, 배포는 하지 않는다. 병합은 허브가 owner 승인 뒤에 한다.
   - main의 worktree 파일을 절대 경로로 고치지 않는다.

**대기 수**: 질문 0건, 승인 대기 0건.
