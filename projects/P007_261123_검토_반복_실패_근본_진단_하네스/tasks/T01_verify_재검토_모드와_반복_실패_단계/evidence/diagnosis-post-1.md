# T01 구현 후 검토 3회 실패 진단 (2026-11-23)

- 추이: reviewer blocking 4 → 4(부분 해소) → 3. tester는 3차 pass(결함 42건 중 40 검출).
- 원인 층: 설계. 파일 덮어쓰기 위험(링크·하드링크·기록 폴더 별칭)을 경로 금지 목록으로 하나씩 막아, 별칭이 생길 때마다 새 갈래가 나왔다. 큰 변경의 비교 생략과 pending 복구 안내도 각각 땜질이었다.
- 근본 조치: (1) 기록·--out 쓰기를 같은 폴더 임시 파일 → rename 교체로 바꿔 기존 파일 내용(inode)을 절대 수정하지 않는다 — 링크·하드링크 별칭 덮어쓰기 부류가 통째로 사라지므로 inode 비교를 걷어낸다. (2) 바뀐 줄을 만들 수 없을 만큼 크게 바뀌면 재검토를 실행하지 않고 진단(전체 검토)으로 안내한다. (3) 남은 pending 기록은 판정 불명 — fail로 보고 복구하도록 안내한다(연속 실패를 줄이지 않는다). (4) pending 정리 실패도 종료 2.
- 다음: 진단 뒤 첫 검토. 이후에도 fail이면 캡틴에게 보고하고 결정을 받는다.
