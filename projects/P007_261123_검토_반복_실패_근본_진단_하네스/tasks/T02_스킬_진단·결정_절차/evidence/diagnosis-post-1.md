# T02 구현 후 검토 3회 실패 진단 (2026-11-23, 대상 evidence/impl-diff.patch, 3차 호출에서 stage=diagnose)

- 추이: reviewer blocking 4 → 3 → 3(자동 재검토 R2·R3). tester 3차 fail — 새 `--void`가 diagnose·ask_user 단계를 우회.
- 원인 층: design — 지적마다 원장 밖의 우회로를 더했다(호스트↔verify를 섞으면 PM이 손으로 세기, 단계 무관 `--void`). 원장이 유일한 근거여야 하는데 평행한 상태와 탈출구를 만들어, 우회로마다 원장과 어긋나는 경우(기준점·단계 불일치, 단계 우회, PRE-REVIEW 전사 모순)가 새로 생겼다.
- 근본 조치: 원장을 유일한 근거로 되돌린다.
  1. 같은 대상의 reviewer는 한 주기 동안 경로를 바꾸지 않는다 — 처음부터 verify, verify 미실행(종료 10)일 때만 그 주기 전체를 호스트로(PM이 같은 규칙으로 세어 project log). 섞어 세는 규칙 삭제.
  2. `--void`는 도구가 normal 단계·fail 검토·같은 대상에만 허용 — 열린 단계는 진단·결정으로만 넘어간다. 기준점과 대상이 같아 거부되면 기준점 지적을 반영해야 한다는 뜻(정상).
  3. 무효 검토는 PRE-REVIEW로 옮기지 않는다(원장·기록에 보존).
