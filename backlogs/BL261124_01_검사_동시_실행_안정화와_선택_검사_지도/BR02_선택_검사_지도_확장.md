## 목적

개발 중 빠른 검사(`pace test changed`)가 **바뀐 곳과 관련된 시험만** 돌게 해 전체 검사 횟수와 대기를 줄인다([백로그 목표](BACKLOG.md#목표)). 게이트(태스크·finish)의 전체 검사는 바꾸지 않는다.

## 범위

- `.pace/test-map.json`에 daemon·telegram·agent·project 등 시험 파일이 많은 영역의 단위를 더한다. 단위는 소스 → 시험의 연결이며, import 의존을 따라 **영향을 받는 시험을 빠뜨리지 않는 쪽**으로 묶는다(예: daemon runner가 agent를 쓰면 agent 변경은 daemon 시험도 고른다). 확신이 없으면 지금처럼 전체 검사로 넘어가는 동작을 유지한다.
- 연결 근거를 남긴다: 단위마다 어떤 import·호출 때문에 그 시험을 골랐는지 짧게(test-map 옆 문서 또는 docs/TESTING.md).
- 브라우저 E2E: **게이트(태스크·finish)의 전체 검사에서는 지금처럼 실행한다** — 이 브리프는 게이트 범위를 줄이지 않는다. 범위는 개발 중 선택 검사(`pace test changed`)에서 브라우저 E2E를 브라우저 관련 변경일 때만 고르는 것까지다. Orca 안에서 E2E가 사용자 탭을 여는 문제는 게이트 범위를 보존하는 **실행 환경 격리**(사용자 탭과 분리된 브라우저 맥락에서 실행)로 다루고, 이 브리프에서 해결할 수 없으면 별도 과제로 올린다. 게이트에서 E2E를 줄이는 방안은 합의 변경이라 사용자에게 먼저 묻는다. 지금의 프로젝트 메모리 규칙(`PACE_SKIP_BROWSER_E2E=1`)은 게이트가 아닌 수동 확인 검사에만 쓴다고 명시한다.
- 제외: 게이트의 전체 검사 축소, 시험 안정화(BR01).

## 완료 기준

- 대표 변경 예시(daemon 어댑터 한 줄, agent verify 한 줄, project harness 한 줄, telegram 상태 한 줄, 문서만)마다 **기대 선택 집합을 먼저 정한다** — 직접 import, 전이 import, CLI·하위 프로세스 호출로 그 소스를 실행하는 시험까지 근거와 함께. 그다음 실제 선택 목록과 대조해 누락 0이고, 기대 밖의 추가 시험은 0이며(새 영향 경로가 확인되면 근거와 함께 기대 집합을 갱신하고 다시 대조한다 — 사후 설명으로 통과시키지 않는다), 예시가 전체 검사로 넘어가지 않는다(대조 표). 공통·미분류 변경이 전체 검사로 넘어가는 동작은 별도 사례로 확인한다.
- 이 대조는 지도가 **기준 브랜치에 반영된 상태에서 정상 개발 명령**(`pace test changed`)으로 한다 — 기준 브랜치의 test-map을 읽는 동작 그대로.
- 단위 추가 전후 `pace test changed`의 평균 실행 시간·시험 수 비교가 기록된다.
- 브라우저 E2E 실행 조건이 문서에 있다: **개발 중 선택 검사(`pace test changed`)**에서는 브라우저 관련 변경이나 명시 옵션일 때만 고른다. **게이트(`pace project check`·`done`·`finish`의 전체 검사)**에서는 브라우저와 무관한 변경이어도 E2E가 실제로 실행된다 — 브라우저와 무관한 변경 하나로 게이트 전체 검사를 돌려 E2E 시험이 건너뛰지 않고 실행된 기록을 남긴다(격리를 별도 과제로 올려도 이 조건은 유지).
