# BR04 독립 검증 세션 기록 관문

- 상태: 대기
- 백로그: [허브 PM main 직접 프로젝트 하네스 정비](BACKLOG.md)

## 목적

검증자(reviewer)·tester를 구현자와 **다른 별도 에이전트 세션**이 맡았다는 사실을 하네스가 기록·확인해, 기록이 없거나 구현 세션이 스스로 검증한 프로젝트는 마감하지 못하게 한다. 태스크 유무와 관계없이 적용한다. 새 장치보다 기존 사전 검토 관문(`PRE-REVIEW.json`, `src/project/pre-review.ts`)과 `pace project log --type review`를 넓히는 쪽을 우선한다.

## 범위

- 검증 기록 형식: 역할(reviewer·tester), `pace agent` 결과 파일 경로(세션·제공자·모델 출처 — BACKLOG 공통 계약 2-3), **검토 대상 내용 해시**(공통 계약 2-1, 태스크면 그 태스크 변경), 판정(pass·fail·blocking/should_fix 수), 대체 사유·재검토 연속성.
- 관문(공통 계약 2-2): 태스크는 `done`, 프로젝트는 `finish`가 확인한다 — 커밋 훅·`check`의 커밋 시점 호출은 검토 기록을 요구하지 않는다. reviewer·tester 결과가 없거나, 결과가 `pace agent` 결과 파일이 아니거나, 최종 판정이 pass가 아니거나, **현재 내용 해시가 검토 대상과 다르면**(재검토 필요) 막는다.
- 순서: 구현 커밋 → 검토(대상 = 그 커밋) → 지적 반영 시 새 커밋 → 재검토 → 마감. 검토 뒤 변경 판정은 공통 계약의 프로젝트 변경 집합(BACKLOG)을 쓴다.
- `pace agent` 검증 모드(공통 계약 2-3): `run`·`verify`에 역할(reviewer·tester)과 대상 내용 해시를 받는 검증 실행을 더한다 — `--resume` 거부, 하네스 발급 실행 ID, 결과 파일에 실행 ID·역할·대상 해시·제공자·모델·세션 ID(보고된 경우) 기록. 세션 ID를 보고하지 않는 제공자도 새 프로세스·재개 없음이 실행 기록으로 남아 인정한다.
- 상태 칸 정규화(공통 계약 2-1): `done`이 TASK·BR·BACKLOG의 상태 줄·현황 표만 바꾼 경우 대상 해시가 그대로다.
- 기존 태스크 사전 검토 관문(구현 전 TASK 검토)과의 관계·중복 기록 제거, 옛 마커 없는 태스크 호환.
- 스킬: 태스크 없는 프로젝트에도 tester ∥ reviewer 단계를 SKILL.md §1·references에 명시.
- 제외: 검토 의미의 자동 판정(관문은 실수 예방 — 브레인 `작업-하네스-흐름` "사전 검토 기록 관문"의 한계 유지).

## 완료 기준

- reviewer 또는 tester 기록이 없는 프로젝트(태스크 유무 각각)의 마감이 실패한다(시험).
- 손으로 쓴(`pace agent` 결과 파일이 없는) 검토 기록이면 마감이 실패한다(시험).
- 검증 모드가 아닌 결과, `--resume`으로 이어 쓴 실행, 역할이나 대상 해시가 다른 결과는 인정되지 않는다(시험). 검증 모드에 `--resume`을 주면 실행이 거부된다(시험).
- `done`의 상태 칸 갱신만으로는 재검토를 요구하지 않는다(시험).
- 검토 뒤 변경 집합 파일이 바뀌면(태그 커밋 추가·태그 없는 수정·되돌림·rebase) 재검토 전까지 마감이 실패하고, 재검토 뒤 통과한다(시험).
- 하네스 소유 파일만 바뀐 마감 커밋은 검증을 무효화하지 않는다(시험).
- 첫 구현 커밋은 검토 기록 없이 커밋된다(훅과의 순환 없음, 시험).
- 기존 태스크 관문 시험과 옛 마커 없는 태스크 호환이 그대로다.
