# BR03 main 커밋 게이트

- 상태: 대기
- 백로그: [허브 PM main 직접 프로젝트 하네스 정비](BACKLOG.md)

## 목적

worktree 브랜치에만 걸리던 커밋 게이트를 main 직접 프로젝트 커밋에도 적용해, 기록·검사 없이 main에 들어가는 프로젝트 커밋을 막는다.

## 범위

- commit-msg 훅이 main에서도 `(P###/T##)` 태그 커밋을 `pace project check`로 확인한다. 태스크 없는 프로젝트의 `(P###)` 커밋 처리 규칙을 정한다(예: 착수 기록 존재·상태 `진행` 확인).
- `start --main`이 훅을 설치한다(worktree start와 같은 안전 경로·사용자 훅 보존 규칙).
- 공통 계약 1: 진행 중인 main 직접 프로젝트의 변경 집합 경로를 태그 없이 고치는 커밋은 거부한다.
- 마감 커밋 예외: `finish`는 상태를 `완료`로 바꾼 뒤 마감 커밋을 만든다. 게이트는 finish 실행 표식이 있고 커밋이 하네스 소유 파일만 담을 때 이 커밋을 허용한다. 표식 없이 `완료` 상태로 하는 태그 커밋은 거부한다.
- 제외: 프로젝트와 무관한 태그 없는 main 커밋(작은 일·메모리)은 막지 않는다.

## 완료 기준

- main에서 `(P###/T##)` 태그 커밋이 형식·상태 검사 실패면 거부되고, 태스크 없는 프로젝트의 `(P###)` 커밋도 착수 기록·진행 상태가 없으면 거부된다(시험).
- 진행 중 main 직접 프로젝트의 변경 집합 경로를 태그 없이 고치는 커밋이 거부된다(시험).
- `start --main` → 태그 구현 커밋 → `finish` 마감 커밋까지 훅을 켠 채 끝까지 성공한다(종단 시험). 표식 없는 `완료` 상태 태그 커밋·하네스 소유 밖 파일을 담은 마감 커밋은 거부된다(시험).
- 태그 없는 main 커밋과 worktree 커밋 게이트는 기존과 같다(시험).
