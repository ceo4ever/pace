## 목적

## 범위

- `templates/project/TASK.md`에 `## 증명 범위` 절을 기준·테스트 앞에 둔다:
  - **판정 주체**: 최종 정답이 무엇으로 정해지는가 — 자동 테스트 / 사람의 결정 / 관찰. 사람 결정이면 태스크 책임은 "입력을 왜곡·누락 없이 옮기고, 불완전하면 '미확인'으로 드러내는 것"까지.
  - **포함**: 목적에 비례해 증명할 것.
  - **범위 밖**: 증명하지 않는 것 + 이유 + 넘길 곳(알려진 한계·후속 브리프).
- `skills/pace-project-dev/references/reviewer.md`와 `pace agent verify --kind task` 프롬프트(`src/agent/verify.ts`): blocking은 "적힌 증명 범위로는 목적·기준을 증명할 수 없을 때"만. 범위를 넓히라는 요구는 should_fix. 증명 범위·판정 주체가 비어 있으면 그것 자체를 blocking 1건으로 낸다(지적을 늘어놓지 않는다). 증명 범위 자체가 목적에 비해 좁으면 그것을 지적한다 — 범위 밖으로 적었다고 검토를 피할 수 없다. **판정 주체의 권한도 대조한다**: 사람의 결정이 정답인 기준에서 그 결정을 승인받은 사람의 원문으로 정확히 옮기면 통과, 작성자나 자동 검사가 그 결정을 대신하거나 필수 안전 기준(보안·데이터·되돌리기 어려운 행동)을 범위 밖으로 빼면 blocking.
- `references/task-steps.md`: 사전 검토 전에 증명 범위 작성 필수. 사전 검토 게이트(`pace project check`의 PRE-REVIEW 검사, `src/project/pre-review.ts`)가 새 TASK의 증명 범위를 검사한다.
- **새 TASK와 옛 TASK 구별**: 절이 있는지로 구별하지 않는다(새 TASK가 절을 통째로 빠뜨리면 옛 TASK처럼 보인다). `pace project task`가 새 템플릿으로 만든 TASK에는 형식 표지(예: 머리 목록의 형식 버전 줄)를 넣고, 게이트는 표지가 있는 TASK에서 ① `## 증명 범위` 절 누락 ② 빈 절 ③ 판정 주체 누락을 각각 거부한다. 표지가 없는 TASK(이 브리프 전 작성)는 지금처럼 통과한다 — 진행 중인 태스크를 깨지 않는다. **같은 형식 경계를 게이트·verify·스킬에 똑같이 적용한다**: verify `--kind task` 프롬프트와 reviewer.md의 증명 범위 규칙(누락 blocking 포함)은 표지가 있는 TASK에만 적용하고, 표지가 없는 옛 TASK는 지금 기준으로 판정한다 — 진행 중인 옛 TASK가 새 verify나 도구 밖 reviewer에서 증명 범위 누락으로 새 blocking을 받지 않게. 표지를 지워 우회하는 것은 기존 "이력 조작" 한계와 같은 급으로 문서에 적는다.
- 측정: 이후 태스크의 사전 검토 통과 회차를 기록한다(기준선: roblox-studio P002 T01~T03, PACE P005 T04). roblox-studio 다음 시제품(bubble-catch)에서 태스크당 2회 이내를 목표로 그쪽이 확인한다.
- 제외: 업무별 기본 증명 범위 표(게임 시제품·문서 등)는 각 저장소 스킬이 맡는다(roblox-studio game-prototype·game-review).

## 완료 기준

- 새 TASK 템플릿에 `## 증명 범위`(판정 주체·포함·범위 밖)와 형식 표지가 있고, 표지가 있는 TASK의 절 누락·빈 절·판정 주체 누락이 각각 사전 검토 게이트에서 거부되며, 표지가 없는 옛 TASK는 지금처럼 통과한다(테스트 4건). verify 프롬프트도 표지 유무로 갈린다 — 옛 TASK에는 증명 범위 규칙이 들어가지 않고, 새 TASK에는 들어간다(시험 2건).
- verify `--kind task` 프롬프트가 증명 범위 기준의 blocking 규칙을 담고, 빈 증명 범위는 blocking 1건으로 낸다는 지시가 있다(시험). reviewer.md·task-steps.md가 같은 규칙을 한 곳(reviewer.md)에서 정의하고 링크한다.
- 실측(다른 제공자 검토, 같은 TASK의 다섯 사례 — 모두 새 형식 표지를 둔 TASK): ① 표지는 둔 채 증명 범위 절만 뺌 → 누락 blocking 1건으로 끝남 ② 목적을 증명하기에 충분한 증명 범위 → 범위 밖 요구가 should_fix로 나옴 ③ 목적을 증명할 수 없게 좁힌 증명 범위 → blocking이 나옴 ④ 사람 결정이 정답인 기준에서 승인받은 사람의 결정을 정확히 옮김 → 통과 ⑤ 같은 기준을 작성자 판단이나 자동 검사로 대신하거나 필수 안전 기준을 범위 밖으로 뺌 → blocking. 다섯 결과를 기록한다. bubble-catch의 태스크당 2회 이내 목표는 설치 뒤 운영 지표로 roblox-studio가 확인한다.
