## 목적

[백로그 목표](BACKLOG.md#목표)의 도구 쪽. `pace agent verify`가 진단 뒤 fail에서 "사용자에게 결정을 받는다"고만 안내하고, `review-note --decision`이 결정 주체를 구분하지 않아 PM이 결정한 기록과 사용자가 결정한 기록이 원장에서 같아 보인다. 결정 주체를 남겨 사후 보고·감사가 가능하게 한다.

## 범위

- 진단 뒤 fail의 단계(현재 `ask_user`)에서 실행을 멈추는 동작(종료 16)은 유지한다. 단계 이름은 결정 주체가 정해지지 않았음을 나타내도록 바꿀지 설계에서 정한다(옛 원장 항목·이름과의 호환 포함).
- 안내 문구(`escalation.next`)를 바꾼다: 진단 단계 안내는 근본 조치 전에 조치의 성격을 분류하라고 말하고(심각한 오류·보안·합의 변경이면 조치 전 사용자 보고), 진단 뒤 fail 안내는 지적 성격을 분류해 PM 결정(근본 조치 → 재검증, 사후 보고) 또는 사용자 결정(심각한 오류·보안·목적·범위 변경 — 고치기 전 보고)으로 가르고, 분류 기준은 스킬 정본을 가리킨다.
- `pace agent review-note --decision`에 결정 주체(`pm`|`user`)를 받는다. 원장 결정 항목에 주체를 남긴다. `pm`이면 근거 파일에 분류 이유와 조치를, `user`이면 사람 결정 원문을 담는다(원문 진위는 지금처럼 PM 책임). 새 결정 기록은 주체를 반드시 받는다(생략하면 거부). 주체 필드가 없는 옛 원장 항목은 단계 계산에는 지금처럼 결정으로 쓰되 주체는 **미확인**으로 읽고 보고한다 — `user`로 읽으면 PM이 내린 옛 결정(P005 T04 v4 등)을 사용자 결정으로 잘못 귀속시킨다. 이 처리를 정한다.
- `docs/AGENT-CALL.md`의 검토 원장·단계 설명, 단위 시험(원장 시험)을 맞춘다.
- 제외: PRE-REVIEW.json의 `waiver.by`는 `user`만 유지한다 — 게이트 예외는 사용자 결정이다. PM 결정 뒤에는 waiver가 아니라 재검증으로 게이트를 통과한다. 지적 성격의 자동 판정(등급·수 기반)은 하지 않는다.

## 완료 기준

- 진단 뒤 fail에서 도구가 실행을 멈추고, 안내가 PM 결정/사용자 결정의 분류와 각 다음 행동을 말한다.
- `review-note --decision --by pm|user`가 원장에 주체를 남기고, 근거 파일 검사(빈 파일·대상 자체 거부)가 두 주체 모두 유지된다. 옛 형식 원장을 읽어도 단계 계산이 바뀌지 않는다.
- 결정 뒤 첫 검토가 전체 검토(`rereview_of` null)인 것과 연속 fail 집계가 지금과 같다.
- 단위 시험과 결함 주입으로 위 동작이 검출되고 `npm run check`가 통과한다.
