## 목표

Windows에서 저장소 전체 검사(`npm run check`)가 약 34분 걸려(2026-11-18 P003 실측: 시험 960개, 5초 넘는 시험 81개), 작업 중 검증과 `finish`가 개발 흐름을 오래 막는다. 상위 목적은 "완료는 테스트·실행으로 증명한다"는 원칙을 지키면서 검증 비용을 낮춰 자주 돌릴 수 있게 하는 것이다.

결과: **Windows 전체 검사 시간을 기준 대비 절반 이하로**, 통과·실패 판정은 그대로(줄인 대가로 놓치는 시험 없음). 목표 수치는 BR01 측정 뒤 다시 맞출 수 있다.

고른 길(효과 대비 위험이 낮은 순서): 측정 → git 준비 재사용 → Windows 병렬 실행 → 빠른 검사 명령 → 느린 시험의 함수 직접 호출. 근거(2026-11-18 확인): `scripts/test.ts`가 Windows에서만 `--test-concurrency=1`로 파일을 순차 실행(16코어 PC에서 1개만 사용, 이유 기록 없음 — 0.1.0부터), 시험 코드에 CLI 새 프로세스 호출 364곳·git 호출 95곳(Windows 프로세스 기동 비용이 큼 [추정]).

버린 길: 시험 삭제·건너뛰기로 시간 줄이기(판정 약화), CI로만 넘기기(로컬 Windows 검증이 열린 이슈의 핵심).

- 2026-11-18 캡틴 보완(코디네이터 전달): BR04 빠른 검사는 다른 Git 저장소에서도 설치된 PACE CLI로 사용하는 제품 기능이다. 기존 pace test·test-map과 프로젝트 선언 검사를 존중하고, 독립 Git 샘플 검증·채택 문서를 제공한다. T01 기준선 및 BR02·BR03·BR05의 자체 저장소 실증은 유지한다.
