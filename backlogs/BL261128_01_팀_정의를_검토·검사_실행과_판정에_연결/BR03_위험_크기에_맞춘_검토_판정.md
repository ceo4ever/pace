## 목적

독립 검토가 위험이 작은 지적으로 반복을 늘리지 않게 해 검토 반복이 끝나게 한다([설계 G7](BACKLOG.md#설계--공백별-선택), 근거 E11·E12·E16·E17). 막지 않게 할 범위는 [Q1](BACKLOG.md#남은-결정)에서 owner가 고른다. 아래는 추천안 (1)의 범위다. owner가 다른 선택지를 고르면 착수 전에 이 BR을 그 선택지로 고친다.

## 범위

`src/agent/structured-review.ts`를 고친다. 행 번호는 main `d82d530` 기준이며 P017 병합 뒤 다시 확인한다.

- **(가) 사전 단계만**
  - 사전 질문의 checks 목록(`:18-22`)에서 `detection`을 빼서 프롬프트가 더는 묻지 않게 한다.
  - 판독은 `detection` 범주를 질문 밖과 같은 note로 받는다(handoff는 tester).
  - 범주를 판독에서까지 지우면 안 된다. 옛 원문은 읽을 때마다 현재 분류기로 다시 계산하므로(E16 — `review-pre.ts:54`, `pre-review.ts:200`, `review-metrics.ts:202`), 옛 사전 기록이 형식 오류가 되고 finish의 완료 태스크 재검사가 막힌다.
  - 이것이 분류 함수의 유일한 변경이다. 새 상태·문턱·옛 기록 전용 경로는 만들지 않는다(메모리 rule 구판 호환 설계 금지). 옛 기록도 같은 규칙으로 계산된다.
- **(나) 모든 단계의 impact 지시**(`:104-105`, 백로그·사전·사후 공통 블록)
  - "합의한 동작의 회귀와 검출력 없는 필수 시험은 … 기준 영향" 문장에서 "검출력 없는 필수 시험"을 뺀다. 회귀는 그대로 둔다.
  - "안전 쪽 과잉 거부(정상 입력을 막는 쪽)와 실제 사용 경로에서 닿지 않는 입력에만 기대는 지적은 minor"를 더한다. 처리는 기존 `minor → should_fix`(`:161`)다.
- `skills/pace-project-dev/references/reviewer.md`
  - 사전 검토 절에 "시험 검출력은 구현 뒤 tester 몫"이라고 한 줄 적고, 같은 뜻의 기존 문장을 지운다.
  - impact 설명에 위 minor 정의를 같은 문구로 적는다.
  - `tester.md`의 검출력 항목은 그대로 둔다.
- **제외**
  - 사후 단계 checks와 P017의 세 묶음.
  - 공동 시도 집계(`review-followup.ts:174-175` — 메모리 idea에 둔다, BACKLOG 설계 절).
  - 판정 선을 둔 자동 측정.

## 완료 기준

- `test/agent-structured-review.test.ts`에서 다음을 확인한다:
  - 사전 프롬프트의 하위 확인에 `detection`이 없다.
  - 모든 단계 프롬프트에 "검출력 없는 필수 시험" 문장이 없고 minor 정의 문장이 있다.
  - 사전 응답의 `category: "detection"` blocking 지적 → 유효 등급이 note다. 응답 전체가 형식 오류가 되지 않는다.
  - `impact: "minor"` blocking → should_fix다(회귀).
  - `security`·`data_loss`·`irreversible` blocking → 지금처럼 blocking 또는 unverified다(회귀).
  - 기존 옛 기록 판독 시험이 그대로 통과한다.
- **인수 사례(실제 실행)**:
  - (a) 옛 blocking이 detection 지적이던 P017 T01 사전 입력(고정 사본, 해시 기록) → 그 지적이 blocking이 아니고, scope·observable blocking으로 다시 나오지도 않는다.
  - (b) 실제 사용 경로에 보안·데이터 손실·되돌릴 수 없는 결함이 있는 사전·사후 입력 각 1건 → 두 단계 모두 blocking으로 남는다(should_fix로 낮아지지 않음).
- `reviewer.md`의 사전 검토·impact 문구와 도구 프롬프트가 같은 뜻이다(문구 대조). 고정 문구 시험을 바꿨다면 바꾼 줄과 이유를 TASK-CLOSE에 적는다.
- `npm run check` 통과.
