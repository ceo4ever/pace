# BR03 기동과 자동 시작

- 상태: 완료
- 백로그: [BL261116_02_PACE_daemon_사용_준비](BACKLOG.md)


## 목적

daemon을 켜고 끄는 방법과(설계 때 정하면) 로그온 자동 시작을 갖춘다.

## 범위

- `pace daemon start`·`status`·`stop`. 자동 시작이면 `pace daemon install --yes --start`(시작 항목 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` "PACE Daemon"), 해제는 `pace daemon uninstall --yes`.
- 기기당 하나(인스턴스 포트) — 두 번째 기동이 거절되는지 확인.
- 이 PC에서 워크트리 작업자·전체 검사와 동시에 돌 때 메모리 여유를 본다(Windows 전체 검사 동시 실행 메모리 부족 이력).

## 완료 기준

- `start` → `status` running true → `stop` 정상 정지, 재기동 가능.
- 자동 시작 선택 시 병합 전에는 정확한 HKCU Run·설치본 런처 등록과 현재 정상 기동을 확인한다.
- 원래의 실제 로그오프·로그온 뒤 running true·콘솔 창 없음 실측은 미확인 상태로 보존한다. 2026-11-21 캡틴이 현재 로그아웃하기 어려워 병합 후 시험으로 이관하도록 승인했으며, 아래 후속 인수 조건과 프로젝트 todo로 추적한다. 승인 자체를 실측 성공으로 간주하지 않는다.

## 사용자 결정과 병합 후 인수

원래 목적은 실제 로그인 시 자동 기동과 콘솔 비표시까지 확인하는 것이다. 2026-11-21 캡틴의 자동 실행·지금 기동 선택으로 등록 및 현재 CLI 실측을 진행했고, 같은 날 캡틴의 병합 후 시험 결정으로 실제 재로그온 관측의 시점만 이관했다. 근거는 [P005 결정·진행 메모](../../projects/P005_261119_PACE_daemon_사용_준비/PROJECT.md)와 T03 변경 로그다.

병합 후 같은 Windows 사용자로 실제 로그아웃/로그인하고, 수동 start 없이 새 인스턴스 running true·단일 인스턴스·Run/런처/설치본 일치 및 콘솔 비표시를 확인한다. 가능하면 General의 새 연결 알림도 본다. 절차와 과거 기준점은 [T03 체크리스트](../../projects/P005_261119_PACE_daemon_사용_준비/tasks/T03_기동과_자동_시작/evidence/relogon-checklist.md)에 보존하고 [프로젝트 todo](../../.pace/memory/로그온-자동-기동-병합-후-실측.md)로 추적한다. T04 재기동/설정 변경 이후에는 인수 직전 최신 기준점을 별도로 확보한다. 에이전트가 사용자 세션을 강제로 로그오프하지 않는다.
