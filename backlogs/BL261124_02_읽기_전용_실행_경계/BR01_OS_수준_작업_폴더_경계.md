# BR01 OS 수준 작업 폴더 경계

## 목적

읽기 전용 차단을 어댑터의 권한 요청이 아니라 실행 경계에서 보장한다([백로그 목표](BACKLOG.md#목표) ①). 지금은 어댑터가 묻지 않는 경로가 생기면 막을 수 없다.

## 범위

- 읽기 전용 ACP 실행(자식 어댑터·그 자손)에 OS 수준 파일 경계를 둔다: 작업 폴더 밖 작업 파일 읽기 금지, 모든 쓰기 금지(어댑터가 필요로 하는 자체 상태·임시 폴더는 목록으로 명시).
- 후보 조사: macOS `sandbox-exec`(또는 Claude Code 자체 sandbox 설정), Linux bubblewrap/landlock, Windows(제한 토큰·AppContainer) — 플랫폼별 가능·불가를 실측으로 판정한다.
- 경계를 적용할 수 없는 플랫폼·버전에서는 읽기 전용 ACP를 `read_only_unenforceable`로 거부하거나, 캡틴이 받아들인 한계로 문서화한다(어느 쪽인지 캡틴 결정).
- 같은 경계로 다룰 관측(P005 T04): 쓰기 모드에서도 승인된 편집 도구는 경로를 대조하지 않고, 작업사본 안 읽기 전용 셸은 PACE 도구 승인 없이 실행된다 — 쓰기 작업의 경계(작업사본 안만 쓰기)도 이 브리프의 실행 경계 설계에 포함한다.
- 제외: PACE 도구(MCP)의 허용 범위 — BR02.

## 완료 기준

- 실제 어댑터로 새 세션·이어간 세션 각각에서, 어댑터 권한 요청을 모두 **허용**으로 바꿔도(경계만 남긴 상태) 작업 폴더 밖 표지 파일 내용이 답에 나오지 않고 작업 폴더·홈에 파일 변경이 없다.
- 작업 폴더 안 읽기 질문은 계속 답한다. 지원하지 않는 플랫폼의 동작이 시험과 문서(docs/AGENT-CALL.md·docs/SECURITY.md)에 있다.
