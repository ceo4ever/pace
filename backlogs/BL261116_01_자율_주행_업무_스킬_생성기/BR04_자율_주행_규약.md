# BR04 자율 주행 규약

- 상태: 대기
- 백로그: [BL261116_01_자율_주행_업무_스킬_생성기](BACKLOG.md)

## 목적

모든 플레이북이 같은 방식으로 지도를 읽고 주행하게 하는 공통 규약을 만든다. 업무마다 주행 방식이 다르면 학습(BR05)과 검증이 업무마다 따로 놀게 된다.

## 범위

- 읽는 순서: `index.json` 한 번 → 해시 최신 확인 → 운영 명령이 있으면 그것으로 범위 단계를 수행, 없으면 단계별 `S0n.json`으로 주행. 화면이 다를 때만 `S0n.html`·캡처를 연다.
- **운영 명령 계약**(부분 실패 안전): 운영 명령은 단계별 진행 상태(완료 단계, 되돌릴 수 없는 행동마다 실행 여부와 조회 근거 — 식별 번호·건수 등 값 없이)를 출력하고, "단계 n부터 재개"를 받는다. 명령 안의 되돌릴 수 없는 행동에도 그 단계의 관문을 적용한다. 명령이 중간에 실패하면 처음부터 다시 돌리거나 단계 주행으로 바로 넘어가지 않는다 — 진행 상태와 조회로 마지막 완료 단계를 판정하고, 첫 미완료 단계부터 재개한다. 판정할 수 없으면 멈춘다. 이 계약을 못 지키는 기존 명령은 읽기 전용 단계에만 쓴다.
- 단계 주행: 현재 화면 판정(어느 단계인가) → 요소 찾기(find·box) → 액션 → 기대 결과·대기 → `extract` → 성공 판정 → 다음 단계.
- 브라우저와 API 두 방식(API는 앱이 부른 응답 관찰과 직접 호출 구분, 직접 호출은 지도에 허용된 것만).
- 비결정 이벤트(`events` — 늦은 공지·자동 탭·일시 덮개) 처리.
- 관문: 위험 등급과 `gate` — 읽기는 자율, 밖으로 나가는 행동은 지도에 승인 규칙이 있을 때만 자율, 없으면 사용자 확인. 승인의 유효 범위와 결과 불명 처리는 BR05 규칙을 같이 따른다(되돌릴 수 없는 행동은 맹목 재시도 금지 — 조회로 실행 여부부터 판정).
- BR03(생성)과 이 규약은 BR02 스키마를 공통 계약으로 쓴다 — 생성기가 쓰는 필드와 주행이 읽는 필드가 같아야 한다(스키마 검사 하나로 양쪽 확인).
- 주행 기록: 단계별 결과·소요·추출 건수(값 없이)·이탈 지점 — 학습(BR05)의 입력.
- 규약은 플레이북마다 복사하지 않고 `pace-playbook-maker`의 참조 문서 한 곳에 두고 링크한다(버전 표기). 설치본 경로가 기기마다 다르므로 링크 방식은 설계 때 정한다(BACKLOG "설계 때 정할 것" 2).
- 제외: 변경 해결·반영(BR05).

## 완료 기준

- 가상 서비스 플레이북(BR03 결과)을 규약대로 주행해 목표를 끝까지 수행한다 — 브라우저 흐름 하나, API 흐름 하나(e2e 증거).
- 관문이 있는 단계에서 승인 규칙이 없으면 멈추고 묻는다(테스트).
- 운영 명령 부분 실패 주입: 되돌릴 수 없는 행동 직후 실패·시간 초과를 넣으면 완료 단계를 조회로 식별하고 다음 단계부터 재개하며, 되돌릴 수 없는 행동의 중복 실행 0, 명령 안 위험 행동 전 관문 동작(테스트).
- 지도 해시가 다르면 주행을 시작하지 않는다(테스트).
- 주행 기록에 추출 값 원문이 남지 않는다(테스트).
- `npm run check` 통과.
