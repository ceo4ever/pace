# BR06 시범 업무 스킬로 끝까지 검증

- 상태: 대기
- 백로그: [BL261116_01_자율_주행_업무_스킬_생성기](BACKLOG.md)

## 목적

가상 서비스가 아닌 실제 웹 업무 하나로 "인터뷰 → 생성 → 자율 주행 → 변경 학습"이 끝까지 되는지 확인하고, fin-link가 새 구조로 넘어갈 수 있게 인계한다. 목표 달성 판정의 근거다.

## 범위

- 시범 업무: 읽기 전용이고 개인정보·외부 전송이 없는 실제 웹 업무 하나(후보는 설계 때 사용자와 정한다). `pace-playbook-maker`로 처음부터 플레이북을 만들고, 새 세션에서 그 플레이북만으로 주행한다.
- 변경 학습 확인: 실제 변경이 없으면 지도 일부를 일부러 낡게 만들어(예: 요소 find·box 변경) 자가 복구·반영을 확인한다.
- fin-link 영향 확인(D6): fin-link `main`의 업무 스킬 3개·흐름 9개가 이관 전과 같이 동작하는지 — 생성물 바이트 동일, fin-link 테스트 통과.
- fin-link 인계 문서: fin-link가 시제품 `opal-auto-flow-maker`를 `pace-playbook-maker`로 바꾸는 방법(프로젝트 스킬 정리 포함)(어댑터 import 9곳 — `tools/hometax/capture.mjs:9`, `tools/amaranth/packages/flowdoc/capture.mjs:17`과 테스트 3곳, `tools/wehago/tests/{capture,flow-doc,imports}.test.mjs`), `agentView` 켜기, 낡은 안내 문구(`node tools/flow/build.mjs`) 정리.
- 브레인 정리: 구조·함정·결정.
- 제외: fin-link 실제 전환 작업(fin-link 세션).

## 완료 기준

- 새 세션이 생성된 시범 플레이북만 읽고 **만들 때와 다른 입력**(예: 다른 기간·다른 조회 조건)으로 목표를 끝까지 수행한다(사람 개입 0 또는 지도에 적힌 확인 지점만) — 주행 기록 증거. 만든 세션의 맥락·사람 보완 없이 성공해야 한다.
- 빠르기·정확도 관측: 같은 업무를 같은 조건에서 각각 3회 이상 (a) 플레이북 주행, (b) 지도 없이 같은 목표를 받은 새 세션으로 수행해(중앙값 비교) 성공 여부·소요 시간·읽은 지도 분량·도구 호출 수·화면 탐색 횟수·추출 정확도(정답 대조)를 기록하고, (a)가 성공하면서 (b)보다 시간·도구 호출이 적어야 한다. 파일 크기는 보조 지표로만 쓴다.
- 낡게 만든 지도가 자가 복구로 반영되고 다음 주행은 진단 없이 통과한다.
- fin-link 흐름 9개 바이트 동일 + fin-link 테스트(`tools/flow`·`tools/amaranth`·`tools/hometax`·`tools/wehago`) 통과 — **PACE 새 버전을 설치한 상태에서**, fin-link 작업 사본은 손대지 않은 채(`git status` 깨끗) 확인한다.
- 설치 후 fin-link 저장소에서 연 새 세션에서 프로젝트 스킬 `opal-auto-flow-maker`·`hometax-invoice`·`amaranth-read`·`wehago-read`와 설치 스킬 `pace-playbook-maker`가 각각 다른 이름으로 보이고, 기존 업무 스킬의 안내(시작 시 `flow/overview.md`)가 그대로 동작한다(세션 기록 증거).
- fin-link 인계 문서가 fin-link 세션이 바로 착수할 수 있는 수준(변경 위치 `file:line`·검사 명령)이다.
- 시범 작성·주행·학습 전 과정에서 저장된 모든 파일에 실값 0건(BR03 기준과 같은 검사를 실제 업무 결과물에 적용).
- `npm run check`·`node scripts/secret-scan.ts` 통과.
