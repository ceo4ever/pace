# BR03 플레이북 작성과 업무 스킬 생성

- 상태: 완료
- 백로그: [BL261116_01_자율_주행_업무_스킬_생성기](BACKLOG.md)

## 목적

목표 하나를 받아 **인터뷰 → 수행하며 기록 → 플레이북 생성**까지 끝내는 절차를 `pace-playbook-maker`에 넣는다(D1·D2·D9). 지금은 지도만 만들고 업무 스킬은 사람이 손으로 짰다.

## 범위

- **인터뷰**(pace-intent의 한 번에 한 질문 방식 재사용): 목표·범위, 입력과 결과물(추출 항목·저장 위치), 서비스·계정·인증 방식, 성공 기준, 위험 행동(밖으로 나가는 것), 예외·빈도, 개인정보. 결과는 인터뷰 기록(steps.json 머리 필드 또는 별도 기록 파일 — 설계 때 정함)으로 남긴다. 이 중간 기록은 플레이북이라 부르지 않는다(용어 표).
- **처음부터 개인정보를 남기지 않는다:** 인터뷰 기록·사용자 답·steps.json·URL·선택자·캡처·flow.html·생성물 어디에도 비밀번호·인증서·OTP·주민번호·계좌·카드 번호·실명·실제 거래처 같은 값을 쓰지 않는다. 계정·인증은 "어떤 방식으로 어디에서 가져오는지"(시크릿 저장소 이름·환경 변수 이름)만 적고, 값이 들어가는 자리는 자리표시(`<기간>`, `<계정>`)로 쓴다. 인터뷰 중 사용자가 실값을 말해도 기록에는 종류만 남긴다.
- **운영 명령을 만들거나 연결할 때** BR04 운영 명령 계약(단계별 진행 상태·재개·명령 안 관문)을 지키게 한다.
- **수행하며 기록**: 실제로 단계를 실행하면서 화면 판정·요소·액션·기대·추출을 steps.json에 쓰고, 어댑터로 가림 캡처·box를 남긴다(BR02). 사용자와 함께하는 지점(인증·애매한 화면·밖으로 나가는 행동·도구에 없는 동작)을 정하고, 사용자 답은 규칙으로 기록한다.
- **플레이북 생성**: 기록에서 플레이북(업무 스킬 한 벌)을 만든다 —
  ```
  <플레이북 = 업무 스킬>/
    SKILL.md            언제 쓰는지·시작 조건·안전 규칙·흐름 색인·주행 규약(BR04) 링크
    references/flows/<흐름>/  steps.json·shots/·agent/(지도)·flow.html(사람 검토)
    references/history.md     학습 이력(BR05)
  ```
  운영 명령(run)이 있으면 연결하고, 없으면 지도만으로 주행한다.
- 서비스 어댑터가 없을 때 만드는 방법(adapter.md)과 템플릿.
- 제외: 주행 규칙 본문(BR04), 학습(BR05).

## 완료 기준

- 가상 서비스(테스트용 로컬 웹 페이지·가짜 API)를 대상으로 스킬 절차대로 인터뷰 기록 → 수행·기록 → 플레이북 생성이 끝까지 된다(e2e 증거).
- 생성된 플레이북이 PACE 스킬 형식 검사(이름·description·크기)를 통과하고, 지도는 BR02 스키마 검사를 통과한다.
- 인터뷰에서 답하지 않은 필수 항목(성공 기준·위험 행동)이 있으면 생성하지 않고 묻는다(테스트 또는 절차 검사).
- 생성물에 실값·비밀이 없다(`secret-scan`, 가림 검사).
- 민감 값 주입 작성 시나리오: 가상 서비스 화면·응답과 인터뷰 답에 가상 민감 값(주민번호·계좌·비밀번호 형식)을 넣고 처음부터 끝까지 작성하면, 작성 중 저장된 모든 파일(인터뷰 기록·steps.json·캡처·생성물·임시 파일)에서 원문 0건(테스트).
- `npm run check` 통과.
