- 상태: 완료
- 작성: 2026-11-14 (2026-11-16 이전 저장소 백로그 BL261114_01에서 옮김 — 결정·기록 첫 줄)
- 프로젝트 기준 경로: projects/

## 목표

**스킬을 만드는 스킬** `pace-playbook-maker`를 PACE에 둔다(D9). 사용자가 목표를 주면 에이전트가 인터뷰로 업무를 파악하고, 실제로 수행하면서(필요하면 사용자와 함께) 화면·위치·액션·추출을 기록한 뒤, **플레이북**(자율 주행 업무 스킬 한 벌)을 생성한다. 플레이북을 실행하면 에이전트가 사람 없이 브라우저·API 업무를 빠르고 안전하게 수행한다. UI·API가 바뀌면 문제를 진단·해결하고, 해결한 내용을 플레이북에 반영해 다음에는 그대로 작동한다.

```
pace-playbook-maker (생성기)
  인터뷰 → 수행하며 기록(캡처·위치·액션·추출, 막히면 사용자와 함께) → 플레이북 생성
                                                                       │
플레이북 = 생성된 업무 스킬 (예: 세금계산서 발행)                          ▼
  SKILL.md + 지도(agent/index.json + 단계별 S0n.html·S0n.json) + 운영 명령 + 학습 이력
  → 주행(자율) → 변경 발견 시 진단·해결·검증 → 플레이북에 반영(학습)
```

**용어** — 문서 전체에서 이 뜻으로만 쓴다.

| 용어 | 뜻 |
|---|---|
| `pace-playbook-maker` | 플레이북을 만드는 스킬(생성기). 사례 저장소 시제품 이름은 `시제품 스킬` |
| 플레이북 | 생성된 업무 스킬 한 벌 — SKILL.md + 지도 + 운영 명령 + 학습 이력. 인터뷰 기록·초안 같은 중간 산출물에는 쓰지 않는다 |
| 지도 | 플레이북 안의 흐름별 `agent/index.json` + 단계별 `S0n.html`·`S0n.json`(원본은 `steps.json`·승인 캡처) |
| 주행 | 플레이북을 실행하는 것 |
**인계 문서:** 로컬 보관(비공개)


**상위 목적:** 반복되는 웹·API 업무(세무·ERP·결재·수집)를 에이전트에게 맡기고, 서비스가 바뀌어도 사람 손을 덜 타게 한다.

**출발점:** 사례 저장소 사례 프로젝트에서 만든 시제품 `시제품 스킬`(흐름 명세 생성기·캡처 코어)와 그것으로 만든 업무 스킬 3개(`업무 스킬 A`·`업무 스킬 B`·`업무 스킬 C`, 흐름 9개)가 시제품이다. 인계 문서: 로컬 보관(비공개)(사례 저장소 `projects/사례 프로젝트_261111_서비스 B_수집_흐름_명세와_운영_수집/tasks/T07_시제품 스킬_검증_·_OPAL_이관/HANDOFF-OPAL.md` 원문 그대로 복사, 사례 저장소 커밋 0dd0f8b — 안의 상대 링크 `evidence/…`는 사례 저장소 기준이라 여기서는 열리지 않는다. 보정 사항은 아래 결정·기록의 2026-11-14 19:10 인계 문서 검토 줄). 지금 도구는 **지도(흐름 명세)만** 만들고 업무 스킬·주행은 사람이 따로 짰다 — 이 백로그는 인터뷰·생성·주행·학습까지 잇는다. 사례 저장소 고유 구성(경로·`orca` 명령·회사명·담당자)은 테스트하며 들어간 흔적이므로 일반화한다.

**고른 길:** 원본(steps.json) 하나에서 사람용·에이전트용을 생성하는 구조는 유지하고, 에이전트용을 흐름 전체 md에서 **단계별 화면(html) + 내용(json)** 짝으로 바꾼다. 흐름 전체 html 한 파일을 에이전트가 읽게 하는 안은 버렸다 — 매번 수십 KB를 읽고 필요한 단계만 다시 읽기 어렵다(경비 정산서 흐름 flow.html 42KB, 단계 파일 1~5KB 실측).
