## 목적

허브 쪽·조건부 호출 필수 역할과 에이전트 호출 기록이 팀 측정·마감을 잘못 움직이지 않게 한다([백로그 목표](BACKLOG.md#목표), 현장 문제 2).

## 범위

- **조건부 역할 미사용 처리 — 이 BR이 소유**(BL261125_01 BR01은 구현하지 않음): 허브 쪽 역할(백로그 기획자)과 조건부 호출 역할(문제 해결자)이 팀 채택 프로젝트 마감에서 매번 미사용 역할 후보(`unusedRoleCandidates`, `src/project/team-metrics.ts:291`)로 걸려 회고 신고를 강제하지 않게 분류한다(`docs/TEAM-METRICS.md:102`, finish 대조 `src/project/harness.ts:1680`). 실제로 호출됐으면 정상 집계한다. 분류 근거는 필수 역할 표지(호출 위치·조건부 여부)다. 이 백로그 시점에는 문제 해결자 원본이 없으므로 조건부 역할 시험은 **픽스처 구성원**으로 한다. 실제 `pace-troubleshooter`에 표지를 적용하는 일은 BL261125_01 BR01이 이 BR의 장치로 한다.
  - **설계 비교안**: (가) 코드로 분류(아래 표지를 읽어 후보에서 빼거나 별도 분류), (나) **코드 없이** 회고 `unusedRoles`에 `coverage: "unconfirmed"`로 언급하는 기존 경로로 처리(`docs/TEAM-METRICS.md:102`·`:104` — unconfirmed는 삭제 근거가 아님). (나)는 코드 변경이 없지만 마감마다 신고 부담이 남는다. 설계에서 둘을 비교해 고른다.
  - **필수 역할 표지 위치 — 이 BR이 정한다**: 팀 원본 프론트매터 키는 닫혀 있어(`src/team/model.ts:22` `KEYS`, 모르는 키 거부 `:87`) 옛 설치본이 새 키를 손상으로 거부한다. 그래서 표지는 프론트매터에 새 키로 넣지 않고 옛 판독기가 보지 않는 **별도 파일·키**에 둔다. 위치·형식은 이 BR이 정해 `docs/TEAM.md`에 적는다. 뒤에 착수하는 BL261125_01 BR01의 `xhigh` 등급 위치는 이 형식을 따르거나 같은 원칙(옛 판독기가 보지 않는 별도 파일·키)으로 정한다.
- **호출 기록과 채택 판정**: 채택 판정은 `hasTeamContract`(`src/project/team-contract.ts:29`, 호출 `src/project/team-metrics.ts:83`)이고, `:84`는 판정이 아니라 **미채택 집계를 반환할지**의 조건이다 — 미채택이어도 소통 원장이 있거나(`ledgerSnapshot.present`) 사건에 `role`·`to`·`requestId`가 하나라도 있으면 미채택 팀 집계를 반환한다. 팀 마감·회고는 `hasTeamContract`로 갈린다(`src/project/team-finish.ts:207`, `src/project/team-retrospective.ts:27`). BL261125_01 BR03의 에이전트 호출 기록이 `:84`의 필드를 쓰면 미채택 프로젝트에서도 팀 집계(예: METRICS 팀 절 — `src/project/team-metrics-document.ts:33`)가 생길 수 있다 — 실제로 막을 대상은 설계에서 특정한다. 호출 기록이 채택 판정·팀 집계를 잘못 시작시키지 않는 **조건(규칙)은 이 BR이 정해** `docs/TEAM-METRICS.md`에 적는다. 뒤에 착수하는 BL261125_01 BR03은 그 규칙을 따라 호출 기록 형식을 만든다. 집계 관계: 채택 프로젝트에서는 호출 기록을 역할별로 집계하고, 미채택 프로젝트에서는 팀 마감·회고 절차를 시작시키지 않고 호출 기록만 별도 집계한다(BL261125_01 BR03 완료 기준과 같음).
- **시험 입력**: 기존 사건 필드(`role`·`to`·`requestId`를 가진 사건)와 소통 원장을 **대체 입력**으로 쓴다(확정). 새 호출 기록 사건 종류의 시험은 BL261125_01 BR03이 이 BR의 규칙에 맞춰 한다.
- **회귀 보호**: 기존 팀 프로젝트의 finish·merge·팀 측정 결과가 그대로인지 시험한다(`src/project/harness.ts` finish·merge가 `team-metrics.ts`를 거침). 옛 설치본이 새 표지·사건을 만났을 때의 동작도 확인한다.
- **민감 경로**: `docs/SECURITY.md` 표의 민감 경로는 `src/team/` 전체와 `src/project/`의 지정 파일(`harness.ts` merge·finish·start 등)이다 — `team-metrics.ts`는 표에 없지만 finish·merge가 거치므로 설계에서 SECURITY 체크리스트를 적용한다.
- **문서**: `docs/TEAM-METRICS.md`, `docs/TEAM.md`(BR03과 같은 파일 — BR03보다 먼저 끝내 직렬화).
- **제외**: 필수 역할 정본·점검(BR01), 갱신 모드(BR03), 역할 정의 내용(BR04, BL261125_01), 호출 기록 형식 자체(BL261125_01 BR03).

## 완료 기준

- 조건부·허브 쪽 역할의 비참여를 **호출 조건 미발생 / 기록 부족(미확인) / 실제 미사용** 셋으로 구분해 기록하고, (나) 회고 `unconfirmed` 안을 고르더라도 이 구분이 회고에 남는 것을 시험으로 확인한다.

- 필수 역할이 포함된 팀 프로젝트에서 호출되지 않은 허브 쪽·조건부 역할이 미사용 후보 오류를 내지 않고, 호출된 경우는 정상 집계됨을 시험으로 확인한다(음성 대조 포함). (나)를 고르면 회고 `unconfirmed` 언급으로 finish가 통과하는 것을 시험으로 확인한다.
- 미채택 프로젝트에 호출 기록이 있어도 팀 마감·회고 절차가 시작되지 않음을 시험으로 확인한다(이미 성립하는지 회귀 확인). 설계에서 특정한 실제 차단 대상(예: 미채택 METRICS 팀 절 생성)이 호출 기록만으로 생기지 않음을 시험으로 확인한다.
- 기존 팀 프로젝트 픽스처의 finish·merge·팀 측정 결과가 변경 전후 같음을 시험으로 확인한다.
- 옛 판독기(병합 전 커밋의 `loadTeam`)가 표지를 둔 저장소를 읽어도 팀 원본 파싱이 깨지지 않음을 시험으로 확인한다.
- 필수 역할 표지의 위치·형식(`docs/TEAM.md`)과 호출 기록이 채택 판정·팀 집계를 시작시키지 않는 규칙(`docs/TEAM-METRICS.md`)이 문서에 있다 — BL261125_01 BR01·BR03이 따를 기준이다.
- `npm run check` 통과.
