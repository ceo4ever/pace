## 목적

`pace project start`가 작업자를 **그 프로젝트에 맞는 역할**(예: 게임 리드)로 띄운다(목표3). 근거: roblox-studio P002(2026-11-23) — 작업자가 일반 claude 세션으로 떠서 코디네이터가 메시지로 "아테나 정의를 읽고 그대로 일하라"고 따로 지시. `workerSpec`(`src/project/harness.ts:629-638`)에 역할이 없고 worker-start 인자(`:681`)는 도구(`--agent claude`)만 넘긴다. PROJECT.md의 `- 작업자 역할:` 줄은 읽지 않는다.

## 범위

- 선행 확인: [BR01](BR01_역할_적재_실측과_도입_전_기준선.md) 실측 표의 호스트별 적재 방식과 [BR02](BR02_팀_원본_형식과_도구별_동기화.md) 원본·생성물. 이 브리프는 실측을 다시 하지 않고 그 결과를 구현한다.
- 선택 순서: `pace project start P### --role <팀 이름>` > PROJECT.md `- 작업자 역할:` > 없음(지금 동작). **자동 기본 lead는 두지 않는다** — 팀을 도입한 저장소의 기존 프로젝트를 다시 시작해도 명시가 없으면 지금 동작 그대로. 없는 이름이면 worktree 만들기 전에 거부(도구 이름 거부와 같은 방식).
- 작업자에 역할을 싣는 방법은 BR01이 호스트별로 정한 것을 따른다: (a) 네이티브(Claude `claude --agent <이름>` — 생성물 `.claude/agents/<이름>.md`를 고른다, Codex는 BR01이 확인한 대응 수단) (b) 시작 지시 — workerSpec 첫 줄에 "원본 `.pace/team/<이름>.md`를 읽고 그 정의대로 일한다". (b)는 정의의 `tier`·`tools`가 자동 적용되지 않으므로 `tier`는 모델·effort 인자로 따로 전달하고, 도구 권한 제한은 적용되지 않는다고 기록한다. Codex에 네이티브 경로가 없으면 Codex는 처음부터 (b)다.
- 이름 구분: PACE `--agent`는 도구(claude·codex), 역할은 `--role`이다. 문서·오류 문구에서 `claude --agent`(역할)와 섞이지 않게 쓴다.
- `log.jsonl` start 기록에 역할·출처와 **실제 적용 항목**(적용 방식 native|prompt, 모델·effort, 도구 권한 적용 여부)을 남긴다.
- 사람 몫과 보정 구분: 사람이 역할을 고르고(`--role`) 승인하는 것은 정상 절차다. 작업자가 뜬 뒤 메시지로 역할을 다시 입력하는 것은 수동 보정이며 BR01 집계 정의대로 센다 — 이 브리프의 목표는 그 보정을 0으로 만드는 것이다.
- 제외: 태스크별 담당 역할 배정(BR07의 스킬 안내로 시작, 장치화는 이후).

## 완료 기준

- Claude·Codex 각각 `start --role`로 띄운 작업자가 작은 실제 태스크를 그 역할로 수행하고, 역할 밖 요청 1건을 정의대로 넘긴다(실측 기록 — 첫 응답만 보지 않는다). 실측 장소는 PACE 쪽 임시 저장소다(기준선 저장소 제외)
- start 기록에 적용 방식·모델·effort·도구 권한 적용 여부가 남고, 시작 지시 방식에서 정의의 `tier`가 모델·effort 인자로 전달된다(테스트)
- 없는 역할 이름은 worktree 생성 전 거부, 역할 미지정은 팀이 있는 저장소에서도 지금 동작과 같음(회귀 테스트)
