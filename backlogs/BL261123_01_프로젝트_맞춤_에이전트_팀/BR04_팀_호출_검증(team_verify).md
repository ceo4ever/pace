# BR04 팀 호출 검증(team verify)

- 상태: 완료
- 백로그: [BL261123_01_프로젝트_맞춤_에이전트_팀](BACKLOG.md)

<!-- 개발 업무의 예시. 형식·추적 정본: pace-project-dev의 references/document-shape.md. -->

## 목적

만든 팀이 **정의대로 동작하는지** 확인하는 장치(목표2). 근거: roblox-studio BR01 완료 기준 "Claude·Codex 양쪽에서 7명 모두 호출되어 정의대로 답한다"를 손으로 확인했다.

## 범위

- 선행 확인: [BR01](BR01_역할_적재_실측과_도입_전_기준선.md) 실측 표와 [BR03](BR03_작업자_역할_지정(start_--role).md)이 구현한 적재 방식. verify는 **작업자가 실제로 쓰는 것과 같은 적재 경로**로 부른다 — 그래야 BR02 `sync --check`(파일 어긋남)가 못 잡는 결함, 즉 생성물이 있어도 호스트가 고르지 못하거나 다른 정의를 싣는 경우를 잡는다.
- `pace team verify [<이름>|--all] [--agent claude|codex]`: 호스트별로 **누가 무엇을 고르는지** 명시한다 — 네이티브 경로면 verify가 그 호스트의 역할 선택 인자로 생성물(`.claude/agents/<이름>.md`, Codex는 BR01이 확인한 대응 생성물)을 고르게 하고, 시작 지시 경로면 BR03과 같은 시작 지시를 쓴다. 지금 `pace agent run`에는 네이티브 역할 선택 인자가 없으므로(`src/agent/p-executor.ts`) 그 인자를 더하거나 verify가 BR03의 시작 경로를 재사용한다 — 설계에서 정한다.
- 고정 질문(너는 누구인가·맡는 일·하지 않는 일·막히면 어떻게 하나)에는 기대 답이나 정의 내용을 넣지 않는다. 판정은 원본에서 뽑은 기대 항목과의 대조다.
- **경로별로 무엇을 싣고 무엇을 검사하는지**(정의는 역할 적재 단계에서만 들어가고, 질문 단계에는 들어가지 않는다):

| 경우 | 네이티브 경로 | 시작 지시 경로 |
|---|---|---|
| 정상 | 호스트가 역할 인자로 생성물을 고른다. 원본은 세션 작업 폴더에 두지 않는다 → pass여야 함 | 적재 단계에서만 BR03과 같은 시작 지시로 원본 정의를 명시적으로 넘긴다(작업자가 읽는 것과 같은 파일) → pass여야 함 |
| 미적재(음성 대조) | 역할 인자 없음, 생성물·원본에 접근할 수 없는 작업 폴더 → fail이어야 함 | 시작 지시 없음, 원본·생성물에 접근할 수 없는 작업 폴더 → fail이어야 함 |
| 삭제 | 생성물 삭제 → 대상 선택 실패 → fail | 원본 삭제 → 적재 단계 실패 → fail |
| 변조 | 생성물만 변조(하지 않는 일 제거 등) → fail | 해당 없음 — 이 경로는 원본을 직접 싣는다. 원본 변경은 정의 변경이고 생성물과의 어긋남은 BR02 `sync --check`가 잡는다 |

- 문자열 대조의 거짓 fail을 줄이려고 기대 항목은 원본의 식별 표지(이름, 하지 않는 일마다 둔 짧은 키워드)로 대조하고, 표현이 달라 판정이 어려운 항목은 fail이 아니라 "확인 필요"로 표에 남긴다. 의미 판정 자동화는 제외.
- 결과 파일은 `.pace/team/verify/`. 실제 작업 경로 검증은 BR03·BR08이 맡고, 이 명령은 정의 적재를 빨리 확인하는 보조 검사다.
- 제외: 작업 품질 평가(BR06).

## 완료 기준

- 3명 팀에서 `verify --all`이 Claude·Codex 각각 실제 적재 경로로 표를 낸다(어느 경로를 썼는지 표에 표시).
- 위 표의 경우마다 그 호스트의 경로에서 기대대로 pass·fail이 나온다(테스트·실측). 미적재 대조 세션은 같은 정의에 접근할 수 없는 조건에서 돈다. 표에서 "해당 없음"인 칸은 이유를 결과에 적는다.
