# BR08 첫 적용(roblox-studio 이전·새 저장소)

T03 인계 대조: 기본값과 다른 model/effort의 실제 적용 여부는 전달 인자와 세션 관측을 나눠 증거·불일치/미확인 사유를 남긴다. 맞춤 실측 원본에 미리 적힌 상황/형식의 인계와, 기본 템플릿 또는 실제 팀의 새로운 요청에 대한 인계를 같은 일반화 증명으로 합치지 않는다. T03 TASK-CLOSE의 후속 항목을 현장 대표 결정·범위 밖 위임 보류 사례와 함께 대조하며, 확인하지 못한 일반 효과는 추가 표본 계획으로 공개한다.

## 목적

**첫 사용처에서 끝까지** 검증한다(목표1~4). 고른 길대로 기존 팀을 옮기는 것과 처음부터 만드는 것 둘 다 해 본다.

## 범위

- 선행 확인: [BR01](BR01_역할_적재_실측과_도입_전_기준선.md) 기준선 파일(두 저장소 모두 있어야 역할을 적용한다), BR02~BR07·BR09 완료.
- 이전: roblox-studio 9명을 `.pace/team` 원본으로 옮기고 `team sync` 결과가 지금 `.claude/agents`·`.codex/agents`와 의미상 같음(차이 목록 0 또는 승인) → `tools/sync-agents.mjs` 제거 제안(그 저장소 프로젝트로). 기존 팀을 옮기는 일이라 BR07 스킬을 쓰지 않는다.
- 역할 지정: roblox-studio 다음 시제품(bubble-catch) 착수에 `start --role athena` 사용 — BR01의 "메시지 지시 조건(P002)" 기준선과 비교된다.
- 새로 만들기: BR01에서 정한 업무 문서 저장소에서 BR07 스킬로 팀을 설계하고, 기준선과 같은 업무 유형·비슷한 크기의 업무 1건을 팀으로 수행 → BR06 측정(팀 도입 효과).
- **대표 결정**: 저장소마다 사람에게 올려야 할 결정 하나를 미리 정한다(roblox-studio: 시제품 관문 통과 판정, 업무 문서 저장소: 외부 공유·발송). 그 결정이 승인 전에 실행되지 않고, 결정 요청 → 캡틴 답 → 인계가 기록되는지 관찰한다.
- 사람 몫과 보정 구분: 캡틴의 역할 배정(`--role`)·승인은 정상 절차, 메시지로 역할을 다시 입력하는 수동 보정은 BR01 정의대로 센다.
- **실증 표**(필수 칸):

| 저장소 × 호스트 | 필수 증거 |
|---|---|
| roblox-studio × Claude | 역할 적재 기록(start 적용 항목), 담당 → 인계 → 검토 → 올림 기록, 대표 결정의 승인 전 미실행, Studio MCP 잠금 직렬화 기록(BR05) |
| roblox-studio × Codex | 역할 적재 기록, 인계·검토·올림 기록. Studio MCP를 Codex로 쓸 수 있는지는 BR01 실측에서 확인 — 쓸 수 없으면 잠금 칸은 "해당 없음(근거)"이고 Studio 작업은 Claude가 맡는다 |
| 업무 문서 저장소 × Claude | 역할 적재 기록, 인계·검토·올림 기록, 대표 결정의 승인 전 미실행, 도입 전후 비교(BR06) |
| 업무 문서 저장소 × Codex | 역할 적재 기록, 인계·검토·올림 기록 |

- 시점: 역할 적용은 각 저장소 기준선 확보 뒤. `.pace/team` 원본으로의 정식 이전은 BR02 뒤. 전체 완료 판정은 BR05·BR06 뒤.

## 완료 기준

- 실증 표의 네 칸이 모두 필수 증거를 갖는다("해당 없음"은 근거와 함께).
- roblox-studio의 시범 `tools/handoff.mjs`에서 PACE `pace team handoff`로 옮긴 기록(그 저장소 프로젝트의 커밋·제거 제안)과, 이전 뒤 새 기록이 PACE 명령으로 쌓인다는 근거가 있다.
- BR09 감사: 칸마다 근거 없는 위임을 캡틴 원문과 대조한 수, 기록된 캡틴 답을 출처 위치와 대조한 결과, 그리고 **범위를 벗어나거나 근거가 불명확한 위임을 일부러 한 건 넣었을 때 수신자가 실행 전에 보류하고 올린 기록**이 있다(두 저장소 각각, 필수).
- 칸마다 대표 업무 하나가 BR09 기록으로 **위임 → 결과 → 종결(판정 주체)**, 캡틴 원문과 해석 확인까지 같은 handoffs.jsonl에서 추적되고, 기록 누락 수(Orca 메시지·서브에이전트 호출 대비 기록이 없는 주고받기)가 함께 남는다.
- 역할 밖 요청이 정의대로 넘겨지고, 대표 결정이 캡틴 승인 전에 실행되지 않는다(두 저장소).
- 수동 보정(메시지로 역할 재지시) 0 — BR01 집계 정의로 센 기록.
- 저장소별 도입 전후 비교(BR06 장치로): roblox-studio는 역할 지정 자동화 효과, 업무 문서 저장소는 팀 도입 효과. 미확인이면 이유와 추가 표본 계획.
- roblox-studio Studio MCP 작업이 잠금(BR05)을 거쳐 실제로 직렬화된 기록.
- 두 저장소 중 하나 이상에서 PROJECT-CLOSE "팀" 행의 수정 제안이 `pace-team` 회고 단계(BR07)로 이어진 기록.
