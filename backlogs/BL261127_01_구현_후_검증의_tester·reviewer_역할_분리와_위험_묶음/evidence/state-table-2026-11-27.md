## 규칙 (판정·기록 상태에 따른 분기 없음)

- **R-집합(H1)**: 유효 집합 = 현재 TASK 지정 ∪ 사후 단계 모든 `format` 행의 추가 합집합(루트·evidence 원장, offsets·void·stale·중단 무관) ∪ 이번 추가. 매 사후 호출의 필수 항목은 이 집합 전체다(일반·공동·상위·수정 확인·owner 회차·`review-hand`).
- **R-추가(H2)**: 추가 입력은 사후 단계에서 그 내용 해시로 실행된 기록이 없을 때만 받는다. 중단 기록과 `ran:false`는 실행된 기록이 아니다. 그 밖에는 예약 전에 거부하고 드문 경우 안내를 낸다.
- **R-빈집합(H4)**: 유효 집합이 비면 예약 전에 거부한다.
- **R-재요청**: 사후 단계의 같은 대상·해시 fail 재요청은 예약 전에 거부한다(`verify-cli.ts:119-120`). owner 회차의 허용(`:350`)은 그대로다.
- **R-미점검(H9)**: A-3로 갈 때 최신 기록에서 답이 없는 묶음 항목은 TASK-CLOSE에 `미점검 — <묶음>`으로 적는다. 증거 공백 판독(`review-followup.ts:250-257`)이 A-3 항목별 판정을 강제한다(`:217-219`).
- **바꾸지 않는 것**: 예산(`review-budget.ts`), 입장 판정(`review-admission.ts:15-25`), 공동·수정 확인·상위 경로(`review-followup.ts:343-344`, `:606-614`). 아래의 "기존"은 이 코드의 현재 동작이다.

## 기호

- **시점 (나)** 실행된 해시에 추가를 시도: 그 해시로 실행된 사후 기록이 이미 있다.

## 시점 (가) 새 해시의 첫 호출 — 추가를 받는다

| 직전 상태 | 예산 | 다음 동작 | 끝까지 |
|---|---|---|---|
| 첫 구현 | 남음 | 일반 호출. 필수 = R-집합. 이유 없는 추가와 빈 집합은 예약 전 거부 | pass → done. fail·unknown → 아래 행 |
| 최신 pass | 남음 | 묶음 질문이 모두 아니오(화면·문서만)면 tester만 돈다(BR03). 아니면 일반 호출(R-집합) | 예 |
| 최신 pass | 일반·공동 소진 | 화면·문서만이면 tester만 돈다. 아니면 일반·공동이 막힌다(`review-admission.ts:19`, `:22`). 소진 응답 → B → A-3(owner 회차 호출도 R-집합, 추가는 이 새 해시 첫 호출이면 받음). A-3로 끝나면 R-미점검 | 예(기존, owner까지) |
| 최신 fail | 남음 | 일반 재검토(R-집합). 직전 지적 해소도 답한다 | 예 |
| 최신 fail | 일반 소진 | `rounds ≥ 2`면 허브 공동 기록 뒤 공동 호출(R-집합)이 열린다. 아니면 B → A-3 | 예(기존) |
| 최신 fail | 공동 소진 | A-3만 남는다. 수정 확인(`canConfirm`, `:343-344`)은 진단·확인 근거가 있으면 열리지만, 이 칸에서 진단 경로를 쓸 수 있는지는 추정이다(사전 점검 N1). 열리면 필수 = R-집합 | 예(기존, A-3 기준) |
| 최신 유효 판정 없음(unknown만) | 남음 | 일반 호출(R-집합) | 예 |
| 최신 유효 판정 없음(unknown만) | 일반 소진 | `calls` 소진이면 첫 판정 공동(`:21`, `:25`). 아니면 B → A-3 | 예(기존) |
| 최신 유효 판정 없음(unknown만) | 공동 소진 | B → A-3, R-미점검 | 예(기존) |

## 시점 (나) 실행된 해시에 추가 시도 — 판정·예산과 무관하게 같은 동작

| 마지막 기록 | 예산 | 다음 동작 | 끝까지 |
|---|---|---|---|
| pass / fail / unknown / stale(실행된 기록) | 모두 | R-추가로 예약 전 거부한다(call 행 불변). 안내는 드문 경우다. 코드 수정이면 새 해시로 (가)로 간다. 수정이 없으면 B → A-3(owner는 생략·완화 또는 코드 수정을 고름)으로 가고 R-미점검 | 예 |
| 중단·`ran:false`만 | 모두 | 실행된 기록이 아니므로 (가)와 같다 | 예 |
| (추가 없이) 같은 해시 재요청 | — | fail이면 R-재요청으로 거부(owner 회차는 허용). pass·unknown이면 기존 동작이고, 필수 = R-집합 | 예(기존) |

## 결과

- **판정 분기 제거 확인**: 추가를 받는지는 "그 해시로 실행된 사후 기록이 있는가" 하나로 정해진다. 유효 집합은 기록 상태와 무관한 합집합이다. 앞선 상태표의 (다) 칸들(pass 거부·fail 거부·unknown 허용)은 (나) 한 줄로 합쳐졌다. 판정에 따라 추가 허용이 갈리는 칸은 없다.
- 모든 칸에 다음 동작이 있고, 기존 일반·공동·수정 확인·상위·owner 경로로 끝난다. 이 백로그가 새로 만드는 입장 경로는 없다.
- **남는 주의**
  - (가)의 최신 pass + 소진 칸에서 코드 수정이 생기면 reviewer 재호출이 owner A-3까지 가야 열린다. 이는 기존 동작이다.
  - (가)의 최신 fail + 공동 소진 칸에서 진단 경로를 쓸 수 있는지는 추정이다. 확정은 BR02 착수 때 `review-followup.ts`로 확인한다.
- **시험 대응**: BR02 완료 기준의 다음 시험이 칸을 덮는다. 기존 경로 칸은 `review-admission.ts` 불변 시험이 덮는다.
  - 합집합 단조 다섯 사례.
  - 추가 새 해시 첫 호출 여섯 사례.
  - 빈 집합.
  - F11·F12.
  - 복구 경로 합집합.
  - A-3 미점검 연결.
  - 예약 전 재요청 거부.
