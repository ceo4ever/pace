## 목적

저장소 안에서 명령 한 줄로 그 저장소를 daemon 워크스페이스로 추가한다. 전역 등록부를 정본으로 삼는다([백로그 목표](BACKLOG.md#목표)).

## 범위

- **명령**: `pace daemon workspace add [<경로>] [--name <이름>] [--yes]`. 경로를 생략하면 현재 폴더의 git 최상위를 쓴다. `pace daemon workspace list`는 daemon 워크스페이스와 등록부 연결 상태를 보여 준다.
- **등록부 기준**: 실제 경로(realpath)로 전역 등록부를 찾는다.
  - 없으면 `pace workspace register`와 같은 규칙으로 등록한다. 이때 대상 저장소에 `.pace/AGENT.md`가 생기므로, 확인 화면에 그 사실을 보여 준다.
  - 있으면 그 이름을 쓴다.
  - daemon 이름 규칙(영문·숫자·`_.-` 40자)에 맞지 않거나 이미 다른 워크스페이스가 쓰는 이름이면 `--name`을 요구한다.
- **설정 기록**: daemon 설정 워크스페이스 항목에 등록 ID(`registryId`)를 함께 기록한다.
  - daemon 기동 때 등록 ID로 등록부의 현재 경로를 확인한다. 기록된 경로와 다르면, 등록부가 옮겨진 것이다(`pace workspace move`). 이때는 그 워크스페이스를 제외하고 사유를 알린다. 자동으로 따라가지 않고 다시 add하게 한다 — 원격 접근 대상이 조용히 바뀌지 않게.
  - 등록 ID가 없는 기존 항목은 지금처럼 동작한다.
- **확인**: 설정을 바꾸는 명령이라, 대화형이면 `[y/N]`으로 묻고 비대화형이면 `--yes`가 있어야만 실행한다(install과 같은 방식). 확인 화면에는 이름·경로·등록부 등록 여부·`.pace/AGENT.md` 생성 여부·접근 기본값(read-only)을 보여 준다.
- **등록부 대조**: 경로만으로 찾지 않는다. 등록부의 **활성** 항목이고, 저장소의 `.pace/AGENT.md` 등록 ID가 그 항목과 일치하며, 현재 경로가 요청 경로와 같을 때만 쓴다(`pace workspace list`의 활성 검증과 같은 규칙). 비활성 후보·정의가 깨진 항목·경로 불일치는 거부하고 사유를 보인다.
- **설정 쓰기 소유권**: daemon 설정(`config.json`)을 쓰는 쪽은 하나여야 한다. daemon이 **실행 중이면** CLI는 설정을 직접 쓰지 않고 Gateway 요청(BR02)으로 daemon이 직렬화해 기록한다. **정지 중이면** CLI는 인스턴스 소유권(포트)을 잡은 구간에서만 기록한다(`pace daemon release`의 소유권 확인과 같은 방식). Telegram `/new`도 같은 직렬 기록 경로를 쓴다.
- **이동·재등록 규칙**: 설정 항목은 등록 ID로 신원을 판단한다.
  - 같은 등록 ID의 경로가 바뀌었으면(등록부 move), 실행 중에도 다음 작업 수락 전에 옛 경로를 차단한다. 기동 때든 작업 접수 때든 등록 ID로 현재 경로를 재확인한다. 명시적 재등록(add)으로만 새 경로를 받아들인다. 기존 토픽 결속은 같은 등록 ID일 때만 이어 쓴다.
  - 같은 이름·다른 등록 ID는 충돌로 거부한다(`--name` 요구).
  - 토픽 결속 표는 이름만이 아니라 등록 ID와 함께 확인한다(이름 재사용으로 옛 토픽이 다른 저장소에 붙지 않게).
- **명시적 노출**: 등록부의 다른 저장소는 daemon에 추가하지 않는다. 확인 화면에 게시될 토픽 이름과 대상 포럼(그룹 이름)을 보인다 — 읽기 전용이어도 응답이 그 포럼 구성원에게 보이기 때문이다.
- **daemon이 꺼져 있으면**: 소유권을 잡고 설정에만 기록하고, 다음 기동 때 반영된다고 안내한다. 토픽은 기동 뒤 다시 `pace daemon workspace add`(BR02 경로)로 만들거나, 캡틴이 포럼에서 토픽을 만든 뒤 그 토픽에서 `/bind <이름>`으로 결속한다.
- 제외: 실행 중 daemon에 반영하고 토픽을 만드는 일 — BR02.

## 완료 기준

- 임시 PACE_HOME 시험으로 다음을 각각 확인한다.
  - 등록부에 없는 저장소 → 등록부 등록 + daemon 설정 추가(등록 ID 포함) + `.pace/AGENT.md` 생성.
  - 등록부에 있는 저장소 → 기존 이름·ID 사용, 등록부 무변경.
  - 이름 규칙 위반·이름 중복 → `--name` 요구, 설정 무변경.
  - 같은 저장소를 다시 add → 멱등.
  - 비대화형 `--yes` 없음 → 아무것도 쓰지 않음.
  - 등록부 move 뒤 기동 → 그 워크스페이스만 제외하고 사유 알림.
  - 등록 ID 없는 기존 항목 → 지금처럼 동작.
  - 비활성 후보·`.pace/AGENT.md` 등록 ID 불일치·요청 경로 불일치 → 거부, 설정 무변경.
  - 정지 중 기록과 동시 기동 → 소유권 경합에서 한쪽만 기록, 설정 유실 없음.
  - 옛 경로가 그대로 남은 상태의 등록부 move → 실행 중 다음 작업부터 옛 경로 차단, 재등록 뒤 같은 등록 ID의 기존 토픽에서 첫 읽기가 새 경로에서 답함. 다른 ID의 같은 이름은 거부.
- `docs/DAEMON.md`와 `pace help`에 명령을 반영한다.
