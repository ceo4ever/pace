## 목적

팀 에이전트(문제 해결 에이전트를 포함한 모든 구성원)를 호출할 때마다 프로젝트 `log.jsonl`에 **발동한 에이전트, 모델, effort, 실행 시간, 사용 토큰**을 남겨, 팀 모델·effort 최적화와 BR01 effort 상향 판단의 근거로 쓴다([백로그 목표](BACKLOG.md#목표), owner 결정 2026-11-25).

## 범위

- **호출 경로와 값의 출처**:
  - 호스트 서브에이전트 경로: 워크트리 PM(프로젝트 리드 에이전트)이 호스트 서브에이전트로 부르면 호스트가 결과에 실행 시간·토큰을 돌려준다(예: Claude Code 서브에이전트 완료 알림의 tokens·duration_ms). 모델·effort는 정의 파일(native 생성물)의 **요청값**이다. 실제 적용값은 별도로 확인한다 — P009 T01에서 정의 high가 실제 medium으로 관측됐다(`projects/P009_…/tasks/T01_…/evidence/tester-stage2.json`, `docs/TEAM.md:95`).
  - PACE 도구 경로: `pace agent run`·`pace agent verify`는 호출 결과에 `duration_ms`와 `usage`(`input_tokens`·`output_tokens`)를 이미 담는다(`src/agent/contract.ts:88-89`, 예: 검토 기록 `review-records/R*.json`의 `result.duration_ms`·`result.usage` — `input_tokens`는 null일 수 있다). 체인 시도에는 `model`·`effort_requested`·`effort_applied`도 있다(`src/agent/chain.ts:235`). 지금은 이 값이 `log.jsonl`에는 들어가지 않는다. `pace project start`의 start 사건은 역할 객체에 요청 model·effort를 남기지만(`docs/TEAM.md:129`) 호출 단위 시간·토큰은 남기지 않는다 — 토큰은 stats가 세션 기록에서 구간 단위로 읽는다(`docs/WORK-PROCESS.md:28`, 역할별 실제 사용량이 아님).
- **기록 방식(owner에게 추천한 안)**: (나) 호스트 훅이 서브에이전트 종료를 잡아 자동 기록하는 것을 기본으로 하고, 훅이 값을 주지 않는 호스트는 (가) 호출한 PM이 `pace project log`로 직접 기록한다. PACE 도구 경로는 도구가 직접 기록한다. Claude·Codex 훅이 에이전트 이름·모델·effort·시간·토큰을 넘겨주는지는 **설계 전 실측**한다(지금 미확인). 훅을 어디에 등록할지(현재 SessionStart 훅 등록 위치 `src/setup/install.ts` 확장 여부 포함)는 설계에서 정한다. 설치 경로를 바꾸면 설치 스크립트 규칙(AGENTS.md — 설치는 main에서만)을 따른다. `src/setup/`(훅 등록)은 민감 경로(`docs/SECURITY.md` 민감 경로 표 — 사용자 홈의 도구 설정 쓰기)이므로 설계에서 SECURITY 체크리스트를 적용한다.
- **기록 형식**: 새 사건 종류(예: `agent_call`) 또는 기존 사건 확장을 설계에서 고른다. 현재 검증과 맞지 않는 부분을 함께 고친다:
  - 사건 종류 목록(`src/project/event-log.ts:8` `LOG_TYPES`)과 수동 기록 허용 종류(`:115` `MANUAL_TYPES`, `:141` 오류 문구)에 새 종류가 없다.
  - `data`는 음이 아닌 정수만 받는다(`:33`) — null·미확인과 모델·effort 문자열을 담을 수 없다.
  - `role` 객체는 start 사건에만 허용된다(`:26`).
  - `pace project log` CLI 옵션(`docs/WORK-PROCESS.md:25` 사건 작성 절)에 에이전트·모델·effort·시간·토큰 입력이 없다.
  - 사건 형식 설명(`docs/WORK-PROCESS.md:21`)과 사건 작성 절(`:25`)을 갱신한다.
- **값의 구분**: 모델·effort는 요청값과 실제값을 따로 두고, 각 값에 측정 출처(호스트 보고 / 도구 측정 / 미확인)를 붙인다. 없는 값은 null·미확인으로 적고 **0으로 추정하지 않는다**. 비밀·프롬프트·응답 원문은 남기지 않는다(기존 사건 기록 규칙과 같음).
- **기존 의미 보존**: 기존 stats·팀 측정의 사건 수·대기 계산·토큰 구간 집계 의미를 바꾸지 않는다. 새 기록은 별도 집계로 읽고, 기존 집계에 섞지 않는다. 옛 판독기(옛 설치본)가 새 종류의 행을 만났을 때 행 단위로 건너뛰는지, 전체를 손상으로 보는지 확인해 호환을 정한다.
- **팀 채택 판정과의 관계**: 호출 기록이 채택 판정·팀 집계를 잘못 시작시키지 않음 — 이 백로그보다 먼저 병합되는 BL261125_02 BR02가 그 규칙(`docs/TEAM-METRICS.md`)을 정했으므로 이 BR의 기록 형식은 그 규칙을 따른다. 지금 팀 집계는 채택(`hasTeamContract`, `src/project/team-contract.ts:29`, 호출 `src/project/team-metrics.ts:83`)이 아니어도 소통 원장이 있거나(`ledgerSnapshot.present`) 사건에 `role`·`to`·`requestId`가 하나라도 있으면 미채택 집계를 반환한다(`src/project/team-metrics.ts:84`). 팀 마감·회고는 `hasTeamContract`로 갈린다(`src/project/team-finish.ts:207`, `src/project/team-retrospective.ts:27`). 집계 관계: 팀 채택 프로젝트에서는 호출 기록을 역할별로 집계하고, 미채택 프로젝트에서는 팀 마감·회고 절차를 시작시키지 않고 호출 기록만 별도 집계한다.
- **BL261124_04와의 관계**: BL04 BR01은 검토 회차마다 시간·토큰을 남기고(토큰 미보고면 `미보고`), BL04 BR03은 검토 측정을 stats에 낸다. 검토 호출이 두 곳에 이중 기록되지 않도록 한쪽을 원본으로 정하고, 값이 없을 때의 용어(`미보고`·`미확인`)를 하나로 맞춘다 — 먼저 착수하는 쪽이 정하고 다른 쪽에 연결 문구를 남긴다.
- **필수 역할 요건 등록(BL261125_02 정본 형식)**: 문제 해결자의 **호출 기록** 요건 행(호출마다 에이전트·모델·effort·실행 시간·토큰, 요청값·실제값·측정 출처)을 `skills/pace-team/references/required-roles.md` 문제 해결자 자리에 요건 ID·근거·선행 장치·요건 버전(새 행은 정본 규칙의 초기 버전)으로 등록하고 이 태스크에서 판정한다. 기록 장치는 구성원 이름과 무관하게 모든 팀 구성원에 같게 적용되므로, 판정은 한 경로 — 이 태스크 실측과 **픽스처 구성원** `pace-troubleshooter` 호출 기록 — 로 한다(BR01과 병행할 수 있으므로 실제 원본 유무에 의존하지 않는다). 실제 원본의 호출 기록 확인은 [백로그 PROJECT-CLOSE 목표 달성 판정](BACKLOG.md#목표)이 맡는다.
- **제외**: 역할 자동 최적화(기록만 하고 모델·effort를 자동으로 바꾸지 않는다), 비용(금액) 환산, 호스트 밖 수동 세션의 사후 수집.

## 완료 기준

- 도구 경로 호출 1건(`pace agent run` 또는 `verify`)과 호스트 서브에이전트 호출 1건(Claude, 가능하면 Codex)이 `log.jsonl`에 다섯 항목(에이전트, 모델, effort, 실행 시간, 사용 토큰)과 요청값·실제값·측정 출처로 남는 것을 실측한다.
- **음성 대조**: 호스트가 값을 주지 않거나 일부만 줄 때 그 항목이 null·미확인으로 남고 0으로 기록되지 않는 것을 시험으로 확인한다. 잘못된 값(비밀 후보·제어문자·음수)은 기록 전에 거부된다.
- 기존 stats·팀 측정 출력이 새 기록 도입 전후로 같은 입력에서 같음을 시험으로 확인한다.
- 팀 채택 프로젝트의 팀 측정(`docs/TEAM-METRICS.md`)에서 새 기록을 역할별로 집계할 수 있는지 확인하고(호출 수·시간·토큰, 미확인 수 분리), 집계 방식이나 남은 한계를 문서에 적는다. 미채택 프로젝트에서는 호출 기록이 있어도 팀 마감·회고 절차가 시작되지 않고 호출 기록만 별도 집계되는 것을 시험으로 확인한다(BL261125_02 BR02와 같은 기준).
- 훅 실측 결과(Claude·Codex가 넘겨주는 값과 넘겨주지 않는 값)를 증거로 보존한다.
- **BR03 소관 요건 ID 대조표**: 호출 기록 요건 ID가 정본에 등록돼 있고, 그 ID가 충족(근거: 위 실측과 픽스처 구성원 `pace-troubleshooter` 호출 기록)인 대조표를 이 태스크 증거로 남긴다.
