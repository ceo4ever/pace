# BR07 호스트 호출 기록과 외부 검토 연동

- 상태: 대기
- 백로그: [BL261125_01_문제_해결_전문가_에이전트](BACKLOG.md)

## 목적

BR03의 호출 기록을 Claude·Codex 호스트의 서브에이전트와 외부 검토에 적용한다. PM이 호스트 보고로 보강해도 한 시도에 한 행을 유지해 팀 모델·effort 조정의 근거로 쓴다. [백로그 목표](BACKLOG.md#목표) · [owner 원문](evidence/owner-call-log-2026-11-25.md)

## 범위

- 선행은 [BR03](BR03_에이전트_호출_기록.md)이다. 그 스키마·수동 명령·집계를 사용한다. PROJECT-CLOSE에서 BR03과 이 브리프의 판정을 합쳐 P-7을 대조한다.
- 호스트 훅 자동 기록이 기본이다. Claude 시작·종료 훅의 자식 식별자와 부모의 자식 결과 보고를 대조한다. 정의 파일은 모델·effort 요청값의 근거다. 실제 적용값은 관측 근거가 있을 때 기록하고, 보고되지 않는 값은 null·미확인으로 둔다. P009 T01에서 native 요청과 실제 effort가 달랐다.
- 훅이 값을 주지 않으면 PM이 호스트 보고를 `pace project log`로 기록한다. 호출 원문의 기록은 금지한다. Claude·Codex가 전달하는 필드를 제품 설계 전 실측하고 보존한다. 훅 등록 위치와 설치 연결은 설계에서 확정하며, `src/setup/` 변경 시 보안 검토·거부 시험을 한다. worktree는 임시 홈에서 검증하며 설치는 main에서만 한다.
- `review-hand` → 외부 실행 → `review-record`를 같은 시도의 행 1개와 원장 판정 `ref`로 연결한다. 시간·토큰의 출처는 외부 호스트 보고 또는 PM 직접 기록이다. 외부 검토 원장에 기록되지 않은 시간·토큰은 호출 측정 근거로 쓰지 않는다. 두 명령은 실제 호출로 계수하지 않는다.
- [필수 역할 정본](../../skills/pace-team/references/required-roles.md)에 호출 기록 요건을 ID·근거·선행 장치·초기 버전으로 등록한다. 실측과 픽스처 `pace-troubleshooter`의 호출 행을 대조해 충족을 판정한다. 제품 원본을 사용한 실측은 PROJECT-CLOSE가 담당한다.

## 태스크 설계 때 확정할 항목

- 자동·수동 기록의 시도 식별(B2). 훅 자동 기록과 PM 수동 기록이 같은 시도를 가리키는 키, 늦게 도착한 훅·수동 재시도의 중복 처리, 도착 순서가 바뀐 경우의 값 보존을 훅 실측과 BR03의 공통 입력에 맞춰 정한다.
- Claude 자동 기본의 훅 등록 위치와 부모 보고 결합 방법을 정한다. 실패·중단 및 호스트가 값을 주지 않는 경로의 상태·출처 판정도 정한다.
- Codex 훅으로 자동 기록을 관측할 수 없으면, 수동 경로(`pace project log`)에서 실제 호출 1건이 1행으로 남는 증거를 설계에서 정한다. 프로젝트·훅 신뢰와 임시 스레드 동작을 실측과 함께 기록한다.

## 완료 기준

- 두 호스트의 훅 실측과 전달·미전달 필드를 증거로 보존한다. Claude는 자동 훅과 뒤늦은 수동 보강 양쪽 순서로 같은 시도 1행을 유지한다. Codex 자동 기록 미관측 시 실제 Codex 호출 1회가 수동 기록의 1행이 됨을 증명한다.
- `review-hand` → 실제 외부 호출 → `review-record`가 1행이다. 외부 시간·토큰과 출처를 보존하고 없는 값은 null·미확인이다. 대응 판정이 없는 실패·중단 시도도 상태와 확인 가능한 값을 갖는 자체 행이다. 외부 원장 참조와 호출 집계를 구분한다.
- 호출 기록 요건 ID가 등록되어 있고, BR03 검증과 이 태스크의 호스트 실측 및 `pace-troubleshooter` 픽스처의 호출 행을 근거로 충족을 판정했다.
