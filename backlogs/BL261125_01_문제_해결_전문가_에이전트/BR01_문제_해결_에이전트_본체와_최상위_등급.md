## 목적

반복 실패를 끊을 독립 문제 해결 전문가를 최상위 모델로 실행할 수 있게 만든다([백로그 목표](BACKLOG.md#목표), 고른 길 1~3).

## 범위

- **최상위 등급 `xhigh`**:
  - `WORKER_TIERS`에 `xhigh`를 추가한다(`src/core/worker-tiers.ts:7`). 팀 원본 `tier`, `pace worker set <도구> tier.xhigh.<model|effort>`, `pace worker show`의 teamTiers, 생성물 매핑이 이 값을 받는다. 설정 항목 정규식(`src/core/worker-tiers.ts:67` `tier\.(high|medium|low)`)과 오류 문구, 모든 등급의 effort를 tier 문자열로 단언하는 시험(`test/team.test.ts:276`)을 함께 고친다.
  - **기본 effort(owner 결정 2026-11-25)**: Claude `high`, Codex `medium`. 등급 이름은 `xhigh`(최상위 모델 등급)를 유지하지만, effort는 tier 문자열이 아니라 **도구별 기본값**으로 둔다 — 현재 규칙 "effort는 등급 override → tier 문자열"(`docs/TEAM.md:83`, `src/core/worker-tiers.ts:62` `effort: override?.effort ?? tier`)의 예외다. 근거: claude-api 스킬(2026-11-03 캐시) — Fable 5.2 API 기본 effort는 high이고, high에서 시작해 xhigh는 이득이 측정된 곳에서만 쓰라고 권한다. Codex 모델의 공식 기본 effort는 미확인이다. 더 올릴지(Claude `xhigh`·`max`, Codex `high`·`xhigh`)는 아래 능력 eval의 실측(해결 일치율 대비 시간·토큰, [BR03](BR03_에이전트_호출_기록.md) 기록)으로 판단한다. BR03이 아직 병합되지 않았으면 같은 다섯 항목(에이전트·모델·effort·실행 시간·토큰)을 eval 증거 파일에 직접 남긴다 — BR01은 BR03을 선행으로 두지 않는다.
  - **기본 모델**: `xhigh` 등급의 기본 model은 일반 worker 기본값이 아니라 각 도구의 최상위 모델로 둔다 — Claude `claude-fable-5-2`, Codex `gpt-6.2-astra`. 문서화된 해석 순서 "tier override → 일반 worker model → 배포 기본값"(`docs/TEAM.md:83`, `:127`)의 예외이므로 두 곳에 예외로 적는다. 사용자 override(`worker-tiers.json`)는 여전히 우선한다.
  - **호스트가 모델을 거부할 때**: 미배포·계정 권한·데이터 보존 요건(claude-api 스킬: Fable 5.2는 30일 보존이 필요하고 ZDR 조직은 400) 등으로 거부되면 처리 방식을 설계에서 정한다 — 선택지: (가) 차하위 모델로 대체 실행하고 실제 모델을 기록, (나) 호출을 보류하고 호출한 PM에게 거부 사유를 돌려준다. 어느 쪽이든 조용히 바꾸지 않고 요청값·실제값을 기록에 남긴다(BR03 병합 전이면 증거 파일).
  - **옛 설치본 호환**: 옛 판독기는 새 값을 전체 손상으로 처리한다 — `worker-tiers.json`의 `xhigh` 키는 파일 전체 거부(`src/core/worker-tiers.ts:48`), 원본 `tier: xhigh`는 팀 원본 파싱 오류(`src/team/model.ts:98`, 모르는 필드도 거부 `:87`)라서 `pace team sync`(`src/team/sync.ts:43` `loadTeam`)와 팀 측정(`src/project/team-metrics.ts:278-280` — 채택 저장소면 오류, 아니면 원본 관측 미확인)이 깨진다. 이는 `docs/TEAM.md:72`가 "옛 설치본이 새 키를 손상으로 읽지 않도록" 등급 파일을 분리한 것과 같은 위험이다(새 판독기가 옛 파일을 읽는 문제가 아니라 **옛 판독기가 새 값을 읽는 문제**). 호환 방식을 설계에서 고른다 — (가) 별도 파일·키 분리(옛 판독기가 보지 않는 위치에 `xhigh` 매핑·구성원 등급 승격을 둔다. 위치·형식은 BL261125_02 BR02가 정한 필수 역할 표지 형식을 따르거나 같은 원칙 — 옛 판독기가 보지 않는 별도 파일·키 — 으로 정한다), (나) 병합 전 재설치 순서 강제(main 병합 직후 `bash scripts/install.sh`, 다른 worktree·기기의 옛 설치본 영향과 안내 포함). **(가)를 기본안으로 둔다**(PM 결정 2026-11-25). (나)를 고르면 프로젝트 게이트(`pace team list`·`team sync --check`·finish·merge)를 어느 실행본(worktree의 `./bin/pace.ts` 대 설치본 `~/.pace`)으로 돌리는지 설계에 명시해야 한다 — 설치본은 main에서만 설치하므로(AGENTS.md) 병합 전 worktree의 설치본은 옛 판독기이고, 옛 판독기는 `tier: xhigh`를 거부하며(`src/team/model.ts:98`), 팀 채택 프로젝트의 finish(`src/project/harness.ts:1678`)·merge(`:1852`)는 `refreshProjectMetrics` → `collectTeamMetrics`를 거쳐 `src/project/team-metrics.ts:278-280`(채택 저장소면 `loadTeam` 오류를 그대로 던짐)에 닿는다. (가)에서도 옛 설치본으로 `pace team sync`를 돌리면 서로 다른 매핑으로 공유 생성물이 번갈아 바뀌는 문제(`docs/TEAM.md:97`)가 생기는지 확인한다. 기존 high·medium·low의 해석·생성물 바이트는 바꾸지 않는다. 새 구성원 자동 배정(`src/team/store.ts:92`)도 바꾸지 않는다 — `xhigh`는 명시한 구성원만 쓴다.
- **호출 수단**: 문제 해결 에이전트를 무엇으로 부를지 정한다. 후보는 (가) 호스트 서브에이전트(native 생성물 `.claude/agents`·`.codex/agents`)와 (나) PACE 도구 경로 `pace agent run --agent claude|codex --model --effort`(`src/cli.ts:156`, 실행 인자로 전달)다. 호출 주체(허브/워크트리 × Claude/Codex)별 제공자와 기본 수단을 표로 정한다. 제약: `pace agent verify`는 구성원·tier를 받지 않는다(`src/agent/verify-cli.ts:20`). tier 해석은 `project start --role`(`src/team/worker-role.ts:74`)과 native 생성물(`src/team/sync.ts:47`)에서만 일어난다. 체인 경로의 effort 정규화(`src/agent/chain.ts:37-40`, Codex `max`→`xhigh` `:44`)는 `pace agent run --chain` 근거일 뿐이고, native 생성물은 effort를 정규화 없이 그대로 쓴다(`src/team/sync.ts:24-25`). P009 T01에서 Claude native 정의 effort high가 실제 medium으로 관측됐으므로(`docs/TEAM.md:95`, `projects/P009_…/tasks/T01_…/evidence/tester-stage2.json`) Claude `high` 기본값이 바로 그 위험한 값이다 — 아래 실제 적용 관문이 필수다.
- **팀 구성원 `pace-troubleshooter`**(역할 종류 reviewer, tier `xhigh`):

  - BL261124_05 BR01(완료, P011)이 팀 원본 전부와 템플릿(`templates/team/member.md:29` 실행 전 대조 보충 문단)에 보충 문단을 넣었으므로, 이 원본은 그 템플릿으로 만든다. BR02 착수 전에는 이 BR01이 병합돼 있고 BL261124_04 BR01·BR02도 병합돼 있어야 한다 — 순서 BL261124_04 BR01·BR02 → BR02(PM 결정 2026-11-25, BL04 재구성 2026-11-25 23:58, [백로그 관련·순서](BACKLOG.md#목표)).

## 완료 기준

- **BR01 소관 요건 ID 대조표**: 위 소관 요건이 `required-roles.md`에 요건 ID로 등록돼 있고, BL261125_02 BR01 점검 장치(`pace-team` 필수 역할 점검)로 `pace-troubleshooter`를 점검한 대조표에서 BR01 소관 요건 ID가 모두 충족이다(실제 적용 관문 ID는 아래 관문 증거로 판정). 대조표를 이 태스크 증거로 남긴다. 호출 조건·호출 기록 요건은 BR02·BR03 태스크에서 등록·판정하고, 문제 해결자 전 요건의 최종 대조표는 [백로그 PROJECT-CLOSE 목표 달성 판정](BACKLOG.md#목표)에서 닫는다.

- 고른 호환 방식의 설정 경로(파일·키 분리면 그 위치, 아니면 `pace worker set claude tier.xhigh.model <값>`)에서 설정·`reset`이 동작한다. 잘못된 등급 이름은 거부한다. 기존 high·medium·low의 생성물 바이트가 바뀌지 않는 것을 시험으로 확인한다.
- `xhigh` 기본 매핑이 Claude `claude-fable-5-2`·effort `high`, Codex `gpt-6.2-astra`·effort `medium`이고 override가 우선하는 것을 시험으로 확인한다. 다른 등급의 effort는 계속 tier 문자열임을 같은 시험에서 확인한다.
- **옛 판독기 시험**: 고른 호환 방식에서 옛 판독기(병합 전 커밋의 `readWorkerTiers`·`loadTeam`, 또는 옛 설치본)가 새 저장소·새 `PACE_HOME`을 읽을 때 기존 등급 해석·`team sync --check`·팀 측정이 깨지지 않음(또는 재설치 순서 강제 시 그 안내·차단이 동작함)을 시험으로 확인한다. (가)에서는 옛 설치본으로 `pace team sync`를 돌려도 공유 생성물이 번갈아 바뀌지 않는지(`docs/TEAM.md:97`)도 확인한다.
- `pace-troubleshooter` 원본·생성물이 있고, `pace team list`·`pace team sync --check --json`이 차이·오류 없이 통과한다. BL261125_02 BR02의 필수 역할 표지(조건부 호출)가 이 구성원에 적용돼 있다.
- **실제 적용 관문**: 정한 호출 수단으로 Claude·Codex 각각 이 구성원을 실제로 불러 런타임 model·effort가 요청값과 같은지 확인하고 증거를 남긴다(전달과 적용을 구별 — `docs/TEAM.md:129`). **불일치·미확인이면 done하지 않는다** — 대체 경로(다른 호출 수단, 실행 인자 전달 등)로 맞춘 뒤 다시 실측한다. 대체 경로 시도는 **2개까지**다 — 그 뒤에도 불일치·미확인이면 결과를 "미확인"으로 기록하고 BL261124_05 A-1 결정 요청(기준 미달 마감 여부)을 올린다. 모델 거부 시 정한 처리(대체 또는 보류)가 동작하는 것도 확인한다.
- **능력 확인(eval)**: 과거 반복 실패 사례 2건 이상(예: P001 사전 검토 14회, P005 T04)으로 실행한다.
  - 입력: 사례마다 당시 실패 원문이 실제로 남아 있는지 먼저 확인하고, 없으면 다른 사례로 바꾼다. 실행은 해결 이전 커밋 checkout(또는 사후 정답 문서를 뺀 사본)에서 새 맥락으로 한다.
  - 대조군: 같은 입력을 기존 high 등급(같은 지침, 현재 high 매핑)으로도 실행한다.
  - 선택 항목(effort 비교 축): 기본 effort에서 실패한 사례에 한해 한 단계 위 effort(Claude `xhigh`, Codex `high`)로 1회 더 실행해, effort 상향의 이득을 비교하는 근거로 쓴다.
  - 판정: 작성자가 아닌 쪽(독립 리뷰어 또는 다른 제공자)이 반환의 필수 항목 충족과, 원인 층·추천안이 실제 최종 해결(사후 기록)과 같은 층을 가리키는지 판정한다. 통과 문턱(예: 사례의 과반 일치, 대조군 이상)은 실행 전에 고정한다.
  - effort 판단 근거: 사례별 실행 시간·토큰(BR03 형식, 병합 전이면 같은 항목의 증거 파일)을 함께 남겨, 기본 effort를 더 올릴지 판단할 수 있게 한다. 판정 근거와 원응답을 증거로 보존한다.
