## 목표

독립 검토를 **"blocking 0까지 도는 수렴 관문"에서 "예산 안에서 판정 질문 하나에 답하는 일"로** 바꾼다. 태스크·백로그 검토의 회차와 호출에 도구가 상한을 두고, 검토 종류마다 판정 질문 하나에 걸리는 재현 근거 있는 결함만 관문을 막게 하고, 예산과 공동 시도를 다 쓰면 허브가 다음 조치를 판정한다. 필요한 독립 수정 확인은 수행해 사후 보고한다. 문턱 뒤에는 구조 진단과 필요한 수정·독립 재검증을 진행한다. 실제 합의 변경, 검증 생략·완화 또는 증거 공백·잔여 blocking 수용을 제안할 때 owner에게 결정 요청한다. 기록과 측정은 도구가 남긴다.

- **상위 목적**: PACE 하네스는 에이전트가 태스크를 자율로 끝까지 수행하되 결과의 품질을 독립 검토로 지키게 한다. 지금 검토는 품질을 지키는 대신 진행을 막고 시간·토큰을 키운다.
- **현장 문제(owner)**:
  1. 검토 상한이 없다. 계획을 다시 쓰면 횟수가 0부터 시작하고, 구현 뒤 검증에는 상한이 없다(2026-11-24).
  2. 사소한 지적으로 재검토가 돌며 시간·토큰을 낭비한다(2026-11-24).
  3. 사전 검토마다 어느 TASK 버전을 봤는지 복원하지 못한 태스크가 있었다(2026-11-24, 앞선 4회).
  4. "사전 검토를 할때에 구현을 계속 지적을 하고, 상한 없으니 20번도 넘게 검토를 해서 백로그를 작성한 서야."(2026-11-25, [owner 결정 원문](evidence/owner-decisions-2026-11-25.md)) — 백로그 검토에도 상한이 없고, 사전 검토가 구현 방식을 지적한다.
- **owner 결정(2026-11-25, 원문 [evidence/owner-decisions-2026-11-25.md](evidence/owner-decisions-2026-11-25.md))**:
  - Q1(a): 백로그 검토에도 태스크와 같은 예산(전체 1 + 범위 재검토 1)과 호출 상한을 도구로 적용한다. 백로그는 owner가 다시 설명하지 않아도 프로젝트가 착수해 끝까지 가도록 무엇을·왜·순서를 확정해 넘기는 인계 문서다. 설계·구현 방식은 프로젝트가 정한다. 판정 질문은 "이 백로그로 착수하면 owner에게 다시 묻지 않고 합의 목표까지 갈 수 있는가?"이고, 설계·구현 방식 지적은 blocking이 될 수 없다.
  - Q2(a): 검토 종류마다 판정 질문 하나를 고정하고 그 질문에 걸리는 결함만 blocking으로 둔다. 구현 전 TASK 검토의 질문은 "이 계획이 목적을 증명할 수 있는가?"다. 구현 방식 지적은 도구가 note로 낮춰 구현 후 검토로 넘긴다. 구현 후 reviewer와 tester도 판정 질문을 하나씩 둔다.
  - Q3(b): 자동 반복은 예산까지 한다. 예산을 다 쓰면 허브 공동 시도를 최대 2회 한다. 공동 시도는 문제 해결자 호출 → 허브 결정 → 적용 → 재검증이고, 문제 해결자 호출은 검토 회차로 세지 않고 재검증만 센다. 총 재검증 상한은 예산 + 2다. 상한에 닿으면 도구가 거부만 하지 않고 정리해서 owner에게 결정을 올린다.
    - 후속 owner 결정(2026-11-26, P013 T01 사례): 일반 검토 상한 뒤에도 기존 기준을 충족하기 위한 독립 수정 확인이 필요하면 수행 후 보고한다. 검증 생략·완화를 선택하면 A-3으로 요청한다. 이 결정은 Q3의 상한 뒤 처리에 적용한다. [반영 계약](BR02_예산_소진_뒤_공동_시도와_owner_결정_요청.md#범위)
  - Q4(a): PM이 남은 blocking을 스스로 수용하는 경로를 없앤다. 남은 blocking은 언제나 owner 결정이다.
  - Q5: 문제 해결자는 백로그 단계에서도 호출한다.
  - 허브 전달(owner 파일 원문에 문장으로는 없음 — 허브가 대화에서 정리해 전달): Q1 하위 확인 4개(목표가 상위 목적·owner 원문에 맞는가 / 완료 기준이 판정 가능한가 / 순서·선행·다른 백로그와 충돌이 없는가 / owner 결정이 남아 있지 않은가), 구현 후 reviewer 질문 "이 변경을 내보내도 되는가?", tester 질문 "기준마다 증거로 통과하는가?", escalation 보고 항목(대상·실패 추이·문제 해결자 진단과 시도한 조치·남은 지적의 A 판정·선택지와 추천), owner 결정 기록 전 같은 대상 verify 금지, Q5의 순서(예산 소진 뒤 허브가 호출 → 허브 결정 → 백로그 기획자 반영 → 재검증 최대 2회 → escalation, 조기 신호가 뜨면 예산 안에서도 호출).
