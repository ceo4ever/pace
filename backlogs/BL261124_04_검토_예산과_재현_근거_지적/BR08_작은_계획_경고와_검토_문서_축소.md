## 목적

검토할 표면을 줄이고, BR01~BR06에서 도구가 강제하게 된 규칙을 문서에서 빼서 검토·작성 세션의 맥락 부담을 줄인다([백로그 목표](BACKLOG.md#목표) 고른 길 5).

## 범위

- **작은 계획 경고**: TASK에는 목표·수용 기준·증명 범위만 두고 구현 상세는 접근 한두 줄로 제한한다. `check`가 TASK 크기 상한을 넘거나 다른 태스크(같은 프로젝트의 다른 T·BR) 기준이 섞이면 경고한다(`src/project/pre-review.ts`). 차단 여부는 설계에서 정한다(옛 원안과 같음). 아래 완료 기준은 경고를 기준으로 쓴다. 상한 값은 설계에서 과거 TASK 크기 분포로 정한다.
- **선례 확인**: 외부 시스템(Telegram·OS 서비스·다른 CLI 등)을 다루는 태스크는 설계 전에 브레인·기존 도구에서 같은 사례를 찾아 TASK에 한 줄 남기고, 검토자에게도 그 결과를 넘긴다(`task-steps.md`). 근거는 다른 OS 기준 계획으로 design 층 반복 실패가 난 사례다(`.pace/brain/pages/concept/검토-반복-실패-하네스.md:25`).
- **문서 축소**: `skills/pace-project-dev/references/reviewer.md`(125줄)·`task-steps.md`·`cross-verify.md`·`coordinator.md:23`·`SKILL.md` §6(`:84`)·`docs/AGENT-CALL.md:12`의 검토 절을 원칙 위주로 다시 쓴다. 도구가 강제하는 규칙(예산·공동 시도·escalation·판정 계산·강등·허가 범위·PRE-REVIEW 생성)은 문서에서 빼고 이유만 남긴다. BR05의 문서 반영(허가 범위·고치고 진행)을 여기서 한다.
- **문구 고정 시험**: `test/project-dev-skill.test.ts:82-93`(reviewer.md 필수 문자열·절 제목·`decision-rights.md#실행-전-승인-확인` 링크·다른 문서의 `reviewer.md#반복-실패-진단과-사용자-결정` 링크)과 `:96-115`(정본 링크 필수·옛 올림 문구 금지)는 지킨다. 절 제목이나 필수 문자열을 바꾸면 시험과 링크하는 모든 문서를 같은 태스크에서 함께 갱신한다. `test/project-dev-skill.test.ts:15` SKILL.md 크기 상한도 지킨다.
- **민감 경로**: 없음(문서와 `pre-review.ts` 경고).
- 제외: 도구 동작 변경(BR01~BR07).

## 완료 기준

- TASK 크기 초과·다른 태스크 기준 섞임 → check 경고(설계에서 차단으로 정했으면 거부, 시험). 지금 check에서는 경고가 없다.
- `reviewer.md` 줄 수·글자 수가 줄어든 전후 비교를 TASK-CLOSE에 남긴다. 도구가 강제하는 규칙이 문서에 중복으로 남아 있지 않음을 대조표(규칙 → 도구 위치)로 남긴다.
- 스킬 eval 시나리오 S1~S7(`skills/pace-project-dev/evals/scenarios.md`)을 새 차수로 다시 돌려 회귀가 없다. 예산 소진 → 공동 시도 → escalation, 사전 검토 구현 방식 지적의 note 처리를 다루는 시나리오가 추가돼 통과한다.
- 문구 고정 시험을 포함한 `npm run check`가 통과한다.
