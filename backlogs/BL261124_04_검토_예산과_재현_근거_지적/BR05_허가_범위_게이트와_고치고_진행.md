## 목적

통과가 무엇을 허가하는지 기록하고 게이트가 그 범위를 지킨다. 그 위에서 should_fix·note 반영처럼 지적 위치 안의 작은 수정은 재검토 없이 진행하게 한다([백로그 목표](BACKLOG.md#목표) 고른 길 4).

## 범위

- **허가 범위**: pass에 허가 범위(예: "탐침까지만", "구현 전체")와 검토한 대상 해시를 원장과 `PRE-REVIEW.json`에 함께 기록한다. 필드 형식은 이 BR이 정하고, BR06 PRE-REVIEW 생성이 그대로 옮긴다.
- **게이트**: check·done(`src/project/harness.ts` `checkTaskRaw` `:1193`, `reviewIssues` 호출 `:1211`, `src/project/pre-review.ts:80`)과, 같은 check를 부르는 commit-msg 훅(`harness.ts:759-771`의 `PACE_COMMIT_CHECK=1 pace project check`)은 허가 범위를 넘는 진행을 거부한다. 훅 설치 경로(`:775-802`)는 바꾸지 않는 것을 기본으로 한다. 범위를 넓히려면 새 검토를 받는다.
- **고치고 진행**: pass 뒤 should_fix·note 반영 변경은 두 조건을 모두 만족할 때만 재검토 없이 진행한다. 바뀐 줄이 그 지적의 위치(BR03 구조화된 지적) 안에 있어야 하고, pass가 근거로 든 위치와 허가 범위를 건드리지 않아야 한다. 도구가 diff 범위로 이를 확인한다. 벗어나면 범위 재검토를 요구한다. 이 재검토는 BR01 예산에서 센다. 진행한 변경은 diff와 함께 기록되어 다음 단계(구현 후 검토)의 입력이 된다. 지금 게이트는 마지막 pass 해시와 현재 TASK 해시가 다르면 거부한다(`skills/pace-project-dev/references/reviewer.md:123`). 고치고 진행은 그 예외를 도구가 확인한 경우로만 연다.
- **민감 경로**: `harness.ts`(check·done 게이트, start가 설치하는 commit-msg 훅)는 `docs/SECURITY.md` 민감 경로다. 설계에서 PROJECT.md 보안 영향에 적고, reviewer가 보안 관점을 먼저 본다. 시험은 거부·오류 경로까지 둔다. 이 BR은 코드와 시험만 바꾼다. 스킬·docs 문서 갱신은 BR08이 한다.
- **문구 고정 시험**: `test/project-dev-skill.test.ts:96-115`는 `harness.ts`에 옛 올림 문구가 없어야 한다고 고정한다. `test/project-role.test.ts:51` workerSpec golden은 바꾸지 않는다. 바뀌면 의도적으로 갱신한다. `test/pre-review.test.ts`의 기존 게이트 시험은 유지한다.
- **겹침**: BL261118_02 BR04(독립 검증 세션 기록 관문, 대기)가 같은 `pre-review.ts`와 done 게이트를 바꾼다. 먼저 착수하는 쪽이 대상 해시·기록 형식을 정하고 다른 쪽 BR에 연결 문구를 남긴다.
- 제외: 지적 형식(BR03), verify 밖 기록·PRE-REVIEW 생성(BR06), 문서(BR08).

## 완료 기준

임시 저장소 시험으로 확인한다. 첫째·셋째·넷째 항목은 지금 게이트에서 실패한다(첫째는 통과해 버리고, 셋째는 해시 불일치로 거부된다). 둘째는 회귀 방지다(지금도 거부, `reviewer.md:123`).

- 허가 범위가 "탐침까지만"인 pass 뒤 허가 범위 밖 구현 변경이 있는 태스크 → check(commit-msg 훅 경로 포함)와 done이 거부한다.
- 허가받은 해시와 다른 TASK로 진행 → 거부한다.
- should_fix 위치 안에서만 TASK를 고친 변경 → 재검토 없이 done 통과, 변경 diff가 기록된다.
- 지적 위치 밖이나 pass 근거 위치를 건드린 변경 → 범위 재검토 요구로 거부한다.
- 허가 범위 필드가 없는 옛 PRE-REVIEW → 지금 동작 그대로다.
- 사용자 commit-msg 훅 보존(`harness.ts:802`) 등 기존 거부 경로 시험이 그대로 통과한다. `npm run check`·보안 검사가 통과한다.
