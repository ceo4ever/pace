# BR09 수정 확인과 상위 근본 검토

- 상태: 완료
- 백로그: [BL261124_04](BACKLOG.md)
- 선행: BR02(T02a), BR03(T03)

## 목적

공동 시도 뒤에도 기존 기준에 필요한 수정 확인을 수행하고 사후 보고한다. 구조 진단 뒤 독립 확인이 다시 실패하면 근본 검토가 끝날 때까지 해당 단위의 수정과 추가 확인을 막는다. [사용자 결정과 분할 근거](../../projects/P013_261126_검토_예산과_재현_근거_지적/tasks/T02_예산_소진_뒤_공동_시도와_owner_결정_요청/evidence/upper-review.md)

## 범위

- 검토 순서는 단계 일반 예산(전체 1 + 범위 재검토 1), 단위 전체 공동 시도 최대 2회, 수정 확인(지적당 1회·단위 최대 2회), 문턱의 허브 구조 진단, 그 뒤 한정 수정 확인 1회다. 직전 독립 지적·변경 지문·근거를 연결하고 누적 횟수와 판정을 사후 보고한다.
- 기존 원장 진단과 수정 확인의 구조 진단을 한 기록으로 표현한다. 진단 이후에도 독립 확인이 실패하면 하네스가 기존 `ask_user` 자리에서 `upper_review`를 반환하고 단위의 수정·재검증을 차단한다. 근본 검토 기록으로 차단을 해제하고 허브 판단을 연결한다.
- 첫 상위 검토의 해결안을 허브가 적용하고 독립 재검증 1회를 수행해 사후 보고한다. 실패하면 두 번째 상위 검토에서 계약·백로그 자체를 새 맥락으로 대조하고 독립 재검증 1회를 수행한다. 두 번째 재검증도 실패하면 A-1로 합의 조정 또는 보류를 요청하며 반복을 끝낸다.
- 작성자·작업자와 다른 새 맥락 독립 검토자가 근본 검토한다. 이 호출은 단위 공동 시도·일반 호출·수정 확인 상한에 포함하지 않는다. 계약을 실제 변경하면 단계 일반 예산만 다시 시작하고 공동·수정 확인 누적은 유지한다.
- 필수 수정과 확인은 허브가 처리하고 보고한다. 실제 합의 변경은 A-1, 검증 생략·완화 또는 미확인 증거·잔여 blocking을 안고 진행하는 선택은 A-3이다.
- 전문가 호출 자동 연결은 BL261125_01의 BR04 호출 절차 연결다. 이 브리프는 하네스 상태, 차단, 독립 근본 검토의 기록 연결만 구현한다.

## 완료 기준

- 태스크와 백로그에서 단계 일반 예산→공동 시도→수정 확인→허브 진단→한정 확인의 순서와 단위 집계를 확인한다.
- **상한 도달과 상위 검토** 시험은 공동 시도 및 호출 상한을 다 쓴 상태에서 구조 진단 뒤 한정 확인이 다시 실패하면 `upper_review`가 나오고 단위 수정·재검증이 차단되는지 확인한다. 근본 검토는 허용되고 기존 횟수는 늘지 않는다.
- 계약 변경 없이 첫 상위 검토 해결안을 적용해 독립 재검증에 통과하는 경우와, 두 번째 상위 검토 뒤 재검증에서도 실패해 A-1로 올라가고 추가 실행이 차단되는 경우를 시험한다. 상위 검토 뒤 재검증은 기존 공동·수정 확인 누적을 유지한다.
- 근본 검토가 제안한 계약이 실제로 바뀌면 일반 예산만 새로 시작한다. 단위 공동 시도 및 수정 확인의 기존 누적은 보존한다.
- 새 맥락 독립 근본 검토의 기록과 허브 결정·사후 보고, 실제 A-1 또는 A-3 선택을 확인하고 선언된 전체 검사를 통과한다.
