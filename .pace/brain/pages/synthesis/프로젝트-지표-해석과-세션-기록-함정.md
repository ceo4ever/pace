## 시간 지표의 근거

착수·완료를 git에서 추론하면 구현이 끝난 뒤 첫 커밋이 생겨 실제 작업 시간이 짧아 보인다. 사건 기록을 우선하고 기록 이전 프로젝트만 git 시각으로 보완한다. rebase는 committer 시각을 다시 쓰므로 author 시각을 써야 한다. 실측을 main 코디네이터가 확인했고, 두 시각이 다른 회귀 테스트로 이 차이를 검증한다.

## 토큰을 해석할 때

도구의 캐시·추론 필드는 같은 합계를 나타내지 않는다. Claude의 별도 캐시 입력과 Codex의 입력에 포함된 캐시·출력에 포함된 추론을 단순 합하면 이중 계산된다. 도구별 필드를 분리하고 공통 총량을 만들지 않았다. 세션이 보존되지 않거나 형식이 바뀌면 기록 없음 또는 일부 누락이 가능하다.

Codex는 구간 이전 baseline을 보존해야 한다. 손상된 음수·문자열 누적값을 0으로 보정하면 가짜 reset이 생겨 다음 정상 누적값 전체를 다시 더한다. 손상 행을 통째로 건너뛰는 회귀를 검증했다. Claude는 스트리밍·복제 기록의 message id를, Codex는 rollout 첫 메타의 id와 timestamp를 기준으로 복제 기록을 줄이고 후속 부모 메타로 정체성을 바꾸지 않는다.

## 안전한 사건과 후속 검토

사건에는 원문 명령 인자·오류·세션 내용 대신 고정 이유 코드를 남긴다. 기록 대상이 링크·FIFO일 때도 명령을 붙잡지 않아야 한다. 끊어진 링크는 존재 검사만으로 거를 수 없고, FIFO는 파일을 열 때부터 대기하므로 링크 추적 금지·비차단 열기와 일반 파일 검사가 필요했다.

개선 후보는 반복 실패 코드·리뷰 등급의 횟수와 TASK-CLOSE 남긴 것 링크다. 내용을 자동으로 브레인에 복제하거나 개선을 확정하지 않고, 사람이 재사용할 교훈을 선택하게 했다. [[작업-하네스-흐름]]과 [[작업-하네스-실측-함정]]을 함께 본다.

## 통합 사건과 대기 시간

사용자가 하네스 사건을 결정·변경·리뷰·질의까지 log.jsonl 하나로 모으도록 승인했다. 명령 출력·세션 내용·diff를 다시 쓰는 작업 일지는 여전히 만들지 않고, 짧은 판단과 수치만 보존한다. decision/change를 명령이 결정 표까지 반영해 두 곳을 손으로 맞추는 중복을 피했다.

질의·에스컬레이션→답변 대기는 같은 태스크/프로젝트 범위에서 겹친 구간을 한 번만 센다. 작업 경과는 달력 시간에서 기록된 질의 대기를 뺀 값으로 CPU 활성 시간이 아니다. finish→merge는 별도 병합 승인 대기이며, 토큰은 러닝 구간인 start→finish에서 끝내야 기다리는 동안의 기록과 섞이지 않는다. 과거 start가 발견한 계약 승인은 확인 시각만 남기며, 알 수 없는 과거 승인 대기는 0으로 단정하지 않았다. 지금은 출처를 착수 결정(CLI decision)으로 기록하고 승인 대기 없이 start한다. 과거 approval 사건은 호환을 위해 계속 읽는다. 출처가 긴 경우 로그의 src 길이 제한에 맞게 줄이고 전체 근거는 PROJECT.md ref로 보존한다(2026-10-24 확인).

## 부모 메타가 섞인 rollout

실제 한 프로젝트의 9개 rollout 중 8개 서브에이전트 파일에는 자기 메타 뒤 부모 session_meta가 다시 나타났다. 후속 메타 id로 세션 map을 바꾸면 서로 다른 누적열이 섞여 94개의 가짜 reset을 만들고 토큰이 약 16~20배 부풀었다. 파일 안의 누적값 자체는 감소하지 않았다. 첫 메타로 정체성을 고정하고 세션마다 [착수, 완료] 마지막 누적값에서 착수 전 마지막 값을 한 번만 뺐다. 감소를 새 과금으로 합산하지 않는다.

태스크 착수 시각을 고정한 독립 Python 집계와 제품이 9개 rollout 출력 102,060으로 정확히 일치했다. 최초 참조 101,931과 129 차이는 후속 턴 첫 도구 호출 뒤 착수 사건이 생긴 시점 차이다. 가짜 기록의 기대값만으로 완료를 판단하지 않고 실제 기록 형식과 독립 계산을 함께 대조해야 한다.

## 병합 뒤 세션 귀속과 문서 정본

현재 체크아웃 경로로 세션을 고르면 worktree를 지운 뒤 main 조회에서 작업자 기록을 잃고 main 코디네이터 기록을 작업자로 오해한다. PROJECT 머리의 worktree 경로를 main 기준으로 풀어 지워진 경로도 문자열로 비교하고, main 세션의 착수→병합 구간을 코디네이터로 분리했다. 같은 시간 main의 다른 대화가 섞이는 한계는 남는다. 실제 재집계에서 작업자 Codex 출력이 마감 당시와 일치했다. 태스크 행 소실은 당시 현재 소스에서 재현되지 않아 추측으로 수정하지 않았다.

지표 정본은 프로젝트 METRICS.md(상세)와 projects/METRICS.md(비교)다. finish·merge가 다시 생성하고 PROJECT-CLOSE에는 링크와 에이전트 해석 1~3줄만 둔다. 비교표는 최신 상세 스냅샷을 모으므로 모든 세션을 다시 읽지 않는다. 태스크 밖은 프로젝트−태스크 합이며, Codex 경계 중복·누적값 감소 때문에 음수가 될 수 있다. 파일 변경은 태그 커밋 numstat로, 생성 시 미커밋 변경과 자기 마감·병합 커밋은 다음 재생성 전까지 빠진다.

상세의 태스크 구간 평균은 태스크 작업 시간 합÷태스크 수이고 비교표의 태스크당 시간은 프로젝트 작업 시간÷태스크 수다. 범위와 도구·기록 누락을 고려하지 않은 생산성 순위로 쓰지 않는다. 병합 때 표 값이 보통 그대로면 재생성 호출을 빼도 테스트가 통과한다. 임시 저장소에서 낡은 비교표를 먼저 커밋하고 merge가 복구·커밋하는지 검증해야 이 누락을 검출한다.

질문은 작업자가 ask 직전 --to coordinator, 답은 수신 직후 같은 태스크/프로젝트 범위로 기록한다. 코디네이터는 누락 질문을 같은 수신자로 보완한다. 사용자에게 실제 전달하면 별도 --to owner 사건과 프로젝트 내부 연결 근거를 남기고, 사용자 답 수신 때 코디네이터 answer로 전달 대기를 닫은 뒤 작업자에게 전달한다. 작업자도 원질문의 answer를 기록한다. 전달 요청 1건은 질문 사건 2·답 사건 2이므로 사건 수를 사용자 개입 수로 쓰지 않는다. FIFO 짝은 대기 합집합용이며 의미상 답 연결이 아니다. 리뷰 회차는 로그 사건을 우선하고 폴더·문서가 없어도 잃지 않으며, 로그 없는 과거 태스크만 TASK-CLOSE로 보완한다.

결정 출처의 표준 표기는 `사용자 결정`이며 기존 `루카스 결정` 기록도 계속 허용한다.

## 팀 측정·표본·회고의 증명 경계 (2026-11-24)

P009 T06은 요청별 도달과 실패 attempt, 수신 의도/옛 미연결 사건을 별도 집계한다. 손작업/추가 지시와 정상 배정·승인은 관측 하한/신고 총량을 분리하고, 닫힌 범위·다른 확인자·typed 영수증 없이는 총량을 null로 둔다. actor와 complete는 사람 인증이 아니다. coordinator 자체 답도 명시 요청별 근거와 사용자 미도달을 대조한다. cwd/구간 토큰은 역할별 실제 사용량이 아니고 역할 결합 관측이 없으면 null이다.

비교 목적은 역할 자동화·팀 도입·정의 수정으로 분리한다. 원본 지문 고정 legacy 주석은 과거 조건을 추정하지 않고 T01 수신 의도를 도달로 승격하지 않는다. 단일 사례는 신고 sampleCount가 커도 unknown이다. N은 동일 조건·비중복·비중첩 명시 표본 기록 수에서 도출하며 전후 N이 다르면 합계 감소로 개선 판정하지 않는다. 전후 중복/닫힌 구간 공유 경계도 중복 집계 위험이다. 품질 수치 감소를 자동 개선으로 부르지 않고 품질/근거 변화·부담 혼재/동률·누락이면 unknown과 추가 수집 계획을 출력한다. 이 문턱은 통계적 인과 효과 입증이 아니다.

프로젝트 전체 종료는 아직 오지 않은 merge 시각과 입력 end를 일치시키도록 요구하지 않고 실제 merge 사건에서 다시 도출한다. 이 오류는 독립 검토에서 발견하고 임시 저장소 finish→merge→지표 재생성으로 회귀 검증했다. 대표 업무는 명시 기간/typed 완료 영수증이 있어야 닫힌 것으로 인정한다. 새 역할 start는 marker와 버전 사건을 남겨 marker 하나 삭제로 새 회고 요구가 해제되지 않는다. 회고의 형식/메타데이터 근거 관문과 실제 후보 의미·승인·적용은 구별하며 후자는 BR07/T08 현장 인터뷰다. 실제 원문은 로컬 Git common dir이고 버전 관리 회고 ref에는 짧은 ID·지문 영수증만 둔다.


T06 독립 목표 대조에서 기록이 없다는 이유로 도달 관측0을 총량0으로 쓰는 구멍을 찾아 request_coverage를 분리했다. 전체 요청 수집에 대한 다른 주체 확인·닫힌 범위·미확인 요청 없음이 있어야 도달 신고 총량을 내며 그 밖은 null이다. 완료 영수증도 period 시작·끝·단위를 표본과 맞춰 다른 구간에 재사용하지 못하게 한다. stats는 실제 merge 사건으로 닫힘을 알지만 내보낸 비교 JSON에는 해당 완료 영수증을 함께 제공해야 하므로 영수증 없는 비교는 미완료다. 새 역할 marker는 PROJECT 머리에서 활성화해 후속 decision 행이 메모 표와 갈라지지 않게 한다. 새 참여 finish는 현재 dashboard의 미사용 후보와 gate/review 반복 후보·횟수를 회고 입력에 모두 언급하게 대조한다. 실패한 finish도 게이트 후보 횟수에 들어가므로 다시 stats를 조회해 회고 count를 맞춘다. 실제 의미·원자료 진위·수정 승인은 자동 인증하지 않는다.


코디네이터 흡수는 BR01 원장4분류를 재정의하지 않고 비교 신뢰의 별도 축으로 다룬다. 명시 자체답·동일요청의 실제coordinator answer·요청에묶인 확인영수증과refs·닫힌전체수집확인이 있어야 원장미확인에서 비교미해결을 줄인다. 사용자답(ref없음포함), owner/수신미상 Q/E, owner decision_request/relay, owner 경로 모든전달phase 등 반대신호가 있으면 신고가 이를 덮어쓰지 못한다. 신뢰대조는 같은ID 전체기록으로 보아 나중사용자답도 확신을 철회하지만 구간안 도달관측수에더하지않는다. 수신의도는log Q/E와원장decision_request를수신자별같은ID로합쳐중복/원장only누락을막으며기존질문사건/FIFO와분리한다.


### 수집과 구조의 경계

새 사람 식별자 owner와 기존 사건 작성자 user는 같은 사람이다. 확정된 T01 captain_* 원본은 legacy adapter에서만 대응하며 원문 bytes를 보존한다. 요청 수집과 품질 로그 수집은 별도 범위다. 파일 부재는 수집0이 아니고 손상된 로그는 오류로 남긴다. 코디네이터 자체답의 확인과 refs 중 하나는 같은 신고 행에서 각각 요청과 기간을 함께 만족해야 한다. 서로 다른 영수증의 부분 조건을 합쳐 확인을 만들지 않는다.

전체 기간은 실제 성공 cli start/merge 사건으로 닫고 종료가 시작보다 이르면 거부한다. legacy Git 메시지 시각 근사는 별개다. 선택 품질 출처만 보지 않고 로그/감사 blocking·리뷰 실패·should_fix·게이트·감사 재검토의 실제 관측 변화를 보존한다. 누락과 안전하지 않은 합은 null이다. 표본별 품질 차이를 합계 상쇄로 숨기지 않으며 수집 출처가 다르거나 섞이면 unknown이다. 실패 전달은 근거 없는 사용자 답을 해소하지 않는다.

회고 기계 구간은 공개한 열0 ATX 제목과 3열 pipe 표만 지원한다. 블록 구조를 먼저 판독하고 inline 표현을 처리해 주석/HTML 제거가 새 구분자나 다른 절의 표를 만들지 않게 한다. 구조 공백은 ASCII space/tab이다. NBSP나 코드/HTML 예시가 경계를 닫지 않는다. 인접한 표 행은 한 후보라 내부에서 새 헤더를 다시 찾지 않는다. 빈 링크 라벨·형식/제어 문자뿐인 셀·HTML/엔티티/코드는 보류한다. 일반 A<B와 표시 문자가 있는 링크는 구분한다. 이는 제한된 기계 형식이며 범용 Markdown renderer나 회고 의미 승인기가 아니다. 역할 --no-launch는 source CLI 흐름을 확인하지만 runtimeObserved:false이며 live 모델 실행 증거가 아니다.

### 실제 입력과 증빙 권한

집계/회고 판독이 실제 사용한 내용 지문, 선택 입력 부재와 역할/TASK-CLOSE 목록을 같은 InputSnapshot에 추적한다. 판독 중 변경은 snapshot을 무효화한다. finish는 최종 자기 영수증 제외 Git tree의 같은 blob·부재·목록과 대조하고 승인된 전체 SHA만 merge한다. ignored 자료와 늦게 추가된 미검증 자료는 보류한다. 검사 명령의 HEAD/인덱스/작업 파일 변경도 성공으로 흡수하지 않는다. 실패 후 로그 몸체·동시 append·이미 만든 커밋은 보존한다. finish 시도 식별자가 있는 같은 프로젝트/태스크 성공만 그 시도 실패로 취소하며 다른 시도·식별자 없는 과거 의미를 바꾸지 않는다. 실제 사용자 원문은 로컬에 남는다.

영수증은 용도와 주체를 구별해야 한다. completion, request-coverage, log-coverage, quality-audit, role-observation, 손작업 키는 같은 기간의 전체 범위이며 requestId/decisionReplyId가 없어야 한다. owner-answer/coordinator-answer는 해당 요청에만 결합한다. 무목적 locator는 읽을 수 있지만 전체0이나 완료 권한이 없다. 목적 필드도 신고이지 사람/수집 완전성 인증은 아니다. 한 requestId에 다른 명시 Task가 있으면 canonical 도달은 unknown이며 같은 Task 중계/프로젝트 거울은 중복 제거한다.

TASK-CLOSE와 완전한 리뷰 행은 전체 이력 수집에 대해 동등한 증명이 아니다. 두 출처 관측을 보존하고 겹침 미확인 때는 종류별 큰 값을 반복 후보 하한으로 삼는다. 합산하면 중복, 단순 대체하면 과거 지적 누락이 된다. 현재 기간 품질 총량과 전체 프로젝트 회고 후보는 별개다. 위 경계는 합성 CLI/Git 대조 대상이며 실제 팀 도입 효과는 후속 현장 관측이다.

같은 requestId라도 독립 시작의 Task가 다르면 충돌이다. 원장의 relayOf는 요청·본문·제안을 검증해 파생 Task를 연결한다. 별도 질문 로그가 그 중계의 거울이라는 주장은 실제 원장 행·요청·본문 지문·시간·Task에 결합된 ref가 필요하다. 연결이 모호해도 원장 답 관측을 남기고 총량과 비교는 보류한다. 로그 답은 사용자와 코디네이터 모두 확인된 원래 Task에만 귀속한다. 명시 Team은 한 판정을 출력과 비교가 공유하고 미채택 프로젝트는 기존 handoffs를 유지한다.

팀 마감의 현재 수집 입력과 영수증을 함께 제거하면 대상 커밋만 읽는 분류가 legacy로 돌아갈 수 있다. 동일 프로젝트 경로의 선조 영수증을 당시 Git tree와 비교해 이전 팀 마감이 검증되면 같은 관문을 유지한다. 관리 형식이 아닌 파일이나 다른 프로젝트 영수증을 채택 근거로 쓰지 않는다.

대표 업무의 동일 시간창에 독립 Task 둘, 태스크와 귀속 미상, 또는 모호한 원장/로그 연결이 함께 있으면 관측과 사유를 남기고 비교 총량을 보류한다. 기존 완료 영수증의 대표 업무 범위 출처는 단독 업무 수집에 대한 명시 신고다. 태스크 번호 없는 단독 문서 표본에도 사용할 수 있다. 역할 활동 출처는 역할과 활동/없음의 종류를 함께 가리키며, 활동의 관측 수치가 0이어도 관측 없음의 근거로 대체할 수 없다.

Team의 채택 여부는 Markdown 문맥에 따라 활성/부재/형식 오류가 달라진다. 과거 Git blob에 실제 활성 v1이 있었는지 보고, 잠깐 노출된 지원 밖 버전은 유효 채택으로 보지 않는다. 프로젝트 번호로 이전 폴더와 연결하고 rebase로 편입된 선조도 다시 확인한다.

원장에 명시된 답 태스크는 직접 참조한 제안 또는 검증된 중계의 태스크와 대조한다. 귀속을 잃은 답이 섞이면 확인된 도달 관측은 남기고 수집 총량과 실패만 남은 요청의 총량을 보류한다. 조회와 비교가 같은 관측 정의를 쓴다. 원질문과 연결되지 않은 사용자·코디네이터 답은 요청 ID 유무에 따라 미귀속 또는 미연결로 남긴다. 신고된 단독 범위가 있어도 명시 태스크보다 이른 미지정 답은 해당 업무에 합치지 않는다.

팀 마감은 회귀 검사한 커밋을 기준으로 출력 경로의 차이만 허용한다. 검증 기간에 읽지 않은 소스라도 뒤늦게 스테이징되면 마감 트리에 포함하지 않는다. 커밋이 생긴 경우 부모와 실제 저장 트리를 확인하고 불일치면 실패 시도로 남긴다. 현재 문서와 Git 이력의 팀 표지는 실제 본문 제목에서 끝나는 같은 투영으로 읽는다. 목록 문단의 들여쓰기 열과 탭을 함께 계산해야 중첩 제목과 본문 제목이 구별된다.

병합 실행은 기존 프로젝트도 계획에 기록한 불변 커밋 SHA로 fast-forward한다. 검증 뒤 브랜치가 전진해 새 작업이 붙으면 그 브랜치와 작업 폴더를 보존한다. 기존 사용자 승인 방식과 팀의 명시 SHA 승인 조건은 각각 유지한다.

### 수집 결과의 이동과 마감 입력

stats의 요청 수집 확인은 실제 입력 지문과 팀 저장소 식별자, 요청 수치·응답 증빙, 지원 및 대표 업무 완료 영수증의 경로와 지문에 결합한다. compare에서 파일과 지문을 다시 대조한다. 누락·손상·교체로 확인이 깨지면 관측과 사유를 두고 총량과 방향을 보류한다. 표본이 여럿이면 서로 다른 요청에 쓰인 같은 응답 증빙도 대조한다. 요청 참조는 공유 연결을 재사용하고 전송 행마다 증빙을 한 번만 내야 긴 참조 연쇄가 결과를 감당하기 어려울 만큼 키우지 않는다.

비교의 입력 출처는 stats 봉투나 stats 전용 수집 요약이 있으면 수기 표지보다 우선한다. 날짜가 있는 독립 수기 v1도 명시 표지로 읽을 수 있으며 참여자 신고 수준을 유지한다. 비교는 확인의 일관성을 검사한다. 사람이나 원자료의 진위를 인증하려면 현장 대조가 필요하다. 일부 표본에만 관측이 있으면 합계에 알려진 관측의 하한을 표시한다.

팀 finish에는 판정에 실제로 사용한 측정·회고 근거가 들어간다. 읽은 뒤 탈락한 영수증까지 반드시 커밋하게 하면 관측을 남기며 진행하도록 한 수집 정책과 충돌한다. 확인 파일의 검사 상태에는 통과·미실행·기록 없음이 구별된다. 기존 병합은 fast-forward 전 실패 로그만 정확히 덧붙은 경우 이전 승인 SHA로 재시도할 수 있다. 그 사이 사용자가 바꾼 다른 작업은 보존하고 재시도를 보류한다.

명시한 영수증 경로는 수집 확인이나 닫힌 구간 여부와 독립적으로 검사한다. 한 조회에서 같은 경로가 여러 용도에 쓰이면 최초 판독 결과를 공유한다. 처음에 없거나 크기를 초과했거나 손상됐으면 그 파일이 도중에 복구되어도 총량을 확정하지 않는다. 처음 유효했던 영수증의 지문이 보고 전 달라지면 조회를 보류한다. Git 마감은 선언 영수증의 형식을 확인하고 원문 필드 또는 판독 불가 상태가 있으면 보류한다. 사용한 자료는 사전 검토 커밋의 Git 내용과 대조한다. 수집 확인이 없더라도 유효한 리뷰·게이트 행과 같은 기간 감사의 관측은 남기며 총량은 별도로 둔다.

프로젝트 요청의 시작과 같은 ID가 속할 태스크의 실제 시작은 별개다. 먼저 받은 프로젝트 답은 관측에 남긴다. 뒤에 붙은 태스크가 앞 사건의 범위를 소급해 확정할 수 없으며, 같은 시각의 연결 없는 로그는 행 순서를 대조한다. 이미 검증한 원장 거울과 실제 답 참조는 해당 제안의 태스크를 사용한다. 답이 오기 전의 첫 질문은 이후 확인된 태스크 요청의 시작이 될 수 있다. 응답 재사용으로 보류한 비교에서는 원본 신고 관측에 중복 근거가 남을 수 있음을 표시한다.

로그의 사용자 답과 원장 거울은 요청 판정 채택 여부와 별개로 마감에서 영수증 형식을 대조한다. 증명에 쓰이지 않은 정상 영수증은 로컬에만 둘 수 있다. 전송의 참조로 찾은 원질문 없는 사용자 요청은 미확인으로 남기고, 채택 판정에는 현재 프로젝트 번호의 착수만 사용한다. 저장한 stats의 호스트·정의·조건 등 비교 맥락은 확인 지문과 함께 대조한다.

과거 로그의 안전한 상대 경로는 파일을 찾을 때 같은 경로 표기로 정리하고 원래 행은 보존한다. 사라진 과거 참조는 검사 대상 Git tree에서 부재를 확인한다. 정리 전 표기가 POSIX에서 별개 이름의 실제 파일을 가리키면 마감을 보류한다. 회고 전용 영수증과 회고 문서도 사전 검토 커밋의 자료와 대조한다.

사용자 전송의 시작과 완료는 제안의 요청·태스크·발신자와 선언된 수신 경로가 맞을 때 도달을 확인한다. 예전 행에서 머리가 모순되면 해당 전달은 미확인으로 보존하고 별도 검증 답, 실패 시도와 응답 재사용 대조는 유지한다.

전송 시도의 최종 확인보다 앞서 등록된 불명 상태도 시간 대조에 포함한다. 조회 기간 밖으로 나간 중간 상태가 있어도 원장 시도 전체를 먼저 검증한다.

팀 마감 입력은 PM이 직접 검토해서 커밋한다. 더러운 팀 작업본은 로그 작성과 Git 반영 전에 보류한다. 현재 표지가 없어도 작업 및 기준 브랜치의 채택 이력을 프로젝트 번호로 찾아 우회를 막는다. 기준 SHA로 rebase한 깨끗한 후보에서 공통 마감 요건과 지표 입력을 검사하고, 최종 커밋은 하네스가 만든 마감 경로로 제한한다. 등록된 원문 보호 경로는 후보 tree와 새로 편입될 중간 커밋에서 대조하고 병합 직전에 현재 보호 목록을 다시 확인한다. 미채택 프로젝트는 기존 목차 커밋 흐름을 사용한다.

최종 커밋은 검증한 Git tree와 부모에서 직접 만들고, 참조가 검사한 부모일 때만 갱신한다. 마감 훅은 별도 인덱스의 후보를 검사한다. 훅이 스테이징한 내용이 후보와 다르면 그 작업 파일은 보존하며 마감은 보류한다. 팀 완료 및 병합 성공 로그는 성공 조건에 들어간다. fast-forward 뒤 기록이 실패하면 실제 반영된 커밋과 상태 기록 실패를 따로 보고한다.

rebase는 검사할 기준 SHA를 고정하고 그 뒤 보안 명령을 다시 적용한다. 팀의 최종 검사 커밋에서는 Git 공통 저장소에 등록한 보호 경로를 모두 대조한다. 파일 모드·내용이나 기준 worktree가 달라져도 같은 경로를 검사한다. 기존 공개 Git 지문을 허용하며 과거 CRLF로 기록한 공개 기준도 대조한다.

## 검토 원장과 프로젝트 사건의 관측 경계

P013의 `reviewLedger`는 프로젝트·태스크·연결 백로그의 정본 검토 원장 파일을 판독한다. 논리 호출 예약과 유효 판정은 다른 단위다. 중단·무효·미완료를 별도로 두고, 검토 비용은 알려진 관측과 미보고를 구분한다. 구조 진단·상위 검토·실제 owner 요청은 따로 세며 옛 형식에 해당 관측이 없으면 미관측이다. 같은 대상의 새 지문과 직전 재현 지적에 연결된 독립 pass는 기록상의 해소 대리 지표다.

Git 후보는 실제로 쓰인 원장 파일과 증거 또는 선택 입력의 부재를 대조한다. 빈 디렉터리나 증거 속 예시 원장은 검토 관측을 만들지 않는다. P009 T06의 옛 원장 83회는 당시 기록의 관측이다. 프로젝트 사건 품질·팀 관측과 합산하거나 비용·결함 개선의 인과로 읽지 않는다.
