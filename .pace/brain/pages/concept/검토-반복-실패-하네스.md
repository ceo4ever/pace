## 결정

독립 검토가 같은 대상에서 거듭 fail하면 지적을 하나씩 막는 땜질이 반복된다(P005 T04 사전 검토 v2 9회·v3 11회, P001 14회). P007은 이를 도구와 스킬로 끊었다.

- **원장을 유일 근거로**: `pace agent verify`가 대상 폴더 `REVIEW-LOG.jsonl`에 판정을 자동으로 쌓고 결과·대상 스냅숏을 `review-records/`에 남긴다. 작성자 수작업 기록(PRE-REVIEW 시도)은 원장에서 옮겨 적는다.
- **재검토 기준점은 도구가 고른다**: 마지막 pass·결정·진단 뒤 구간의 가장 최근 fail. 직전 원문과 바뀐 줄을 주고 "직전 blocking 해소와 그 수정의 새 결함만" 판정하게 한다(현재 산출물 전체는 맥락). 호출자가 기준 기록을 고르게 하면 오래된 기록을 넘길 수 있다.
- **단계**: 연속 3회 fail이면 diagnose(원인 층 structure·planning·design·other 진단), 진단 뒤 fail이면 ask_user(결정 필요 — 영향 분류로 PM/user 선택). 단계를 연 호출은 종료 0과 `escalation`, 다음 호출은 종료 16.
- **버린 길**: 단계와 무관한 무효 처리(`--void`)·호스트와 verify를 섞어 PM이 손으로 세기 — 원장 옆에 평행 상태를 만들어 단계 우회·기준점 불일치가 생겼다. void는 normal 단계의 실행된 fail만.

## 실측

- 매 회 새 맥락 전체 검토는 고칠 때마다 새 갈래를 찾았다(수렴하지 않음). 범위를 지정한 재검토는 직전 지적만 다뤄 blocking이 3→1→1로 줄었다.
- 3회 실패 원인은 대부분 design 층이었다: 다른 OS 기준 계획을 옮김(T04), 경로 금지 목록 땜질 → rename 교체로 부류 제거(P007 T01), 시나리오 경계를 한 줄씩 덧붙임 → 사례 표(T02), 원장 밖 우회로(T02).
- 진단 뒤 전체 검토도 새 갈래를 찾아 사용자 결정까지 가는 일이 많았다 — 사용자 결정 게이트가 실제로 반복을 끊었다.

## 함정

- 결함 주입 tester가 작업본 파일을 복사·복원하는 동안 작성자가 같은 파일을 고치면 수정이 지워질 수 있다 — tester는 스크래치패드 복사본에서 주입한다.
- 대상 diff 파일 경로를 차수마다 바꾸면 원장이 매번 새 대상으로 센다 — 같은 경로를 갱신해 쓴다.
- macOS launchd는 시스템 기본 PATH만 준다 — plist에 등록 때 PATH를 넣는다(main 3970e51, T04 사전 검토에서 발견).
- 알려진 한계: goal-review 2단계(호스트) blocking은 원장에 안 들어간다(이슈).

## 증명 범위와 결정 주체를 나눈 이유

P008은 새 TASK 형식 v2에 증명 범위·판정 주체를 먼저 적어 검토가 목적에 필요한 증명에 집중하도록 했다. 표지 없는 옛 TASK는 호환하며, 구조 누락을 한 건만 지적한 뒤에는 아직 평가하지 못한 목적·안전까지 전체 검토로 연다. 충분한 범위의 확장 제안은 should_fix이며 확장 승인·반영 의무는 아니다. 사람의 정답을 작성자나 자동 검사가 대행하지 않는다.

진단 뒤 fail을 매번 사람 결정으로 올리면 일반 갭도 중단되어 근본 조치·재검증을 PM에게 맡긴 취지와 어긋났다. PM/user를 새 결정에 반드시 기록하고 옛 주체 없는 결정은 unknown으로 남기는 이유는 P005의 옛 PM 결정을 사용자 승인으로 오귀속하지 않기 위해서다. ask_user 이름은 호환 때문에 유지하되 주체를 뜻하지 않는다.

정본 reviewer 반복 실패 절은 모든 수정 직전에 합의와 실제 영향을 확인하도록 한다. 일반 갭은 PM 근본 조치·재검증·4요소 사후 보고, 심각한 오류·보안·합의 변경 등은 수정 전 사용자 결정과 원문·해시·첫 수정 증거다. 애매함은 먼저 조사하며, 횟수로 주체를 자동 선택하지 않는다. PM 결정은 waiver가 아니다.

실측은 실제 다른 제공자의 행동 순서 응답과 소스 CLI 합성 fixture를 구별한다. fixture의 cross 메타데이터를 실제 모델 판정으로 오해하지 않으며, 승인 입력도 실제 사람 승인으로 보고하지 않는다. 사람 원문의 진위·모델의 일반적 규칙 준수는 기계가 보장하지 않는다.
