## 결정

브레인은 부트 때 넣지 않는다. LLM이 필요할 때 `pace brain search`로 찾고, 도구는 **관련 절을 모아** 출처와 함께 돌려준다(기본 약 800토큰, 페이지당 2절). 목록만 보려면 `--list`.

## 버린 대안

- 부트에 페이지 제목 목록 넣기 — 무조건 들어가는 토큰이라 브레인의 취지(필요한 것만)와 어긋난다(사용자 지적).
- 목록만 돌려주고 페이지를 다시 읽게 하기 — 호출이 두 번, 페이지 전체를 읽어 토큰이 더 든다.
- 사용자 메시지마다 훅이 자동 검색해 끼워 넣기 — 관련성을 LLM이 아니라 키워드가 판단한다.

## 찾게 만드는 장치

- `pace-brain` 스킬 설명을 "언제 찾을지" 트리거로 쓴다(스킬 설명은 원래 늘 보이므로 추가 토큰 없음).
- 검색어는 LLM이 한국어·영어·동의어로 넓힌다. 의미 검색(임베딩)은 의존성이 필요해 쓰지 않는다.

## 명령 구성

검색은 공백 무시 매칭·type/tag 필터·초안 용어 제외·점수 방식에 절 단위 취합을 더했다(목록만 돌려주는 방식을 버림).
add·update·log·lint·ingest-scan을 두고 형식 검증은 lint에 합쳤다. 코드 머리 주석에 기대는 동기화·분석 명령은 두지 않았다.
쓰기(add·update)는 형식·깨진 링크·추정 표지를 검사한 뒤 기록한다. 쓴 페이지와 양방향 빠진 링크·고아 변화만 점검하고 목차를 갱신하며 전체 점검 명령을 안내한다. 전체 lint는 `pace brain lint`, `pace brain index`, 프로젝트 마감에서 수행한다.

## LLM Wiki 보강: stale claims와 file back

형식 lint만으로는 코드 변경 뒤의 낡은 주장이 남고, 검색 실패 뒤 찾은 답이 대화에서 사라지는 빈틈을 메웠다. 브레인은 raw sources를 복사하는 곳이 아니라 여러 근거의 이유와 연결을 축적하는 위키다.

- lint의 `stale-source`는 근거가 사라졌거나 페이지 확인일 뒤에 관련 파일이 커밋된 경우를 **검토 후보**로 알린다. 코드가 바뀌었다고 주장이 틀렸다고 단정하지 않으므로 경고이고 쓰기를 막지 않는다. 의미상의 모순(contradictions)은 사람이 근거와 비교한다.
- 날짜는 최신 관련 커밋의 author 날짜를 쓰고, 커미터 날짜(rebase 시 바뀜)로 과대 경고하지 않는다. 날짜가 하루 단위이므로 같은 날 수정·미커밋 변경은 별도 검토가 필요하다. git 오류는 날짜 검사 생략을 알리되 missing 경로 검사는 유지한다.
- 근거마다 git을 띄우면 페이지가 쌓일수록 add/update 비용이 늘었다. 전체 lint는 한 번의 NUL 구분 이력 조회로 날짜 맵을 만들고, 쓰기는 변경한 페이지의 근거만 조회한다. 하위 프로젝트의 브레인은 상대 경로 출력으로 맞춘다. 백로그 약칭·파일 뒤 단순 심볼은 파일명과 구분해 거짓 missing을 줄인다.
- 검색 출력은 더 찾은 답의 file back을 안내하지만 검색 자체는 읽기 전용이다. 다시 물을 만한 답이나 여러 원본의 synthesis만 기존 페이지부터 갱신한다. query log는 질문·발견·페이지 참조의 짧은 기록이며, 페이지를 대신하지 않는다. 현재 상태·개인정보·코드에서 바로 보이는 사실을 되적립하지 않는다.
- 질의 요약의 줄바꿈은 한 줄로 접고 공개 log op를 제한한다. 자유 텍스트가 별도 기록처럼 보이는 것을 막기 위함이다.
