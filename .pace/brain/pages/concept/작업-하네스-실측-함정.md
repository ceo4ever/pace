## BL·BR 연결에서 확인한 경계

검토에서 새 4칸 표의 태스크 이름에 “백로그 단계”가 들어가면 옛 표로 오인하는 결함을 재현했다. 표 형식은 내용 전체가 아니라 헤더의 정확한 칸 이름으로 판별한다. CRLF 개요는 표 처리 때 정규화하고 저장 때 원래 줄바꿈을 보존한다.

macOS의 /var·/private/var 별칭은 실제 경로로 포함 여부를 판단한다. 검증 후 경로를 정규화할 때도 **검증한 실제 대상의 이름**을 써야 한다. 별칭 이름으로 다시 조합하면 다른 BL을 반환할 수 있었다. backlogs 루트·BR·개요의 외부 심볼릭 링크를 거부하며, 테스트는 대상 파일과 상태가 그대로인지까지 비교한다. 근거: test/backlog.test.ts·test/project-harness.test.ts의 별칭·CRLF·누락 무변경 회귀.

## CRLF 설치 템플릿의 절 인식

Windows CRLF 템플릿에서도 new·task·check·done이 같은 절과 표를 처리하고 기존 줄바꿈을 보존하도록 검증했다(2026-11-05). 설치본은 git 저장소가 아닐 수 있어 git 속성만 고치는 대신 읽는 하네스가 두 줄바꿈을 지원한다. 원인·재현 조건은 [[install-and-launch-pitfalls]]의 Windows CRLF 절을 본다.

## 자식 세션에서 회귀 검사할 때

독립 tester가 PACE_AGENT_CHILD=1을 상속한 채 실행하자 일반 부트 출력을 기대한 13건이 실패했다. 당시 test/helpers.ts의 sessionFreeEnv는 이 변수를 지우지 않아 CLI가 정상 자식 부트 생략 경로를 탔다. 테스트 하위 프로세스에서만 변수를 제거한 일반 환경은 전부 통과했다. 제품/helper 변경이나 자식 세션의 부트 억제 해제는 하지 않았다. 검사를 보고할 때 환경 조건과 최초 실패를 함께 적고, 세션 격리용 환경이 테스트에 상속되는지 확인한다.

## 테스트 임시 폴더와 자식 수명

테스트별 종료 훅을 지연 import 중 등록하면 해당 테스트 직후 실행돼 다음 테스트의 임시 루트를 지웠다. 프로세스 종료 훅과 테스트 소유 비동기 자식의 명시 등록을 함께 쓰고, 활성 자식이 남은 예외·명시 종료나 시간 초과에는 지우지 않고 실패를 보고한다. helper를 불러오는 자식은 부모의 삭제 영역 밖에 독립 루트를 만든다. 미등록 자식·신호로 종료 훅이 실행되지 않는 경우·같은 UID의 검사와 삭제 사이 동시 교체 원자성은 보증하지 않는다. npm은 별도 Node 컴파일 캐시를 만들 수 있으므로 TMPDIR 잔여 측정과 속도 비교에 캐시 위치·설정과 원시 목록을 함께 남긴다.

## HTML 디자인 토큰과 비밀 탐지의 경계

2026-11-14 다른 저장소(Canvas Studio)의 GUIDE 증거 72개 중 35개가 디자인 토큰 속성 때문에 finish에서 차단됐다. 비밀 키워드의 단어 경계는 하이픈 뒤도 허용하므로 HTML 속성의 일부를 일반 토큰 대입으로 읽었다. 파일 제외나 증거 편집은 같은 파일에 들어간 실제 비밀도 숨기므로 버렸다. 알려진 디자인 범주의 짧은 경로와 정확한 속성 경계만 판정에서 구별하고, 전역 자격증명 패턴 검사는 먼저 유지한다. hasSecret과 redactSecrets가 같은 속성 판정을 써야 검사 통과 뒤 수집 원문이 불필요하게 변형되지 않는다. 정식 소스로 원본 72개의 해시 불변·오탐 0개와 프로젝트 전체 findSecrets 통과를 확인했고 그 저장소의 finish 자체는 실행하지 않았다. 근거: src/project/secrets.ts·test/secret-precision.test.ts.
