## 원문과 신고를 구별한다

명시 등록한 업무 원문·상세 답/결과/판정·계약 사본·전송 payload는 Git common dir의 로컬 content ID로 보존한다. Git에는 짧은 구조 metadata·지문·출처 locator와 기존 project log 요약만 둔다. 별도 원문 Git 승인이 없는 보수적 로컬 보존은 사용자의 clone 재감사 한계 수용이나 원문 Git 승인이 아니다. 같은 common dir의 worktree/두 호스트는 bytes를 대조하지만 다른 clone에는 본문이 없어 metadata-only다.

## 실행과 종결은 연결된 근거로 판단한다

해석은 특정 원문/제안 ID·본문·계획 digest의 캡틴 확인을 필요로 한다. input/contract도 계획 파일의 본문 지문·수신자·판정자·증명 범위와 같아야 한다. 수신자의 scope_check와 ready는 참여 절차이며 임의 직접 실행을 차단하는 권한 경계가 아니다. done은 within과 실제 증거 지문을 필요로 하고 지정 decisionOwner만 최신 done 결과를 닫는다. partial/blocked는 열린 위임으로 finish 경고에 남는다.

## 쓰기와 전달의 실패 창

원장/started를 fsync한 뒤 guard 밖에서 기존 전송을 호출한다. 기록 실패 시 발송하지 않고 성공 후 영수증 실패는 불명·재발송 금지다. 쓰기 전 검증 오류는 guard를 정리하고 쓰기/동기화 중 실패는 보존한다. 실제 잠금의 intent→상태 transitionId→applied 뒤만 프로젝트 사건을 만들며 hook 실패는 적용 상태를 원복하지 않고 pending/guard와 명령 미실행을 남긴다. reconcile은 실제 근거만 중복 없이 보완하고 guard 회수/작업 재개를 하지 않는다. 원장 수신 시각과 producer appliedAt은 다르다.

## 집계의 한계

requestId로 같은 요청의 log/중계를 합치되 식별자 없는 과거 사건은 추정 연결하지 않는다. 캡틴 답 신고/실제 사람 경로 성공/실패만/불명 순으로 분류하며 Orca 에이전트 성공이나 coordinator 자체 답은 캡틴 도달이 아니다. actor·sourceRef·by:user와 근거 ref는 참여자 신고라 실제 사람/의미 인증이 아니다. ref에는 짧은 위치/응답 ID/지문 영수증만 두고 답 원문은 로컬 decision_reply 본문에 보존한다. 실제 출처·두 호스트 업무 효과는 현장 감사로 확인한다.

## 보존과 운영

원내 body 파일 입력은 거부하고 알려진 staging 후보를 보호하되 사용자 파일을 자동 이동/삭제하지 않는다. 이미 공개 추적된 파일의 오입력은 공개 기준선으로 구분한다. 미확인 intent·중단 guard·손상 원장은 자동 정상화하지 않는다. 큰 원장 replay 비용·신고 근거 진위·옛 설치본과 전이 필드 호환은 별도 운영 한계다.
