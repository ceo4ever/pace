## 결정

- **독립 에이전트**: 사용자 정보까지 공유하면 한 에이전트의 여러 모드가 된다. 코드·로그인 정보 외 모두 격리. 협업은 기억 공유가 아니라 위임.
- **파일**: `SOUL.md`(frontmatter 이름표 + 성격·가치관), `USER.md`. `AGENTS.md` 이름은 프로젝트 파일과 헷갈려 쓰지 않는다.
- **운영 규칙은 공통(2026-10-23 수정)**: `RULES.md`는 처음에 프로필마다 템플릿을 복사했지만, 복사본이 갱신되지 않아 CLI와 어긋났다(`--type feedback` 안내가 남음). 규칙 내용이 사용자마다 같으므로 `templates/RULES.md` 하나로 두고 부트가 설치본에서 직접 읽는다. 사람마다 다른 자율 범위·선호는 프로필 메모리 `rule`로 덧붙인다.
- **역할 고정**: 역할 질문을 뺐다. 개발 파트너·프로젝트 매니저·리서치 파트너는 별도 역할이 아니라 비서가 요청의 성격에 맞춰 바꾸는 방식 — RULES "일의 성격별 방식" 표(방식·먼저 확인할 것). 2026-10-31 RULES를 1,200자 이하로 압축하며 "스스로 해도 되는 것"·"남길 곳" 열은 뺐다 — 자율 범위는 "먼저 확인" 열이, 남길 곳은 RULES 메모리 절과 `pace-memory`·`pace-brain` 스킬이 맡는다(부트 크기).
- **온보딩**: 설치가 아니라 첫 세션에서 LLM이 인터뷰(객관식 + 직접 입력 + 예시). 질문 원본은 `src/profile/onboarding.ts` 하나를 세션 스킬과 터미널이 공유.
- **사실과 근거(2026-10-29)**: 확인하지 않은 내용을 확인된 절차처럼 안내한 일이 반복되어, SOUL의 원칙을 답 형식으로 구체화한 절을 RULES에 더했다 — 확인 우선, 사실·단계마다 `[확인: 출처]`/`[추정]`. 모든 사용자에게 같은 품질 규칙이라 프로필 rule이 아니라 시스템 규칙에 둔다.

프로젝트의 활성 AGENT는 선택한 프로필의 정체성을 바꾸지 않고 해당 프로젝트 역할만 더한다. 프로젝트 역할과 메모리는 상위 지시·프로필의 안전 경계를 완화하지 않는다.

## 업무 독립 사고와 형식 선택

2026-11-08 공용 RULES에 업무 독립 사고 원칙을 추가했다. 업무별 표는 역할/권한 확인으로 유지하고 개인 선호는 계속 프로필 rule에 둔다. 처음 1,200자였던 단위 분량 가드는 승인된 추가 원칙에 맞춰 1,700자로 조정했다. SOUL·USER·RULES 비축약과 8,000자 부트 가드는 보존했다. 프로젝트 문서가 업무 형식을 강요하는 대신 목표·전략·결정·결과의 추적과 명령용 최소 구조를 구별하게 했고, 이는 프로필 정체성/안전 경계를 바꾸지 않는다.
