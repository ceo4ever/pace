# 검사와 테스트

정의서 [`docs/README.md`](README.md)에서 옮긴 상세다. 정의서에는 한 줄 요약과 이 문서 링크만 남는다.

이 문서가 다루는 경로 중 `src/test-runner/`는 민감 경로다 — 고치기 전에 [SECURITY](SECURITY.md)의 민감 경로 표와 체크리스트를 본다.

## 검사 선택

- 경로: `src/test-runner/`, `.pace/test-map.json`
- 스택·형식: TypeScript·Node·Python unittest·vitest

`pace test changed`는 작업본 변경의 관련 단위와 명시 사전 검사를 실행하고, 불확실하면 해당 프로젝트 전체 선언을 실행한다. file/unit의 Vitest는 단위 파일을 한 프로세스로 실행하며 changed의 Vitest는 부분 실행 전 실제 전체 검사로 전환

## 테스트 임시 루트

테스트는 프로세스마다 소유한 임시 루트를 만들고 정상 종료와 일반적인 테스트 실패 뒤 정리한다. 자식 프로세스는 임시 경로를 상속하며 helper를 불러오는 자식은 독립 루트를 소유한다. 테스트가 비동기 자식을 직접 만들면 `spawnTestChild`로 생성하거나 `registerTestChild`로 등록해 종료를 기다린다. 제한 시간에 끝나지 않거나 예외·명시 종료 시 등록 자식이 아직 살아 있으면 해당 루트를 보존하고 실패로 보고한다. 등록하지 않은 임의의 자식은 자동으로 관리하지 않는다. 디버깅할 때만 `PACE_KEEP_TEST_TMP=1 npm test`로 보존하며, SIGINT·SIGTERM·SIGHUP, 강제 종료 등 정리 훅이 실행되지 않는 경우와 같은 사용자 권한 프로세스가 검사와 삭제 사이 경로를 동시에 교체하는 경우의 원자성은 보장하지 않는다.

## 보안 검사

정의서 환경 표 `보안 검사` 행의 전체 설명(명령 선언 자체는 정의서에 있다):

> `node scripts/secret-scan.ts` — 커밋될 파일(추적 + 무시되지 않는 새 파일)의 비밀 원문(제외: 교본 원문 예시 파일 5개, 테스트 파일의 가짜 값(별도 이유 표기), 대시보드 data.js는 JSON을 풀어 값별 검사(코드 파일 키만 표현식 완화), Canvas 묶음 2.0.1의 JS 오탐 5개는 정확한 경로와 SHA-256이 일치할 때만 제외)
