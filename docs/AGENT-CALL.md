# 에이전트 호출과 PACE 도구 서버

정의서 [`docs/README.md`](README.md)에서 옮긴 상세다. 정의서에는 한 줄 요약과 이 문서 링크만 남는다.

## 에이전트 호출

`pace team verify`는 프로젝트 작업자와 같은 원본 읽기 역할 지시를 read-only `p` 실행기에 전달하고 정의 내용을 넣지 않은 고정 질문을 대조한다. 단발 점검의 한계·종료 코드·결과 기록은 [TEAM](TEAM.md#실제-적재-빠른-점검)을 따른다. 요청 effort를 런타임 관측으로 표시하지 않는다.

- 경로: `src/agent/`
- 스택·형식: TypeScript

`pace agent setup [--agents claude,codex] [--yes] [--login] [--install-adapters]`(`setup.ts` — 감지(읽기만) → 계획·확인 → 적용, 공식 CLI 로그인만 쓰고 토큰·자격증명 파일은 읽거나 복사하지 않는다, 프로필 `agent-chains.json`의 `default` 체인은 기존 파일을 보존·병합하고 바꾸기 전 확인과 `.bak`) · `pace agent` — 호출 계약(`contract.ts`: 입력·정규화 결과·오류 코드·능력 검사)과 실행기 등록(`registry.ts`). 실행기: `-p`(`p-executor.ts`)·ACP(`acp-executor.ts`), 프로세스 수명·env 허용 목록(`process.ts`), 체인·폴백(`chain.ts`·`limits.ts`·`snapshot.ts`, `pace agent run --chain <이름>` — 프로필 `agent-chains.json`의 단계 순서대로, 한도·인증·실행기 없음이면 다음 단계로 폴백하고 쓰기 요청이 시작된 뒤에는 기본적으로 `handoff_required`로 사람에게 넘긴다. 읽기 전용 요청은 읽기 전용 강제가 실측으로 확인된 단계만 실행), ACP 보강(`hooks.ts`·`acp-executor.ts` — 실행 훅: 이벤트 스트림 `onEvent`(상한 큐, 원본 `--raw-dir` 저장은 별도 64MB 상한)·권한 위임 `onPermission`(식별 실패·읽기 전용의 허용 밖은 강제 거절, 읽기 전용에서 콜백은 허용을 낮추기만. Claude ACP 읽기 전용은 `default` 모드 — `plan`은 Read·읽기 셸을 작업 폴더 밖까지 권한 요청 없이 실행해 쓰지 않는다. `default`에서는 시험한 밖 읽기·쓰기가 권한 요청으로 와 강제 거절됐다(macOS·어댑터 0.81.1 실측). 한계: 차단은 어댑터의 권한 요청에 기대며 OS 수준 파일 경계가 아니고, 읽기 전용에서도 PACE 읽기 MCP 도구(프로필 메모리 조회 포함)·부트 맥락은 허용된다)·`paceMcp`·정체성 맥락 `context`·이전 대화 요약 `handoffSummary`, 대화 이어가기 `session/resume`은 호출자 보관 `savedSession` 대조 필수, 읽기→쓰기 전환은 `continueSession`이 새 세션+요약으로), 교차 검증(`verify.ts`·`verify-cli.ts`, `pace agent verify` — 다른 제공자 에이전트가 읽기 전용으로 독립 검토, 미실행이면 종료 10과 사유 및 결정 권한 정본에 따른 다음 행동). 검토 원장(`review-log.ts`, P007): 실행된 검토마다 대상 폴더 `REVIEW-LOG.jsonl`에 판정(결과 마지막 줄 끝의 pass·fail 단어 — `판정: fail`도 인식, 그 밖은 unknown)을 덧붙이고 결과·대상 스냅숏을 `review-records/R<n>.json`에 저장한다(세션 ID 제외, `--out`은 추가 사본). 마지막 pass·결정·진단 뒤 구간에 fail 검토가 있으면 원장이 그 구간의 가장 최근 fail을 기준점으로 골라 **재검토**한다 — 기준점 검토 원문과 그때→지금 바뀐 줄을 주고 직전 blocking 해소와 그 수정이 만든 새 결함만 판정하게 한다(대상 무변경·기록 불일치면 거부). 연속 fail 3회면 diagnose, 진단 뒤 fail이면 ask_user(호환을 위한 역사적 이름이며 사용자만 결정한다는 뜻은 아님) 단계로 다음 실행을 막는다. 단계를 여는 응답은 종료 0과 escalation이며 기록 없이 다음 호출은 종료 16이다. 안내는 매 수정 전에 합의·실제 영향을 분류하도록 하고, 단계와 기록은 reviewer.md의 반복 실패 절, 조치의 결정 주체와 B1 폴백은 [결정 권한 정본](../skills/pace-project-dev/references/decision-rights.md)을 따른다. 다른 제공자가 미실행이면 같은 제공자의 새 세션(교차 아님)을 사용하고, 양쪽 미실행에서 검토 생략은 A-3에 따라 판정한다. `pace agent review-note --diagnosis`는 근본 진단을, `--decision --by pm|user --choice ... --summary ... --file ...`는 결정 주체를 기록한다. 새 결정은 by 필수이며 pm 근거에는 분류 이유·조치, user 근거는 승인 원문에 연결한다(원장 사용 시 영수증과 로컬 원문은 결정 권한 정본 적용). 생략·잘못된 주체는 거부하고 두 주체 모두 비어 있지 않은 일반 근거 파일을 요구하며 대상 자체는 거부한다. by는 decision에서만 허용한다. 옛 주체 없는 decision은 단계 계산에서 계속 인정하되 `last_decision_by: unknown`으로 보고하고 user로 추정하지 않는다. 결정 이력이 없으면 null이며 이 대상의 마지막 주체를 보고하는 메타데이터이지 현재 승인 권한이 아니다. 원장에 잘못된 by가 있으면 손상으로 거부한다. 진단·결정 뒤 첫 검토는 전체 검토(rereview_of null), 실패 집계는 기존 방식이다. 구조 누락 단건 판정 뒤도 미평가 목적·안전까지 전체 검토로 열며 실패 집계를 지우지 않는다. PRE-REVIEW waiver.by는 user만 허용하며 PM 결정은 재검증으로 게이트를 통과한다. 검토 도구 결함으로 무효인 검토는 `review-note --void --record review-records/R<n>.json`(normal 단계의 실행된 fail 검토만, 근거 파일 필수 — 열린 단계는 진단·결정으로만 넘어간다)으로 표시하면 횟수·기준점에서 빠져 대상이 그대로여도 다시 검토할 수 있다. 같은 원장은 잠금 파일로 직렬화하고, 실행 전에 기록 자리(`{"pending": true}`)를 먼저 만들어 실행 중 중단·기록 끊김이 원장에 없는 기록으로 남아 다음 검토를 막게 한다. 손상·잠금·기록·쓰기 실패는 종료 2. 대상은 실제 경로로 열고(링크 별칭도 같은 원장), 기록·`--out`은 같은 폴더 임시 파일에 쓴 뒤 rename으로 바꿔 끼워 링크·하드링크로 이어진 다른 파일의 내용을 고치지 않는다(`--out`은 대상·원장·잠금·기록 폴더 이름 자체는 가리킬 수 없다). 바뀐 줄은 같은 앞뒤 줄을 뗀 뒤 비교하고 남은 구간이 너무 크면 그 구간을 통째로 준다(재검토가 막히지 않는다). 원장에 없는 기록(실행 중 중단·기록 끊김)은 다음 실행이 자동 복구한다. 확인된 판정은 복구한다. 중단(`interrupted`)은 재검토 기준점에서 빼고 예산이 적용된 단위의 호출에는 남긴다(출력 `recovered`). 일반 산출물은 기존 진단 규칙으로 중단을 센다. 잠금에는 PID를 기록한다. 소유 프로세스가 끝났으면 별도 복구 표지로 복구자를 직렬화한다. `--out` 경로 비교는 대소문자를 구분하지 않는다. 원장·기록은 태스크 폴더에 있어 TASK와 함께 커밋·공유된다 — 기록에는 대상 원문과 검토 원문이 들어가므로 노출 범위는 그 TASK·산출물과 같고, 구조화된 세션 ID는 지운다(본문에 든 값은 거르지 않으므로 대상·검토 원문에 비밀을 쓰지 않는다). Codex 호스트에서 쓸 때는 호스트 샌드박스의 네트워크 허용이 필요하고(기본 차단 → 타임아웃), Codex를 다시 부르려면 호스트 샌드박스 해제가 필요하다. Claude ACP는 모델을 보고하지 않아 교차 검증 근거로 쓸 수 없다(`-p` 사용). 회수 보증: POSIX는 프로세스 그룹, Windows는 최선 노력(`process_cleanup: best-effort-unverified`, 실기 검증은 병합 후). 용어: **에이전트**(도구를 쓰며 일하는 프로그램: Claude Code·Codex) · **모델** · **제공자**(모델 회사) · **호출 방식**(`p` 헤드리스 단발 / `acp` 세션) · **Client**(ACP에서 부르는 쪽 = pace agent). 프롬프트는 stdin·파일만(argv 금지), 기본 읽기 전용, 미지원 옵션은 오류

태스크·백로그의 검토 예산은 대상 파일이 아니라 단위와 단계로 센다. 태스크는 루트 및 `evidence/REVIEW-LOG.jsonl`을 합산해 루트 `TASK.md`의 사전 검토와 그 밖의 구현 후 검토를 구분한다. `--kind task`는 태스크 루트의 `TASK.md`에만 사용할 수 있다. 백로그는 `--kind goal`을 포함해 폴더당 한 단계다. 단계마다 전체 1회와 범위 재검토 1회, 호출 4회를 허용한다. 검토 전에 원장에 `call`을 예약한다. 소진 이후에는 `reason: budget_exhausted`와 단위·단계·판정·호출 수를 내고 종료 16이다. 옛 원장의 확인 가능한 호출과 유효 판정도 합산한다. 옛 판정 기록과 스냅숏 지문이 구조 전용 검토를 입증하면 호출에 포함하고 첫 전체 판정을 열어 둔다. 같은 단계에서 대상이 달라져도 직전 유효 판정의 원문·스냅숏으로 범위 재검토한다. 이전 기록이 손상 또는 유실됐으면 재검토가 거부된다. 위의 연속 fail 진단 단계는 예산 관리 밖의 일반 산출물에 적용한다. 시간·토큰의 집계 원본은 원장의 `duration_ms`·`usage`다. 제공자 미보고 토큰은 `null`로 기록하고 `미보고`로 표시한다.

## PACE 도구 서버

- 경로: `src/mcp/`
- 스택·형식: TypeScript

`pace mcp --workspace <경로> --access read-only|write` — ACP 세션에 `mcpServers`로 주입되는 stdio MCP 서버. 워크스페이스·접근 권한은 기동 때 고정하고 도구마다 서버가 강제한다: 읽기 전용이면 변경 도구(`memory_add`) 직접 호출도 거부, 다른 워크스페이스·링크·하드링크·상한 초과 거부(`safefs.ts`의 `scan` 앞뒤 비교). 도구: 메모리 조회·추가, 프로젝트·백로그 조회, 브레인 검색. 쓰기 세션과 다른 세션의 동시 실행 금지는 호출자(daemon)의 전제

## 프로젝트의 팀 구성원 선택

`pace project start P123 --agent codex --role builder`에서 agent는 도구, role은 저장소 팀 구성원 이름이다. `team new --role maker`의 role은 역할 종류다. 프로젝트 작업자는 원본을 읽는 prompt와 명시적인 model/effort 인자를 받으며, 이 경로는 native subagent 선택·권한 집행과 다르다. 기존 worktree 재실행은 `--launch`를 쓰고, 선택·재현·시작 기록의 전달/실제 관측 구별은 [TEAM](TEAM.md#프로젝트-작업자-역할)을 따른다.
