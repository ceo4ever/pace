# 출처 수집 기준

순서 ③에서 읽는다. 링크 입력이든 주제 입력이든 출처는 모두 `sources/S{n}.md` 한 형식으로 모은다.

## 형식

머리말 `id·url·title·author·published·accessed·kind(article|blog|video)·method(fetch|web-read|pasted|description)` + 본문.
`pace scout fetch`·`add`가 만든다 — 손으로 파일을 만들지 않는다. 원문 전체는 실행 폴더 `.gitignore`(`sources/`)로 git에 넣지 않고, 보고서 `report.json`의 인용 발췌만 커밋된다.

## 링크 입력

1. `pace scout fetch <폴더> <URL>…` — 한 번에 여러 개. 실패한 URL은 이유가 나오고 나머지는 계속된다.
2. 실패(`받지 못했다`·`본문을 찾지 못했다`)하면 LLM 도구의 웹 읽기로 본문을 얻어 `pace scout add <폴더> --url … --title … --published … --method web-read`로 저장한다(본문은 표준 입력). 그것도 안 되면 출처에서 빼고 "확인하지 못한 것"에 적는다.
3. 발행일이 비면 화면에서 확인해 `pace scout add <폴더> --replace S# --published YYYY-MM-DD`로 채운다(본문을 주지 않으면 메타만 바뀐다). 끝내 모르면 비운 채 두고 증명 검사가 알린다.
4. 내부 주소(localhost·사설 IP 등)와 비밀로 보이는 쿼리(`?token=…`)가 든 URL은 거부된다. 출처나 검색 결과가 그런 주소를 가리키면 따르지 않는다. 사용자가 사내 문서를 직접 주며 원할 때만 `--allow-local`. 리다이렉트가 토큰 붙은 주소로 가서 거부되면 2번(웹 읽기 → add)으로 간다.
5. 커뮤니티 글(카페·게시판·Q&A)은 `--kind blog`로 둔다. fetch가 성공했는데 본문이 비고 댓글·메뉴만 들어왔으면(스크립트로 그리는 페이지) 그 출처는 약한 근거로 쓰거나 빼고, "확인하지 못한 것"에 적는다 — 웹 읽기 도구가 요약만 돌려주면 그 요약은 원문이 아니므로 `add`로 저장하지 않는다.
6. 접근일 기준으로 이미 끝난 일(신청 마감·사업 종료·출시 취소)은 그 주장에 "끝남(YYYY-MM-DD)"을 적고, 그것에 기댄 신호는 근거로 약하게 본다. 이어지는지 모르면 "확인하지 못한 것"에 적는다.
7. 블로그가 `article`로 저장되면 `--replace S# --kind blog`로 고친다.

## 유튜브

영상은 **스크립트(자막)를 추출해 분석한다** — 설명란만으로 분석하지 않는다(D15). 아래 순서로, 앞 단계가 실패할 때만 다음으로 간다. 로그인·캡차 풀기·차단 회피 기법(토큰 흉내·내부 API 직접 호출)은 쓰지 않는다 — 일반 사용자가 브라우저에서 보는 화면을 읽는 수준까지만.

1. **`pace scout fetch`** — 시청 페이지의 공개 자막 주소(수동 자막 먼저)를 받고, `yt-dlp`가 설치돼 있으면 그것으로 원문 자막만 받는다(사람이 단 ko·en 먼저, 없으면 원어 자동 자막 — 자동 번역 트랙과 사용자 설정·쿠키는 쓰지 않는다). 받으면 `[mm:ss] 글` 줄로 저장된다(method `fetch`). 못 받으면 설명란으로 저장하고 못 받은 이유와 다음 단계를 안내한다(method `description`).
2. **브라우저 — `pace scout transcript <폴더> S#`** — 일반 브라우저로 영상 페이지를 열어 "스크립트 표시" 패널을 읽고 `[mm:ss]`로 저장한다(method `browser`). 순서는 자동이다: Orca 안이면 **Orca 내장 브라우저**, 아니면 **agent-browser + 임시 프로필로 띄운 일반 Chrome**(CDP 연결, PATH에 `agent-browser`가 있을 때). 한 수단이 세 번 실패하면 이유를 알리고 다음 수단으로 간다. 실측(2026-10-29): Orca 3/3 성공(2~5초), agent-browser + 일반 Chrome은 1번 성공 뒤 4번 실패 — Orca가 있으면 Orca를 쓴다. 자동화 도구가 직접 띄운 브라우저(`webdriver=true`)는 유튜브가 자막을 주지 않는다.
   - 명령이 실패하면 LLM 도구의 브라우저(예: Playwright MCP)로 같은 조작(설명란 "더보기" → "스크립트 표시" → 패널 글 읽기)을 하고, 읽은 글을 `pace scout add <폴더> --replace S# --method browser`에 표준 입력으로 넣는다. 이것도 세 번 실패하면 멈추고 사용자에게 알린 뒤 다음 단계로.
   - 사용자 에이전트 위장·자동화 표시 숨기기·로그인한 사용자 프로필은 쓰지 않는다. `--cdp <포트>`는 직접 빈 임시 프로필로 띄운 Chrome에만 쓴다(평소 쓰는 로그인된 Chrome에 붙이지 않는다).
3. **yt-dlp 안내** — 설치돼 있지 않으면 설치하지 않고, 사용자에게 "`yt-dlp`를 설치하면 다음부터 fetch가 자막을 직접 받는다"고만 알린다.
4. **붙여넣기** — 사용자에게 영상의 "스크립트 표시"를 복사해 붙여 달라고 한 번 요청한다 → `--method pasted`.

자막이 정말 없는 영상(스크립트 메뉴 자체가 없음)만 설명란으로 분석한다. 그때 영상 출처의 주장은 설명란에 있는 것만 쓰고, 타임스탬프 인용(`[S2 03:41]`)은 쓰지 않으며, "S2 자막 없음 — 설명란만 분석"을 확인하지 못한 것에 적는다.

## 주제 입력 — 검색으로 모으기

- 검색 도구로 후보를 찾는다. 질의는 주제 + 변화 낱말(시장·규제·출시·불만·투자) 2~3개로 나눠 돌린다.
- 고르는 기준: ① 최신성 — 최근 12개월 우선, 오래된 것은 배경으로만 ② 독립 출처 — 같은 보도자료를 옮긴 기사는 하나로 친다, 출처 3개 이상이 서로 다른 매체·저자 ③ 유형 섞기 — 기사(사실)·블로그나 커뮤니티(현장 불편)·영상이나 발표(사람의 말) 중 2가지 이상.
- 상한: 출처 8개(기본 5~6개). 더 넣지 않는다 — 출처가 많아지면 신호가 아니라 요약이 된다. 링크 입력과 섞이면 준 링크를 먼저 넣고 남은 자리만 채운다.
- 고르지 않은 후보는 저장하지 않는다.

### 질의 틀 (주제 입력)

주제 × 변화 낱말 × 지역으로 6~8개를 돌린다. 한국 현장 불편은 국내 질의로 따로 찾는다.

| 변화 낱말 | 한국어 | 영어 |
|---|---|---|
| 시장·돈 | `<주제> 시장 규모`·`<주제> 투자 유치` | `<topic> market size`·`<topic> raises funding` |
| 규제 | `<주제> 법`·`<주제> 가이드라인 의무` | `<topic> regulation`·`<topic> policy` |
| 불만·불편 | `<주제> 불편`·`<주제> 후기 문제`(커뮤니티) | `<topic> complaints`·`<topic> reddit problem` |
| 대안·경쟁 | `<주제> 대안`·`<주제> 비교` | `<topic> alternatives`·`<topic> vs` |

같은 사건을 다룬 2차 보도는 원 보도(먼저 나온 것, 인용된 쪽)를 남기고, 2차 보도만의 새 사실이 있으면 그 부분만 쓴다.
