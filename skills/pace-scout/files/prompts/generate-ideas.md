# 아이디어 생성

순서 ⑤의 첫 단계. 신호 목록을 보고 사업 아이디어 후보를 만든다. 넓고 얕게 — 선별까지만(깊은 기획은 기획 단계로).

## 만드는 법

1. 신호마다 [신호 분류](../rules/signal-taxonomy.md)의 "이어지는 질문"을 던진다. 두 신호가 겹치는 곳(예: 행동 변화 + 문제)에서 더 강한 후보가 나온다.
2. 후보를 5~8개 떠올린 뒤 3~5개로 줄인다. 줄이는 기준은 SKILL "결정"의 약한 후보 버리기. 버린 것은 `dropped`에 이유와 함께.
3. 서로 다른 후보가 되게 한다 — 같은 해결 방식을 고객만 바꾼 것은 하나로 친다. 가능하면 크기도 섞는다(바로 해 볼 작은 것 1개 이상).
4. 사용자 적합도 재료(순서 ②)를 염두에 두되, 그것 때문에 근거 없는 후보를 만들지 않는다.

## 후보마다 쓰는 칸(report.json `ideas`)

| 칸 | 한두 줄로 |
|---|---|
| `name` | 무엇인지 알 수 있는 짧은 이름 |
| `problem` | 누가 어떤 불편을 겪나 — 근거 `[S#]` |
| `customer` | 처음 팔 대상 한 무리(가장 좁게) |
| `solution` | 무엇을 어떻게 해 주나 |
| `revenue` | 누가 얼마를 어떻게 내나 — 출처에 없는 금액은 "추정" |
| `signals` | 근거 신호 `G#` 1개 이상(없으면 후보가 아니다) |
| `estimates` | 출처에 없는 수치·판단 문장 |

`kill_assumptions`는 [비판](critique-ideas.md)에서 채운다. Lean Canvas·BMC 같은 양식은 쓰지 않는다.
