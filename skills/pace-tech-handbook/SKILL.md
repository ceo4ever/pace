# 기술 교본

교본은 외부 원문(ECC·Vercel·Trail of Bits)을 그대로 두고, PACE가 만든 색인으로 필요한 절만 읽는다. 전문을 읽지 않는다 — 토큰을 아끼는 것이 목적이다.

## 우선순위

**저장소 규칙(`AGENTS.md`·`docs/`) > 주변 코드 > 교본**이 기본이다. 주변 스타일과 교본이 다르면 주변을 따른다.
다만 아래 셋 중 하나면 이번에 바꾸는 코드는 **교본을 따른다**:

1. 주변 방식에 보안·성능 문제가 있다.
2. 따를 주변 코드가 없다 — 새 프로젝트, 새 모듈, 저장소에 처음 들어오는 언어나 계층.
3. 주변 코드가 교본 안티패턴에 해당하는, 문제가 많은 방식이다.

이 경우 TASK-CLOSE "남긴 것"에 교본·절과 이유를 적는다. 주변 코드 전체를 고치는 일은 범위 밖이라 메모리 `issue`·`idea`로 남긴다.

## 찾는 순서

1. [`references/INDEX.md`](references/INDEX.md) 연결표에서 언어 + 프레임워크로 색인을 고른다. 공통(API 설계·TDD)은 `references/common/INDEX.md`, 테스트·E2E 판정은 `references/verification/INDEX.md`.
2. 평소에는 그 언어 색인(`references/<언어>/INDEX.md`)만 읽고, 안티패턴 항목으로 주변 코드를 대조한다.
3. 규칙 위반·안티패턴·버그 위험이 보이거나 참고할 코드가 없을 때만, 색인의 줄 범위를 `references/<언어>/<교본>/GUIDE.md`에서 offset/limit로 읽는다. "읽지 않음" 절은 읽지 않는다.
4. 연결표에 없는 조합이면 언어 색인만 쓰고, 결과에 "연결표 없음"을 적는다. 교본이 아예 없으면 저장소 규칙·코드·테스트로 판단한다.

라이브러리 API의 최신 사용법은 교본이 아니라 context7 등 최신 문서로 확인한다. 교본은 패턴·관례를 맡는다(원문 기준일은 `references/SOURCES.md`).

## 쓰는 곳

교본은 막힐 때만 쓰지 않는다. 코드를 바꾸는 태스크는 매번 언어 색인을 읽는다. 색인만 읽으므로 비용이 작다.

- 테스트 설계: 테스트 표를 짤 때 언어별 testing 교본과 `verification/` 색인의 안티패턴을 대조한다.
- 구현: 언어 색인의 안티패턴으로 주변 코드와 이번 변경을 대조한다. 새 모듈·예외 처리·타입·구조를 정할 때는 해당 절을 읽는다.
- 리뷰: 바뀐 코드를 언어 색인의 안티패턴과 대조하고, 지적 근거로 교본·절 이름을 인용한다.
- 기록: TASK-CLOSE "리뷰"에 `교본: <색인> — <대조 결과·따른 절>` 한 줄을 남긴다. 코드 변경이 없으면 "교본: 해당 없음(코드 변경 없음)".

## 관리

- 원문(`GUIDE.md`와 그 폴더)은 고치지 않는다. 출처·커밋·라이선스·해시는 `references/SOURCES.md`, 고지는 `references/licenses/`.
- 라이선스가 확인된 원문만 둔다. 원문을 바꾸면 `SOURCES.md` 기록과 색인의 줄 범위를 함께 고친다.
