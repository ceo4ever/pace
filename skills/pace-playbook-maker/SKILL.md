# 자동화 흐름 명세 만들기 (pace-playbook-maker)

한 업무 흐름 = 폴더 하나. 원본은 `steps.json`과 승인된 `shots/S0n.jpg`뿐이다. 생성물(`flow.html`·`flow/overview.md`·`flow/S0n.md`)은 **직접 고치지 않는다** — 원본을 고치고 다시 생성한다.
실행하는 에이전트는 시작할 때 `overview.md`를 한 번, **각 단계 직전에 그 단계 파일만** 읽는다. 긴 대화·요약 뒤에도 실행 시점에 정확한 명세를 다시 읽게 하려는 구조다.

| 문서 | 언제 |
|---|---|
| [references/schema.md](references/schema.md) | steps.json을 쓰거나 고칠 때 — 필드 사전 |
| [references/adapter.md](references/adapter.md) | 서비스 캡처 어댑터를 만들거나 캡처가 거부될 때 — 계약·함정·템플릿 |
| [references/playbook-making.md](references/playbook-making.md) | 목표 하나로 인터뷰 → 수행·기록 → 플레이북 생성 |

## 도구 위치

도구는 이 스킬 폴더 안에 있다(PACE 설치본 `~/.pace/app/skills/pace-playbook-maker/`). `<스킬>`은 그 폴더다. 경로는 이 절에서만 정한다.

| 이름 | 지금 위치 | 역할 |
|---|---|---|
| 생성기 | `node <스킬>/tools/build.mjs --dir <흐름 폴더>` | steps.json → flow.html·flow/*.md |
| 캡처 코어·지도 | `<스킬>/tools/capture-core.mjs`·`agent-map.mjs` |
| 플레이북 | `<스킬>/tools/{interview,scaffold,orca-adapter,playbook}.mjs` | 인터뷰·뼈대·어댑터·생성 | 가림·번호 태그·사후 검사(fail-closed)·캡처 기록·승인 / `agent/` 지도 계산 |
| 테스트 | PACE 저장소 `test/playbook/` (`npm run check`가 실행) | 생성기·코어·이 스킬 문서 검사 |
| 서비스 어댑터 | 각 서비스 도구 폴더의 캡처 모듈 | 탭 범위·화면 판정·대기·승인 |

옮길 때: 이 스킬 폴더 + 도구·테스트를 한 묶음으로 옮기고 이 표, 생성기 `GEN` 상수(머리말 명령 문구), 스킬 문서 테스트의 스킬 경로, 어댑터의 코어 import 경로를 새 위치로 바꾼다.

흐름 폴더는 업무 스킬의 `references/flows/<흐름>/`에 둔다(흐름이 하나뿐이면 `references/`). 업무 스킬 하나에 흐름 여러 개를 두고, 업무 스킬 `SKILL.md`는 공통 규칙 + 흐름 색인으로 짧게 둔다.

## 절차

1. **범위** — 흐름 하나만 고른다. 시작점은 **브라우저 탭 열기 → 로그인**(이미 열린 세션에 기대지 않는다), 끝점은 정리(창 닫기·임시 파일 삭제)다. 등록·전송처럼 밖으로 나가는 단계는 위험 등급과 승인 관문(`gate`)을 단다.
2. **기존 도구·규칙 대조** — 그 업무의 고정 도구·실행 규칙·분류 규칙을 먼저 읽고 단계·요소를 도구 명령에 맞춘다. 명세에 새 규칙을 지어내지 않는다. 도구에 없는 동작은 "구현 전(할 일)"으로 적고 할 일로 남긴다.
3. **단계 나누기** — 경계는 "화면이 바뀌는 곳"과 "도구 명령 하나"다. 메뉴로 뜬 화면과 다음 조작 화면이 다르면 나눈다. 목록 행 클릭처럼 사람이 하던 클릭도 단계로 남기고 에이전트가 직접 실행해 기록한다. 스크롤해야 보이는 영역은 별도 단계로 캡처한다.
   - 여러 단계를 명령 하나가 수행해도 단계는 화면대로 나누고, 그 명령은 `run`에 적는다(범위 단계의 단독 명령은 진단용). `tool`은 경로·CLI만, 함수·인자 설명은 `toolNote`. 앱이 스스로 여는 탭·늦은 공지·일시 덮개는 `events`.
   - API 단계(화면 없음)는 앱이 부른 응답을 받아 적는 수동 관찰 방식 한 사례만 있고, API를 직접 부르는 방식은 **미검증**이다 — 표기는 [schema.md](references/schema.md) "API 단계 표기".
4. **steps.json 작성** — [schema.md](references/schema.md). 흐름 `mask`가 없으면 캡처는 전부 거부된다. 개인정보 원본 화면(신분증·통장·카드·등록 화면)은 `capture:false` + `captureNote`이고, 기준 형식은 비식별 참조 자료 링크로 대신한다.
5. **어댑터 준비** — 서비스 어댑터가 없거나 필수 기능이 빠졌으면 [adapter.md](references/adapter.md)대로 만든다. 캡처는 어댑터로만 한다.
6. **단계별 실행·캡처** — 실제 도구로 단계를 실행 → 어댑터로 캡처(화면 판정·대기 경로 저장·짧은 해시 출력). 거부되면 이유 코드대로 고친다(adapter.md 함정 표). 확인 창처럼 중간에 멈춰야 보이는 화면은 별도 단계로 두고, 도구가 그 화면에서 멈출 수 있을 때만 캡처한다(아니면 `capture:false`).
7. **사람 확인 → 승인** — 사람이 대기 이미지를 직접 연다. "확인했다"는 말을 받으면 에이전트가 메타 해시와 파일 해시를 대조한 뒤 `--approve S0n --sha <해시>`로 승인한다. 고칠 점이 있으면 `--reject` 뒤 재캡처. 에이전트가 이미지를 대신 판정하지 않는다.
8. **생성·검사** — 생성기를 돌리고, overview·단계 파일의 링크와 도구 명령이 실재하는지 확인한다. 업무 스킬 `SKILL.md` 색인에 흐름 명세 링크와 "캡처는 어댑터로만" 한 줄을 넣는다.
9. **재구성 검증** — 새 맥락 에이전트에게 overview·단계 파일만 주고 명령·시작 조건·실패 동작을 재구성하게 한다. 다르면 명세를 고치고 그 부분을 다시 확인한다.
10. **에이전트 지도(선택)** — `agentView:true`면 `agent/`도 만든다. 승인 때 어댑터가 `captureRecord`→`approveStep`을 부르고, 사람이 값 자리를 확인해 `--review-hash` 값을 `valueReview`에 적는다. 낡음은 `--check-agent`. 경계는 [schema.md](references/schema.md) "에이전트 지도" 절.
11. **UI 변경 갱신** — 화면이 달라지면 steps.json·캡처를 같은 커밋에서 고치고 `changes`에 날짜·단계·내용을 더한 뒤 다시 생성한다.

## 보안 규칙

- 가림은 fail-closed — 규칙이 없거나, 덮지 못했거나, 캡처 중 화면이 바뀌면 파일을 남기지 않는다.
- 실데이터 화면 캡처는 실행 직전 사람에게 확인받는다. 노출 허용 범위(이름·금액·기간 등)는 사람이 정하고 `maskRequireNote`에 날짜와 함께 남긴다.
- 값 있는 입력칸은 기본으로 가린다. 날짜처럼 공개할 입력만 `revealInputs`에 `^…$` 고정 패턴으로 연다.
- 대기 캡처는 버전 관리 밖 경로에 두고, 승인 때만 `shots/`·steps.json에 반영한다.
- 계정·번호·실값을 steps.json·`captureNote`·로그·출력에 넣지 않는다. 명령은 자리표시(`<page>`)로 적고, 도구 출력의 페이지 발췌는 버린다. 계정은 환경 변수로만 받는다.
- 흐름 실행 중 등록·저장·결재·전송 동작은 사전 승인 없이 누르지 않는다.
- 자동 로그인·외부 등록은 저장소 규칙이 그 서비스에 허용한 범위에서만 한다. 허용이 없으면 사람이 로그인하고 그 단계는 사람 단계로 적는다. 한 서비스의 예외를 다른 서비스로 넓히지 않는다.
- 같은 실패가 세 번이면 멈추고 사람에게 묻는다. 흐름·단계 추가, 가림 범위 변경, 실행 관찰로 범위·기준을 바꾸는 일은 멈추고 사람 결정을 받아 `changes`에 남긴다.
