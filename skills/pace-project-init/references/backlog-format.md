# 백로그 형식

아래는 개발 업무의 예시다. 업무별 형식·추적과 명령용 최소 구조는 [문서 형식과 추적](../../pace-project-dev/references/document-shape.md)을 따른다.

## 이름과 연결

```text
backlogs/BL{YYMMDD}_{NN}_{이름}/
  BACKLOG.md
  BR01_{이름}.md
  BR02_{이름}.md
projects/P{NNN}_{YYMMDD}_{이름}/
  PROJECT.md
  tasks/T01_{이름}/TASK.md
  tasks/T02_{이름}/TASK.md
```

- 백로그(폴더) 하나 → 프로젝트 하나, 브리프(영어 **brief**, BR 파일) 하나 → 같은 번호 태스크 하나. `BR03`은 `T03`이다.
- BL의 `YYMMDD`는 만든 날, `NN`은 같은 날 01부터 증가한다. BR 번호는 백로그 안에서 01부터 증가한다. 이름의 공백은 `_`로 정리한다. 짧게 `BL261023_01/BR03`으로 부른다.
- 백로그는 기획(무엇을·왜·순서), 프로젝트는 실행이다. 완료 백로그에 브리프를 덧붙이지 않는다. 새 묶음은 새 백로그, 작은 아이디어는 프로젝트 메모리 `idea` 또는 대화에서 바로 프로젝트로 발의한다.
- BL 출처 프로젝트의 추가 업무는 진행 중인 BL의 같은 번호 BR을 먼저 기획한다. main에서 `pace backlog brief`를 실행하기 전 다음 BR 번호와 필요한 T 번호를 대조하고, 불일치나 worktree 반영 충돌이 있으면 덮어쓰지 않고 판단한다. 이미 연 태스크는 BR과 현황을 맞춘 뒤 `done`을 재실행한다. 완료 BL에는 추가하지 않는다.
- 상태는 `대기 · 진행 · 완료 · 보류`. 브리프 파일의 상태가 원본이고 BACKLOG.md 현황 표가 따른다. BACKLOG.md 전체 상태는 start 성공 시 진행, worktree 프로젝트는 실제 merge 성공 시 완료, main 직접 프로젝트는 finish 성공 시 완료로 바뀐다. 전체 백로그가 보류면 자동 전환을 거부하고 개별 보류 BR은 그대로 둔다. 보류 해제는 사용자가 결정해 백로그 원본을 갱신하고 대시보드를 새로 생성한 뒤 명령을 다시 실행한다. 마감 때 BR·태스크·현황의 번호와 완료/보류 상태가 일치하지 않으면 멈춘다.

## 화면 산출물

화면이 필요한 기획은 `docs/plan.json`에 IA·화면 ID·흐름을 기록하고 `docs/canvas/`의 편집 가능한 Canvas를 BACKLOG의 `## 화면 설계` 표(`BR | 화면 ID | Canvas 파일 | 화면 이름`)와 각 BR 범위의 화면 ID·표 링크로 연결한다. 화면이 필요 없으면 BACKLOG의 `## 확정된 결정`에 생략 이유를 남긴다. plan.json의 IA·흐름·Canvas 상태와 명시적 연결은 의미 정본, Canvas는 시각 정본이며 HTML은 파생 뷰다. 자동 왕복 동기화는 없다. 변경 시 화면 ID로 대조해 의미 정본·HTML·Canvas·링크를 맞추되 기존 편집본 교체는 해당 파일의 명시적 허가를 따른다. 기존 문서는 이 형식으로 소급 이전하지 않는다.

## 생성과 착수

main 체크아웃에서:

```sh
pace backlog new "백로그 이름"
pace backlog brief BL261025_01 "첫 브리프"
pace project new "프로젝트 이름" --from BL261025_01
```

BL 폴더 전체 경로(저장소 상대 경로 포함) 또는 유일하게 맞는 `BL{YYMMDD}_{NN}` 앞부분을 받는다. 모호한 앞부분·브리프 파일·`backlogs/` 밖 경로는 거부한다. `new --from`은 출처를 BACKLOG.md로 걸고 BR 번호·이름대로 T 대기 행을 만든다.

템플릿 정본은 `templates/backlog/BACKLOG.md`·`BRIEF.md`. 생성 뒤 목표·범위·완료 기준을 채운다.

## BACKLOG.md

```markdown
# BL261025_01 백로그 이름

- 상태: 대기
- 작성: 2026-10-25

## 목표

무엇을 왜 만드는가.

## 진행 현황

| 브리프 | 상태 | 선행 | 프로젝트 | 비고 |
|---|---|---|---|---|
| [BR01 첫 브리프](BR01_첫_브리프.md) | 대기 | — | P010 | |

## 결정·기록

| 작성일시 | 내용 |
|---|---|
| 2026-10-25 14:30 | 첫 브리프 범위를 조회 기능으로 좁힘 — 저장은 다음 백로그 |
```

결정·기록은 `| 작성일시 | 내용 |` 표에 한 줄씩 덧붙인다. 작성일시는 로컬 시각 `YYYY-MM-DD HH:mm`으로 프로젝트 결정·진행 메모(`pace project log`)와 같은 형식이다. 이 절을 쓰는 명령은 없으니 직접 적는다. 표가 없는 예전 백로그는 고치지 않는다.

## BR{NN}_{이름}.md

```markdown
# BR01 첫 브리프

- 상태: 대기
- 백로그: [백로그 이름](BACKLOG.md)

## 목적

## 범위

## 완료 기준
```

## 마감과 메모리

- `pace project done P### T01`은 BL 출처 프로젝트의 BR01 상태와 BACKLOG.md 현황 행을 함께 `완료`로 맞춘다. 태스크 표에 별도 백로그 단계 칸은 필요 없다. 대화 출처 프로젝트는 백로그를 건드리지 않는다.
- 진행 상황은 `pace memory status --project`로 BL/BR과 다음 행동을 가리킨다. 세션을 넘길 일은 `todo`, 발견한 문제는 `issue`, 아직 착수하지 않은 개선은 `idea`로 둔다.
- 이전된 역사 문서의 옛 5칸 태스크 표는 읽을 수 있다. 앞으로 만드는 프로젝트는 4칸(태스크·이름·상태·커밋)을 쓴다.

## 보관 경로

BACKLOG.md의 `- 프로젝트 기준 경로: projects/`는 저장소 루트 기준이며 생략 시 같은 기본값을 쓴다. 프로젝트를 `projects/backup/`으로 옮기면 해당 백로그의 이 한 줄만 바꾼다. 백로그는 `backlogs/backup/BL…/`으로 보관해도 대시보드에서 조회한다. 경로 설정은 프로젝트 목록·ID 링크·태스크·자료 조회에 공통 적용된다. 숨김 경로나 저장소 밖 경로는 지원하지 않는다. 이동·설정 변경 후 `pace backlog refresh`를 실행한다.
