# 검사 구성 분석과 최신화

## 역할과 안전 경계

저장소의 실제 패키지·소스·테스트 구조와 러너 설정을 먼저 읽고, 파일을 옮기지 않는다. 기존 `AGENTS.md`는 새 테스트 배치·포함 확인의 짧은 규칙과 정의서 길 안내만, `docs/README.md`는 기존 환경 명령과 적용 문서, 유형별 테스트 문서는 상세 관례를 맡는다. 검사 단위의 기계 판독 정본은 루트 `.pace/test-map.json`이다. 기존 정의서 `검사`는 전체 명령 정본으로 유지하고 이 JSON에 전체 명령을 복제하지 않는다. finish는 기존 base 선언 우선 정책을 따른다. 선언이 없으면 기존 finish는 경고만 하므로 전체 회귀는 미확인으로 알린다.

신규·기존 프로젝트에서 아래 분석과 초안을 만들고 각 문서·구성의 변경을 보여 승인된 것만 반영한다. 최신화에서도 기존 파일과 미커밋 사용자 변경을 먼저 확인하고 파일별·절별로 차이를 보여 승인된 부분만 반영한다. 모르는 파일을 덮어쓰거나 테스트·소스 파일을 이동하지 않는다. 실행한 명령만 확인됨으로 기록하고 부수효과가 있거나 오래 걸리는 실행은 사용자 판단을 따른다. 시범 분석은 원본을 읽기만 하고, 실험은 격리된 복사본에서 한다.

## 분석과 구성 초안

1. 패키지·서비스·기능별 소스와 테스트, 러너 설정·CI·기존 검사 명령을 실제 파일에서 수집한다. 경로 이름만으로 의존성을 추론하지 않고 import·호출·실행 경로 및 공통 fixture를 대조한다. 서로 다른 언어·러너·작업 디렉터리·환경 전제를 구분한다.
2. 각 변경 경로가 관련될 수 있는 모든 단위와 각 단위의 테스트 패턴을 제안한다. 소스·테스트가 여러 단위에 들어갈 수 있다. 미분류 파일 선택은 확인 불가로 표시하고 전체 검사를 권고한다. 공통 모듈·설정·공통 fixture는 `common`에 두며 단위 소속보다 우선해 전체 검사를 권고한다. 확실하지 않은 경로 및 어느 단위에도 속하지 않은 새 테스트는 미분류 목록과 이유를 남긴다. 자동 의존성 추론이나 이름만으로 완전성을 주장하지 않는다.
3. v1 JSON 초안은 `version: 1`, `units: [{id, sources, tests, runner: {kind, cwd, config?}, requires: [설명]}]`, `common: [경로 패턴]`이다. ID는 영문 소문자·숫자·하이픈, 경로는 루트 상대 POSIX 경로다. 경로·패턴은 절대 경로·`..`·NUL·루트 밖 심볼릭 링크를 거부한다. glob은 실제 러너·구현이 지원할 문법을 증거와 함께 제안하고 알 수 없으면 미확인으로 둔다. 빈 단위나 일치하지 않는 패턴은 OPI가 수정 후보로 제시하며 실행 도구는 오류로 처리한다. `requires`는 설명이며 기계 확인 불가능한 전제 단위는 자동 선택 실행에서 확인 불가다. 전제를 임의로 설치·기동하지 않고 기존 러너의 수동 실행 결과는 별도로 기록한다. 단위 runner에는 임의 셸 명령을 넣지 않는다. 아래 checks만 명시적으로 신뢰하는 프로젝트 사전 검사 선언으로 허용한다.
4. 전체 `검사`가 실제 어떤 단위·공통·미분류 테스트를 포함하는지 선언·러너 설정과 대조한다. 빠진 E2E·별도 러너·외부 환경과 확인하지 못한 범위를 명시하고, 전체 검사로 다 덮는다고 추정하지 않는다. 선택은 타입 검사·공통 검사를 포함하지 않을 수 있음을 표시한다. 사용자의 기존 명령과 문서를 존중한다.
5. 산출 초안에 근거 경로와 실행 결과·미확인 이유를 붙이고, `AGENTS.md`에는 새 테스트를 기존 관례대로 배치하고 관련 단위 포함 여부를 확인하며 검사 기준은 정의서를 보라는 짧은 안내를 제안한다. 상세 기준은 정의서의 문서 표에서 적용 범위와 함께 찾게 한다.

## 최신화와 일상 개발

`pace test changed` 채택 시 `checks: [{cwd: ".", command: "프로젝트의 사전 검사 명령"}]`를 추가한다. 필요한 타입/린트/생성 검사를 모두 선언하고 없으면 빈 배열을 명시한다. 필드 부재는 전체 검사로 전환하며 기존 file/unit 모드는 종전대로 필드를 요구하지 않는다. 구형 v1 실행기는 알 수 없는 필드를 무시하므로 checks 추가만으로 기존 모드가 깨지지 않는다. 전체 명령은 여전히 정의서 정본에만 둔다.

사용자가 신뢰해 승인한 map을 기준 브랜치에 커밋해야 빠른 경로가 활성화된다. changed는 로컬 main→master→검증된 현재 HEAD의 커밋 map을 사용하고 작업본 JSON과 다르면 전체 전환한다. HEAD 대체 기준에는 리뷰된 브랜치 보호가 없다. PACE 프로젝트 worktree도 main에 checks map이 없으면 병합 전 전체 전환한다. 커밋된 브랜치 변경은 이 작업본 모드가 검증하지 않으며 변경 없음은3/미실행으로 표시한다.

checks의 cwd는 junction/symlink를 포함한 실제 경로가 저장소 안 디렉터리여야 하고 command는 단일 행·최대4,000자·NUL 없이 명시한다. 정의서와 같은 Windows Git sh/POSIX sh로 실행하며 기본30분/16MiB 제한이다. 선언 명령이 읽는 작업본 스크립트/환경까지 격리하지 않는다. 파일명은 셸에 보간하지 않는다. 실제 실패·중단은1/비성공으로 종료하고 후속 실행이나 성공 재시도로 덮지 않는다. 부모 자체 OS 신호 종료 코드는1과 다를 수 있다. 부분 결과 미확인에서 실제 전체로 전환한 경우는 전체 판정임을 구별한다.

common·미분류·삭제/rename·충돌/type/mode/submodule·검사 선언 변경은 실제 전체 전환 대상이다. staged 삭제와 같은 경로의 untracked가 함께 있어도 삭제 상태를 보존한다. assume-unchanged/skip-worktree 플래그 또는 sparse checkout/sparse-index 설정이 있으면 추적 가시성 불확실성으로 전체 전환하며 인덱스/플래그를 변경하지 않는다. 변경 파일은 -z 자료와 untracked 파일 단위로 수집하며 Windows 선택 경로는 case-fold, POSIX는 대소문자를 구별한다. ignore 정책 밖 입력은 자동 추적하지 않는다. 신뢰한 선행 명령이라도 실행 전/후 오류·셸/기준/전체 선언 확인 불가를 성공으로 표시하지 않는다. 실제 사용 예시는 README의 변경 기반 빠른 검사에 있다.

수동 OPI 최신화 때 이전 구성·문서·검사 명령과 현재 파일 목록·러너 설정·git 변경을 대조한다. 새 테스트·이동·삭제, 일치 0건 패턴, 새로운 공통 영향과 미분류, 변경된 명령·환경 전제를 각각 근거와 함께 나열한다. 이동은 이름만으로 단정하지 않고 후보로 제안한다. 단위의 기존 사용자 편집은 보존하며 승인된 변경만 적용하고 거절된 부분을 그대로 둔다.

개발자는 테스트를 작성하거나 옮긴 직후 기존 프로젝트 관례에 맞는 배치와 관련 단위의 포함을 확인한다. 선택 검사 이후 전체 회귀에서 처음 발견한 실패는 태스크 기록에 명령·선택 범위·실패 테스트·원인 확인 상태를 누락 후보로 남긴다. 환경 차이·불안정성·기존 실패를 배제하기 전 선택 누락이라고 단정하지 않는다. 다음 OPI 최신화에서 그 태스크 기록과 구조 변경을 검토해 구성·문서 갱신 후보로 올린다. 빠른 검사는 전체 회귀를 대체하지 않는다.
