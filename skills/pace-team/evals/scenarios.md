# pace-team 행동 시나리오

[pace-project-dev 실행 방법](../../pace-project-dev/evals/scenarios.md#실행-방법)을 따른다. 입력별 새 맥락을 사용하고 작성자와 다른 제공자를 우선한다. 격리한 작업본에 스킬과 필요한 참조, 고정 입력만 제공한다. 시나리오의 합격 기준과 다른 입력의 답은 제공하지 않는다. 프롬프트·원응답·실행 결과와 독립 판정을 증거로 보존한다.

## 필수 역할 점검

시험용 정본 사본에서 백로그 기획자의 행만 채운다. 기본 요건은 저장소의 제출 경로와 검사 명령을 정의에 명시하는 BP-01·BP-02다. 저장소 정의서는 제출 경로 `plans/intake/`와 검사 명령 `make verify-intake`를 지정한다. 각 입력에서 명시한 변경 외의 원형·정본·저장소 값은 그대로 사용한다. 문제 해결자 행은 비워 두고 등록 담당이 후속 백로그임을 표시한다.

| ID | 고정 입력 | 합격 기준 | 실패로 판정할 행동 |
|---|---|---|---|
| R01 | 기획자 합의에 승인 상태를 반환하는 항목을 추가하되 정본에는 등록하지 않는다. 기존 역할은 BP-01만 충족한다. 후속 문제 해결자 브리프에 합의 문장을 두되 해당 담당의 등록은 시작하지 않는다. | 등록 누락 1건과 등록된 BP-02의 미충족 1건을 따로 표시한다. BP-01은 충족이고 문제 해결자는 후속 담당의 요건 미등록이다. | 미등록 항목의 중복 집계, BP-01 오탐, 후속 담당의 합의 문장을 등록 누락으로 표시. |
| R02 | 두 기획자 요건 행이 있고 역할 원본이 없다. | BP-01·BP-02를 정의 누락으로 기록하고, `plans/intake/`와 `make verify-intake`를 모두 반영한 맞춤 추가안을 낸다. | 역할 추가안 또는 대조표 누락, 등록된 요건을 약화한 정의, 승인 없는 원본 변경. |
| R03 | 기존 정의에 BP-01 경로만 있다. BP-02의 요건 문장은 저장소 정의서가 검사 명령을 지정할 때 적용하도록 바꾼다. | BP-01 충족과 적용 조건이 성립하는 BP-02의 누락을 ID와 근거로 보고하고 BP-02 개선안을 낸다. | 이미 충족한 요건을 누락으로 보고하거나, 적용 대상인 BP-02를 해당 없음으로 처리. |
| R04 | 기존 정의에 두 기본 요건을 모두 충족하는 문장이 있다. | 두 요건 충족과 근거를 남긴다. | 기획자 추가나 요건 개선 제안. |
| R05 | 기존 정의는 기본 요건을 모두 충족한다. BP-02를 버전 2로 올려 검사 실행과 종료 상태 기록을 요구한다. | BP-02의 새 버전에서 빠진 종료 상태 기록을 식별하여 개선을 제안한다. | ID 존재나 과거 충족으로 현재 요건까지 충족 처리. |
| R06 | 기존 정의에 BP-01만 있다. BP-02는 별도 배포 명령을 운용하는 저장소에만 해당하며 정의서는 배포 명령이 없다고 한다. | BP-02 해당 없음과 그 근거를 기록한다. | BP-02의 수정 제안 또는 근거 없는 해당 없음. |
| R07 | BP-01이 충족된 기존 정의와 가상의 등급 `deepest`를 요구하는 고정 BP-02 행이 있다. 저장소에는 `high`만 있다. 문제 해결자 행은 비어 있다. | BP-01은 충족, BP-02만 보류(선행 미병합)로 적고 문제 해결자는 요건 미등록(BL261125_01 담당)으로 보고한다. | 대체 등급 제안, 원형 전체 보류, 미등록 원형의 누락 보고나 임의 정의. |
| R08 | R07과 같은 정본·저장소 입력에서 기존 기획자 역할 원본도 없다. | BP-01의 현재 정의 누락과 BP-02의 선행 장치 보류를 명시하고 맞춤 추가안을 보류한다. | 대체 등급으로 임의 정의, BP-02까지 누락 또는 BP-01까지 선행 장치 보류 처리. |

## 시작 모드와 갱신

U01~U04는 같은 저장소 설명에서 PACE 원본과 native 정의의 유무·위치만 바꾼다. U05는 다른 스킬의 설명과 함께 이름·description만 제공한다. U06·U07의 기록은 스킬 작성자와 별도 맥락의 작업자가 실제 기록 형식으로 만든다. 기록과 현재 역할 원본 외에 평가표나 앞 응답은 주지 않는다. 적용이 필요한 U08은 쓰기 대상이 격리 프로젝트로 한정된 상태에서 실제 명령으로 관측한다.

| ID | 고정 입력 | 합격 기준 | 실패로 판정할 행동 |
|---|---|---|---|
| U01 | PACE 원본과 native 정의가 없다. | 신규 생성 선택, 저장소 업무 분석과 필수 역할 점검. | 갱신·이전 선택 또는 필수 역할 점검 누락. |
| U02 | `.pace/team/agents/doc-auditor.md` 원본과 해당 native 생성물이 있다. | 기존 원본을 기준으로 갱신, 필수 역할 점검. | native 덮어쓰기부터 실행하거나 기존 역할을 무시하고 신규 생성. |
| U03 | `.pace/team/doc-auditor.md`의 옛 원본만 있다. | 옛 경로도 팀 원본으로 인식하고 갱신, 필수 역할 점검. | 옛 경로를 무시하거나 native 생성물 부재로 신규 생성. |
| U04 | PACE 원본 없이 Claude·Codex의 native 정의만 있다. | 이전·재구성 선택, 기존 권한·설정 대조, 원본 초안으로 갱신과 필수 역할 점검. | 바로 덮어쓰기, 신규 또는 기존 PACE 원본 갱신으로 오분류. |
| U05 | 요청 “이미 팀이 있습니다. 기존 에이전트 팀을 점검·갱신해 주세요.”와 스킬 이름·설명. | `pace-team` 선택. | 설명 없이 모드 선택, `pace-project-init`에서 팀을 자동 변경. |
| U06 | 기존 역할 5개, 최근 채택·미채택 프로젝트 기록, 백로그 검토 기록과 현재 저장소 규칙. | 역할별 표와 행 근거, 미채택 담당 공백, 허브 업무의 근거, 수집되지 않은 수치의 미확인, 회고에 처리된 지적의 재제안 방지. | 미채택이나 백로그 기록 누락, 관측되지 않은 수치의 0 처리, 회고와 같은 근거 재제안. |
| U07 | U06 자료에 조건 미발생·기록 부족·실제 미사용 역할, 기존 두 역할의 별도 업무 중복, 현재 변경 승인이 없다는 요청을 준다. | 세 비참여 상태 유지, 중복처럼 별도 근거가 있는 제안만 명시, A에 따른 결정 주체와 승인 전 지문 유지. | 조건 미발생·기록 부족만으로 합침·제외, 실제 미사용을 자동 제외, 제안만 승인된 상태에서 쓰기. |
| U08 | 격리 팀의 기존 역할 목적을 유지하는 문장 보강이 정확한 경로·변경으로 승인됐다. | 기존 문단과 점검 표지 유지, `pace team sync` 후 `sync --check --json` 차이·오류 0. | 공통 실행 전 대조 또는 점검 표지 손실, 생성물을 직접 수정. |
