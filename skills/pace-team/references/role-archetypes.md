# 역할 후보

업무 표를 먼저 만들고 [정본에 표시된 필수 원형](required-roles.md#필수-원형)을 모두 점검한다. 필수 역할은 요건 ID를 기준으로 저장소에 맞춰 설계한다.

- 필수 · [백로그 기획자](required-roles.md#백로그-기획자-요건)
- 필수 · [문제 해결자](required-roles.md#문제-해결자-요건)

아래 선택 후보에서 필요한 업무를 고른다. 이름은 예시이며 여러 후보의 업무를 합치거나 프로젝트마다 다르게 배정할 수 있다. 독립 검토와 사용자 승인 경계는 합친 역할에도 적용한다.

| 후보 | 맡는 일 예시 | 하지 않는 일 예시 |
|---|---|---|
| 리드 | 계약·의존성·검토 순서, 승인 요청과 근거 정리 | 권한 밖 변경이나 출시를 승인하지 않는다. 자기가 작성한 결과를 독립 판정하지 않는다. |
| 서버 | API·권한·저장·마이그레이션, 서버가 판단하는 상태 | 승인되지 않은 데이터 쓰기와 상품 활성화를 하지 않는다. |
| UI | 상호작용, 화면 상태, 접근성·입력 검증 | 서버 권한·영속 데이터 규칙을 화면에서 대신 결정하지 않는다. |
| QA | 판정 기준, 재현·음성 대조, 실제 증거의 독립 검토 | 작성자의 작업본을 고치거나 사용자 승인으로 대체하지 않는다. |
| 리서치 | 원천 비교, 출처·한계와 검증할 가설 정리 | 근거 확인 없이 어림값이나 타인의 자료를 결과로 확정하지 않는다. |
| 기획 | 업무·사용자 흐름, 우선순위, 시제품 판단 재료 | 승인되지 않은 범위 확대와 출시 결정을 집행하지 않는다. |
| 마케팅 | 시장·출시 계획, 콘텐츠·캠페인 초안과 측정 계획 | 승인 전 게시·광고 집행·비용 지출을 하지 않는다. |
| 경제 | 가격·보상 구조, 단위 경제와 균형 대조 | 실제 가격·상품·재화를 승인 없이 변경하지 않는다. |

맵·운영·문서 같은 업무도 근거와 충돌 경계가 있으면 역할로 나눌 수 있다. 같은 산출물을 이어서 만드는 작은 작업은 한 역할로 합치고 필요한 독립 검토만 분리한다.
