# 저장소 맞춤 에이전트 팀

필수 업무의 담당과 권한, 독립 검토, 인계를 저장소의 팀 문서나 프로젝트 설계에 표로 남긴다. 이 스킬은 저장소 역할을 설계한다. 개인 비서의 이름·말투·개인 메모리는 사용자 프로필에서 관리한다.

## ① 분석

정의서, `AGENTS.md`, 백로그, 기존 역할·스킬, 스택과 실행 명령을 읽는다. 업무 단계, 반복 산출물, 필수 검토, 사용자 승인과 공유 자원을 뽑고 파일·절 또는 행으로 근거를 남긴다. 기존 역할이 있으면 맡는 일·하지 않는 일과 실제 업무 표부터 대조한다. 신규 저장소라면 합의한 예상 단계와 미확인 항목을 표시한다.

병렬 프로젝트, 세 단계 이상의 지속 업무, 다른 제공자가 필요한 검토는 팀 설계를 검토할 단서다. 한 역할과 기존 검토 절차로 필수 업무를 충족하면 그 근거를 남긴다.

## ② 인터뷰

출처에서 이미 정한 항목을 적고 다시 묻지 않는다. 누가 결정하는지, 독립 worktree와 공유 자원 사용, 요청 모델·등급·비용 한도를 확인한다. 이름과 말투는 기존 선호를 쓰고 없으면 기능 이름과 간결한 보고를 기본값으로 둔다.

실제 설계나 실행을 바꿀 미정 결정이 있으면 한 번에 하나만 묻는다. 선택지, 추천과 이유, 직접 입력을 제공한다. 다룰 질문 수를 알리고 앞 답을 다음 질문에 반영한다. 새 질문 수와 경과, 재질문할 필요가 없었던 출처를 기록한다. 운영 비용·범위·권한이 미확인이면 그 결정에 의존하는 작업을 보류한다. 사람의 상세 답은 소통 계약의 로컬 본문으로 보존하고 기록에는 안전한 참조만 남긴다.

## ③ 설계

필수 업무 표에 담당, 맡는 일, 하지 않는 일, 결정 주체, 다음 수신자와 증거를 적는다. 역할마다 근거가 있는 필수 업무 또는 독립 검토를 하나 이상 맡긴다. 업무를 합치거나 나눌 때는 권한, 검토 독립성, 작업 충돌·동시성, 도구·제공자 근거를 적는다. 담당 누락과 근거 없는 역할이 모두 0인지 확인한다. 원형은 [역할 후보](references/role-archetypes.md)에서 필요한 것만 고른다.

팀 계약에서 제공자 독립성이 필요한 검토는 작성자와 다른 역할과 실제 제공자로 배정한다. 다른 제공자가 미실행이면 [결정 권한 정본](../pace-project-dev/references/decision-rights.md) A-3의 B1에 따라 같은 제공자의 새 세션을 쓰고 사유와 `cross: false`를 남긴다. 양쪽이 미실행이면 A-3으로 판정한다. 같은 파일·환경을 다루는 작업은 충돌 자원을 먼저 확인하고, 독립 범위만 worktree로 병렬화한다. 합의 변경·프로덕션 배포·새 유료 비용은 각각 A-1·A-2·A-4를 대조한다.

상태를 넘길 때 `HANDOFF: <수신자> | <요청> | <근거>`와 검증 기준을 적는다. 실행 전 대조에서 근거가 불명확하면 먼저 조사한다. 조사 뒤에도 근거와 범위를 확인할 수 없거나 위임 범위가 다르면 해당 실행을 보류하고 역할의 HANDOFF 수신자에게 결정 주체·근거·선택지·추천을 보낸다. 해결안을 반환하는 역할의 수신자는 호출자다. 결정 주체는 정본 A로 판정하고 독립 작업은 계속한다. 소통 원장이 있는 프로젝트에서는 `scope_check`와 `ready`를 대조하고 실제 증거를 확인해 종결한다.

## ④ 작성·동기화

설계와 쓰기 권한이 확인된 저장소에서 `pace team new <이름> --role <lead|maker|reviewer|coordinator>`로 원본을 만든다. `.pace/team/agents/`의 원본에 단계, 업무, 금지 항목과 결정 경계를 채운다. 기존 원본·공통 실행 전 대조 문단·점검 표지를 보존하고, 공통 문단 바로 뒤에 위 조사와 정본 A를 설명하는 별도 문단을 둔다. `pace team sync`로 Claude와 Codex 생성물을 갱신한다. 기존 역할 이전은 대상 역할과 추가 설정을 대조하고 승인된 변경만 적용한다.

권한 조율은 lead, 산출물 제작은 maker, 독립 판정은 reviewer, 위임·승인 전달은 coordinator 종류를 검토한다. 실제 업무 배정은 `pace project start P### --role <이름> --agent <claude|codex>`에 역할과 제공자를 함께 지정한다.

## ⑤ 검증

`pace team sync --check --json`에서 exit와 `differences`를 확인한다. 원본·생성물의 차이가 있으면 원본을 검토한 뒤 sync를 다시 실행한다. 승인된 호출 범위와 비용을 확인한 뒤 단일 역할은 `pace team verify <이름> --agent <claude|codex>`, 전체 역할은 `pace team verify --all`로 적재를 확인한다. 전체 역할에서 한 호스트만 확인할 때는 `--all --agent <호스트>`를 쓴다. `Report:` 경로의 호스트·원본 지문·요청 설정·관측 모델·판정과 누락 이유를 기록한다. 확인 필요와 실패, 미실행을 구별한다. 이 판정은 prompt 적재 관측이다. 현장 업무, 사용자 승인 이행, native 역할 유지에는 별도 실행 근거가 필요하다.

## ⑥ 회고

마감의 `METRICS.md` 팀 절과 사용 가능한 팀 stats JSON·`TEAM-RETROSPECTIVE.json`을 읽는다. 미사용 후보와 반복 지적에서 관측 구간, 출처, 수집 누락, 실제 맡긴 일을 확인한다. 부분 수집으로 드러난 후보는 유지하며 빠진 근거를 요청한다. 충분히 관측된 중복 업무는 합침·제외 후보로 제안하고 필수 업무와 독립 검토를 다시 대조한다. 반복 지적은 조건·금지·인계 중 실제로 바꿀 문장과 연결한다. 변경 1~3건 또는 근거 있는 무변경과 다음 검증 방법을 제안한다. 실제 적용·승인은 해당 결정 주체에게 남긴다.
