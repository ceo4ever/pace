# 저장소 맞춤 에이전트 팀

필수 업무의 담당과 권한, 독립 검토, 인계를 저장소의 팀 문서나 프로젝트 설계에 표로 남긴다. 이 스킬은 저장소 역할을 설계한다. 개인 비서의 이름·말투·개인 메모리는 사용자 프로필에서 관리한다.

## 시작 모드

저장소 루트에서 `pace team list`로 현재 원본을 확인한다. `loadTeam`이 읽는 새 경로 `.pace/team/agents/<name>.md`와 옛 경로 `.pace/team/<name>.md`를 모두 포함한다. 전용 xhigh 경로 `.pace/team/agents-xhigh/<name>.md`도 확인한다. 목록 읽기나 원본 검증이 실패하면 문제를 확인하고 모드 선택을 보류한다. 원본이 비어 있을 때만 `.claude/agents/*.md`와 `.codex/agents/*.toml`에 실제 native 정의가 있는지 살핀다.

| 확인 결과 | 모드 | 수행 |
|---|---|---|
| PACE 원본과 native 정의가 모두 없음 | 신규 생성 | ①~⑤에서 실제 업무와 권한을 분석해 원본을 설계한다. |
| 새 경로나 옛 경로에 PACE 원본이 있음 | 갱신 | 현재 팀 원본 전체를 기준으로 아래 갱신 절차를 따른다. |
| PACE 원본 없이 native 정의가 있음 | 이전·재구성 | 기존 업무·권한·호스트 설정을 대조해 PACE 원본 초안을 만들고, 그 초안과 최근 기록을 갱신 절차에 넣는다. 원본 쓰기와 native 재생성은 ④에서 적용한다. |

세 모드 모두 ①·③의 필수 역할 점검과 ⑤의 증거 확인을 거친다. 이전에서 사용자 소유 native 경로와 새 생성물이 겹치거나 기존 권한을 보존할 방법이 확인되지 않으면 해당 반영을 보류하고 근거와 대안을 낸다.

## ① 분석

정의서, `AGENTS.md`, 백로그, 기존 역할·스킬, 스택과 실행 명령을 읽는다. 업무 단계, 반복 산출물, 필수 검토, 사용자 승인과 공유 자원을 뽑고 파일·절 또는 행으로 근거를 남긴다. 기존 역할이 있으면 맡는 일·하지 않는 일과 실제 업무 표부터 대조한다. 신규 저장소라면 합의한 예상 단계와 미확인 항목을 표시한다.

병렬 프로젝트, 세 단계 이상의 지속 업무, 다른 제공자가 필요한 검토는 팀 설계를 검토할 단서다. 한 역할과 기존 검토 절차로 필수 업무를 충족하면 그 근거를 남긴다.

세 모드 모두 [필수 역할 정본](references/required-roles.md)의 원형 자리를 확인한다. 등록 담당과 판정 시점에 맞춰 합의 원문을 요건 ID와 대조하고, 등록 누락을 별도 표로 기록한다.

## 기존 팀 갱신

1. 기존 원본 전체의 맡는 일·하지 않는 일·결정 경계·등급을 기준으로 고정한다. 실제 업무와 기대가 달라진 곳을 찾기 위해 정의서·`AGENTS.md`·백로그·스킬의 변경도 대조한다.
2. 실제 완료 시각을 근거로 최근 프로젝트 최대 다섯 건을 고른다. 요청이 특정한 프로젝트나 진행 중 기록을 더 볼 때는 선택 이유와 관측 범위를 남긴다. 팀 채택 여부와 무관하게 `log.jsonl`의 질문·에스컬레이션·결정·검토와 역할 배정·업무 기록을 읽는다. 팀 미채택 기록은 수행 업무와 담당 공백의 근거로 쓰고 구성원별 호출 수·시간·토큰은 미확인으로 적는다.
3. 마감 `METRICS.md`의 팀 절, `TEAM-RETROSPECTIVE.json`의 `definitionChanges`·`unusedRoles`, 프로젝트와 태스크의 `REVIEW-LOG.jsonl`, 참여 소통 원장의 확인 가능한 사건을 대조한다. 수치는 `호출 수 … / 시간 … / 토큰 …`으로 구분해 적는다. 역할과 관측 구간에 맞는 [팀 측정 근거](../../docs/TEAM-METRICS.md#측정-입력)가 확인된 수치만 적고, 해당 근거 또는 수집값이 없는 수치에는 `미확인`을 적는다. 호출 조건과 미사용 영수증은 비참여 칸의 근거다. 호출 수 0은 호출 수치 자체가 수집됐을 때 쓴다. 업무 메모는 업무 칸의 관측에 사용한다. 허브 쪽 업무는 `BACKLOG.md` 결정·기록과 백로그의 `REVIEW-LOG.jsonl`에서도 찾는다. 마감 회고가 처리한 지적은 처리 근거를 연결하고 같은 근거로 재제안하지 않는다.
4. 에이전트별 검토표를 쓴다. 모든 행에는 저장소 기준 실제 상대 경로와 행 번호를 `파일:행`으로 남긴다. 역할 원본을 대조했지만 관측 자료가 없으면 비교한 원본 위치와 미확인 항목을 남긴다. 담당이 배정되지 않은 반복 업무는 실제 기록과 함께 별도 행에 둔다.

| 에이전트·정의 | 실제 맡은 일 | 담당 공백 | 반복 지적 | 비참여 | 호출 수·시간·토큰 | 근거(파일:행) |
|---|---|---|---|---|---|---|
| 역할 이름과 원본 | 관측된 업무 | 반복됐으나 담당이 없는 일 | 다시 발생한 지적과 처리 여부 | 관측 상태 | 관측값과 범위 또는 미확인 | 근거별 위치 |

검토표를 내기 전에 호출 수의 숫자마다 집계된 호출 자료의 위치를 대조한다. 시작 행·업무 메모의 행 수와 비참여 영수증만 있는 경우 호출 수는 `미확인`이다. 작업 시간과 토큰은 두 수치의 역할·구간 근거를 따로 확인한다.

5. [팀 측정](../../docs/TEAM-METRICS.md#필수-역할-비참여와-호출-기록)의 호출 조건 미발생·기록 부족(미확인)·실제 미사용을 유지한다. 호출 조건 미발생이나 기록 부족만으로 합침·제외를 제안하지 않는다. 업무 중복이나 합의된 담당 변경처럼 별도의 근거가 있으면 그 근거를 제안에 명시한다. 실제 미사용 관측도 역할의 필수 업무와 독립 검토 담당을 다시 대조할 입력으로 쓴다.
6. 개선·추가·합침·제외 제안마다 관측 근거, 바꿀 역할·범위, 필요한 검증과 결정 주체를 적는다. [결정 권한 정본 A](../pace-project-dev/references/decision-rights.md#a-결정-주체)로 주체를 판정한다. 합의 범위 안의 정리는 위임받은 PM이 결정하고, A에 해당하는 변경은 owner 결정까지 보류한다. 해당 주체의 승인과 반영 대상이 대조되기 전에는 팀 원본과 native 생성물을 유지한다. 승인 범위는 ④·⑤에서 적용하고 확인한다.

## ② 인터뷰

출처에서 이미 정한 항목을 적고 다시 묻지 않는다. 누가 결정하는지, 독립 worktree와 공유 자원 사용, 요청 모델·등급·비용 한도를 확인한다. 이름과 말투는 기존 선호를 쓰고 없으면 기능 이름과 간결한 보고를 기본값으로 둔다.

실제 설계나 실행을 바꿀 미정 결정이 있으면 한 번에 하나만 묻는다. 선택지, 추천과 이유, 직접 입력을 제공한다. 다룰 질문 수를 알리고 앞 답을 다음 질문에 반영한다. 새 질문 수와 경과, 재질문할 필요가 없었던 출처를 기록한다. 운영 비용·범위·권한이 미확인이면 그 결정에 의존하는 작업을 보류한다. 사람의 상세 답은 소통 계약의 로컬 본문으로 보존하고 기록에는 안전한 참조만 남긴다.

## ③ 설계

필수 업무 표에 담당, 맡는 일, 하지 않는 일, 결정 주체, 다음 수신자와 증거를 적는다. 역할마다 근거가 있는 필수 업무 또는 독립 검토를 하나 이상 맡긴다. 업무를 합치거나 나눌 때는 권한, 검토 독립성, 작업 충돌·동시성, 도구·제공자 근거를 적는다. 담당 누락과 근거 없는 역할이 모두 0인지 확인한다. [선택 역할 후보](references/role-archetypes.md)는 필요한 것만 고른다.

[필수 역할 점검](references/required-roles.md#정의-대조)에서 등록된 요건 전부를 검토한다. 역할이 없고 적용할 요건의 선행 장치를 모두 사용할 수 있으면 저장소 맞춤 추가안을 낸다. 정의가 있으면 빠진 요건의 개선안을 낸다. 요건 ID마다 판정과 근거를 남기고, 요건 미등록과 선행 장치 보류는 정본에 정한 상태로 표시한다.

팀 계약에서 제공자 독립성이 필요한 검토는 작성자와 다른 역할과 실제 제공자로 배정한다. 다른 제공자가 미실행이면 [결정 권한 정본](../pace-project-dev/references/decision-rights.md) A-3의 B1에 따라 같은 제공자의 새 세션을 쓰고 사유와 `cross: false`를 남긴다. 양쪽이 미실행이면 관문을 보류하고 허브와 독립 검토를 복구한다. 검토를 생략·완화하거나 증거 공백을 안고 진행할 때 A-3으로 owner에게 묻는다. 같은 파일·환경을 다루는 작업은 충돌 자원을 먼저 확인하고, 독립 범위만 worktree로 병렬화한다. 합의 변경·프로덕션 배포·새 유료 비용은 각각 A-1·A-2·A-4를 대조한다.

상태를 넘길 때 `HANDOFF: <수신자> | <요청> | <근거>`와 검증 기준을 적는다. 실행 전 대조에서 근거가 불명확하면 먼저 조사한다. 조사 뒤에도 근거와 범위를 확인할 수 없거나 위임 범위가 다르면 해당 실행을 보류하고 역할의 HANDOFF 수신자에게 결정 주체·근거·선택지·추천을 보낸다. 해결안을 반환하는 역할의 수신자는 호출자다. 결정 주체는 정본 A로 판정하고 독립 작업은 계속한다. 소통 원장이 있는 프로젝트에서는 `scope_check`와 `ready`를 대조하고 실제 증거를 확인해 종결한다.

## ④ 작성·동기화

설계와 쓰기 권한이 확인된 저장소에서 `pace team new <이름> --role <lead|maker|reviewer|coordinator>`로 원본을 만든다. `.pace/team/agents/`의 원본에 단계, 업무, 금지 항목과 결정 경계를 채운다. 기존 원본·공통 실행 전 대조 문단·점검 표지를 보존하고, 공통 문단 바로 뒤에 위 조사와 정본 A를 설명하는 별도 문단을 둔다. `pace team sync`로 Claude와 Codex 생성물을 갱신한다. 기존 역할 이전은 대상 역할과 추가 설정을 대조하고 승인된 변경만 적용한다.

권한 조율은 lead, 산출물 제작은 maker, 독립 판정은 reviewer, 위임·승인 전달은 coordinator 종류를 검토한다. 실제 업무 배정은 `pace project start P### --role <이름> --agent <claude|codex>`에 역할과 제공자를 함께 지정한다.

[문제 해결자 원형](references/required-roles.md#문제-해결자-요건)의 TS-07~TS-15는 독립 동작과 호출자 인계를 검증한다. `team new --role reviewer`의 공통 문단·표지를 보존한 뒤 전용 `xhigh` 원본으로 옮기고 동기화한다. `team verify`의 지침 적재 관측과 [지정 모델·effort의 실제 적용](../../docs/TEAM.md#문제-해결자-호출과-실제-적용)을 각각 확인한다. 검토 판정 역할은 원래의 독립 검토 절차로 배정한다.

## ⑤ 검증

필수 원형마다 등록 대조와 정의 대조 결과가 있는지 확인한다. 미등록과 선행 장치 보류는 담당·재점검 조건을 남긴다.

`pace team sync --check --json`에서 exit와 `differences`를 확인한다. 원본·생성물의 차이가 있으면 원본을 검토한 뒤 sync를 다시 실행한다. 승인된 호출 범위와 비용을 확인한 뒤 단일 역할은 `pace team verify <이름> --agent <claude|codex>`, 전체 역할은 `pace team verify --all`로 적재를 확인한다. 전체 역할에서 한 호스트만 확인할 때는 `--all --agent <호스트>`를 쓴다. `Report:` 경로의 호스트·원본 지문·요청 설정·관측 모델·판정과 누락 이유를 기록한다. 확인 필요와 실패, 미실행을 구별한다. 이 판정은 prompt 적재 관측이다. 현장 업무, 사용자 승인 이행, native 역할 유지에는 별도 실행 근거가 필요하다.

## ⑥ 회고

마감의 `METRICS.md` 팀 절과 사용 가능한 팀 stats JSON·`TEAM-RETROSPECTIVE.json`을 읽는다. 미사용 후보와 반복 지적에서 관측 구간, 출처, 수집 누락, 실제 맡긴 일을 확인한다. 부분 수집으로 드러난 후보는 유지하며 빠진 근거를 요청한다. 충분히 관측된 중복 업무는 합침·제외 후보로 제안하고 필수 업무와 독립 검토를 다시 대조한다. 반복 지적은 조건·금지·인계 중 실제로 바꿀 문장과 연결한다. 변경 1~3건 또는 근거 있는 무변경과 다음 검증 방법을 제안한다. 실제 적용·승인은 해당 결정 주체에게 남긴다.
