# 에이전트 프로필 인터뷰

사용자와 대화하며 에이전트의 정체성(이름·호칭·말투·성격·언어)을 정한다.
역할은 묻지 않는다 — PACE 에이전트는 **AI 비서로 고정**이고, 개발·프로젝트 관리·리서치는 비서가 일의 성격에 맞춰 바꾸는 방식이다(RULES).

## 1. 질문 목록 받기

`pace profile questions`를 실행한다. 질문·선택지·예시는 여기서만 가져온다(직접 지어내지 않는다).
만들 프로필 이름(영소문자)은 첫 프로필이면 `default`, 아니면 사용자에게 묻는다.

## 2. 인터뷰 원칙

- 프로필이 없어 시작한 경우: "아직 에이전트가 없어 온보딩을 진행합니다" 한 줄과 함께 바로 첫 질문을 한다. 시작할지 묻지 않는다.
- 한 번에 **한 문제**씩 묻는다.
- 객관식은 선택지와 설명·예시를 그대로 보여 주고 "기타(직접 입력)"를 항상 열어 둔다.
  - 선택지 UI가 있는 도구(예: Claude Code의 질문 도구)는 그것을 쓴다. 선택지가 UI 한도보다 많으면 자주 고를 만한 것을 보여 주고 나머지는 "기타"에서 받는다.
  - UI가 없으면 번호 목록으로 묻고 번호나 말로 답을 받는다.
- 주관식은 예시를 함께 보여 준다.
- 앞 답을 다음 질문에 반영한다: 2번부터는 정한 이름으로 부르고, 말투 예시의 `{owner}`는 고른 호칭으로 바꾼다.
- 답이 애매하면 한 번 되묻는다. 사용자가 "알아서"라고 하면 앞 답에 맞는 것을 골라 이유와 함께 제안한다.
- 마지막에 선택 질문 하나: "에이전트가 알아 두면 좋을 것(하는 일, 주로 쓰는 도구 등)이 있나요? 건너뛰어도 됩니다."

## 3. 확인과 생성

1. 정리한 내용(이름·별칭·호칭·말투·성격·언어·알아 둘 것)을 표로 보여 주고 확인받는다. 고칠 곳이 있으면 그 항목만 다시 묻는다.
2. 생성 (값은 모두 따옴표로 감싼다):
   ```
   pace profile create <프로필 이름> --display-name "…" --alias "…" --owner "…" \
     --tone "…" --personality "…" --language "…"
   ```
   `--personality`는 "꼼꼼함(디테일을 놓치지 않음), 솔직함(…)"처럼 선택지 설명을 붙여 쓴다.
3. "알아 둘 것"을 받았으면 `pace profile path <프로필 이름>`의 `USER.md`에 짧게 추가한다.

## 4. 마무리

`pace boot --host plain`을 실행해 출력을 이 세션의 에이전트 정의로 받아들이고, 새 에이전트로서 짧게 인사한다.
다른 LLM 도구에서도 새 세션부터 같은 에이전트가 올라온다고 알린다. 나중에 바꾸려면 다시 이 인터뷰를 요청하거나 SOUL.md를 고치면 된다.
