# Canvas preview contract

`plan.json` is the semantic source. Each `canvas` entry has `screen`, relative `document`, product `frame`, `state`, trace `refs`, and an array of `links` with `element` and exactly one of `to: {screen,state}` or `unlinked: true`. Invalid destinations are errors, never silently converted to unlinked. A screen/state, document/frame, and element within a frame must be unique. Use BR references as format-only identifiers; UC/AC/F references must exist in the plan. A data screen needs 기본, 오류, and 빈 or 로딩. Mixed legacy input uses Canvas for covered screens. A screen without any visual entry is not checked for states.

Create Canvas first, then inspect it with canvas-read and record actual frame and element IDs. A missing or replaced ID is an error; inspect the edited document and explicitly change the plan ID before regenerating. Names never select replacements. Product frames, not explanatory panels, are inputs. Relative paths use forward slashes and end in `.canvas.json`; absolute paths, drive prefixes, backslashes, control characters and empty, dot or parent segments are rejected. The preview generator must additionally reject Windows reserved names and unsafe realpaths or symlinks.

Frame and element IDs beginning with `-` are not accepted by the preview contract. If a generated document has one of these IDs, explicitly assign a supported ID in the editable document and update the plan before generating; a name is not substituted automatically.

The generator rejects recognized canvas-wireframe board labels among the selected frame's direct children; choose the product frame inside the board. It does not determine whether a sibling element visually obscures a hotspot, so inspect the rendered result for that condition.

An exact renderer warning that a requested font is missing and fallback was used is retained per screen in the map and shown as a review notice; inspect text clipping and layout. The map records the generating platform, architecture and Node version, not an inferred fallback font or browser version. Unknown, mixed or malformed renderer warnings, read warnings and unsupported geometry remain errors. The recorded environment is informational and does not itself make verification stale.

`pace intent preview <OUT> [--root <product-repository>]` reads plan.json, selected Canvas documents and product frames using the bundle adjacent to the running PACE source or installation, and creates `canvas/renders/`, `preview-map.json`, and `preview.html` under OUT. Use `pace intent preview <OUT> --verify` to check the existing output and its sources without regenerating it. No application API, AI call, Canvas rewrite, manually supplied coordinates or guessed navigation is allowed. Unsupported transforms, missing Chrome, frames, elements, targets or images fail with exit 1.

For existing or changed screens, pass `--root <product-repository>` during generation to resolve plan evidence paths; the default is the current working directory, matching `pace intent render` and `verify`. Preview `--verify` checks the recorded plan, Canvas, output and tool hashes and does not recheck external evidence paths.

The map records document paths, IDs, element names and bounds, render origin and dimensions, and tool/template versions. Hash the entire plan.json and Canvas bytes and each PNG; any plan edit, including unrelated content, makes the result stale. The map records a SHA-256 over its own canonical JSON with its hash field omitted; HTML includes a generation marker and that map hash. The map also records an HTML hash calculated with the embedded map hash replaced by a fixed placeholder; verify using the same normalization to avoid a circular dependency. Canonical JSON sorts object keys recursively while preserving array order and encodes UTF-8 without whitespace. These hashes detect accidental edits, not a malicious writer who recalculates them. Revalidate all sources and image dimensions before use.

Replace generated outputs atomically only after validating marker, prior provenance and hashes. A missing marker, changed map/HTML/image or conflicting user file is an error; preserve it and direct the user to another output path or explicit handling. A failed replacement preserves the previous valid outputs. Canvas is never overwritten by preview regeneration. Windows locked-file failures must be surfaced and preserve existing content.

If a stopped or failed run leaves `.pace-preview.lock` or `.pace-preview-work-*`, do not remove them automatically. Confirm no preview process is still using the output, inspect the work folder's `journal.json` and backups, and compare the recorded paths and hashes with the affected files before deciding how to restore them. Preserve both the work folder and existing user files if ownership or recovery is uncertain; use a different output folder until the retained material is handled explicitly.

Legacy `wireframes` input is readable and verifiable. Default `pace intent render <OUT>` preserves any old wireframe.html and reports `--legacy-wireframe`; the explicit option renders old wireframes when present. New plans do not need wireframes. Non-wireframe planning documents continue to render.

Preview output must render untrusted text using escaped JSON data and text nodes under a restrictive CSP; it must not execute document strings or load external URLs. Store document paths relative to OUT, never absolute machine paths. Derive PNG filenames from safe indices or hashes, not frame, state, or element strings. BR03 must compare document/frame identity after realpath and Windows case normalization so aliases cannot bypass uniqueness checks. Reject Windows reserved names and segments ending in a dot or space.

A link may target its own screen and state. UNC paths are absolute and rejected. BR03 must validate each source and destination after resolving aliases; same document/frame reached through different case or path spelling is a duplicate.

For HTML hashing the marker is exactly `<meta name="pace-preview-map-sha256" content="__PACE_MAP_HASH__">`. Generate it once, hash the exact UTF-8 HTML bytes with that single marker placeholder (no BOM or newline normalization), then insert the map self-hash into that marker only. Verification requires exactly one correctly formed marker and restores its value to the placeholder before hashing. Embedded display data excludes the map `htmlHash` and self-hash fields to avoid a second cycle. Missing or multiple markers are errors.
