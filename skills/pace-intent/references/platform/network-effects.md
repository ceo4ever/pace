## Looks at

Whether each new user makes the product better for others (same-side or cross-side), the smallest "atomic network" that works on its own, and how to reach it.

## Key questions

- What is the smallest group (a city, a genre, a niche) where both sides find value?
- Which side is seeded first, and how (manual matching, subsidies, bringing existing contacts)?
- Is the effect real for this product, or is value mostly single-player?
- What breaks as it grows (quality drop, spam, saturation)?

## Common gaps

- Planning for scale before one atomic network works.
- No single-player value, so early users leave an empty platform.
- Growth assumptions without a seeding plan.

## Turning gaps into questions

Propose an atomic network from the request and evidence; ask the user to pick the first niche.
Example: "처음 성공시킬 작은 시장은? ① 요리·먹방 쇼츠 편집 하나(추천 — 편집 양식이 비슷해 매칭이 빨라요) ② 서울 지역 크리에이터 ③ 장르 제한 없이 · 직접 입력 — 첫 백로그의 범위와 초기 모집 방법이 달라져요."

## Tensions

- With **unit economics**: seeding costs money per user — ask the budget and how long.
- With **Now-Next-Later roadmap**: expansion sits in Next, but growth pressure pulls it into Now — ask what evidence from the atomic network unlocks the next niche.

## When not to use

Products without user-to-user value; L0–L2 internal features.

## Output form

Form: a short plan — 효과 종류(같은 쪽/다른 쪽) · 원자 네트워크 · 첫 시딩 방법 · 혼자 써도 되는 가치 · 커지면 깨지는 것.
Link to first layer: multi-sided market gives the sides; journey map gives single-player value; roadmap sequences the expansion.
When to produce: L3 platforms; it becomes the "Now" of the roadmap.

## Closing

End with the atomic network written as one sentence and the seeding action for the first week.
