## Looks at

The one metric that captures delivered value (North Star), and the time-boxed objectives and measurable key results that move it.

## Key questions

- Which single number grows only when customers get the core value (e.g. "matched edits delivered per week")?
- What inputs drive it, and which can this team move?
- For the next period: one or two objectives, each with 2–3 key results that are numbers, not tasks?
- How is it measured — which event, where logged?

## Common gaps

- Vanity metrics (sign-ups, downloads) as the North Star.
- Key results written as tasks ("launch X").
- No baseline, so targets are guesses.

## Turning gaps into questions

Propose the North Star from the core interaction; ask the user to confirm it and the period.
Example: "성공을 하나의 숫자로 본다면? ① 주간 완료된 편집 건수(추천 — 양쪽이 모두 가치를 얻었을 때만 늘어요) ② 가입자 수 ③ 월 거래액 · 직접 입력 — 첫 대시보드와 완료 기준이 달라져요."

## Tensions

- With **unit economics**: a growth North Star can hide negative margins — ask "which margin floor would make you stop growth spending?" and make it a guardrail key result.
- With **MoSCoW**: features that do not move the North Star input drop out — ask which input each Must moves.

## When not to use

L0–L2 requests; a one-off internal tool.

## Output form

Form: North Star (definition, event, baseline) + for the first period 1–2 objectives × 2–3 key results with numbers.
Link to first layer: purpose ladder gives the outcome; GWT criteria make the measurement events concrete.
When to produce: L3 plans; it sets each backlog's goal line.

## Closing

End with the North Star sentence, its measurement event, and the first-period target — each backlog's goal points to one key result.
