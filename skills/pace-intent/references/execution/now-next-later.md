## Looks at

What is being worked on now, what comes next, and what is later — as problems to solve, not dated features — and how the plan splits into backlogs.

## Key questions

- Which problem must be solved now for the atomic network / first fit to work?
- What is next once that works, and what evidence moves an item from Next to Now?
- What is explicitly later (and why), so it does not leak into Now?
- Which items are separate backlogs (different users, independent start, different repository)?

## Common gaps

- Dates on items that depend on unvalidated assumptions.
- Everything in Now.
- No rule for moving items between columns.

## Turning gaps into questions

Propose the columns from story-map slices and strategy; ask only to confirm what is in Now.
Example: "지금(Now) 칸에 둘 것은? ① 요리 쇼츠 편집 매칭과 에스크로 결제(추천 — 원자 네트워크가 돌아가는 최소) ② 매칭만, 결제는 밖에서 ③ 매칭·결제·리뷰 전부 · 직접 입력 — 첫 백로그 하나의 범위가 정해져요."

## Tensions

- With **MoSCoW**: a Must in one release pulls work into Now while the roadmap tries to keep Now small — ask "which Must can wait for Next without breaking the atomic network?"
- With **network effects**: expansion (Next) depends on the atomic network (Now) — state the evidence that unlocks Next.

## When not to use

L0–L2 requests that fit one project.

## Output form

Form: three columns — Now · Next · Later — each item a problem with its unlock evidence; each Now/Next item maps to a backlog.
Link to first layer: story-map slices and the chosen strategy (multi-sided market, network effects) fill the columns; handoff splits backlogs by the column items (references/handoff.md).
When to produce: L3 always; it is the parent note across sibling backlogs.

## Closing

End with the list of backlogs to create (Now first) and the evidence that moves each Next item forward.
