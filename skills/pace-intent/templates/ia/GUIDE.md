# Information architecture — `ia`

Generated by `pace intent render <docs>` from `docs/plan.json`; this folder holds `template.html` (layout and render code), `schema.json` (page data, `x-pace` metadata), `example.html` (the example rendered), and this guide. While planning, read only this guide, [schema.json](schema.json), and the example data [../_example/plan.json](../_example/plan.json) — never the HTML (D12). Screen text is in the user's language.

## When to make it

L1: only changed or new screens in their place. L2: full tree. L3: top level only.

## First-layer lens questions

Drawing this document exposes these gaps:

- Is every screen reachable from the menu tree (no orphan screens)?
- How deep is each screen, and does depth match how often it is used?
- Which screens need login or a role?
- For an existing product: which screens are 기존 · 변경 · 신규?

## IDs and links

Screens are `SCR-n`; the IA tree nodes point to them. Screen IDs link to IA screen details.

## Data in plan.json

`ia[]` tree (`label`, `screen`, `children`) and `screens[]` (`auth`, `data`, `status`, `evidence`). `evidence` is `path:line` in the product repository and is required for 기존·변경 (collection ladder step 6, names and lines only). Cite source files only — never `.env*`, keys, or other secret files (the check reveals whether a file exists and how long it is). Full shape: [../_base/plan.schema.json](../_base/plan.schema.json).

## Checks

`no-orphans`, `steps-screens`, `existing-evidence` (run `pace intent verify docs --root <product repo>`).

## When not to use

L0; a backend-only change with no screens.
