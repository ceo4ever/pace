# User flows — `flow`

Generated by `pace intent render <docs>` from `docs/plan.json`; this folder holds `template.html` (layout and render code), `schema.json` (page data, `x-pace` metadata), `example.html` (the example rendered), and this guide. While planning, read only this guide, [schema.json](schema.json), and the example data [../_example/plan.json](../_example/plan.json) — never the HTML (D12). Screen text is in the user's language.

## When to make it

L2 always; L1 when the change spans several screens; L3 core flows only.

## First-layer lens questions

Drawing this document exposes these gaps:

- Where does each flow start and end?
- At every decision, are both branches drawn?
- Does any node lead nowhere (dead end) or loop forever?
- Where do error states send the user back to?

## IDs and links

`FL-n` flows list their use cases; screen nodes point to `SCR-n` (click opens the IA screen).

## Data in plan.json

`flows[]` with `nodes` (`start` · `end` · `screen` · `decision` · `state`, grid `col`/`row`) and `edges` (`label`, optional `route` `vh`/`hv`). Full shape: [../_base/plan.schema.json](../_base/plan.schema.json).

## Checks

`flow-dead-ends`, `id-refs`.

## When not to use

Single-screen features.
