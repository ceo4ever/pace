# Wireframes (low fidelity) — `wireframe`

Generated by `pace intent render <docs>` from `docs/plan.json`; this folder holds `template.html` (layout and render code), `schema.json` (page data, `x-pace` metadata), `example.html` (the example rendered), and this guide. While planning, read only this guide, [schema.json](schema.json), and the example data [../_example/plan.json](../_example/plan.json) — never the HTML (D12). Screen text is in the user's language.

## When to make it

L1: changed screens only. L2: every screen. L3: none (or one core screen).

## First-layer lens questions

Drawing this document exposes these gaps:

- Does every screen that shows loaded data have error and empty (or loading) states?
- What does the user see first, and what is the one primary action?
- Which numbered notes explain behaviour, and which feature or AC do they point to?
- Mobile and desktop: does the layout change?

## IDs and links

Each wireframe is a `SCR-n`; notes reference `F-n`, `AC-n`, `UC-n`.

## Data in plan.json

`wireframes[]` with `states` (`기본` required; `빈` · `로딩` · `오류` as needed) made of blocks (`t`: appbar · field · chips · button · card · list · image · message · stats · tabbar …; see the example data), and numbered `notes`. No pixels or styles (D12). Full shape: [../_base/plan.schema.json](../_base/plan.schema.json).

## Checks

`data-states`, `id-refs`.

## When not to use

This template is for explicitly requested legacy rendering. New plans use Canvas as the visual source; see [preview](../../references/preview.md).
