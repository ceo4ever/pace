# 보안

보안은 세 겹이다: **설계에서 영향 판단** → 태스크 reviewer의 보안 관점 → **finish 전 전체 diff 검사**.
저장소 `security` 용도 기준 문서(`docs/README.md` 문서 표)가 있으면 그것이 먼저다. 아래는 PACE 기본값.

## 기본 체크리스트

- **비밀**: 키·토큰·비밀번호·개인 정보가 코드·설정·테스트·`e2e/`·`evidence/`·로그에 원문으로 없다. 환경 변수 이름만.
- **입력**: 외부 입력(인자·요청·파일·환경 변수)을 검증한다. 셸 명령은 인자 배열로 넘기고 문자열 이어 붙이기로 만들지 않는다. SQL은 바인딩.
- **경로**: 사용자 입력으로 만든 경로가 의도한 폴더 밖으로 나가지 않는다(`..`, 심볼릭 링크). 삭제·덮어쓰기는 대상을 확인한다.
- **권한**: 인증·인가 확인을 우회하는 경로가 없다. 기본값이 안전하다(거부 기본).
- **의존성**: 새 의존성은 필요성·출처·버전 고정을 확인한다.
- **오류**: 오류 메시지·로그에 비밀·내부 경로를 흘리지 않는다. 실패가 조용히 성공으로 바뀌지 않는다.
- **되돌리기**: 사용자 설정·데이터를 바꾸는 동작은 백업이나 되돌리는 방법이 있다.

## 민감 경로 모드

설계에서 아래를 건드리면 PROJECT.md 설계의 보안 영향에 적고, 그 태스크 reviewer에게 **보안 관점을 먼저** 보라고 한다. 해당 테스트는 실패 경로(거부·오류)까지 넣는다.

- 인증·권한·세션, 결제·비용
- 사용자 설정·홈 폴더 쓰기(설치기·훅), 세션 시작 경로
- 파일 삭제·복사·이동, 셸 실행
- 외부 전송(네트워크·메시지), 개인 정보

저장소가 기준 문서에 민감 경로 패턴을 선언했으면 그 목록을 쓴다.

## finish 전 판단 검사

PROJECT-CLOSE "보안" 절을 쓰기 전에, 새 맥락(서브에이전트나 새 세션)에 아래를 넘겨 검토받는다.

```
프로젝트 브랜치의 전체 diff(`git diff main...HEAD`)를 보안 관점으로 검토하라.
기준: <이 파일의 체크리스트 또는 저장소 security 문서>. 민감 경로: <설계에 적은 것>.
지적마다 등급(blocking·should_fix·note)과 파일:줄, 문제, 고칠 방법. 파일은 고치지 마라.
```

도구에 보안 리뷰 기능이 있으면 그것을 써도 된다(`tools.md`).

## PROJECT-CLOSE "보안" 절

1. **기계 검사**: `docs/README.md` 환경의 "보안 검사" 명령과 결과. 선언이 없으면 "선언 없음 — 경고"(finish도 경고를 낸다).
2. **판단 검사**: blocking 0건, should_fix 처리, 남긴 위험.
3. **비밀 노출**: finish가 프로젝트 폴더(`e2e/`·`evidence/` 포함)를 검사한다 — 걸리면 원문을 지우고 `*_ref`로. 소스 코드의 비밀은 이 검사가 보지 않는다 — 보안 검사 명령이나 판단 검사로 잡는다.
