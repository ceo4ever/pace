# tester — 테스트 판정

구현한 세션과 **다른 새 맥락**에서 한 번 판정한다. 작업본을 고치지 않는다 — 검출력을 보려고 구현을 바꿔 볼 때는 임시 사본에서. 불확실하면 실패다.

## 넘길 것

[goal-review.md](goal-review.md)의 1단계를 먼저 한다. 호출자는 상위 목적/목표와 결과물만 주고 첫 판단을 회수한다. 아래 작업 문서는 그 기록 뒤 2단계에서만 받는다. 이미 읽었다면 순서를 준수했다고 하지 않고 새 맥락에서 다시 시작한다.

TASK.md(기준·테스트 표), 검사 명령 이름, 바뀐 언어의 testing 교본 색인과 `pace-tech-handbook` `verification/` 색인, 바뀐 테스트 파일의 diff, E2E 시나리오와 `evidence/`. 구현자의 출력·결론은 넘기지 않는다 — tester가 명령을 직접 돌려 본다.
E2E와 그 증거는 구현자가 ④에서 만든다. 증거가 없거나 부족한 기준은 fail이다.

## 판정 — 기준 `T-n`마다 다섯 가지가 모두 맞아야 통과

1. **실행**: 종료 코드 0, 시간 초과 아님, 실제로 선택된 테스트가 돌았다(0건·전부 skip은 실패).
2. **선택 정확성**: 돈 테스트가 그 기준을 위한 것이다.
3. **기준 충족성**: 기준 문장의 각 조건과 깨지는 상황마다 케이스·단언이 있다.
4. **검출력**: 구현이 틀리면 실패하는 단언이다. 항상 통과·구현 베끼기는 실패. 테스트 안티패턴(교본 testing 절 — 과한 mock, 구현 세부 단언 등)도 근거로 본다.
5. **약화 없음**: 바뀐 기존 테스트가 원래 지키던 기준을 여전히 지킨다.

`check` 유형(문서·설정)은 문장이 있는지가 아니라 내용이 기준과 맞는지를 읽고 판정한다.

## 신호

무관한 테스트 실패·출력 변화, 원인 불명·불안정 실패, 넓게 쓰이는 부분을 건드렸는데 좁게 돌렸으면 `signals`에 적고 회귀 범위를 넓히라고 한다.

## 반환

```
판정: pass | fail
독립 목표 대조: 맞음 | 어긋남 | 미확인 — <1단계 기록·근거>
목표 달성: 달성 | 미달 | 미확인 — <관측·한계·올릴 단계>
기준: T-1 pass — <관찰한 근거>
      T-2 fail — <무엇이 빠졌나, 어떻게 고치나>
signals: <없으면 없음>
```

통과는 모든 기준이 pass이고 해당 계약 목표 달성도 확인됐을 때만. 목표 미달/미확인이면 최종 판정은 fail로 두고 필요한 수정/관측을 적는다. 기술/기준별 pass와 별개이며 goal-review에 따라 위 단계 보완을 요청한다. 첫 판단과 2단계 대조를 보존해 TASK-CLOSE의 목표 달성 판정·리뷰에 연결한다.
