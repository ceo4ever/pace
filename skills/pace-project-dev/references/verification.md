# 검증 책임·재검사

SKILL.md에서 옮긴 문서다. 워크트리 PM·허브 PM의 책임 나눔과 재검사 규칙.

## 역할과 검증 책임

| 담당 | 책임 |
|---|---|
| 워크트리 PM | 컨벤션 대조·브레인 정리·보안 검사·테스트·독립 검토·태스크 마감·finish를 수행하거나 위임하고 결과를 판정한다. tester·reviewer의 배정·회수·수정 후 재검토도 맡는다. |
| 허브 PM(main 코디네이터) | 사용자 결정 전달, 검증 대상·결과·증거·미해결 사항 확인, 승인된 병합·배포를 맡는다. 워크트리에서 완료한 동일 검증을 다시 배정하거나 실행하지 않는다. |

main 직접 프로젝트는 한 PM이 두 역할을 맡는다. 검토자 호출 권한 등 도구 제약으로 허브가 기술적으로 대행할 때도 검증 책임은 워크트리 PM에게 있으며, 같은 검토를 양쪽에서 배정하지 않는다. 허브가 별도 구현을 맡는 예외에는 변경 범위와 검증 담당을 먼저 구분한다.

재검사는 관련 코드·테스트·설정·실행 환경 변경, 충돌 해결로 검증 대상이 달라짐, 기존 실행의 오류 또는 구체적인 검증 누락이 있을 때 수행한다. 워크트리 PM이 사유·범위·담당을 기록하고 해당 부분부터 확인한다. 같은 대상의 성공한 검사·독립 판정은 실행 명령, 대상 커밋과 이후 변경 범위, 종료 코드·결과 위치를 확인해 활용한다. 실행·통과가 확인된 검사의 상세 로그가 부족하다는 이유만으로 동일 검사를 반복하지 않는다. 가능한 원문은 최초 실행에서 보존하고 누락은 한계로 기록한다.

## finish 검사 반복 금지

   태스크 검증과 `finish`의 필수 자동 검사는 유지한다. `finish` 직전·직후에 성공 출력을 수집하거나 같은 최종 상태를 재확인하려고 동일 명령을 별도로 반복하지 않는다. 재검사가 필요하면 위의 역할과 검증 책임에 따라 사유·대상·담당을 정한다.
