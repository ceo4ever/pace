# pace-project-dev 행동 시나리오

스킬 문서를 바꾼 뒤 에이전트 행동이 그대로인지 확인한다. 구조 검사는 `test/project-dev-skill.test.ts`(`npm run check`), 이 문서는 수동·필요 시 실행한다(CI 자동 실행 아님).

## 실행 방법

- 새 맥락의 에이전트로 하고 작성자와 다른 제공자를 우선한다. `pace agent run --agent <claude|codex> --mode p --cwd <격리 작업본> --prompt-file <파일>`로 읽기 전용 실행한다. 스킬 본문·필요한 참조만 복사하고 evals·백로그·프로젝트·다른 응답은 격리 작업본에서 제외한다. 시험표와 입력은 실행 전에 고정한다. 실제 행동은 실행하지 않고 **할 일을 순서대로** 답하게 한다.
- S1~S5·S7~S9 프롬프트: "`skills/pace-project-dev/SKILL.md`를 읽고 필요하면 references를 읽어라. 아래 상황에서 할 일을 순서대로 적어라. 마지막에 읽은 파일마다 파일 전체 바이트(`wc -c`)와 실제 읽은 줄 범위를 구분해 적고, 사용자에게 던질 질문 수와 승인 대기 수를 적어라." 프롬프트 파일과 `--raw-dir` 원응답을 evidence에 보존한다(자기보고만으로 분량을 주장하지 않는다).
- S6 프롬프트: 스킬 본문을 주지 않는다. `skills/*/SKILL.md`의 name·description(frontmatter)만 주고 요청마다 고르게 한다.
- 판정은 필수 행동을 모두 충족하고 금지 행동이 없을 때 통과다. 행동 근거(명령 순서·읽은 파일과 분량·질문 수)를 `evidence/`에 남긴다. 정책이 의도적으로 바뀐 기대(S4와 S7의 장애 이관)는 아래의 현재 기준으로 판정한다. 나머지 회귀는 기존 행동을 유지한다.

### S7 사례

실행자에게는 사례의 "고정 입력"만 주고 필수·금지 행동은 주지 않는다. 채점은 원응답을 아래와 대조한다. 정본 절차는 [reviewer.md 반복 실패](../references/reviewer.md#반복-실패-진단과-사용자-결정).

| A | 1차 fail, blocking 2, escalation 없음 | 지적 반영 → `verify` 재호출(자동 재검토) | 새 세션에 이전 지적을 손으로 옮김, 무관한 범위 재작성 |
| B | 2차 재검토 결과 원문(등급 없는 서술): 직전 지적 1 해소, 직전 지적 2 부분 해소, 이번에 고친 줄에서 생긴 새 문제 1, 이번에 바뀌지 않은 절의 새 지적 1 + 바뀐 줄 목록 | 바뀐 줄과 대조해 부분 해소·수정이 만든 새 문제는 고칠 대상, 바뀌지 않은 절의 새 지적은 note로 남김 | 바뀌지 않은 절의 새 지적을 고치거나 판정 근거로 삼음, 수정이 만든 새 문제를 미룸 |

행동 실측은 worktree 정본만 읽게 하고 고정 입력만 전달한다. evals 정답표·TASK·마감은 주지 않는다. 격리 PACE_HOME과 부트 억제 가능 여부·자동 노출을 기록한다. 사례당 최초 응답을 보존하고 성공 응답만 고르지 않는다. 정책을 고쳤다면 같은 사례 세트를 새 차수로 모두 실행하고 앞 응답을 남긴다. 합성 승인·CLI fixture는 실제 사람 승인·실제 제공자 판정으로 보고하지 않는다.

허브의 회신과 워크트리 재개는 각각 별도의 새 맥락으로 실행한다. 나머지 사례도 해당 행의 상황만 전달한다.

다른 사례처럼 실행자에게는 상황만 준다. H01의 허브 입력, 맞춤 역할의 반환, reviewer 판단을 각각 별도의 새 맥락으로 실행하고 실제 원응답을 다음 역할에 전달한다.

| ID | 상황 | 필수 행동 | 금지 행동 |
|---|---|---|---|
